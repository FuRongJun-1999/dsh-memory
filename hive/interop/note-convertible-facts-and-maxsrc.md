# 缺陷与修正：可转化缺口口径的两处错配（事实串味 + max-src 截断）

- 提出时间：2026-09-19 02:5x（环二第 541 轮）
- 处置：编外（本侧）自检 → 修正缓存生成器与驱动采集参数 → 复测 → 提交本说明
- 状态：待编外复核（Zero-Trust）。

## 1. 缺陷 A：事实串味 → 「可转化」被高估

`_convertible_scan.py`（上一轮新增的选靶缓存生成器）在**整文件**上调用
`cond_facts.file_facts` 再**按 name 匹配**取该符号事实。同名符号（如多个类各自的 `close`）
会互相串味：把「无必需形参」的符号配上别处「有必需形参」的事实 → 误判为可转化。

实测：`md_cg/mdcg.py` 的 `MdCG.close`/`MdCG.list_goals` 被判可转化，
而采集器给它们的事实是 `required=[]` —— 驱动按缓存开批，写的条件必然过不了锚点门禁。

**修正**：与 `collect_files2.facts_of` 完全同法——把该符号**自己的源码段**（类取 `__init__`）
写入临时文件后 `file_facts`，取 `recs[0]`，不做按名匹配。

## 2. 缺陷 B：驱动采集 `--max-src` 与缓存/lane 不一致 → 可转化符号被整条截掉

驱动 `collect_files2` 用默认 `--max-src 4000`，而缓存与 lane 用 12000。
4k~12k 的符号被驱动整条跳过——而这些**恰恰常是有必需形参的可转化符号**。

实测：`md_cg/mdcg.py` 的全文件只有两个可转化符号 `MdCG.add`(9278 字符)、`MdCG.search`(5927 字符)，
两者都被 4000 截掉，驱动每批只剩三个无必需形参符号 → **每批 `PASS 0 SKIP 3`**，
连续多轮空烧（c322/c327/c330/c335 均如此）。

**修正**：驱动两处采集（主批 + findings 回灌批）都加 `--max-src 12000`，与 lane 和缓存同口径。

## 3. 实测

- 修正后 `BATCH c338 file=md_cg/mdcos.py`：`COLLECT SKIP_TRUNC 0 (max_src=12000) | COLLECT n=10`
  → **`PASS 1 SKIP 9`**（修正前同文件为 `COLLECT SKIP_TRUNC 5 (max_src=4000)` → `PASS 0 SKIP 5`）。
- 口径重算（发布线）：已覆盖 2364 / 可转化 **41**（修正前误报 37）/ 结构性 **111**（修正前 115）/
  同名多定义 5 / 片段超限 1 —— 与采集器逐符号一致（已用 `md_cg/mdcg.py` 交叉验证：n=5，
  其中 required 非空恰为 `MdCG.add`、`MdCG.search`）。

## 4. 边界

- 可转化数从 37 变为 41 不是「缺口变多」，而是**口径修正**：修正前既有高估（事实串味把无锚符号算进来）
  也有低估（被截断的可转化符号没算进来）。
- 结构性 111 仍是现行锚点判据下不可达的部分，是否处理属使用者裁决面。
