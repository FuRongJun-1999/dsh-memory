# 方法改进：多文件批次 lane（长尾 1 符号文件不再逐文件开批）

- 提出时间：2026-09-19 03:1x（环二第 543 轮）
- 处置：编外（本侧）自检 → 用多文件批次覆盖长尾 → 复测 → 提交本说明
- 状态：待编外复核（Zero-Trust）。

## 1. 背景

可转化缺口收敛到长尾后呈「每文件 1 个符号」形态（实测 27 个文件、28 个符号）。
单文件 lane 每轮一份 LLM + 一次独立复核，开销与收益（1 条条件）严重不成比例。

## 2. 做法

`collect_files2` 的 `--files` 本就支持逗号分隔，`apply_batch`/`unit_review` 也按文件逐个处理；
因此 `single_lane --file a,b,c,...` 可直接组成**多文件批次**。本侧补齐两处工程细节：

1. **逐文件去重**：原判据只看单个 `--file` 字符串；改为对批次内每个文件分别判断
   「驱动近 30 分钟是否已开批」，命中者从本批剔除，其余照跑（全部命中即退出）。
2. **逐文件认领**：原把整串写一行认领清单；改为每个文件各写一行，驱动侧 `SKIP_CLAIMED` 才真正生效。

## 4. 边界

- 复核是**整批**判定：任一条不符即整批 REJECT。故每批控制在 5~6 个 1 符号文件，
  且保留既有的 findings 回灌修复阶梯（上表 C 批即走此路径）。
- 落地仍是逐候选校验和（内部复核 ACCEPT ∧ 零删除 ∧ 干净树回归绿），多文件不降低判据。
