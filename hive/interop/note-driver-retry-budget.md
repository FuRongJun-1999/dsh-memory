# 缺陷与修正：驱动重试判据退化导致空转（attempts=41）与反向空转（NO_FRESH_CANDIDATE）

- 提出时间：2026-09-19 02:0x（环二第 537 轮）
- 处置：编外（本侧）自检 → 改 `_coord/auto_batches.py` 重试判据 → 复测 → 提交本说明
- 状态：待编外复核（Zero-Trust）。

## 1. 缺陷 A：判据退化 → 同一文件无限重试

`gap_min` 只在驱动启动时从日志播种（历史各次 `gap=` 的最小值），循环中不更新。
于是「历史最小 18 < 当前 10」恒成立 → 判为「有进展」→ 永远合格。
实测（2026-09-19 01:59）：`md_cg/mdcos.py attempts=41`、`md_cg/mdcg.py attempts=22`，
每次都是整轮 LLM 预算，缺口却不再下降（剩余符号过不了锚点门禁）。

## 2. 缺陷 B：计数从历史播种 → 反向空转

`done_files` 同样从日志播种（整日累计，可达数十次）→ 重试上限 `n<4` 一开跑就被压满，
驱动直接 `NO_FRESH_CANDIDATE（无进展且达上限）sleep 900`，**在仍有缺口时停摆**。
实测（2026-09-19 01:59，同一次启动）：整轮空转。

## 3. 修正（`auto_batches.py`）

1. `done_files` **不再**从日志播种：改为「每轮独立开批预算」，绝对上限 `n >= 6 → 不合格`，
   由本轮预算（默认 5400s）自然封顶。
2. `gap_min` 只保留「历史最小 gap」语义，并在**每次开批时**以本次 gap 取 min：
   下一次若没更好，progress 判据不再放行。
3. `BATCH` 日志的 `gap=` 改用该文件自身 gap（原打印 `cands[0]` 的最大 gap，会误导人工判断）。

## 4. 实测

- 重启后立即恢复选靶并开批（`BATCH c313 file=md_cg/mdcos.py gap=10`），不再空转。
- 同轮 `iter-backfill-c2 +4`、`iter-evalcommon-c2-fix +4` 正常落地；
  `CORE have 2329→2334→…`、`gap 193→188→184`。
- `md_cg/mdcos.py` 连续两批 `PASS 0 SKIP 5`（全部过不了锚点门禁）→ 属「无必需形参」的
  结构性停滞，已由停滞台账单列，不再无限烧预算。

## 5. 边界

- 上限是「每轮 ≤6 次」而非「永久放弃」：下一轮预算（下一次驱动启动）会重新给机会，
  因此上游工具改进（基线口径、歧义剔除、锚点口径）后，旧硬骨头仍可再试。
