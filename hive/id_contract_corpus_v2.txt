# 蜂巢任务标识契约 v2 · id 闸跨语言对照语料（B6）
#
# 用途：把 rust 侧唯一判据 `hive/src/job.rs::valid_job_id` 与 python 侧孪生闸
# (`hive/hive_mcp/mcp_server.py::_valid_job_id` / `_dep_gate`) 的判定**逐例钉死**：
# 两侧必须对每一例同判（accept/reject），任何分歧即红。**不许改语料迁就实现**
# （改语料 = 改判据面：先改判据、两侧同步、留痕，再改语料）。
#
# 格式（三列，TAB 分隔；以 `#` 开头或空行忽略）：
#   <verdict>	<utf8-hex>	<说明>
#   verdict ∈ accept | reject
#   utf8-hex = id 的 UTF-8 字节的十六进制（小写、无分隔）——用 hex 而非裸字符，
#             是因为零宽/双向控制/组合标记这些不可见样本在编辑与 diff 中极易被悄悄
#             改坏（hex 与字面量一对一，可机械比对；本文件生成时用码点构造，不经
#             字符串转义，杜绝 `ᵀ0` 这类「4 位截断」陷阱）。
# python 解码一行：bytes.fromhex(hex).decode("utf-8")
#
# 本实现的两处口径（语料里各有一例，两侧必须同判）：
#   * `h_a.b` = accept：`.` 非尾点、非单独即收（由 B4 拒收项的存在反推）；
#   * `h_端_任务_反思单元_0000` = accept：字符集闸不判编号数值——旧形态 id 根本没有
#     编号槽，按形态判编号会误杀存量；分配器自 0001 起，永不产出 0000。
# 拒收清单（B4/B5′）：路径成分（`/` `\` `:`、单独 `.`/`..`）、首尾空白、尾点、控制字符
# （含 NUL）、零宽（U+200B..U+200F/U+2060/U+FEFF）、双向控制（U+202A..U+202E/
# U+2066..U+2069）、Windows 保留设备名（含 CON.txt 形态，整 id 与按 `_` 分段的任一段）、
# 以及**区块白名单之外**的一切字符（B5′：判据 = hive/id_charset_blocks.txt 的区间并集，
# 三处读者共读同一份数据；旧机制点名的「会改写区块」形态现在由「不在表内」承载）。
# **零 verdict 变更留痕（2026-09-30 ①-(c) 判据换面）**：本语料 54 例在换面前后的
# verdict **逐例相同**（无 accept↔reject 翻转）；判据换面带来的改判集（表收而旧机制拒的
# 14 码点：0132-0133 / 01C4-01CC / 01F1-01F3）本语料未覆盖，理由见生成的区块表表头。
# 本行只同步「判据指针」（旧 `job.rs::NFC_REWRITE_BLOCKS` 已随换面退休），**未改任何
# verdict 行**。
# **反方向登记补全（2026-09-30 独立复算）**：上段「改判集」只覆盖 reject→accept 方向。
# 反方向（旧机制收而本表拒）在本语料内**同样无载体**——旧机制收下的字母里，凡不落在
# c4 候选区块内的文种（阿拉伯/希伯来/天城文/泰文/亚美尼亚/格鲁吉亚/埃塞俄比亚/藏文/
# 彝文…）由收转拒，是 **c4 区块选择裁决**的必然（候选清单即表达面），不是漏判。
