## 二、判定顺序（固定）

先拒绝，后接受。顺序不可颠倒：

```
候选 C
 │
 ├─ ① 存在足以证明「不适用」的条件冲突？       → REJECT
 │      判据：能力级不适用条件命中（关键词像但能力不同）
 │
 ├─ ② 无法建立判断路径？                       → BLINDSPOT
 │      判据：从未编码的知识域 / 无任何可用条件链
 │
 ├─ ③ 候选存在但区分条件未定？                 → DEFER
 │      判据：多个候选均可能，缺可区分的条件
 │
 └─ ④ 条件充分，获得执行资格                   → ACCEPT
        判据：条件匹配 + 知识存在 + 白箱三问均可回答
```

**为什么 REJECT 在 BLINDSPOT 之前**：负路由是结构性能力（行 2954-2955）。能证明「不适用」时，不必进入盲区判断——拒绝比猜测更省导航税。

## 三、每态的动作与产出

| 状态 | 动作 | 产出 |
|------|------|------|
| ACCEPT | 交给操作层执行 | 判定单 + 执行建议（不代执行） |
| REJECT | 指出冲突的不适用条件 | 判定单 + 负路由依据 |
| DEFER | 列出缺失的区分条件，继续递归补条件 | 判定单 + 待补条件清单 |
| BLINDSPOT | 停止猜测，指出缺失的条件维度 | 判定单 + 缺失维度 + 关注信号 |

## 四、边界声明

1. **不代替验证**：本裁决判断的是「有没有资格执行」，不是「执行结果对不对」。事实裁决归验证单元与 `mdcg_verify`。
2. **不代替概率**：相似度产生候选是合法的，只是不能单独授予资格。
3. **四态判定不交给 LLM 独自完成**：持续跟踪判断进程的成本是导航税（行 2983-2985），条件判断应外部化到确定性机制。
4. **判定必须可核查**：每条裁决须给出条件证据；无法给出即降级为 DEFER 或 BLINDSPOT。
5. **不硬答盲区**：BLINDSPOT 是合法结论，不是失败。

## 五、与 md_cg 的对应

| 能力 | 工具 | 说明 |
|------|------|------|
| 四态检索 | `mdcg_search` | 返回 score/state/tier；T0–T3 阶梯 |
| 验证裁决 | `mdcg_verify` | `verdict=confirmed|weakened|falsified`；falsified 移入 rejected/ 负记忆 |
| 遗忘裁决 | `mdcg_forgetting_history` | ACCEPT/MERGE/DROP/DEFER 四态及三问判据（重复度/重要度/自信息代理），可审计「为什么没被记住」 |
| 元认知自检 | `mdcg_metacognition` | `action=self_check`——回答前自检：该直接答还是先补条件 |
| 自信校准 | `mdcg_metacognition` | `action=calibration`——期望正确率 vs 实际验证通过率，识别过度自信/过度保守 |
| 负记忆 | `mdcg_rejected` | 读取已拒绝候选，供负路由复用 |

写操作（`verify`）只输出建议参数，由 agent 经 MCP 显式发起。
