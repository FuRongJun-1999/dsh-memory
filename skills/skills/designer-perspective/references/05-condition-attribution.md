## 二、三方条件空间

失败 = 三方失配。归因时分别声明三者，再定位差异：

| 条件空间 | 含义 | 来源 |
|---------|------|------|
| 任务真实条件 | 任务本身实际要求的条件 | 任务定义、验证基底 |
| 模型感知条件 | 模型在决策时以为的条件 | 提示/上下文中的声明 |
| 机制声明条件 | 机制（工具/脚本/流程）对外声明的条件 | 工具契约、SKILL.md 的 when |

**归因顺序**：先固定「任务真实条件」为基准 → 对比「机制声明条件」是否覆盖 → 再对比「模型感知条件」是否对齐 → 三者差异即为失配点。

## 三、五失配维度（定位到具体维度）

| 维度 | 失配表现 | 典型症状 |
|------|---------|---------|
| 观测位置 | 谁在观测/从哪个尺度观测未对齐 | 用操作层视角回答全局问题 |
| 观测工具 | 测量方法不一致 | 用相似度代替条件证据 |
| 时间窗口 | 观测范围/迭代周期错位 | 用过期快照回答当前状态 |
| 存在约束 | 物理-信息层允许范围被忽略 | 违反锚点层公理或资源约束 |
| 条件边界 | 适用极限未被承认 | 跨条件空间直接迁移结论 |

## 四、蒸馏流程（失败资产化）

```
失败集合
 │
 ├─ ① 聚类：按失败家族聚合（同因不同形）
 │
 ├─ ② 定位根因：归到条件层，落到五失配维度之一
 │
 ├─ ③ 形成纪律：一句话规律 + 适用条件（带 when，不是无条件规则）
 │
 ├─ ④ 验证：用验证基底检验该纪律能否稳定解释误差
 │
 └─ ⑤ 注入：写进知识结构（下次自动走另一条路径）；不通过则标记待验证
```

**纪律必须带适用条件**：无条件规则=读而不应用；带条件规则=能判断触发时机（附录22.3）。

**注入极性**：把纪律写成「事实/无条件行动」优先，避免写成需要模型自行判断的模糊条件规则（附录22.2）。

## 五、与 md_cg 的对应

| 能力 | 工具 | action | 参数要点 |
|------|------|--------|---------|
| 误差转 unresolved | `mdcg_flywheel` | — | `error_report={query, expected_state, actual_state, missing}`；把一次误差转为 unresolved 条目，驱动补条件 |
| 演化账本 | `mdcg_evolution` | `record` | `rule`（一句话认知规律）/ `missing`（补的是哪一维缺失条件）/ `change` / `kind`（`condition_gap`|`layer_shift`|`general`）/ `evidence` / `source`（`consolidate`|`verify`|`manual`） |
| 规律沉淀 | `mdcg_evolution` | `patterns` | 读取已沉淀的认知规律 + 状态（confidence/layer/importance/负条件/验证基底） |
| 回滚 | `mdcg_evolution` | `rollback` | 支持 `dry_run` 预演；撤销本身也记条目（不可静默） |
| 未解问题 | `mdcg_unresolved` | — | 读取待补条件条目 |
| 元认知自检 | `mdcg_metacognition` | `self_check` | 回答前自检：该直接答还是先补条件 |
| 盲区地图 | `mdcg_metacognition` | `blindspots` | 反复 BLINDSPOT 的查询邻域 + 未解问题 |

**记账纪律**：每一次修改 = 对一条缺失条件的补充（`mdcg_evolution` 的账本语义）。实现细节属于 git，账本只记认知规律与状态。
