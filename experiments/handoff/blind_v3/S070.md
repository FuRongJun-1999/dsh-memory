## 补齐路径（你自己跑，我不代你断言）

1. `git rev-parse HEAD` 拿 40 位候选 SHA。
2. `python scripts/release_gate.py` —— 只查登记表自身一致性，**返回 0 不代表能发布**，别误读。
3. `python scripts/release_gate.py --profile production --candidate <SHA>` —— 0 = 证据齐全；3 = 缺必需 PASS；2 = 登记/证据/参数无效。
4. 每个 PASS 落一份以 SHA-256 命名的独立 JSON 证据，含项目 ID、提交、环境范围、数据/策略摘要、命令、原始输出、退出码、**一次注入 FAIL 与一次撤销 PASS 的对照**、不同复核人。
5. R01–R09 必须在真实生产环境挂接上跑；注意"临时合成证据只测试判定逻辑"，不能当验收证据。
