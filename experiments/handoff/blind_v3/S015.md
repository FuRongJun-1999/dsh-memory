# 灵枢 Memory · 人话版

**一句话**：这是一个让 AI 的记忆「可以被人查账」的设计方案，加一套能自己跑的自检脚本。**现在还在设计阶段，没有可用的正式版本。**

## 先说它不是什么（这段最重要）

- 不是装上就能用的记忆服务，没有在线存储、没有对外接口、没有「断电不丢数据」的保证。
- 里面有个「参考实现」，它只用来验证规则写得对不对，**不是给人用的产品**。
- 检查全部通过，只说明「规则自己说得通」，不说明「真能拿来用」。**CI 绿灯 ≠ 完工。**

## 它想解决什么

AI 会记错，会把甲的话记成乙说的，会不知道「我为什么记得这件事」。这个项目的方向是：每条记忆都得能回答三个问题——**从哪听来的？什么时候发生的？谁改过？** 答不上来的，就不该拿它去指导行动。

## 那些术语，其实就这意思

| 原文说法 | 人话 |
|---|---|
| 结构化规格 / `spec/core.json` | 把规则写成机器能读的表格，不靠嘴说 |
| 契约 / 契约框架 | 两边事先约定好格式，谁也别临场发挥 |
| 血缘 | 这条记忆的出处链 |
| 回执 | 干完事留下的凭据 |
| 双时间 | 分开记「事情何时发生」和「我何时记下它」 |
| 隔离验收 / 可运行动作环 | 在没有真实用户数据的环境里完整跑一遍 |
| 只读检查器 / 一致性清单 | 不许悄悄改，改了要有人看见 |

## 想快速了解，按顺序看

- 搞清「到底想干嘛」→ `ARCHITECTURE_OVERVIEW`、`CHARTER`
- 「为什么这么设计」→ `SOURCES`、`adr/0001-baseline`（旧版五个问题逐个怎么处理的）
- 「记忆怎么取用 / 怎么存 / 怎么重放」→ `CONTEXT_LOOP`、`CONTEXT_STORE`、`CONTEXT_REPLAY`
- 「怎么算合格」→ `BASELINE_ACCEPTANCE`、`ACCEPTANCE`、`CONTEXT_ACCEPTANCE`
- 安全、删数据、恢复 → `SECURITY_MODEL`、`RETENTION`、`RECOVERY`
- 具体格式 → `spec/core.json`、`CONTRACTS.generated.md`、`spec/api.schema.json`
- 以后怎么走 → `ROADMAP`、`MIGRATION`

## 怎么自己验证

装 Python 3.11 以上，不需要装任何依赖，在仓库根目录敲：

```
python scripts/check_all.py
```

另外带一份目录清单：逐个文件比对名字和内容指纹。增、删、改都要有人看过才算过，脚本不会自己把清单覆盖掉。**清单一致 ≠ 获准发布。**

## 三条我做得到的承诺

1. 不搬生产环境的记忆，不复制原始对话、私人路径、执行日志。
2. 上游项目是「借鉴对象」，不是我「升级了它」，也不是生产替代品；引用的基线提交写死，不假装永远最新。
3. 不许改测试来掩盖规则变化——规则动了就升版本、写理由。

## 三条我现在做不到的

真实存储、并发、认证、平台持久化、数据迁移。这些都要**单独验收**，现在没做。
