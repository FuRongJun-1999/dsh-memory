## 改写版 README

> # 灵枢 Memory
>
> **一个给 AI 用的记忆系统——重点是：它记了什么、为什么这么记、错了能不能查出来。**
>
> ### ⚠️ 现在的状态（请先看这一行）
>
> **这是设计中的东西，不是能直接拿来用的成品。** 没有生产存储、没有对外服务、也不保证断电不丢数据。
> 现在仓库里只有**规格**（写清楚“应该怎么做”）和**验证它的参考实现**（证明规格本身没自相矛盾）。
> 验证通过 ≠ 能用。存储、并发、认证、平台持久化、迁移，这些都还没验收。
>
> ### 为什么做这个
>
> 人会把事记错，AI 也会。区别是：AI 记错了，通常没人能查出来是**哪一句错了、什么时候错的、凭什么这么说的**。
>
> 这个项目要做的是：让每一条记忆都能倒查回去——它从哪来、当时依据什么、我什么时候才知道这件事。**记错不可怕，查不出来才可怕。** 因为替你做事的人，会照着错的记忆去行动。
>
> ### 它想解决的五个问题（README 里那些缩写就是这个）
>
> | 文档里叫 | 人话 |
> |---|---|
> | 上下文主动取用 | 不是等人问了才翻记忆，而是在需要的时候自己把相关的几件事取出来 |
> | 隔离存储 C1 | 记忆单独放，和用它的程序隔开，一边出问题不污染另一边 |
> | 可运行动作环 C2 | 每取一次记忆、每做一步动作都留痕，事后能原样重走一遍 |
> | 隔离事件重放 C3 | 把过去一段按时间顺序重放，看当时的结论是不是真能从当时的材料里得出 |
> | 行为基准 C4 | 一批固定题目，每次改完都跑同样的题，看有没有变差 |
> | 隔离验收 C5 | 在隔离环境里把完整流程走完一次，签收 |
>
> 上面五项**在隔离环境里已经跑通了**。但请注意：**没有接过真实宿主，也不证明在真实大模型上的效果。**
>
> ### 它跟别的项目什么关系
>
> 它接着 [dsh-memory](https://github.com/FuRongJun-1999/dsh-memory) 的设计和实践往下做，**不是它的升级版，也不是生产替代品**。
> 比对的基线版本固定为 `2d67f0bf…`；开始观察上游版本是 `b450d2f4…`——这只说明“我某天看到的是那一版”，不代表它现在还是。
>
> 这里**不放**你的生产记忆，不搬原始对话、私有路径、执行日志。
>
> ### 你怎么自己验证（不用信我）
>
> 需要 Python 3.11+，只用标准库，不用装依赖。在仓库根目录执行：
>
> ```text
> python scripts/check_all.py
> ```
>
> 还有两个东西专门用来防止“说得比做得好”：
>
> - `scripts/spec-tree.lock.json`：规格目录里**每个文件的名字和内容指纹**都记着。有人偷偷改了规格里的一个字，对不上。
> - `scripts/spec_tree.py`：只读的核对器，逐条比对上面那份清单。
>
> 增删改都必须被人看过一遍才能进；**CI 不会自动重写清单**。
> 而且——**清单一致，不等于这些内容就获准发布了。** 这是两件事。
>
> ### 三条我不会松口的约定
>
> 1. **测试不许改。** 语义变了就是变了，靠改测试让它变绿，等于骗后面所有信这个仓库的人。
> 2. **CI 绿了不算做完。** 自动化能证明的东西很有限。
> 3. **核心规格要改，必须升版本号，并写清楚为什么改。**

## 改了什么，为什么

- **`docs/` 里原有的术语对照表是新增的。** 这是“看不懂”的主要来源——原文默认读者知道 C1~C5 是什么。翻译成人话之后，外人才能判断自己该看哪一篇。
- **开头加了一句“为什么做这个”。** 原文一上来就是状态声明和链接清单，读者不知道为什么值得读下去。那句“记错不可怕，查不出来才可怕”是整份文档的立意，本来藏在字缝里。
- **链接按“你想问什么”重新分组。** 原来是 20 条平铺列表，读者得逐条点进去才知道是不是自己要的。
- **三种“未完成”的声明全部保留并加粗**：设计开发中、隔离通过但未接真实宿主、CI 绿不等于做完。
- **`2d67f0bf` / `b450d2f4` 两个提交号我缩短成前 8 位**，并补了一句“这只说明我某天看到的是那一版”，原意不变但更好读。**如果你要贴给别人看，建议改回完整 40 位**——短哈希在远程仓库里偶有歧义，而这份文档的信用就在于能精确复核。

## 两件我得提醒你的事

1. **我没核对 `docs/` 里的任何内容。** 上表“C1~C5 在隔离环境里已经跑通了”是从你的 README 原文搬过来的。如果实际验收状态和 README 写的不一致，那就是比“看不懂”严重得多的问题——**夸大的通过状态，正是让信任你的人吃亏的那种差错**。建议你自己对着 `docs/CONTEXT_ACCEPTANCE.md` 和 `docs/BASELINE_ACCEPTANCE.md` 复核一遍再发布。

2. **“能自己验证”这节是这份 README 最值钱的部分，但也最容易被高估。** `check_all.py` 跑绿只能说明规格自洽、参考实现符合规格；它不能证明真实环境里不丢数据。要不要在那一节里再补一句“这些检查覆盖什么、不覆盖什么”，由你定——我倾向于补，因为写清边界的代价，比被人发现边界小得多。
