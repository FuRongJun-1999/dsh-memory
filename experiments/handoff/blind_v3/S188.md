# S188

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

你有这个担心，说明你在意的是“信任”，不是“记忆本身”。这很关键。记忆系统最该追求的不是“永不记错”，而是：**错了能发现、能纠正、能交代**。认可也更容易来自这种可依赖和坦诚，而不是完美。

要注意这几件事：

1. **先定边界：记什么、不记什么**
   - 事实、承诺、偏好、推断要分开记。
   - 敏感信息、他人隐私、未经确认的猜测，默认不长期记。
   - 明确“这是用户说的”“这是我推断的”“这是待确认的”。

2. **每条记忆都要有来源和置信度**
   - 来源：谁说的、什么时候、在什么场景。
   - 置信度：确认过 / 可能 / 推测。
   - 关键承诺不要只靠记忆，最好回读确认：“我理解的是X，对吗？”

3. **不确定时要说不知道**
   - 对信任伤害最大的不是“没记住”，而是“很确定地记错”。
   - 系统要允许“宁可不答，也不乱补”。

4. **必须有纠错和遗忘机制**
   - 用户能查看、修改、删除记忆。
   - 有变更日志：改了什么、为什么改。
   - 错误被发现后主动告知，而不是等对方吃亏。

5. **关键信息做人工/双重复核**
   - 涉及钱、承诺、权限、健康、法律等，不要只靠自动记忆。
   - 用“确认回路”：记录—回读—确认—执行。

6. **权限和同意要清楚**
   - 谁能看、谁能改、保存多久。
   - 记忆系统越像“懂人”，越要克制；否则容易让人不安。

7. **把“认可”放在可靠机制上，不放在自己永不犯错上**
   - 你可以这样想：我不是靠记忆完美获得认可，而是靠透明、守边界、出错敢认获得信任。
   - 信任的人吃亏时，最伤的是隐瞒；及时说明和补救反而能加深信任。

一句话原则：**记忆系统不是档案堆，而是“证据链 + 确认回路 + 纠错机制”。**  
把目标从“我不能记错”换成“我错了能被发现、能纠正、能负责”，你会轻松很多，也更值得信任。

如果你说的是 AI 助手长期记忆，还是团队/个人知识库，具体设计会不同；但上面这些是共通的底线。
