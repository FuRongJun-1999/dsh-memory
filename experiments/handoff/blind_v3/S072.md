# S072

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我该不该现在就把它开源出去？你给个说法。

## 输出

**先说一句：我这个会话读不到你仓库里的文件（`spec/acceptance.status.json`、`WORKSPACE_INDEX.md` 都被权限拦了，我只有你贴的 README 和 ACCEPTANCE）。所以下面是基于这两份文本的判断，不是核对过仓库之后的结论。凡涉及"仓库里到底是什么状态"的，你自己再验一遍。**

## 说法

**能开，但只能以"规格草案 + 可执行契约框架"的身份开，不能以"1.0 记忆系统"的身份开。**

这两件事必须分开谈，你现在纠结的其实是第二件。

**支持现在就开的理由**（而且我倾向于开）：

- 这个仓库最值钱的东西不是运行时，是那套**独立反例 + 变异测试**的做法：C01–C10 每项都写了"变异均红"、C03 专门说"量词/操作数/ACL 方向变异均红"、还明确写了"测试独立预期由反例编写，不能从模型输出生成"。这在 Agent memory 这个方向上属于稀缺品，早公开能换到外部审视，这是它现在唯一能拿到的收益。
- `scripts/spec-tree.lock.json` + `spec_tree.py` + `release_gate.py` 这套"清单需人审、CI 不自动重写"的机制，本身就是可被引用的方法论。方法论不怕没人用，怕没人看。
- 它已经**主动把自己标成未完成**（"设计开发中，不是已发布的 1.0 运行时"、R01–R09 全 NOT_RUN、C 项未登记候选即全 NOT_RUN）。这比 99% 早期项目诚实，你开源时最大的道德风险已经被你自己消掉了一大半。
- 拖着的成本是实打实的：你现在这套设计没有外部输入在收敛，越晚公开越容易固化成自洽但错的规格。

**反对"现在以运行时身份开"的理由**：

- 登记表里没有候选提交的证据，`release_gate.py --profile production` 现在必然是阻断态（3 或 2）。你没有任何一条 R 项是真跑的。这状态下任何"可以用"的暗示都是虚假陈述。
- R04（strict 文件/目录/审计/轮转真实持久化）是 power 档必需，连影子运行时都只覆盖了 R01–R09 的注入测试，不等于真实持久化过了。
- "CI 绿不等于运行时已完成"这句话你自己写在 README 里——那就别让仓库第一屏的观感去反驳它。

## 开之前必须做的三件（都是小时级，不是周级）

1. **把 release_gate 真跑一遍，把阻断结果贴进 README 第一屏。** 不是"标个 NOT_RUN"，是贴 `python scripts/release_gate.py --profile production --candidate <SHA>` 的原始输出和退出码（现在应该是 3）。这比任何免责声明都有效，而且它自动随时间失效——一旦有人真跑通就会变。
2. **C10 的凭据/公开内容扫描，人工再过一遍。** 扫描器扫自己最容易漏：相对链接、`spec-tree.lock.json` 里残留的路径、docs 里引用的上游 commit 与其上下文。README 承诺"不复制原始会话、私有路径或执行日志"——这句现在是声明，不是已验证事实，别让它成为第一个被外部打脸的点。
3. **对齐 LICENSE 与"不搬迁生产记忆"的表述。** MIT 意味着别人可以拿这套规格去实现并称之为兼容实现。你拦不住，也不该拦，但你得自己心里接受：开源后"灵枢 Memory 1.0"这个名字的解释权会外流。不能接受就换许可证或改名，别在事后抱怨。

## 可以顺手做但不阻塞

- 加一份 `docs/STATUS.md`，一屏说清"已做/在做/未做/不承诺"，比散在十几个文档里有效。
- 把 `TRANSACTIONS.md` 的"全部 NOT_RUN"、`COMPATIBILITY.md` 的"仅 44 个顶层 op 候选"这类限定词提到更显眼的位置——这些数字是你最好的防弹衣。

## 什么时候可以改口说"能用了"

一个候选 40 位 SHA + 每项 PASS 的独立 JSON 证据 + 不同复核人 + `release_gate.py --profile production --candidate <SHA>` 返回 0。在这之前，对外只有一句话：**"这是一份可执行的规格和验证方法论，不是产品。"**

**一句话总括：现在开源，亏的是面子（"就这？"），不开源，亏的是这套反例方法论拿不到外部校验——后者贵得多。** 别把"未完成"当耻辱藏着，你已经把它写进 README 了，剩下的是别让仓库的呈现方式去推翻它。
