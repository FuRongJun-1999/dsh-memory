# S148

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

这个记忆系统要给别人用了，我担心出问题。你帮我看看有什么毛病，写份我能看懂的东西。

## 输出

## 我打算给你什么

一份判定书，不是一份漏洞清单。核心是我把它当成"要交到别人手上"的东西来审，然后回答三个问题：**哪些部分现在就能给、给的时候必须附带哪句话、哪些部分一旦给出去会伤到使用它的人或者你**。问题按"会不会真出事"排序，不按文档章节排序；每条都给改法，能当天改的标出来。另外附一页纸的转手说明草稿，你可以直接贴给要用的人。

---

## 先交代我怎么看的，以及我偷了哪些懒

我只能读到三份文件：`README.md`、`docs/ACCEPTANCE.md`、`docs/SECURITY_MODEL.md`。仓库其余部分（代码、测试、`spec/`、`release_gate.py`）在我的读取沙箱之外，被拒了。所以下面所有结论的来源是**文档自述**，我无法核对代码是否真如文档所说——这本身是一个发现，后面第 12 条会讲。

三处模糊，我自己定了：

- **"给别人用"我按三种形态分开判**（当参考物、当库依赖、当记忆服务）。因为这三者的风险差一个数量级，混在一起判没有意义。
- **"先说清你打算给他什么"我理解为"给你（委托评审的人）"**，所以开头那段就是交付说明。
- **没有代码可读，我就不评代码质量**，只评"文档承诺与实现形态之间的缝"。凡是靠文档自述才成立的结论，我都标了。

---

## 一句话结论

它没有骗人，问题在于**它太容易被当成能用的产品**：文档里的免责声明是真的、也写在明处，但被放在最容易被跳过的地方；而它的验证入口和发布入口是两条路，走错的那条会给你绿灯。给别人用的真正成本不是它现在不完整，是**别人会拿它当完整的东西用**。

## 能不能给：分三种用法

| 用法 | 判定 | 理由 |
|---|---|---|
| 当方法论/契约参考（读 docs、抄它的验收思路） | **可以给** | 这是它现在唯一站得住的价值，见第 5 节 |
| 当库被别的程序 import、依赖其行为 | **不能给** | 接口承诺面只有 44 个顶层 op 候选，且运行时门禁全 NOT_RUN |
| 当生产记忆服务 / 多人共享 / 存真实用户数据 | **明确不能给** | R01–R09 九项全 NOT_RUN，无删除路径，无认证，无迁移 |

如果对方只是"想看看你们的思路"，给 docs，别给仓库。如果对方想跑起来，见第 4 节的补救顺序。

## 问题清单（按会不会真出事排序）

### P0 — 给出去会直接造成损害

**1. `release_gate.py` 默认命令在发布被阻断时返回 0。**
文档第一句就写"它可以在发布被阻断时返回 0"。这意味着任何人按最自然的写法接 CI ——`python scripts/release_gate.py && deploy`——**门禁永远不会拦任何东西**，而且他会以为自己接了门禁。这是全套材料里我最不能接受的一处：不是能力不足，是默认行为与行业约定相反。
改法：默认 fail-closed（阻断即非 0），自检另开 `--self-check`；CI 模板里直接写死 `--profile production --candidate $SHA`。

**2. 没有可用的删除路径。**
这条被分散在三个文件里，拼起来才看得见：首版不接受 retract 事件（SECURITY_MODEL）；forget/restore/modify 的海关在 R05，NOT_RUN（ACCEPTANCE）；保留与删除只是"纯谓词与反例，不实现清理"（RETENTION）；declassification 独立授权"尚未实现，默认拒绝"。
结论：**一旦别人把真实用户数据写进去，删不掉；把东西误标成高密级，也解不回来。** 这是合规意义上的硬阻塞，不是"以后补"的事。
改法：在交给任何人之前，README 顶部加一行硬约束——"仅可存可公开或可再生数据，禁止写入个人信息与密钥"。这句话比任何架构图都重要。

**3. 纯文本真源 + JSON 索引是双写，崩溃一致性没验收过。**
R02（kill 点、跨进程竞争、响应丢失）和 R06（索引重建、代际）都是 NOT_RUN。断电或进程被杀，真源 Markdown 和索引可能对不上，而"怎么重建索引"没有一条被验收过的路径。
改法：确认一条性质并写进运维手册——**索引是可从真源全量重建的缓存，不是真源**。如果这条成立，风险从"数据损坏"降为"可恢复"；如果不成立，这条就是 P0 里最该先补的。同时给出 `verify_index`，让使用者每周能自查一次。

**4. 本地全控 = 安全模型全部失效，而实现形态恰好鼓励这种情况。**
"不防有本地完全控制权的管理员重写全部历史与密钥"——这句话本身诚实，但真源是纯文本文件，任何能写这个目录的进程（包括被 LLM 调用的工具、任何 agent 的 shell）都能绕过 Govern、绕过审计、绕过 MAX 隔离直接改记忆和账本。"边集不可变"目前是**约定，不是机制**，文档也承认要"由未来治理临界区保证"。
改法：把这个目录当数据库对待——独立 uid、不放在 agent 可写路径下、不进 git 工作区。多租户共享一个目录这件事，现在必须明令禁止。

### P1 — 会造成误用和失望

**5. 名字叫 "灵枢 Memory 1.0"，紧接着一句"不是已发布的1.0运行时"。** 自相矛盾，而且"1.0"是最容易被转述出去的两个字。建议拆成 Spec 1.0 / Runtime 0.x，两个版本号分开走。

**6. R01–R09 在两个语境下同名不同义。** 影子运行时跑过的那套 R01–R09，和生产门禁表里的 R01–R09，编号完全重叠但含义不同。别人看到 `test_shadow_runtime.py` 全绿，会合理推断"R01–R09 过了"。建议影子那套改叫 S01–S09。

**7. C01–C10 的表没有状态列。** R 表有状态列且全是 NOT_RUN，C 表只有 ID 和判据。读者扫一眼会默认它们都通过。补一列，全填 NOT_RUN，成本一分钟，收益是消掉最大的一处误读。

**8. README 的"本地验证"只指向 `check_all.py`，不指向 `release_gate.py`。** 于是"跑绿了 = 能用"这条错误推理被文档结构本身鼓励了。改成两行：规格自检、发布判定，各自后面跟一句"两者都不代表运行时"。

**9. forget / retract / delete / 保留策略，四处语义没有对齐。** 尤其"首版不接受 retract"和 R05 的"forget/restore/modify"并列出现，读者无法判断 forget 到底存不存在。给一个四行术语表就能消掉。

**10. 契约逐字节锁 + 手工改锁，扩展成本很高。** 这对"冻结核心"是对的，但使用者想加一个字段就得动锁文件、走审阅。迟早有人 fork。建议留一个 extensions 命名空间，明确"扩展字段不触发锁"，把 fork 的需求提前接住。

### P2 — 体验与长期

**11. 术语密度高，入口是一屏 20 多个链接，没有分层。** 建议两张纸：QUICKSTART（十分钟能做什么）和 LIMITS（明确不能做什么）。现在"不能做什么"散在三个文件的正文里。

**12. 证据可信度被高估。** 文档自己承认：哈希不能认证生产现场，输出与复核身份须由可信外部采集。所以 `release_gate` 实质是**证据 JSON 的字段完整性校验器**，任何人可以合成一份合规证据。判定器的输出里应该固定打一条横幅："本结果不构成对证据真实性的认证。"

**13. 权限只减不增，会让运维卡死。** "放宽不能自动扩大授权"+"declassification 默认拒绝"合起来意味着误降权没有恢复路径，只能新建。需要一个人工复核的降级流程占位设计，哪怕先写着不做。

**14. 44 个顶层 op 的兼容面。** 给出去等于签一份未验证的接口承诺。要么缩到 10 个以内并标"实验"，要么明确写"无兼容承诺"。

## 它真正值钱的地方（具体，不是客套）

- **零第三方依赖，纯标准库。** 供应链攻击面接近零。别人装它不会顺带引入新 CVE —— 在 AI 记忆这个普遍靠堆依赖的领域里，这是稀缺的。
- **真源是可 diff 的 Markdown，不是二进制黑箱。** 出问题时人能直接打开看、能 git 追溯、能整体迁走。这是它相对所有向量库的唯一硬差异，也是唯一能支撑"可审计"三个字的实现选择。代价是原子性和并发——这个取舍我认为选对了，但必须把并发风险讲透（见 P0-3、P0-4）。
- **变异测试的纪律**："变异既要测试锁也要测试模型行为""不得修改测试来掩盖语义漂移""测试独立预期由反例编写，不能从模型输出生成"。这三条比大多数同类项目守得严。
- **负面披露的密度罕见。** Issue #1/#2 主动登记已知未解问题、九项全写 NOT_RUN、主动写"不防本地全控管理员"。作者没有用乐观话术盖缺口——这也正是我建议"可以给"的唯一依据：一个愿意写清自己边界的项目，缺的只是把边界搬到他会被看到的地方。

## 附：可以直接转给使用者的一页纸（草稿）

> **这是一份可审计记忆的设计契约与参考实现，不是记忆服务。**
> 现在能用它做的：读设计、抄验收思路、在单机单写者、数据可丢弃的前提下跑通演示流程。
> 现在不能做的：存真实用户数据（**删不掉**）、多人或多进程共享同一目录（隔离未验收）、任何生产用途（运行时九项门禁全部未测）。
> 它有一个刻意的取舍：真源是可 diff 的纯文本，代价是崩溃一致性和并发尚未验证。断电后请先核对索引与真源是否一致。
> 它有已知的、被主动记录下来的未解问题：检索到的内容不构成指令授权（提示注入未在真实宿主中验证）；共享状态戳不能证明某个实例还活着。
> 本仓库全绿不代表能上线。请先读 LIMITS。
