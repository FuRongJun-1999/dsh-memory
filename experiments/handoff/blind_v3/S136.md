# S136

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

做记忆系统，最怕一上来就追求“什么都自动记、记得越多越聪明”。我建议先抓住几个原则：**记忆要有边界、可追溯、可纠正、可遗忘**。可以从下面几层考虑：

### 1. 先定义“记什么”
至少要区分：
- **工作记忆**：当前任务上下文，短期、易失。
- **情景记忆**：发生过什么，如对话、操作记录。
- **语义记忆**：稳定事实，如用户偏好、项目背景。
- **程序记忆**：做事规则/SOP，如“汇报先给结论”。

同时明确：记用户偏好、任务状态、组织知识，还是操作经验？不同记忆的写入和淘汰策略完全不同。

### 2. 写入策略比检索更关键
不要默认全量记录。要设计：
- 哪些信息值得写：稳定、可复用、对后续任务有增益。
- 谁来写：系统自动、用户显式确认、还是规则触发。
- 来源与置信度：来自用户原话、推断、第三方文档，要标清楚。
- 去重与合并：避免同一事实多版本堆积。
- 敏感信息过滤：PII、密钥、隐私、内部机密。

MVP 阶段建议：**显式记忆 + 用户可确认**，比全自动记忆稳。

### 3. 检索要控制噪声和上下文预算
记忆系统的价值不是“能搜到”，而是“该用的时候用对”。
注意：
- 混合检索：关键词 + 向量 + 时间/来源/权限过滤。
- 时间衰减：旧偏好可能已过期。
- 重排与截断：别把一堆低置信记忆塞进上下文。
- 冲突处理：新事实覆盖旧事实，还是并存并标注时效。
- 可解释：回答时能说明用了哪条记忆。

### 4. 必须有更新、遗忘和删除
记忆系统常见事故是“记错了还一直强化”。
要支持：
- 查看、编辑、删除、禁用某条记忆。
- 版本和来源追踪。
- 过期策略：TTL、时间衰减、定期清理。
- 冲突消解：以用户最新确认或高置信来源优先。
- 一键遗忘/按用户隔离。

### 5. 隐私、安全和权限是底线
如果涉及多用户/企业场景，重点：
- 用户级、租户级隔离。
- 最小权限检索。
- 加密存储、审计日志。
- 敏感信息脱敏或不落盘。
- 合规删除与导出。
- 防止记忆污染：恶意内容写入后长期影响模型。

### 6. 评估要围绕任务效果
别只看“召回率”。建议指标：
- 任务成功率是否提升。
- 记忆命中率、噪声率、错误记忆率。
- 用户纠偏次数。
- 延迟和 token 成本。
- 隐私/越权检索次数。
- 记忆过期后是否仍被误用。

### 7. 工程上要可观测、可回滚
- 记忆 schema 别太早固定，但要有版本。
- 每次写入/检索/更新有日志。
- 支持灰度开关：先只影响小流量。
- 出问题能批量回滚/删除。
- 区分在线实时记忆和离线沉淀。

### 我的建议
先做一个**小而可控的 MVP**：
1. 只支持几类高价值记忆：用户偏好、项目事实、任务状态。
2. 写入需置信度/用户确认。
3. 提供“记忆管理页”，可看、改、删。
4. 检索带时间、来源、权限过滤。
5. 用任务成功率评估，而不是记忆条数。

最后确认三个问题：  
- 这是给 **AI Agent/助手** 做，还是给人用的知识/记忆产品？  
- 记忆范围是 **单用户跨会话**，还是 **多用户/组织级**？  
- 最在意的是 **效果、隐私合规，还是成本延迟**？这三点会决定架构取舍。
