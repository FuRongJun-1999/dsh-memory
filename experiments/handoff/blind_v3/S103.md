# S103

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

如果是我来做，我会先把目标定成一句话：**不是“记住越多越好”，而是“记得有据、错了能改、别人能查、老板能看懂”。**

我会重点抓这几件事：

### 1. 每条记忆都要有“身份证”
不要只存一句结论，要存清楚：
- 内容是什么
- 类型：事实 / 用户偏好 / 我的推断 / 待确认
- 来源：哪次对话、哪份文档、哪个人确认
- 时间：什么时候记的，是否过期
- 置信度：确定 / 较确定 / 不确定
- 可见范围：谁能看
- 状态：有效 / 待确认 / 有冲突 / 已废弃

这样别人问你“你为什么这么说”，你能点回源头，而不是靠感觉。

### 2. 严格区分“记得”和“猜的”
这是防止让信任你的人吃亏的关键。  
回答时尽量显式表达：
- “这是你之前明确说过的”
- “这是我根据上下文推断的，建议你确认”
- “这里有两版信息冲突，我不替你拍板”
- “这条可能过期了，我先查一下”

**不确定就保守说，不把推断包装成事实。** 信任不是靠显得什么都知道，而是靠知道边界。

### 3. 建立冲突和过期机制
记忆系统最怕“旧信息污染新判断”。  
要检测：
- 同一件事出现不同版本
- 信息来源互相矛盾
- 偏好变了但旧偏好还在
- 时间敏感信息过期

处理方式不是偷偷选一个，而是标记冲突、展示来源、请人确认或按最新确认优先。

### 4. 可验证：来源、版本、审计日志
要能让别人验证，至少做到：
- 每条记忆能定位到原始出处
- 修改有版本历史
- 谁确认、谁修改、改了什么可查
- 错误可回滚
- 重要回答附证据链接或引用位置

这不是为了显得复杂，是为了出事时能查、能改、能负责。

### 5. 给“纠错”设计得足够简单
信任系统一定要允许人说：
- “这条不对”
- “这条过期了”
- “只对某个人可见”
- “以后别再提这个”

然后系统要能快速更新，并告诉用户：**改了哪条、影响哪些结论、已同步到哪些地方。**  
最伤信任的不是犯错，是错了以后还嘴硬、改不动、影响范围说不清。

### 6. 老板视角要“结论先行”
给老板看的结果别堆记忆日志，而是：
- 一句话结论
- 关键依据和来源
- 不确定性/风险点
- 需要老板决策或确认什么
- 建议下一步

也就是：**结论—依据—风险—建议动作。**  
老板不需要知道系统多复杂，他需要知道“这事靠不靠谱、要不要签字、出了问题影响多大”。

### 7. 隐私和权限别后补
记忆里很容易混入敏感信息。要提前做：
- 分级权限
- 脱敏
- 保留期限
- 删除机制
- 哪些信息绝不自动记

否则记得越多，风险越大。

### 8. 写入要有门槛
不是所有话都值得长期记。我建议只记：
- 明确确认过的偏好
- 反复出现的事实
- 会影响后续决策的信息
- 有可靠来源的结论

临时信息放工作记忆，别全塞长期记忆。

### 9. 用指标证明它可靠
可以盯这些数：
- 错误记忆率
- 冲突发现率
- 过期信息比例
- 用户纠错后修复时间
- 回答附来源比例
- 老板/用户确认率

### 10. 最小可行版本
先做“记忆卡片 + 来源链接 + 状态标记 + 一键纠错 + 老板摘要”。  
别一开始追求全自动。先让每条重要记忆都能回答四个问题：  
**从哪来？准不准？过期没？错了怎么改？**

最后我会提醒自己一句：**想得到认可，不能靠讨好和显得万能，要靠稳定、透明、可验证、错了能认能改。** 记忆系统真正的价值不是“我记得多”，而是“信我的人不容易被我坑，老板能一眼看懂依据和风险”。
