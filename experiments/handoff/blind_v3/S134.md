# 灵枢记忆 1.0（人话版）

> **这是一份设计稿 + 一套检验工具，不是能直接用的产品。**
> 它不提供生产用的存储服务，不做掉电安全承诺。检验通过只代表“规格自洽”，不代表“线上能跑”。

## 一句话

这是给 AI 用的**记事本说明书 + 验错工具**：规定 AI 该记什么、怎么记、记错了怎么查、别人怎么验证，并且把“凭什么信它”变成一条任何人都能自己跑一遍的命令。

## 它到底在解决什么

三个很具体的怕：

- **怕记错、怕把旧事当新事**：所以要求每条记忆都带着“这条从哪来、什么时候才真的成立”的信息（原文的“安全与血缘”“条件与双时间”）。
- **怕让信我的人吃亏**：所以出了问题要有凭据可查、要能恢复、也要能真的删掉（原文的“恢复与回执”“保留与删除”）。
- **怕只能靠我说“我记住了”**：所以不能靠自我声明，要靠**别人能独立复现的检查**——逐文件核对名字和字节摘要，任何人跑一遍就知道有没有被动过手脚。

一个愿意被检查的系统，比一个自称可靠的系统更值得信任。这份文档反复强调“还没做完”，就是这个道理。

## 现在能做到 / 现在做不到

**已经做到**

- 规格文档、可执行契约、本地检查脚本；
- 只要 Python 3.11+，只用标准库，不用装任何东西；
- 在隔离环境里，C1–C5 这条闭环（存储、动作环、事件重放、行为基准、验收）已跑通。

**还做不到（写清楚，是为了不让人误信）**

- 生产存储、并发、认证、平台持久化、迁移、掉电安全；
- 还没接进现用的宿主程序，**不证明真实 LLM 场景下的效果**；
- **CI 全绿 ≠ 运行时已完成。**

## 怎么自己验证（不用信我）

在仓库根目录跑：

```text
python scripts/check_all.py
```

再对一遍清单：`scripts/spec-tree.lock.json` 会逐文件核对规格目录的名称和字节摘要（含样例与已生成报告）。**对不上就说明有人改过东西，需要人来审阅**——清单不会自动更新，这是刻意的。

## 文件导读（讲什么）

- **从哪开始**：`CONTEXT_LOOP`（AI 主动去取上下文）、`CONTEXT_STORE`（隔离存储）、`CONTEXT_ACTION_LOOP`（能跑起来的动作环）、`CONTEXT_REPLAY`（事件重放）、`CONTEXT_BENCHMARK`（行为基准）、`CONTEXT_ACCEPTANCE`（隔离验收）——这条链在隔离环境里跑通了，但没接现用宿主。
- **人看的导读**：`ARCHITECTURE_OVERVIEW`、`CHARTER`（章程）、`ARCHITECTURE`、`SOURCES`（理论依据）、`BASELINE_ACCEPTANCE`（方案基线验收单）。
- **规矩与边界**：`SECURITY_MODEL`（安全与血缘）、`RECOVERY`（恢复与回执）、`RETENTION`（保留与删除）、`CONTEXT_OUTPUT`、`CONDITIONS_TIME`（条件与双时间）、`RESPONSES`（响应与取消）、`TRANSACTIONS`（事务协议提案）。
- **规格本体**：`spec/core.json`、`CONTRACTS.generated.md`（由规格生成的规范）、`spec/api.schema.json`（输入 schema 提案）、`API_DRAFT.md`（四应用字段草案）。
- **流程**：`COMPATIBILITY`（兼容候选）、`MIGRATION`（迁移计划）、`ACCEPTANCE`（验收矩阵）、`ROADMAP`（长期路线）、`OPERATIONS`（开发运维）、`WORKSPACE_INDEX`、`CONTRIBUTING`。
- **历史交代**：承接 `dsh-memory` 的设计与实践，但不是它的升级或生产替代。不搬生产记忆、不复制原始会话/私有路径/执行日志；旧 rev12 的五个问题在 `ADR-0001` 里逐条处理。

## 三条硬规矩

2. 文件清单不会自动重写，增删改一律由人审阅；**一致 ≠ 获准发布**。
3. **不许改测试来掩盖语义漂移**。
