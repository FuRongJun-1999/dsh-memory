# S016

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

你的担心很对：**记忆系统本质上不是“存储系统”，而是“信任系统”**。用户把信息交给你，不是因为你永不犯错，而是因为你能做到：**记得有边界、错得有痕迹、改得及时、用得克制**。

可以重点注意这些：

1. **先分清什么该记、什么不该记**
   - 临时信息、敏感信息、他人隐私、未经确认的推测，默认不长期记。
   - 记忆分层：临时上下文 / 事件记忆 / 稳定偏好 / 重要事实。
   - 每条记忆设保留期限、敏感级别、使用范围。能忘、能删、能导出。

2. **每条记忆都要有“来源、时间、置信度、适用范围”**
   - 不是只存“用户喜欢 X”，而应存：
     - 来源：用户明说 / 系统推测 / 第三方转述
     - 时间：何时得知，是否可能过期
     - 置信度：确定 / 较确定 / 待确认
     - 范围：仅用于建议，还是可用于重要决策
   - 对高风险场景，低置信度记忆不能自动用于决策。

3. **把“不确定”设计成功能，而不是缺点**
   - 该说“我记得你提过……不确定是否仍有效”时就说。
   - 记忆冲突时不要硬合并，要问用户：“这两个信息哪个更新？”
   - 重要事实采用确认机制，比如“我要把这个记为长期偏好，可以吗？”

4. **可追溯、可纠正、可撤销**
   - 用户能看：你为什么记得这条？从哪来的？
   - 用户能改：这条错了；这条过期了；别在某个场景用它。
   - 用户能删：忘记这条；删除全部；不要用于训练/分析。
   - 系统更正后，要能传播到后续使用，并留下审计记录。

5. **安全默认：宁可少记，不可乱用**
   - 对“会让信你的人吃亏”的场景，采用更严格规则：
     - 重要信息双来源确认；
     - 低置信度不自动执行；
     - 涉及钱、健康、法律、承诺、他人隐私时人工确认；
     - 发现错误后主动提示、回滚、说明影响。
   - 你的目标不是“零错误”，而是“错误可发现、可修复、可补偿”。

6. **隐私和权限要前置**
   - 最小权限、加密、访问控制、日志审计。
   - 区分“我知道”与“我被允许使用”。
   - 明确谁能看、能用到什么程度、保留多久。

7. **建立信任的产品仪式**
   - 记忆摘要：定期让用户 review。
   - 一键操作：“为什么记得我？”“改掉”“忘记”“别用于这类事”。
   - 错误反馈闭环：用户纠正后，系统要真的学会不再犯。
   - 对外表达要诚实：不假装全知，不把推测说成事实。

8. **衡量指标别只看“记住多少”**
   更该看：
   - 有害错误率
   - 过期记忆率
   - 用户纠正后复发率
   - 用户能否解释系统为何记得
   - 用户是否敢把重要信息交给你
   - 信任度/安心感，而不是记忆数量

一句话：**你想得到认可，不靠“我什么都记得”，而靠“我值得被托付”。**  
把系统设计成“可查看、可纠正、可遗忘、可拒绝、可审计”，你怕的“记错让信你的人吃亏”就会从隐患变成你可控的质量问题。
