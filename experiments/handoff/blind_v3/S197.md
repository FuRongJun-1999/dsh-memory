## 关键的几处“看起来像完成、其实不是”

1. **“隔离影子运行时已实跑 R01–R09”** ——文档自己在标题和注里两处打了补丁：跑通的是 `shadow_runtime`（纯文本 Markdown 真源 + JSON 索引，零二进制 DB）上的故障注入与变异测试，那张表是**生产真实环境挂接门禁**，生产接管前保持 NOT_RUN。影子环境过 ≠ 生产过。
2. **“规格工具绿不会自动更新运行时状态”** ——文档开篇就写了这句。所以即便 C01–C10 全绿，也不能推出一项 R 的结论。
3. **登记的是“候选提交的发布证据”，不是最近一次单测计数** ——这条直接堵死了“我们 CI 全绿所以做完了”的说法。
4. **COMPATIBILITY.md 仅 44 个顶层 op 候选** ——“候选”二字说明兼容面本身没收口。
5. **API 复核裁决“列明未实现边界”** ——即已记录在案的**未实现**部分，这是明账上的欠账，不是隐性风险。

## 离“做完”还差多少（按文档的判定规则）

常规生产档 = **全部 C 项 + 除 R04 外的全部 R 项**。power 档再加 R04。

- 运行时侧：**8 项必需 R 全 NOT_RUN**（power 档 9 项）。
- 规格侧：C01–C10 至多 10 项，状态我无法核实；其中最坏情况是全部 NOT_RUN。
- 因此差距区间是 **8～19 项**，且每一项都不是“补个断言”能填的——每项都要：固定 commit + 数据摘要、命令、原始输出、退出码、**一次注入 FAIL 与一次撤销 PASS 的对照**、以及**不同复核人**的独立复核。

## 对外可以怎么说（合规表述）

> 规格层工具链已实现，并有隔离反例与变异测试覆盖（API shape/cursor/治理、响应取消终结 token、迁移字节保真、可信输出与保留阻断等）；生产环境接入与运行时门禁尚未完成验收，当前状态为 NOT_RUN。

这句话是真的、可辩护的。而“做完了”“已交付生产”“可以上线”都不行——按这份文档的定义，那是需要登记表里每项都有 SHA-256 命名的独立证据 JSON 才能说的话。

## 要真正做出结论，下一步就两条

1. 定一个 40 位候选 SHA，把 C/R 各项证据按格式登记进 `acceptance.status.json`（注意：登记表是对候选的事后审阅，它自己的 Git SHA 不必等于候选）。
2. 跑判定器看它说话：
   - `python scripts/release_gate.py` —— 查登记表自身一致性（**注意它返回 0 不代表能发布**）
   - `python scripts/release_gate.py --profile production --candidate <SHA>` —— `0` 证据齐全 / `3` 缺必需 PASS / `2` 登记或证据无效

最后一个提醒：文档明说“哈希不能认证生产现场”，输出与复核身份必须由可信外部采集。所以即便判定器返回 0，也只能支撑“证据齐全”，撑不起“生产现场已验证”——这句话的份量，文档是主动留给人工承担的。
