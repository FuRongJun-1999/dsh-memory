# S027

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

你怕“记错让信你的人吃亏”，这其实是个很好的起点：**信任不是靠“永不犯错”建立的，而是靠“可检查、可纠正、可预期”建立的。** 记忆系统最该注意的，不是记得多，而是让人知道它记得什么、为什么这么记、错了怎么改。

### 1. 先定原则：记忆系统不是“事实机器”
要区分四类信息：
- **事实**：用户明确说过、可验证的信息
- **推断**：系统根据上下文猜的，比如“他可能喜欢简洁”
- **偏好**：用户表达的喜好，可能变化
- **承诺/重要事项**：时间、金额、责任、他人利益相关

不同类别要用不同置信度和展示方式。**推断绝不能伪装成事实。**

### 2. 每条记忆都要有“来源和置信度”
建议每条记忆至少带：
- 来源：哪次对话、谁说的、原文是什么
- 时间：何时记录，是否过期
- 置信度：确定/较确定/推测
- 敏感级别：普通/隐私/高敏感
- 可修改/可删除

重要信息不要只存结论，要能回溯原始上下文。这样别人问“你为什么这么记”，你能解释。

### 3. 对“怕记错”的设计：默认谨慎，重要事项二次确认
- 涉及钱、时间、承诺、他人利益：**必须二次确认**
- 不确定时明确说“我可能记错/这是推测”
- 关键记忆变更要留版本记录
- 提供“纠错入口”，而且纠错要容易
- 错误发生后，不只改数据，还要通知受影响的人

你可以把系统目标定为：**不保证不犯错，但保证错误可见、可追、可改、可补救。**

### 4. 权限、隐私和同意
记忆系统很容易越界：
- 谁能读、谁能写、谁能删
- 是否跨场景共享
- 是否用于训练/分析
- 高敏感信息单独授权
- 支持“忘记我”和导出
- 不要默认替别人记关于第三方的敏感信息

### 5. 防止“过度记忆”和“错误强化”
- 设置过期和衰减：偏好会变，旧信息要降权
- 冲突记忆不要自动覆盖，要标记冲突
- 避免把一次情绪表达当成长期偏好
- 定期让用户 review 关键记忆
- 不要把记忆当证据链，除非有来源

### 6. 建立信任的关键：可预测的诚实
你想得到认可，但更稳的路径是：
- **说清楚边界**：我能记住什么、不能保证什么
- **主动暴露不确定性**
- **犯错后快速承认和修正**
- **重要事项不甩锅给记忆**
- **让用户有控制感**

别人真正信你，不是因为你从不出错，而是因为：**你出错时不会藏着，且会负责。**

### 7. 最小可行版本建议
先做窄一点：
1. 只记用户明确要求记的内容
2. 每条记忆带来源、时间、置信度
3. 重要事项二次确认
4. 一键纠错/删除
5. 每周或关键节点 review
6. 高敏感信息默认不记

一句话：**把“记忆”做成可审计的承诺，而不是黑箱的自信。** 你这样在意别人会不会因你吃亏，已经是在做信任系统最重要的底层品质了。
