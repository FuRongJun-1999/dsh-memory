# S202

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

先确认一下场景：你说的更偏 **AI Agent/大模型的长期记忆系统**，还是 **产品里的用户记忆/知识库**？两者重点不同，但通用上我会优先注意这些：

1. **先定义“什么算记忆”**
   - 区分：事实、偏好、事件、任务状态、对话摘要、文档知识。
   - 不是所有日志都该进记忆；否则会污染、膨胀、检索变差。
   - 明确写入标准：用户显式要求？高置信抽取？还是自动推断？

2. **分层设计，不要一个库打天下**
   - 工作记忆/短期上下文
   - 长期事实与偏好
   - 情节记忆（发生过什么）
   - 语义知识库
   - 程序性记忆（怎么做）
   - 存储上常见组合：结构化库 + 向量库 + 可选图/全文索引。

3. **写入策略比检索更关键**
   - 去重、合并、冲突检测、置信度、来源追踪。
   - 区分“用户说的”“系统推断的”“过期事实”。
   - 对敏感/高风险信息不要自动写入。
   - 最好支持显式记忆：用户能说“记住/忘掉”。

4. **检索要有多路召回和权限过滤**
   - 向量召回 + 关键词/结构化过滤 + 时间衰减 + 重要性。
   - 先做权限/租户隔离，再做语义召回，避免越权泄漏。
   - 注意“相似但不相关”和“旧记忆压过新事实”。

5. **冲突、版本和遗忘机制**
   - 记忆会变：地址、偏好、项目状态都会更新。
   - 要有版本、时间戳、有效区间、来源。
   - 支持 TTL、软删除、用户删除权、纠错入口。
   - 没有遗忘机制的记忆系统最后通常不可用。

6. **隐私、合规和安全**
   - 敏感信息分类、加密、访问审计、租户隔离。
   - 明确同意、保留期限、删除与导出。
   - 防记忆投毒：恶意内容/提示注入写入长期记忆。
   - 防越权召回：检索前过滤，而不是召回后再遮。

7. **可观测与评估**
   - 指标不只看“召回率”：记忆准确率、污染率、冲突率、过期率、延迟、成本、用户纠错率。
   - 建离线评测集：该记住的、该忘记的、冲突更新、跨会话召回、越权测试。
   - 记录每次记忆写入/检索/使用链路，方便排障。

8. **成本与工程复杂度**
   - 写入常是异步管线：抽取→去重→冲突→审核→索引。
   - 向量库不是万能，结构化字段和时间过滤很重要。
   - 备份恢复、迁移、冷热分层、批量清理要提前想。

9. **用户体验：记忆要可见、可控、可编辑**
   - 让用户知道系统记住了什么。
   - 提供查看、修改、删除、关闭记忆的入口。
   - 对“为什么想起这条”给出简短解释，能显著降低不信任。

如果做 MVP，我建议：**显式记忆优先 + 结构化字段 + 向量混合检索 + 强权限隔离 + 冲突可追溯 + TTL/删除 + 离线评测**。先把“记什么、何时忘、谁能看、冲突怎么办”定清楚，再选存储和模型。
