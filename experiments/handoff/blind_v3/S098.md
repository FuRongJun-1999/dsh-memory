# S098

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

你问的“记忆系统”如果指 **AI 产品 / Agent 的长期记忆**，我觉得核心不是“把东西存下来”，而是 **决定什么值得记、什么时候取、如何更新和遗忘、怎么让用户可控**。几个关键注意点：

1. **先定边界：记忆解决什么问题**
   - 是记用户偏好、历史任务、知识事实，还是对话上下文？
   - 哪些绝不该记：敏感信息、一次性信息、低置信度猜测、他人隐私。
   - 记忆不是越多越好，错误记忆比没有记忆更伤。

2. **分层设计，不要一锅粥**
   - 工作记忆：当前对话/任务上下文。
   - 情景记忆：某次交互、事件、任务过程。
   - 语义记忆：稳定事实、偏好、知识。
   - 程序记忆：用户习惯的流程/模板。
   - 每条记忆建议带元数据：内容、类型、来源、时间、置信度、权限、过期时间、是否可编辑。

3. **写入策略比存储更重要**
   - 什么时候写：显式让用户说“记住”，还是模型自动判断？
   - 写入前去重、合并、冲突检测。
   - 重要性和时效性评分，别把闲聊全存。
   - 敏感信息过滤；写入异步化，别阻塞主流程。
   - 支持撤销和用户纠正。

4. **检索要混合，不要只靠向量**
   - 语义召回 + 关键词 + 规则 + 时间/重要性排序。
   - 先做权限、租户、时间过滤，再重排。
   - 控制注入上下文预算，取最相关而不是最多。
   - 检索结果要可解释：为什么想起这条。

5. **更新、冲突和遗忘机制**
   - 用户偏好会变，事实会过期。
   - 冲突时按来源、时间、置信度、用户确认来解决。
   - 设计 TTL、衰减、摘要压缩、冷热分层。
   - 删除权要真正贯通：原始存储、索引、缓存、备份。

6. **隐私与安全**
   - 多租户隔离，权限继承，加密存储。
   - 审计日志：谁写入、谁读取、谁删除。
   - 防“记忆投毒”和 prompt injection：外部内容不能随便写成高置信记忆。
   - PII 识别、脱敏、保留期限、合规删除。

7. **评估要看长期价值**
   - 不只是召回率，还要看：记忆准确率、污染率、冲突率、用户纠正率、延迟、成本。
   - 离线评估 + 在线 A/B；重点看任务成功率、重复询问率、用户信任。
   - 建立 bad case 集：错误记忆、过期记忆、越权记忆。

8. **工程上要可观测、可回滚**
   - 记忆版本化、变更历史、灰度、回滚。
   - 成本控制：存储成本、检索成本、上下文 token 成本。
   - 降级策略：检索失败时不能把主流程拖死。

常见坑：**什么都记、只靠向量检索、没有时间戳和来源、没有冲突解决、没有删除机制、写入阻塞主流程、评估只看“能不能召回”**。

一句话：记忆系统本质是一个 **策略系统**——写入策略、检索策略、更新策略、遗忘策略、权限策略缺一不可。你要做的是 AI Agent 记忆，还是学习/知识记忆类产品？场景不同重点会差很多。
