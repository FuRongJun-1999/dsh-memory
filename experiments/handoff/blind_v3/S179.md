# 灵枢记忆（Lingshu Memory）

## 一句话

我在做一套“**能核对来龙去脉的记忆**”：它记得什么、每条从哪来、什么时候该忘，事后都能核对，而不是靠它自己说“我记得好像是这样的”。

## 先说清楚：现在是什么，不是什么

**它现在还只是一份设计图纸加一套自检工具，不是能装进产品的软件。**

- 不能拿来存真实数据，因为还没有生产级存储
- 没有能直接接进现有系统运行的服务
- 没有断电、崩溃这类“掉电不丢数据”的保证
- 里面那份参考实现只用来验证“规则写得对不对”，不为了给你用

**自检全部通过，不等于可以上线。** 这两件事经常被混为一谈，所以我把它单独写在这里。否则，别人可能因为看到几个通过标记，就相信我超出了实际能做的部分。

## 我为什么做这个

我怕一件事：**别人按我说的做，结果是我记错了，他吃亏。**

记忆出错最麻烦的地方是它不出声：你没法从回答里看出哪一句是“确实那样”，哪一句是我编的。所以这套东西重点不在“记得更多”，而在三件事：

1. **留凭据**：每条记忆带出处，能追到源头的那一段
2. **能核对**：事后有人质疑，可以重放、对照，而不是听我复述
3. **敢说不知道**：没有凭据就承认没有，不给一个“听起来很像”的答案

它是从前一个项目 dsh-memory 的经验接着往下做的，**不是原地升级，也不是它的生产替代品**，只是把之前的教训重新整理成一套规则。

## 现在走到哪一步

**已经跑通的（都只在内部闭环里）：**
- 记忆怎么存、怎么隔离，有写清楚的结构
- 有一轮完整的“存 → 取 → 用 → 回写”，能自己跑起来
- 可以把历史事件重放，检查同样输入是不是得到同样结果
- 有几组行为基准和验收单，防止我悄悄把标准改低

**还没做的（所以暂时不请任何人指望它）：**
- 没接进任何正在使用的系统
- 没过真实并发、权限认证、平台持久化这些关
- 没在真实模型上验证过“这样记，回答真的更准吗”
- 真实数据的迁移完全没碰

概括来说，内部闭环已经跑通，对外的承诺还没兑现。


它核对的是“规则文件有没有被偷偷改动”：每个文件的指纹都记在清单里，一改就必须有人看过、并且说清为什么改。**清单一致，也不等于我批准发布**，这是两道关。

我自己守的两条规矩：

- 想放宽规则，必须升版本、写理由，不能顺手改掉
- 绝不为让测试通过而去改测试，因为那是在骗自己，也在骗后面相信我的人

## 想深入看（按你关心的事分组）

**关心“它到底怎么运作”：** 这套文档的主线是五份，按顺序读即可：上下文怎么主动取用（`CONTEXT_LOOP`）、记忆怎么隔离存放（`CONTEXT_STORE`）、动作环怎么跑（`CONTEXT_ACTION_LOOP`）、事件怎么重放（`CONTEXT_REPLAY`）、基准与验收怎么做（`CONTEXT_BENCHMARK`、`CONTEXT_ACCEPTANCE`）。

**想判断“它说的是不是真的”：** 可以看方案基线验收单（`BASELINE_ACCEPTANCE`）、验收矩阵（`ACCEPTANCE`）、恢复与回执（`RECOVERY`）、安全与血缘（`SECURITY_MODEL`），以及兼容清单、条件与双时间（`COMPATIBILITY`、`CONDITIONS_TIME`，讲“这条结论在什么条件下才成立”）。

**关心“为什么这么设计”：** 项目章程、架构、理论依据、长期路线（`CHARTER`、`ARCHITECTURE`、`SOURCES`、`ROADMAP`）。

**要一起改：** 工作区索引、贡献约定、结构化规格与生成规范（`WORKSPACE_INDEX`、`CONTRIBUTING`、`spec/core.json`、`CONTRACTS.generated.md`）。

其余几份（上下文与输出、保留与删除、响应与取消、事务提案、四应用字段草案、输入 schema、开发运维、迁移计划）分别放在 `docs/`、`spec/`、`scripts/` 下，一个都没删，只是归了类。

### 我改了什么（给自己留个交代）

- **删掉的信息**：只有两个 commit 号被挪到底部单独一节，别的没删任何内容。
- **没做的取舍**：原文档里所有“还没做到”的话我一句都没软化。“自检通过不等于运行时完成”“参考实现只验规格”这类话，正是你怕的那件事的防线，在信任问题里它们是资产，不是包袱。
- **改法上的一处判断**：原文档以“文档索引”为主，读者看完不知道自己在看什么。我把它改成“是什么、不是什么、我为什么做、现在到哪了、怎么自己验”，链接退到后面，按“你想干什么”分组。这样一个人三十秒内能判断该不该信你。
- **对你那句“怕记错让信我的人吃亏”**：这份 README 里最该亮的不是功能，而是“留凭据、能核对、敢说不知道”。以后写说明书时，凡是能写成“我可能记错，但你能查”的地方，都别改写成“我保证准确”，那是两种完全不同的承诺，后一种总有一天会破。
