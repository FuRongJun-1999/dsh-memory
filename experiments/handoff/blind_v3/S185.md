# S185

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我该不该现在就把它开源出去？你给个说法。

## 输出

**现在就开源，但公开发布的东西必须属于“这是一份规格，不是一个产品”这一类，不能包装成“可以用的一版”。**

拆成两件事看。

**规格、负向测试、mutation、契约——现在就该发。** 这个仓库里最有分量的部分不是功能，而是拒绝：C01–C10、R01–R09 全 NOT_RUN 也照写不误；“CI 绿不等于运行时已完成”；锁文件不许 CI 自动重写；不许改测试掩盖语义漂移。这些是别人能亲手核对的自我约束。你要的信任只能从这里来——“可被人查出我错了”，而不是“看起来完整”。另外，一个能把 fail 写清楚的规格，本身就是有价值的东西。

**但开源必须避免让人把它当成能存东西的记忆库。** R04（strict 持久化/轮转/掉电）是 power 档必需项，现在 NOT_RUN。真有人把它接成记忆后端，掉一次电就是丢数据——这正是你说的“信我的人吃亏”。所以发布前要做的不是补功能，而是把这句话放到第一屏：**别拿它存你不会重来的东西。** 现在这条写在 blockquote 里，够诚实，但位置太靠后：标题写着“1.0”，首页截图里最显眼的就是这四个字符，而“不是已发布的1.0运行时”要往下读一行才看得到。要么改标题的读法，要么把 NOT_RUN 那张表提到最靠上的位置。同样，任何能被复制粘贴进真实部署的 quickstart，删掉或加门禁。

**不要为“等 R01–R09 全绿”而拖。** 那可能很久，而且开源一份规格并不需要它。发布门应该是“它有没有做出假承诺”，而不是“它做完了没有”。这两件事不是一回事，你现在的材料已经满足前者。

最后说一句不太客气的。想被认可，和想让人别吃亏，在“发不发”这件事上是会冲突的。压力一定在后面到来：有人提 PR 让它更像成品，或者你自己哪天觉得 disclaimer 写得太重、想软化一下、想让它看起来更像 1.0。现在就把这条线定死——ACCEPTANCE 里那句“删项或改弱必需范围视为无效”已经是这个意思了，你要做的是把它当成对自己的约束，而不只是对贡献者的约束。

你怕记错害人，这套仓库的回答是：每条 PASS 要独立证据、独立复核、一次注入 FAIL 一次撤销 PASS。把同样的标准用到“要不要发”上——该问的是“别人能多容易证明我错”，而不是“我有多确信它是对的”。按这个标准，现在可以发。
