## 为什么"测试绿了"不等于做完

文档里三句话把判定规则固定下来，绕不过去：

1. 「规格工具绿不会自动更新运行时状态」——CI 通过是不动运行时状态的。
2. 「模型形式成立不证明平台前提成立」——影子运行时是 Markdown 真源 + JSON 索引，它证明不了 strict 文件权限、审计轮转、进程 kill、跨进程竞争这些平台级前提。
3. 「未登记候选及其证据时……均标 NOT_RUN；这不否认已有隔离测试」——所以 NOT_RUN 不是"没做事"，是"还没证据"。

## 要补齐的最小步骤

1. **固定候选**：定一个 40 位 SHA，别用"最近一次单测"当证据。
2. **采证据**：每项一份 SHA-256 命名的 JSON，含命令、原始输出、退出码，且要有**一次注入 FAIL + 一次撤销 PASS** 的对照；复核人要不同于执行人。
3. **外部采集**：输出和复核身份必须由可信外部渠道采集，哈希本身不能认证生产现场。
4. **过门禁**：`python scripts/release_gate.py --profile production --candidate <SHA>`，看返回码——**3 = 缺必需 PASS，2 = 登记/证据/参数无效，0 只表示证据齐全，不代表执行了发布**。
5. 常规生产档：全部 C 项 + 除 R04 外的全部 R 项；power 档再加 R04。删项或改弱必需范围按文档是无效应答。
