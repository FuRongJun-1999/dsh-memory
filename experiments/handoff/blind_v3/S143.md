# dsh-lingshu-memory（人话版）

灵枢 Memory 1.0：一套公开的“AI 记忆”设计说明，加上能跑起来的检查工具。
目标是让 AI 记下的东西可查账：这条记忆从哪来、什么时候写的、谁看过、删了没有，都有据可依。

## 先讲清楚：这不是成品

- 它还在设计开发中，**不是已发布的 1.0 运行时**。
- 没有生产可用的存储服务，也不对外提供 MCP 服务。
- 不承诺掉电不丢数据。
- 仓库里的参考实现只有一个用途：**证明规格写得通、彼此不矛盾**。它证明不了性能，也证明不了实际使用效果。

## 第一次来，按这个顺序看

如果你手上是个长期任务——今天做的事，几个月后还得接着做——按 1→5 的顺序读：

1. [上下文主动取用](<docs/CONTEXT_LOOP.md>)：AI 该在什么时候自己去翻记忆，而不是等人喂。
2. [隔离存储（C1）](<docs/CONTEXT_STORE.md>)：记忆放在一套独立环境里，不碰你现在用的系统。
3. [可运行动作环（C2）](<docs/CONTEXT_ACTION_LOOP.md>)：从“读记忆”到“照着做”这一整圈能真的跑起来。
4. [隔离事件重放（C3）](<docs/CONTEXT_REPLAY.md>)：把事情发生过一遍的过程重放出来，好复盘。
5. [行为基准（C4）](<docs/CONTEXT_BENCHMARK.md>)：拿统一标准量一量行为对不对。
6. [隔离验收（C5）](<docs/CONTEXT_ACCEPTANCE.md>)：在隔离环境里从头到尾验收。

C1–C5 这条闭环**已经在隔离环境里跑通了**，但**没有接进现用的宿主系统**，所以也**不能拿来证明生产效果，更不能证明大模型效果**。

## 我对原文做了哪些“翻译”

- **拆开了三句最重的限制条件**，改成三条独立短句：不是成品、没有服务、不保证掉电安全。原文把这些限制条件分散在段尾的括号和粗体里，读者会跳过。
