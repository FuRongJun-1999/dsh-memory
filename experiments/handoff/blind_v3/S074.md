# S074

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

这类交付物最怕三件事：把“能跑”当成“可用”，把“系统记得”当成“事实正确”，把“供应商说安全”当成“有人负责”。所以我建议交付一份可签字、可复核、可追责的《记忆系统决策说明书》，而不是一份技术方案。下面这版可直接作为初稿改。

**版本：** v0.1  
**编制：** [团队/负责人]  
**审核：** [安全/隐私/法务/业务负责人]  
**批准：** [有权上线的人]  
**日期：** [日期]  
**有效期：** [建议不超过 6 个月，到期复核]  
**文件性质：** 本文件用于非技术决策者判断“能不能用、怎么用、出问题找谁”，不是技术白皮书。未经批准不得修改。

## 0. 给决策者的一页纸

**一句话：** 本系统用于 [保存/检索/使用哪些记忆]，帮助 [业务目标]；它不是事实来源，不能替代人工判断。

**当前建议：** [有条件试点 / 限制范围上线 / 暂不通过]。  
**上线条件：** [列出 3—5 条必须完成的控制，例如权限隔离、删除流程、审计日志、人工复核、应急预案]。  
**绝对禁止用途：** 不得用于 [医疗/法律/财务/雇佣/安全等高风险决定] 的最终决策；不得保存 [密码、密钥、无授权的敏感个人信息]；不得把 A 用户的记忆用于 B 用户。  
**必须停用的情况：** 发现越权泄漏、记忆投毒、删除失败、重大错误导致业务损失、监管或客户投诉。  
**出问题找谁：** [姓名/角色/电话/工单入口]，停用权限在 [角色] 手中。

## 1. 这是什么、不是什么

- **是：** 对 [来源数据] 做记忆写入、检索、更新、删除的辅助系统。
- **不是：** 唯一事实来源；不是自动决策人；不保证记忆真实、完整、最新；不能因为“系统记得”就认为“可以照做”。
- **原则：** 源系统是事实来源，记忆系统只是缓存/索引/摘要。冲突时以 [源系统/审批记录/人工确认] 为准。

## 2. 使用边界

| 场景 | 是否允许 | 要求 |
|---|---|---|
| [低风险辅助查询] | 可 | 显示来源与时间 |
| [涉及个人信息] | 限制 | 告知、授权、最小化、可删除 |
| [涉及钱/合同/人事/健康/法律] | 需人工复核 | 人签字，系统不得自动执行 |
| [未授权敏感数据/密钥] | 禁止 | 不写入长期记忆 |

## 3. 记忆生命周期必须管住的点

1. **写入：** 什么能记、谁批准记、记多久；敏感信息默认不写；高风险记忆需人工确认。
2. **来源：** 每条记忆保留来源、时间、写入人/系统、可信度；防止坏数据和恶意内容被长期记住。
3. **存储：** 分类分级、加密、租户/用户隔离；长期记忆默认少而短。
4. **检索：** 必须带权限过滤；A 的记忆不能进 B 的回答；不要把所有记忆一股脑塞给模型。
5. **使用：** 输出要标明引用了哪条记忆、来源和时间；高风险场景必须人工复核。
6. **更新：** 冲突记忆怎么处理、过期怎么标记、模型/规则变更怎么回滚。
7. **删除：** 用户可查看、更正、删除、关闭记忆；删除要覆盖缓存、索引、备份和第三方。
8. **审计：** 谁写入、谁检索、谁使用、谁批准、哪一版、哪条记忆，都要能查。

## 4. “凭什么信”的证据清单

交付件必须附上，没有就写“缺失+风险”：

- 数据清单：记什么、不记什么、是否含个人信息/商业秘密；
- 数据流图：从哪来、存哪、谁能看、传给谁；
- 权限矩阵：用户/管理员/供应商各能做什么；
- 测试与评估报告：正确召回、错误召回、过期、冲突、越权、恶意注入、删除是否彻底；
- 隐私/安全评审：告知同意、保留期限、跨境、供应商条款；
- 运维与应急：监控指标、告警、一键停用、降级为“无记忆模式”、回滚方案；
- 责任表：产品负责人、数据负责人、安全/隐私/法务、值班人、停用授权人。

## 5. 上线前检查清单

- [ ] 已列出“可记/禁记”清单；
- [ ] 已做权限隔离和越权测试；
- [ ] 已做删除和更正流程，抽查能真正删掉；
- [ ] 高风险场景有人工复核；
- [ ] 有审计日志且防篡改；
- [ ] 有一键停用/回滚方案；
- [ ] 有明确负责人和事故报告入口；
- [ ] 已向非技术使用者说明局限和禁止用途。

## 6. 出事后怎么回答

按这个模板留记录：**发生了什么、何时、影响哪些人/数据/决定；涉及哪条记忆、哪个来源、哪个版本、谁批准上线；当时依据哪些测试和评审；哪个控制点失效；已如何隔离、通知、修复、防复发。** 这样才回答得了“这是什么、谁做的、凭什么”。
