# S105

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

这个记忆系统要给别人用了，我担心出问题。你帮我看看有什么毛病，写份我能看懂的东西。

## 输出

先说结论：**只凭你这句话，我没法判断“这个记忆系统”具体有没有毛病**——你没把系统说明、记录规则、权限、备份、测试情况发给我。但我可以先给你一份**给人用之前能照着查、也能直接给使用者看的说明**。你照着打勾；把材料发我，我再帮你挑具体问题。

你的担心是对的。建立信任的关键不是承诺“我绝不记错”，而是做到：**记得有来源、错了能发现、能改、能删、查得到、有人负责**。别用“我记得准”做承诺，要用制度做承诺。

---

## 一、先查这 12 条：有一项“没有/不确定”就先别大面积给人用

| 检查项 | 要问自己的话 | 过关标准 |
|---|---|---|
| 1. 记什么、不记什么 | 会不会把猜测当事实？会不会记密码、身份证、健康、家庭矛盾等敏感信息？ | 写清楚“只记必要信息”；敏感信息不记或必须本人同意 |
| 2. 来源和更新时间 | 每条记忆能不能看出“谁说的、什么时候说的、原话/推断”？ | 至少标来源、时间、是事实还是推断 |
| 3. 写入规则 | 是系统自动记，还是本人确认后才记？ | 关键信息必须人工确认；不能把推测直接写成事实 |
| 4. 更正入口 | 用户发现记错了，找谁、怎么改？ | 有明确联系人/入口，约定处理时限，比如 24 小时内响应 |
| 5. 删除能力 | 用户要求删除时，能不能删干净？备份里怎么办？ | 主数据可删；备份按周期自然覆盖，并提前说明 |
| 6. 冲突处理 | 同一件事两个说法，以哪个为准？旧信息会不会过期？ | 有“最新确认优先/本人确认优先”规则；过期信息要提醒 |
| 7. 权限 | 谁能看、谁能改、谁能导出？离职/退出后怎么收回？ | 最小可见；共享范围写清楚；退出即撤销 |
| 8. 备份恢复 | 数据丢了能不能恢复？试过恢复吗？ | 定期备份，且至少实际恢复演练过一次 |
| 9. 审计日志 | 谁读过、改过、删过，能不能查？ | 关键操作留痕；普通使用者知道会被记录 |
| 10. 人工兜底 | 关键决定会不会只凭记忆自动做？ | 钱、健康、法律、承诺类事项必须人工再确认 |
| 11. 测试 | 有没有试过重名、串人、错记、删除、越权、导出泄露？ | 至少做 5 类坏情况测试，并记录结果 |
| 12. 出事故怎么办 | 发现记错后，谁告知、谁止损、谁复盘？ | 有简单流程：发现→停止使用→告知受影响的人→更正→复盘 |

**几条红线：**
- 不要把不同人的记忆混在一起。
- 不要把“我猜”写成“事实”。
- 不要让使用者找不到“更正/删除/找人负责”的入口。
- 不要对外说“100% 准确”。要说“可核对、可更正、有记录”。
- 关键信息使用前，向本人再确认一次。

## 二、可以直接给使用者看的一段说明（草案）

> **关于这个记忆系统的说明**
>
> 这个系统用来帮我记录和回忆与你相关的必要信息，目的是减少重复沟通、避免遗漏。它**不是万能的，也可能记错、记旧或理解偏**。
>
> 我们只记录提供服务/合作所必需的信息，不记录密码、身份证号等敏感信息；涉及重要事项时，我会再向你确认。每条重要信息尽量标明来源和更新时间。
>
> 如果你发现我记错了、记旧了，或者不希望某条信息被记录，请直接告诉我。我会在 **【填写时限，如 24 小时】** 内更正或删除，并告诉你处理结果。系统有权限控制和操作记录，不会随意共享给无关的人。
>
> 重要决定不会只凭系统记忆自动做出，会经过人工确认。出现问题请联系 **【姓名/联系方式】**。
>
> 我不能保证永远不出错，但可以保证：**你可以查、可以改、可以要求删除，出了问题有人负责。**

这段话比“请相信我”更能建立信任，因为它把责任和纠错办法写清楚了。

## 三、最可能出的毛病，先重点防

1. **把猜测当事实记下来**——最伤信任。  
2. **把甲的信息记到乙头上**——重名、多人场景特别危险。  
3. **旧信息不更新**——用户已经改了，系统还按旧的来。  
4. **删除不彻底/备份里还有**——要提前说清楚。  
5. **权限太大**——一个人用，结果一群人能看。  
6. **没有备份**——一丢全丢。  
7. **错了没人知道**——没有更正入口和反馈渠道。  
8. **关键事项自动执行**——比如承诺、付款、健康建议，必须人工兜底。

---

## 四、你接下来可以这样做

先别一次性全开放。建议先做“小范围试用”：

1. 只给 1—2 个信任的人用；
2. 关键记忆必须本人确认后才写入；
3. 每天备份一次；
4. 给一个明显的“记错了/请删除”入口；
5. 每周收集一次问题，改完再扩大范围。

---

## 五、如果你要我看具体毛病，把这些发我

不用发真实隐私，脱敏即可：

- 系统怎么记录、怎么读取的流程；
- 记录字段长什么样；
- 谁能看/改/删；
- 有没有日志、备份、恢复记录；
- 写入规则或提示词；
- 做过哪些测试；
- 一份脱敏示例记录。

你怕信你的人吃亏，这个态度本身就是信任的基础。**但对外别承诺“不会错”，要承诺“错了能查、能改、有人管”。** 你把这些材料发我，我可以继续帮你按上面清单逐条挑问题。
