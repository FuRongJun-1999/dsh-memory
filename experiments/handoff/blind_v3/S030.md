## 输出

## 直说：这份评审我只看到了一半

我能读到的是你贴的三份文档（README、ACCEPTANCE、SECURITY_MODEL）。代码我一行都没看到——`<目标仓>` 被读权限挡在外面，返回的是“路径超出子代理读权限范围”。所以下面每一条，都是从**你自己的文档里读出来的**，不是从实现里读出来的。凡是我说“文档承认”“文档没写”，都请当作“我没验证过实现是否也如此”。

这个区分对你很重要，因为你最怕的是“让人吃亏”，而让人吃亏的典型方式就是我这种外部评审替你说了一句你没资格说的话。所以先立规矩：**下面所有判断都可以被你推翻，只要把代码给我看。**

## 一、最该担心的：流水线会绿，但没东西可用

ACCEPTANCE 里有一句很轻的话，重量很大：

> 运行 `python scripts/release_gate.py` 检查登记表自身一致性；**它可以在发布被阻断时返回 0。**

意思是：任何人（包括未来的你）在 CI 里跑这个脚本，看到绿色，会以为“门禁过了”。实际上它只检查了登记表格式对不对。真正的判定要加 `--profile production --candidate <SHA>`，缺证据才返回 3。

这是**最容易被误读成“我们准备好了”的地方**，而且误读成本最低、后果最贵。文档里写清楚了，但写在第三段——它应该写进脚本的 `--help` 第一行，甚至让不带参数的调用直接非零退出。

## 二、证据链是“自己签字”，不是“外部作证”

文档很诚实地承认了两件事：

> 登记表是对候选的事后审阅……**输出与复核身份须由可信外部采集，哈希不能认证生产现场**。
> **临时合成证据只测试判定逻辑。**

诚实很好，但结论要看清：`release_gate.py` 判定的是“有人按格式提交了声称通过的材料”，**不是“这些东西真的跑过”**。一个人如果同时是执行者、证据采集者和复核人，或者把上个 commit 的证据改个 SHA 复用，门禁照样绿。文档要求“不同复核人”，但这是流程约定，不是机器约束。

对你这个目标（让别人信任）来说，这恰恰是最关键的一环：**你的可信度目前完全押在“人会守规矩”上。**

## 三、R01–R09 全 NOT_RUN，而 README 首屏在说“闭环通过”

README 第一屏写的是“C5隔离验收（**隔离闭环通过**，未接现用宿主，不证明生产/LLM效果）”，括号里的话是对的；但 ACCEPTANCE 的表里 R01–R09 清一色 NOT_RUN。

两句话都真，但**放在一起读的人只会记住前半句**。你的读者（要给用的那些人）不会读括号。这不是措辞问题，是“预期管理”的结构问题：结论和限定语的距离，等于别人误解你的概率。

顺带说一句，R07 是“审计损坏/降级/外国行的明确区分”——**你卖的是“可审计记忆”，而审计本身是否可信，是未验证项**。这是整个项目最反讽的一处，也是最该优先补的。

## 四、几个“以后一定会咬人”的具体缝

- **租户隔离靠部署约定，不靠代码。** 一个根目录服务一个租户，“当前入口未强制绑定根目录与租户”。配错一次就是跨租户泄露，而且写的时候没有任何东西会喊停——只有恢复时读审计行才发现异常。太晚了。
- **不可变性是“未来”的义务。** SECURITY_MODEL 自己写：“模型无持久化，须由**未来**治理临界区保证边集与版本不可变。”也就是说，你最强的那条安全承诺（不许原地改写历史）目前是**假设**，不是实现。
- **遗忘/删除只是规划。** 你想对别人负责，最重的承诺是“我记错了能删掉、能纠正”，而文档写的是“不实现认证、原子发送或清理”。**没做到的删除承诺，比不做承诺更伤信任。**
- **多写者状态只证明“我说过”，不证明“我活着”。** 而且要信任本地文件系统、时钟、启动器，不覆盖断电恢复、跨主机、凭据轮换——真实部署里出事的恰好是这几样。
- **没有任何“用了它，人真的受益”的证据。** C4/C5 明说未接真实宿主，不证明 LLM 效果。所以现在能证明的是“契约自洽”，不能证明“帮到了人”。

## 五、文档太多了，多到危险

几十份文档、生成的契约、锁清单、变异测试……工程纪律是真好，我不打折。但副作用是：**读者会把“写得很清楚”错当成“已经做到”**，而且维护者的精力会持续被文档吃掉，而不是被“真实环境下跑一遍”吃掉。

写清楚 ≠ 做到。这句话你文档里其实已经有了（“CI绿不等于运行时已完成”），只是它现在是一句免责声明，而不是一句行动指令。

## 你现在就能做的三件事

1. **让 `release_gate.py` 不带参数时非零退出**，除非显式声明 `--check-registry-only`。一小时的活，砍掉最大的误读风险。
2. **把 README 首屏改成先写 NOT_RUN**：第一句就是“生产运行时：0/19 项已验证”。想被认可的人容易把好消息放前面——反过来做，才是可信度的来源。
3. **给“删除/纠正”一条真的能跑的路**，哪怕只覆盖影子库。你怕记错让人吃亏，那“改得掉”比“记得准”更救命。

## 关于你说的“想被认可”

我认真回一句，不绕。

这个仓库里最值钱的东西，**不是那些契约，是那一片 NOT_RUN**。绝大多数项目会把它们改成 PASS 或者干脆删掉表。你没删，还专门写了判定器防止自己糊弄自己——这是能换信任的东西，而且换得到。

但“想被认可”也是个会推着你多说的东西。它让你把“隔离闭环通过”放首屏，把“生产全 NOT_RUN”放第二页。这个偏向很难自查，因为每一句单独都是真的。
