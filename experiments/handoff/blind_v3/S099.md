# 记忆系统对外使用前风险说明（简版）

## 一、先说三个最可能出事的毛病

1. **不是记不住，而是记错了还像真的。**  
   如果一条记忆没有来源、时间、置信度、状态，用户没法判断它对不对。

2. **记忆会被污染。**  
   错误写入、重复记录、新旧冲突、过期信息、越权信息混在一起，会越用越错。

3. **身份和责任边界不清。**  
   AI 用人类口吻回答没问题，但不能让用户误以为“这是真人确认过的”。涉及钱、健康、法律、承诺、权限的事，必须有人复核或明确提示风险。

---

## 二、每条记忆最少要有这些字段

没有这些，用户很难验证：

- 记忆 ID
- 内容：一句话说清楚
- 来源：谁说的 / 哪份文件 / 链接 / 原文位置
- 记录时间
- 最后确认时间
- 适用对象和场景
- 置信度：高 / 中 / 低，或 0—1
- 状态：有效 / 待确认 / 过期 / 有冲突 / 已删除
- 负责人
- 可见范围 / 敏感级别
- 版本号和变更记录

**白话版：**每条记忆都要能回答“哪来的、什么时候的、谁负责、现在还算不算数”。

---

## 三、回答输出要守的规则

- 能引用来源就引用；不能确认就说“我不确定”或“系统里没有可靠记录”。
- 区分“事实”“推测”“建议”，不要混在一起。
- 时间敏感信息必须写“截至某日”。
- 旧记忆不能直接当现在用。
- 发现两条记忆冲突，要展示冲突，不要擅自选一个。
- 涉及钱、健康、法律、承诺、权限、隐私：必须人工复核或明确提示。
- 每条回答下面给一个纠错入口：“这条不对，点这里反馈”。
- 不要承诺“100% 正确”，要承诺“有来源、可纠错、错了能追”。

---

## 四、写入、更新、权限要查

- 谁能写？写之前要不要审核？
- 重复记忆怎么合并？
- 新旧冲突怎么处理？
- 过期记忆怎么标记和清理？
- 删除是否彻底？有没有审计记录？
- 不同用户/客户的数据是否隔离？会不会串记忆？
- 敏感信息能不能记？谁能看？能不能导出和删除？
- 出错了能不能回滚？

---

## 五、怎么证明它靠谱：给老板看指标

不要只说“我们会小心”，要给几个能看的数：

- 抽样检查多少条，错了多少条
- 有来源引用的回答占比
- 过期记忆占比
- 冲突记忆占比
- 用户反馈纠错后，多久改完
- 高风险场景人工复核覆盖率
- 有没有日志：谁在什么时候写入、修改、查询、删除

建议先小范围试点两周，高风险场景人工兜底，达标再扩大。

# 给老板的一页纸模板

**标题：记忆系统对外使用前说明（简版）**

1. **它是什么：**  
   一个带来源、时间和纠错入口的记忆辅助系统，不是全知数据库。

2. **它能做什么：**  
   查已记录信息、给出来源、提示不确定、接收纠错。

3. **它不能做什么：**  
   不保证 100% 正确；不替人做高风险决定；不处理未授权数据；不把旧信息当现在。

4. **最大风险：**  
   - 红色风险：错误信息被用户当成事实。  
   - 黄色风险：记忆过期、冲突、重复。  
   - 绿色基础：每条结论有来源、可反馈、可追溯。

5. **怎么验证：**  
   每条关键结论带来源；每周抽检 20 条；用户可一键纠错；统计错误率和纠错时长。

6. **上线方式：**  
   先小范围试点，高风险场景人工复核；出错可回滚；达标后再扩大。

7. **需要老板拍板：**  
   谁负责复核；哪些数据不能记；出错谁处理；是否明确告知用户“AI 辅助，可能出错，请核对来源”。

8. **一句话承诺：**  
   不确定就说不确定；错了能查到、能改、能通知、能止损。

# 给用户的一段话模板

> 我会尽量基于有来源的记录回答。记录可能过期、冲突或缺失，我会尽量标出来。涉及重要事项，请你点开来源核对。发现错误请点反馈，我们会修改并记录。这是 AI 辅助整理，不替代人工判断。
