## 一、改写版：人话 README

### 这是什么
这是一份**设计说明书**，不是已经能用的产品。
它想解决一件事：AI 记住的东西，**别人能查、能核、能追责**。
但请注意：现在它只做到了“把规矩写清楚，并且用程序验证这些规矩没写互相矛盾”，**没有做到**“帮你存记忆”“给你当服务用”“断电不丢数据”。

### 现在到了哪一步（这段最重要，别跳过）
- 已经做到：文档和规格一致，跑一个脚本就能查出来有没有对不上。
- 还没做到：真实的存储、多人同时用、身份认证、跨平台长期保存、老数据搬迁。
- 结论一句话：**“检查通过”不等于“能上线用”。**

这不是我谦虚，是这份文件自己写的。我一字不改地保留，因为一旦有人拿它当成品去用，吃亏的是相信你的人。

### 你为什么可以相信它（给要信任你的人看的）
它不要求你“信我”，它给你三样能自己动手核实的东西：
1. **一条命令自检**：装有 Python 3.11 以上，在仓库根目录运行 `python scripts/check_all.py`，绿了就是内部规矩没打架。
2. **逐文件清单**：`scripts/spec-tree.lock.json` 记着每个规格文件的名称和内容指纹。谁偷改了，一核就露。
3. **只读检查器**：`scripts/spec_tree.py` 专门干这活，只查不改。

有一句话请你也替我守住：**清单一致不代表批准发布**。它只能证明“没被偷偷动过”。

### 改规矩的时候守什么
- 不许为了“让检查变绿”去改测试。那等于把体温计砸了说没发烧。
- 核心规矩一改，就得升版本号，并写清为什么改。
- 这上面没有“自动放行”：改了清单，等着人来审。
