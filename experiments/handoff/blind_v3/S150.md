## 现在的真实进度（三层，别混）

**1. 规格工具 C01–C10：全部 NOT_RUN。**
注意这不是 FAIL。文档第一句就写了：“未登记候选及其证据时，C01–C10、R01–R09 均标 NOT_RUN；这不否认已有隔离测试。”也就是说测试大概是不缺的，缺的是**按候选提交登记证据**这道流程。NOT_RUN 的含义是“没验”，不是“验了没过”。

**2. 运行时 R01–R09：生产门禁全部 NOT_RUN。**
文档加了一行注：在 `shadow_runtime`（纯文本 Markdown 真源 + JSON 索引，零二进制 DB）上，R01–R09 的故障注入测试和变异测试**已实跑通过**。但紧接着写了：“下表为生产真实环境挂接门禁，生产接管前仍保持 NOT_RUN。”这是两个不同的东西，影子运行时跑通不等于生产挂接验收。power 档还额外要求 R04，同样是 NOT_RUN。

**3. 周边模块：**
API 提案有明确列出的“未实现边界”；迁移与事务“仍全部 NOT_RUN”；兼容清单只有 44 个顶层 op **候选**。

结论：常规生产档要全部 C 项 + 除 R04 外的 R 项，power 档再加 R04。两个档现在都过不了。

## 最容易让你在乎的人吃亏的三句话

你说你怕记错、怕信你的人吃亏——风险恰好集中在这三句上，都是“听起来是同一件事，其实是两件事”：

- **“测试全绿了” → 说成“验收通过了”。** 文档明写“规格工具绿不会自动更新运行时状态”。
- **“影子运行时跑通了 R01–R09” → 说成“运行时做完了”。** 影子跑通的是故障注入逻辑，不是生产环境的文件/目录/审计/轮转真实持久化。
- **“判定器返回 0” → 说成“可以发布”。** 文档明写“它可以在发布被阻断时返回 0”，且“两种命令均不执行发布”。这条最阴,因为 0 通常被读成“没问题”。

还有一条：文档说“哈希不能认证生产现场”“临时合成证据只测试判定逻辑”。意思是**编一份漂亮的 JSON 让判定器变绿，是完全可能的，而且毫无意义**。如果你哪天为了让别人安心去凑证据,那就是你说的“让信我的人吃亏”本身。
