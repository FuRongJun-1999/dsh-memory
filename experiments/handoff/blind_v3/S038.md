# dsh-lingshu-memory

灵枢 Memory 1.0：给 AI 助手（agent）做长期记忆的一套公开设计图纸，加上一批能自动核对的规则文件。

## 三段话看懂它

**它是什么。** 一套设计文档 + 规则文件，讲清楚 agent 的记忆该怎样存、怎样取、怎样回放、怎样测、怎样验收；"可审计"的意思是，每一步都能被第三方拿着文档和脚本复核，而不是靠作者口头保证。"可执行契约"的意思是，这些规则写成了机器能校验的格式，不是散文。

**它现在到哪一步。** **设计开发中，不是已发布的 1.0 运行时。** 没有生产可用的存储服务，没有 MCP 服务，不承诺掉电不丢数据。仓库里的代码只有一个用途——验证规格本身写不写得通。

**它证明了什么。** 五块核心机制（C1–C5）在一个隔离环境里能首尾串起来跑通；但没接到任何现用宿主上，所以既不证明生产可用，也不证明接上真实模型后效果会变好。

## 五块核心

新接一个长期任务，按这个顺序看：

| 块 | 一句话 | 文档 |

## 它和 dsh-memory 的关系

承接 [dsh-memory](https://github.com/FuRongJun-1999/dsh-memory) 的设计与实践，**不是它的原地升级，也不是它的生产替代**。

不搬迁生产记忆，不复制原始会话、私有路径或执行日志。

## 三条硬规矩

1. **CI 绿≠运行时做完。** 规范与工具能通过验证，只说明文档自洽；真实存储、并发、认证、平台持久化和迁移，都还要单独验收。
2. **规格目录动一个字都要人审。** 规格目录有逐文件清单（名字 + 字节摘要，样例和已生成报告也算在内）和只读检查器，增删改都要审阅；CI 不会自动重写清单；清单对得上，也不等于获准发布。
3. **不许改测试来掩盖语义漂移。** 检查变红了就是规格变了，不是测试错了。
