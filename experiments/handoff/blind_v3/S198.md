# S198

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

做“记忆系统”先别急着选向量库，核心是想清楚：**记什么、什么时候记、怎么取、如何更新/遗忘、出错谁负责**。如果你们做的是 AI 助手/Agent 的长期记忆，我会重点注意这些：

### 1. 先定义“记忆”的边界
- 区分：**工作记忆**（当前会话）、**情节记忆**（发生过什么）、**语义记忆**（事实/知识）、**偏好/程序记忆**（用户习惯、做事规则）。
- 不是所有对话都值得记。要明确：哪些信息有长期价值？哪些只是上下文？
- 记忆要分用户/租户/会话隔离，避免串数据。

### 2. 写入策略比存储更重要
- 支持**显式记忆**（用户说“记住…”）和**隐式抽取**（从对话中提炼），但隐式写入要有置信度和审核/纠错机制。
- 要做**去重、合并、冲突检测**：同一事实多次出现怎么办？新旧冲突听谁的？
- 给记忆加元数据：来源、时间、置信度、敏感级别、过期时间、可删除标记。
- 避免“记忆污染”：错误信息、临时状态、他人信息、提示注入内容不能随便进长期记忆。

### 3. 读取要控质量和上下文预算
- 检索不是“相似度 top-k”就完事，要结合**时效性、重要性、置信度、用户权限、场景**重排。
- 控制注入上下文的量，避免记忆挤占当前任务上下文。
- 对冲突记忆要有策略：最新优先、显式优先、高置信优先，或向用户确认。
- 检索不到时宁可不编，不要拿弱相关记忆硬凑。

### 4. 更新、过期和遗忘机制
- 记忆会过时：偏好、地址、项目状态都要能更新。
- 支持 TTL、时间衰减、软删除、硬删除、用户可查看/修改/清空。
- 合规上要考虑被遗忘权、数据导出、审计日志。
- 删除要贯穿缓存、索引、备份，别只删主表。

### 5. 安全与隐私是硬约束
- 敏感信息分级：密码、证件、医疗、财务等默认不长期存，或需明确授权。
- 防记忆投毒和提示注入：外部网页/文档内容不能直接变成高置信长期记忆。
- 权限继承：某条记忆只在特定应用/场景可用，不要全场景裸奔。
- 日志脱敏，访问可审计。

### 6. 可解释、可调试
- 每条记忆要能回答：从哪来、为什么记、什么时候用过、被谁改过。
- 提供记忆管理界面或 API，让用户/运营能查看、纠正、删除。
- 出问题时能回放：这次回答用了哪些记忆？为什么检索到它？

### 7. 评估体系要提前建
- 离线：记忆抽取准确率、去重合并、冲突解决、检索命中率、错误记忆率。
- 在线：任务成功率、用户纠正率、延迟、成本、记忆命中后的收益。
- 特别关注失败模式：记错、记串、过期未更新、检索噪声、隐私泄漏。

### 8. 工程上别过度设计
- MVP 可以：结构化用户画像 + 关键事件表 + 向量检索 + 显式纠错。
- 先保证**可删、可查、可纠错**，再追求自动抽取和智能合并。
- 存储成本通常不是最大问题，**错误记忆和不可控注入**才是。

一句话：**记忆系统的难点不在“存”，而在“该不该记、记得对不对、该不该用、能不能删”。**

如果你们是做 AI Agent 记忆，我可以再帮你按“最小可行架构 + 数据模型 + 评估指标”拆一版。
