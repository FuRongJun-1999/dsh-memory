# S081

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

如果你们要做的是 **AI/Agent 产品的记忆系统**，最核心的一句是：**记忆不是越多越好，而是要“记得准、找得到、可解释、可纠正、可删除”。**

我会重点注意这些：

### 1. 先定义“记什么、为谁记、记多久”
不要把所有对话都当记忆。至少区分：
- 短期会话状态
- 长期用户偏好
- 稳定事实（如用户职业）
- 任务上下文
- 知识库内容
- 敏感信息

不同类型用不同存储、生命周期和读取策略。**不要把知识库、用户画像、会话摘要混成一坨。**

### 2. 写入要有门控
常见坑是“什么都自动记”，最后记忆膨胀、污染、过时。
建议：
- 显式记忆优先：用户说“记住…”才记
- 隐式记忆要带置信度和来源
- 去重、合并、冲突检测
- 保留原始证据，别只存模型总结
- 重要信息结构化，非重要信息摘要化

### 3. 读取比写入更关键
用户感知到的是“你有没有在该记的时候想起来”。
注意：
- 召回准确率比召回数量重要
- 支持时间、权限、场景过滤
- 混合检索：向量 + 关键词 + 结构化条件
- 控制上下文预算，别把一堆记忆塞进 prompt
- 命中后要能解释“为什么用了这条记忆”

### 4. 冲突、过期和纠错机制
记忆一定会冲突：
- 用户搬家了
- 偏好变了
- 两条记忆互相矛盾
- 模型总结错了

要有：
- 版本/时间戳/来源/置信度
- 有效期和衰减机制
- 冲突解决策略
- 用户可查看、编辑、删除
- 纠错后要能影响后续行为

### 5. 隐私、安全和权限是底线
尤其多租户产品：
- 最小化收集
- 敏感信息分类与脱敏
- 加密存储、访问控制、审计日志
- 租户隔离，检索前做权限过滤
- 支持导出和彻底删除
- 防提示注入污染记忆
- 防越权召回别人的记忆

### 6. 生命周期和遗忘
没有遗忘机制的记忆系统迟早不可用。
需要：
- TTL
- 冷热分层
- 归档
- 摘要压缩
- 重要性衰减
- 定期清理和回放校验

### 7. 用户可控和透明
最好让用户能：
- 看到系统记住了什么
- 知道为什么记
- 一键删除/关闭记忆
- 纠正错误记忆
- 区分“临时使用”和“长期保存”

### 8. 评估体系要提前建
不要只看“回答像不像”。
建议指标：
- 召回率/精确率
- 记忆命中后任务提升
- 错误记忆率
- 过时记忆率
- 用户纠正率
- 延迟和成本
- 隐私违规/越权召回次数

离线做场景集，线上做 A/B 和可观测。

### 9. 架构上别过度设计
MVP 可以先做：
- 显式记忆
- 结构化存储 + 向量检索
- 来源和置信度
- TTL
- 用户可管理
- 简单冲突规则
- 检索日志

等有真实数据后，再上自动抽取、记忆压缩、复杂衰减和个性化排序。

### 10. 最危险的不是“记不住”，而是“记错了还反复用”
常见失败模式：
- 把一次性信息当长期偏好
- 模型总结失真后被反复召回
- 过时信息污染回答
- 记忆越多检索越差
- 权限过滤放在召回之后导致泄露
- 用户不知道怎么删

**总结：** 先做“可控的显式记忆”，把来源、权限、过期、纠错、评估做扎实；不要一上来追求全自动长期记忆。你们如果告诉我具体场景——是 AI 助手、客服、教育、还是多 Agent——我可以给更具体的架构和优先级。
