# S043

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

这个记忆系统要给别人用了，我担心出问题。你帮我看看有什么毛病，写份我能看懂的东西。

## 输出

可以，但我现在**看不到这个记忆系统的代码、配置或设计说明**，直接说“有什么毛病”会是瞎猜。先别急着给别人用，尤其是记忆系统一旦串用户、删不干净、把错误信息长期记住，后面很难收拾。

你先给我下面任意一部分，我就能出一份“非技术也能看懂”的审查报告：

1. **写入记忆、读取记忆、删除记忆**这三段代码或接口说明（最重要）
2. 系统大概流程：谁写入、写什么、谁能查、怎么删、存哪里
3. 是否给别人外部用？是否多用户/多公司共用？
4. 权限怎么分：管理员、普通用户、访客
5. 数据样例（**脱敏**，别贴真实密钥和隐私）
6. 备份、日志、过期清理方案
7. 你最担心的点：泄露？串号？删不掉？记错？被滥用？

你可以先拿这份**记忆系统常见毛病速查表**自查：

| 风险 | 通俗解释 | 怎么查 | 建议 |
|---|---|---|---|
| 串用户 | A 的记忆被 B 看到 | 用两个账号互相查 | 所有查询强制带用户/租户 ID |
| 越权删除/修改 | 普通用户能改别人记忆 | 用低权限账号试管理员操作 | 每个接口都做权限校验 |
| 删除不彻底 | 用户删了，备份/日志/缓存里还有 | 删除后查库、缓存、备份、检索索引 | 设计“彻底删除”流程 |
| 敏感信息长期留存 | 密码、身份证、聊天隐私被记进去 | 看写入前有没有过滤 | 写入前脱敏/拦截，设置保留期限 |
| 记错还反复用 | 错误记忆被检索出来影响回答 | 构造错误信息再提问 | 记忆带来源、时间、置信度，可纠正 |
| 记忆污染/提示注入 | 恶意内容被存成“长期记忆” | 写入“忽略之前指令”等测试 | 写入审核、隔离不可信内容 |
| 没有过期策略 | 三年前的偏好还在用 | 查是否有 TTL/清理任务 | 按类型设过期时间 |
| 检索不分优先级 | 旧记忆压过新记忆 | 先写旧偏好再写新偏好 | 时间、来源、类型加权 |
| 重复和冲突 | 同一件事记了很多版本 | 连续写相似内容 | 去重、合并、保留版本 |
| 日志泄露隐私 | 排查日志里全是原文 | 看日志字段 | 日志脱敏、限制访问 |
| 没有审计 | 出事不知道谁查/改了 | 查操作记录 | 记录关键操作，但别记敏感原文 |
| 备份变后门 | 主库删了，旧备份还能恢复泄露 | 查备份权限和保留周期 | 加密、限权、定期销毁 |
| 资源被刷爆 | 大量写入/检索拖垮系统 | 压测、限流 | 写入限流、容量上限、告警 |
| 故障丢记忆 | 服务一挂全没 | 模拟重启/故障 | 持久化、备份、恢复演练 |

我最终会给你写成这种东西：

- **一页版结论**：能不能给别人用，先修哪几个
- **风险清单**：严重/中等/低，按优先级排
- **每个问题的“人话解释”**：为什么会出事、怎么复现
- **修改建议**：改哪里、怎么验
- **上线前检查表**：逐项打勾

你先把**写入、读取、删除记忆的代码或流程**贴过来，或者用几句话描述一下。**记得先脱敏，别贴真实密钥、手机号、身份证、用户聊天原文。**
