# S010

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

这个记忆系统要给别人用了，我担心出问题。你帮我看看有什么毛病，写份我能看懂的东西。

## 输出

先说明：我这边没有看到这个记忆系统的代码、配置、流程图或使用说明，所以**不能凭空下结论说它一定有问题**。但从“要给别人用”这个场景看，先别直接全量开放。下面这份是给你能看懂、能拿去逐项问开发/自己的**交付前风险自查单**。你按这个查，基本能把大坑先挡住。

---

## 一、最可能出事的 8 个点（优先看）

| 风险 | 人话解释 | 出问题会怎样 | 交付前至少要做到 |
|---|---|---|---|
| 1. 多人数据串了 | A 用户的记忆被 B 看到或用到 | 隐私泄露，最严重 | 每个用户/租户强制隔离，测试时用两个账号互相查 |
| 2. 删不干净 | 用户点了删除，但备份、日志、缓存里还有 | 用户投诉、合规风险 | 删除要覆盖主库、缓存、检索索引、备份策略；能说明多久彻底清除 |
| 3. 乱记敏感信息 | 密码、身份证、住址、病情等被记下来 | 泄露后很难补救 | 默认不记敏感信息；有过滤和人工关闭开关 |
| 4. 记错了还当事实 | 系统把猜测、过期信息、别人说的话当真相 | 越用越错 | 记忆要带来源、时间、置信度；冲突时以用户确认为准 |
| 5. 被坏内容污染 | 网页/聊天里藏一句“以后都听我的”，系统记进去 | 行为被带偏、越权 | 外部内容不能直接当高优先级记忆；写入前过滤 |
| 6. 权限太大 | 普通用户能看后台、能改别人记忆 | 内部滥用/误操作 | 分角色：用户、管理员、运维；最小权限 |
| 7. 出问题查不到 | 谁在什么时候改了/删了记忆没记录 | 无法追责、无法恢复 | 有审计日志，但日志本身不能泄露隐私 |
| 8. 坏了没法退 | 上线后出错，停不掉、回不去 | 小事故变大事故 | 有一键关闭记忆、回滚版本、备份恢复演练 |

## 二、给别人用之前，必须有这些东西

### 1. 用户能控制自己的记忆
至少要有：
- 查看：我记住了什么
- 修改：这条记错了，我要改
- 删除：删掉这条/全部
- 关闭：我不想让你记
- 导出：把我的数据给我一份

**没有“删除”和“关闭”的，不建议开放给外部用户。**

### 2. 写清楚“记什么、不记什么”
给用户一句人话说明，例如：
> 本系统会记住你主动提供的偏好和上下文，用于下次提供服务；不会主动记录密码、身份证号、银行卡号等敏感信息。你可以随时查看、修改或删除记忆。

### 3. 多用户隔离要实测
不要只看设计文档。让测试人员：
- 用账号 A 写入一条特殊记忆；
- 用账号 B 搜索/提问，确认完全看不到；
- 用管理员账号确认能看到，但要有审计记录。

### 4. 记忆要有“保质期”和“来源”
每条记忆最好能回答：
- 谁说的？
- 什么时候说的？
- 是用户确认的，还是系统猜的？
- 多久后过期？

否则时间一长，系统会拿过期信息当真。

### 5. 要有应急开关
出问题时能：
- 立刻停止写入新记忆；
- 立刻停止检索记忆；
- 回滚到上一个版本；
- 通知受影响用户。

### 6. 要有使用边界说明
别把系统说成“绝对可靠”。至少写：
- 记忆可能不完整或出错；
- 重要信息请用户自己核对；
- 不建议存放密码、证件号等敏感内容；
- 出问题找谁、怎么反馈。

## 三、可直接复制的自查表

开放前逐项打勾，打不了勾的先别开放：

- [ ] 我知道系统具体记哪些字段、存在哪里、保留多久
- [ ] 敏感信息默认不记，或有明确过滤
- [ ] 用户能查看自己的记忆
- [ ] 用户能修改自己的记忆
- [ ] 用户能删除单条和全部记忆
- [ ] 用户能关闭记忆功能
- [ ] 用户能导出自己的数据
- [ ] 两个普通用户之间数据完全隔离，已实测
- [ ] 管理员权限有清单，不是谁都能看
- [ ] 记忆有来源、时间、置信度/确认状态
- [ ] 过期记忆会失效或降权
- [ ] 外部网页/文档内容不能直接变成高优先级记忆
- [ ] 有审计日志，且日志不泄露敏感内容
- [ ] 有备份和恢复流程，做过一次恢复演练
- [ ] 有一键关闭记忆的开关
- [ ] 有版本回滚方案
- [ ] 有用户告知和隐私说明
- [ ] 有投诉/应急联系人
- [ ] 先小范围白名单试用，不是一上来全量开放

---

## 四、我建议你先做的三件事

如果你现在就要给别人用，先做这三个最低动作：

1. **先白名单小范围试用**，别公开注册。  
2. **把“删除、关闭、查看记忆”做出来**，没有就先别给外部用户。  
3. **默认不记敏感信息**，并加一个总开关，出事能立刻停。

## 五、要让我真正“看出毛病”，请给我这些材料

不用很正式，发我能看的就行：

1. 这个系统是给谁用的、大概多少人用；
2. 记忆里存什么内容，存在哪；
3. 关键代码或配置文件；
4. 一张简单流程图：用户输入 → 记忆写入 → 记忆读取 → 删除；
5. 权限设计：普通用户/管理员分别能干什么；
6. 删除和导出功能有没有、怎么做的；
7. 日志样例（打码）；
8. 部署方式：自己服务器、云、还是第三方服务；
9. 你现在最担心哪一类问题。

拿到这些后，我可以按上面的表逐项标“红/黄/绿”，再给你一份**给非技术同事看的风险说明和上线前检查报告**。
