## 三处最容易被转述成"已通过"的地方

1. **小节标题**："运行时（隔离影子运行时已实跑 R01–R09；生产接入仍 NOT_RUN）"——同一屏上"已实跑"和"NOT_RUN"并存。技术上不矛盾，转述时几乎必然被读成"R01–R09 已通过"。对外统一用两个词：**影子实现层验证过** / **生产门禁未执行**，别用"跑过"。
2. **`python scripts/release_gate.py` 不带参数返回 0**。文档明写"它可以在发布被阻断时返回 0"——它查的只是登记表自身一致性。谁把这条 CI 绿灯贴出去，等于零信息，而且是负信息（会让人以为门禁过了）。真正的判定只有带 `--profile production --candidate <40位SHA>` 那一条。
3. **证据规格被低估**。每个 PASS 要一份独立保存、以 SHA-256 命名的 JSON，含文件字节、项目 ID、提交、环境范围、数据/策略摘要、命令、输出、退出码、**一次注入 FAIL 加一次撤销 PASS 的对照**、以及**不同复核人**。"不同复核人"意味着这事单人干不完——它是个双人流程，不只是写代码的活。这条现在显然没满足（未核实，但缺口明显）。

## 就算将来全绿，这几句也不能说

文档已经把免责声明写在自己身上了，我照抄加重：

- "输出与复核身份须由可信外部采集，**哈希不能认证生产现场**。"——证据是自采的，哈希只能防篡改，不能证明当时生产环境真是那样。
- "登记表是对候选的**事后审阅**，不要求其自身的 Git SHA 等于候选。"
- "临时合成证据**只测试判定逻辑**。"——别拿合成证据去对外。
- "删项或改弱必需范围视为无效。"——所以也别想着把 R04 划掉换个说法过。

一句话：这套机制能证明"有人按清单采过证"，不能证明"生产现场没坑"。对外话术要卡在这个粒度上。
