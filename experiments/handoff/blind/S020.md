# S020

## 题面（所有样本同一题面；输出由不同条件产生，评分时不必关心条件）

我们要做个记忆系统，你觉得要注意什么？

## 输出

如果你们做的是 **AI/Agent 的记忆系统**，最核心的提醒是：**记忆系统不是“接个向量库”就完了，它本质上是数据模型 + 写入策略 + 检索策略 + 遗忘机制 + 权限隐私 + 产品预期管理的组合。**

建议重点看这几块：

### 1. 先定义清楚“记什么、给谁用、什么时候取”
- 记忆分几类：工作记忆、会话记忆、用户长期偏好、事实知识、任务经验、流程性记忆。
- 哪些需要显式让用户确认？哪些可以自动提炼？
- 记忆是给单个 Agent 用，还是跨 Agent/跨团队共享？
- 先做窄场景 MVP，不要一上来做“全能记忆”。

### 2. 写入策略比存储更重要
要避免什么都记：
- 什么值得记：稳定偏好、长期事实、重要决策、可复用经验。
- 什么不该记：一次性上下文、敏感信息、过期信息、低置信度推测。
- 写入最好有置信度、来源、时间、过期策略、可撤销机制。
- 自动记忆要有“用户可查看、可编辑、可删除”。

### 3. 检索策略要控制“召回”和“注入”
- 不是召回越多越好，关键是准确、相关、少而精。
- 要处理：语义检索、关键词、时间衰减、重要性权重、冲突记忆。
- 注入上下文时注意 token 成本和噪声；错误记忆比没有记忆更危险。
- 做分层：摘要记忆、事实记忆、原始片段；先取摘要，再按需展开。

### 4. 冲突、版本和时效性
- 用户偏好会变：旧记忆要能失效、覆盖、版本化。
- 多条记忆冲突时怎么办？按时间、来源、置信度、显式确认裁决。
- 要支持 TTL、软删除、遗忘、合并/压缩，避免记忆库越来越脏。

### 5. 隐私、安全和权限是底线
- 敏感信息识别与脱敏；明确存储位置和保留周期。
- 多租户隔离、访问控制、审计日志。
- 防记忆投毒：不可信来源写进长期记忆要谨慎。
- 删除要彻底：用户删除、账号注销、合规要求。

### 6. 可观测和评估
不要只看“像不像有记忆”，要量化：
- 记忆命中率、相关率、误用率、冲突率、过期率。
- 对最终任务的成功率、延迟、成本影响。
- 用户是否能理解“AI 为什么记得这个”。
- 做离线评测集：偏好记忆、事实更新、跨会话任务、冲突处理、删除后不召回。

### 7. 产品体验很关键
- 用户要知道系统记了什么，并能管理。
- 不要制造“偷记隐私”的不安。
- 记忆出错时要有纠正路径。
- 区分“临时这次对话记住”和“长期记住”。

### 8. 推荐 MVP 起点
可以先做：
1. 显式用户记忆：用户说“记住我偏好 X”才长期存；
2. 会话摘要记忆：跨会话保留任务上下文；
3. 可控检索：按相关性 + 时间 + 重要性召回少量记忆；
4. 记忆管理页：查看、编辑、删除；
5. 审计与评估指标。

一句话：**先把记忆当成一个有生命周期的产品能力，而不是一个存储组件。重点不是“能存多少”，而是“该不该记、能不能取对、错了能不能改、用户能不能控”。**
