# 子代理配置标准 v0.3

> **本文件定义：向蜂巢派发任何子代理时的配置标准。**
> **体系定位**（收敛裁定 2026-09-15）：三份核心文档之**工程层**——《并发必然性理论_v0.2》（理论层：定理 T 与判据）→《认知代理与收敛结构_条件论重构_v0.1》（架构层：代理定义与收敛结构）→ 本文（工程层：spec 配置）；理论概念的工程投影见 §6。
> 系统提示词真源：`docs/mdcg/单元自我锚点_系统提示词标准_v0.3.md`（子代理系统提示词标准）。
> 工作记忆机制真源：`docs/mdcg/主代理子代理记忆架构设计.md`（三层记忆/session 隔离/卡片回流，已实测）。
> v0.2 修订：按使用者指示——模型可选默认 flash、上下文=任务+读记忆、数量可选、200k 拆解信号、提示词随任务保留。
> v0.3 修订：新增 §6「与理论层的对应」（条件论公设 P1/P2、CA-T1/T3/T4 落为配置判据）；其余不变。

## 1. spec 参数

| 字段 | 取值 | 说明 |
|---|---|---|
| `model` | **可选，默认 `deepseek-flash`** | 不指定即 flash；深度任务（复杂逻辑/长链推导）可显式指定更强模型（如 `deepseek-v4-pro`）。**实测（2026-09-15）：蜂巢 spec 校验 `model` 必填**——「不指定即 flash」在提交层须显式写 `"model": "deepseek-flash"` 落地，否则 submit 被拒（`spec 缺必填字段 model`） |
| `system_prompt` | 底座段 + 单元模板 | 按《子代理系统提示词标准》§7.2 组装（见 §2） |
| `user_prompt` | 工作任务 + 记忆读取指引 | 见 §3 |
| `context_budget_tokens` | **200000** | 单子代理上下文预算；预估超出 → **继续拆解子代理**，不是硬塞（见 §4） |
| `timeout_s` / `max_tokens` / `temperature` | 按任务性质定 | 非本标准约束项。**实测：思考模型（`deepseek-v4-pro`）的 reasoning_tokens 计入 `max_tokens`**——8000 被思考吃满导致 `content` 为空但 `ok=true`（假成功，usage 里 completion_tokens≈reasoning_tokens 是指纹）；思考模型建议 ≥20000，且回收时校验 content 非空而非只看 ok |

**子代理数量：可选。** 可开多个反思单元、多个验证单元，各自负责不同细化任务（例：反思单元×2=概念一致性/边界完备性各一个；验证单元×2=逻辑面/锚点面各一个）。数量由编排者按任务拆解决定，无固定配额。

## 2. 系统提示词（真源：子代理系统提示词标准）

按《单元自我锚点_系统提示词标准_v0.3.md》§7.2 组装，两段固定：

1. **协议底座段**（§1，逐字，不得按任务改写）；
2. **单元模板**：按子代理身份选一——记录（§2）/ 反思（§3）/ 验证（§4）/ 输出（§5）/ 维生（§6）。

注入位置：任务消息开头（任务级注入优于纯 system 静态注入）；长任务在关键决策点重申该单元负面锚点清单（「你不是 X」）。

## 3. 任务上下文 = 工作任务 + 读取记忆

上下文不静态堆文件，由两部分构成：

1. **工作任务**：要做什么（任务描述+验收标准+产出格式）。
2. **读取记忆**：子代理被赋予读记忆的能力与指引，而非被动接收全文——
   - `lingshu_cg(op="route", intent=…)` / `op="read"` 按需检索；
   - 主代理从 L0 全局态裁剪**该子任务相关的部分**直接注入（最小充分上下文，不注入全部）；
   - 产出按《主代理子代理记忆架构设计》回流：五栏卡片（L1）+ 细节层（L2），`session` 硬隔离，`derived_from` 溯源。

**实测边界（2026-09-15 已补机制）**：~~蜂巢 Python 执行器环境未挂载 `lingshu_cg` 工具~~ → **worker 侧工具面已落地**（`hive/exec.py` agent loop，同日）：`spec.tools: ["lingshu_cg", "web_search"]` 白名单启用。实测要点：
- **lingshu_cg**：op=route/read/write 白名单（复用 MCP 面同一 dispatch）；权限硬编码 recorder（写入过闸门：DEFER 入审核队列/REJECT 负记忆是设计行为，**裁决权仍归设计者**，子代理不得自裁自决）；会话隔离 `session=hive_job_<id>`；部署要求 serve env 设 `MDCG_ROOT`（或 `spec.mdcg_root` 兜底，任务级隔离用临时图）。
- **web_search**：zhipu 后端（`HIVE_WEB_SEARCH_BASE` 缺省智谱官方端点，与 `HIVE_API_BASE` 解耦——中转网关无搜索路由必 404；`HIVE_WEB_SEARCH_KEY` 缺省回落执行器密钥，**key 与 base 不配对时 401，须独立设置**）；duckduckgo 零 key 兜底。
- 每轮工具调用记入 `result.json` 的 `tool_trace`（审计可回放）；`max_tool_rounds` 默认 5，耗尽强制终答。
- 主代理的「最小充分上下文直接注入任务体」原则**保持不变**：工具是增量不是替代——任务体仍须自包含，工具用于按需深挖与回写。

## 4. 200000 token 预算 = 拆解信号

单子代理上下文预算 200k。**预估任务体+记忆+产出会超出 200k → 说明任务需要继续拆解**：拆成更多子代理（结合 §1 数量可选），每个拿到更小的子任务。禁止把超长材料整体塞给单个子代理。

## 5. 提示词随任务保留 · 长期任务复用 · 满上下文换人续跑 · 产出物生命周期

1. **保留**：子代理的提示词（system_prompt+任务体）随任务持久化（落任务目录），不随单次调用消失。
2. **复用**：执行长期任务时，同一子代理身份（同一提示词+同一 session）跨多轮复用，持续累积该任务的工作记忆。
3. **满上下文接续**：上下文将满 → 终止当前实例，**派新子代理**接替：新子代理带同一提示词（从任务目录恢复），**通过读取工作记忆**（L0 全局态+前序卡片，`recall(session=…)`）恢复进展，继续执行剩余任务。状态在库里，不在实例里。
4. **产出物生命周期（使用者裁定 2026-09-15，长期有效）**：子代理给出的资料（R/V/v 编号的单元产物、结果文件等）一律视为**中间件**——其结论被主代理整合进系统正式文档/记忆后，中间件即行清理，不留工作区。此后派发子代理写正式产出文档时，命名规范：**`test_<身份>_<id>_<任务名>`**（身份=反思者/裁决者/记录者等单元身份；id=job id 或实例 id；任务名=审查面/子任务短名，如 `test_裁决者_h1789458307647_56cc_逻辑有效性.md`）。整合的唯一凭证是主代理落盘的结论（留痕表/正式文档/灵枢记忆），不是中间件文件本身。

## 6. 与理论层的对应（v0.3 新增）

本标准是并发理论体系的工程层。理论概念 → 工程投影：

| 理论概念（出处） | 工程投影（本文位置） |
|---|---|
| 认知任务原子性 P1（架构层公设） | spec=一个原子收敛单位：每个子代理领一个完整子任务（工作任务+验收标准），产出即裁决单位 R_i（result.json 终态）。**spec 不是「任务切块」，是条件投影的落地** |
| 条件投影可分性 P2 + CA-T1（架构层） | 子代理数量可选（§1）：数量由条件投影的**实质区分**决定（观测位置/工具/时间窗/存在约束任一维不同且影响信息可得性），不由任务大小/长度决定 |
| 收敛带宽 B_c（理论层定理 T） | context_budget_tokens=200000（§4）：**200k 不是资源配额，是拆解信号**——预估超出 = W > B_c（信息流宽度超过调用带宽），收敛粒度必须下沉 |
| 收敛位唯一、责任不分散 T4（理论层） | 编排者（agent 本体）收 result 做融合裁决；worker 只产出 R_i，不自裁 |
| 串行正当四分类（架构层 §5.1） | 派发前自查：任务链是否真有数据依赖——基座/约束/成本串行才拆串行，认知伪串行应并发 |
| 融合位裁决纪律（架构层 §4.2） | 主代理汇总时以 R_i 的证据与四态资格裁决，**不以「多个 result 一致」代替验证** |

**理论 → 配置判据速查**：

1. 「这个任务要不要拆？」→ CA-T3 判据：预估信息流宽度（任务体+记忆注入+产出+工具回传）是否超 200k；超 = 拆，不超 = 可单收敛位。
2. 「拆成几个？」→ 条件投影可分性：数**实质区分的观测位置/工具/时间窗**有几个，不是按任务长度均分。
3. 「子代理任务体写多细？」→ spec 自包含原则（§3）= 该投影的 C/G/O 显式化：观测通道（tools 白名单）、目标信息差态（验收标准）、条件边界（任务边界）缺一不可。
