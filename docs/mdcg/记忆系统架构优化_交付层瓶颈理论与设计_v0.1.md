## 一、结论先行

**一句话**：DeliverMem 与 GroundingPI 不矛盾——它们是**同一条判据在两种任务开放度下的两个解**。判据是两条：**压缩是否相对任务 lossless**；**压缩决策是否放在任务信息最大化处**。开放式记忆（未来问题不可知）→ 保留原始、把抽象推到查询时刻；封闭任务族（定位）→ 压到该任务族的充分统计量 `(label, box)`。所谓"矛盾"，是任务开放度的函数，不是原理的冲突。

**五条可迁移原则**（第二章逐条给出机制）：

| # | 原则 | 一句话 |
|---|---|---|
| 1 | 瓶颈律 | 级联有损信道的端到端质量被**最差一级**钳制；收益只来自修复当前主导损耗级 |
| 2 | 延迟抽象 | 压缩决策放在任务信息最大化处；写入侧保原文，抽象推到查询时刻 |
| 3 | 显式索引优于内容寻址 | 给稳定地址（编号/来源/轮次/层级），让下游按号取值而非重建内容再比对 |
| 4 | 表示与领域语义对齐 | 把领域结构（序、邻近、类型）压进表示层，不留给注意力重建 |
| 5 | 注意力经济 | 交付预算是有限资源，按边际信息量分配，清掉不承载知识的块 |

**灵枢的定位（按证据强度分级，不作混合陈述）**：

- **已取证·交付层 D**：交付面是**纯文本**；注入文本的显式标记只有 `layer` 与 `role` 两个维度；**时间信号完全隐式**（仅由条目次序承载）；预算按**位置先验**分配（分级递减 ＋ 等宽 ＋ 整块上限），非按边际信息量。
- **已取证·检索层 R**：投入充分（多路 RRF 融合、四态资格裁决、路径指纹可复算、时效与角色过滤）。但**从未做过检索上界实验**——"R 已不是瓶颈"在本仓证据下**不可判定**。
- **已取证·与 D1 直接冲突的一处**：写入面 `extractText` 只收 `type === 'text'` 的块，非文本块**入口即蒸发**——图像当前既不进知识面也不进窗口；且既有脱敏 `desensitize` 只作用于文本，图像走旁路会绕过"写入前脱敏"的既有纪律。
- **已取证·指针化基座已存在**：`md_cg/refindex.py`（写侧唯一入口）与 `md_cg/docindex.py`（`frontmatter.doc_ref` 指回原文 + 回读漂移判定）已实现"卡片 → 真源"的可回读指针。缺口不在基座，而在**注入面不传 id**。
- **未取证**：宿主 `assembly.contexts` 是否接受图像 part、图像计费口径、DSH 是否暴露步序（`[seen #k of N]` 的 N 来源）。凡未取证处，本文逐处显式标注，不作"已可交付"的表述。

**本轮结论的性质**：**假设 ＋ 可执行的判定方案**，不是结论。"瓶颈在 D"须由第五章的两个 oracle 跑完才可升级为结论；在此之前任何方向选择都只是在赌瓶颈位置。

**本轮不做什么**：不改生产代码、不落实现补丁、不宣称任何未实测读数。

## 二、机制拆解：两篇论文其实在同一条原理上

### 2.1 数据处理不等式在记忆流水线上的显形

记忆系统是级联信源 A→M→R→D→模型（采集→记忆→检索→交付→消费）。按数据处理不等式，逐级确定性或随机映射都不增加互信息：I(A; 模型) ≤ I(A; D) ≤ I(A; R) ≤ I(A; M)。端到端质量因此被**最差一级**钳制——不是被平均，也不是被最好一级带动。DeliverMem 的两组读数正是这条不等式的形状：把 R 做成 oracle（"完美检索上界"）只 +2.31，而 D 层改造 +13.87。含义不是"D 比 R 重要"，而是**当前被钳制的那一级已经不在 R**。两条推论随之成立。其一，瓶颈会迁移：一级被抬高后，钳制点下移，此前在该级的优化收益塌陷为测量噪声。其二，指标脱钩：召回率是 R 的**模型化**代理（对 R 充分），答案正确率才是端到端目标；瓶颈同在一级时二者同向，迁移之后解耦——R 的曲线继续上扬，端到端却不动。GroundingPI 同构：OCR 缺席时钳制点在"文字的空间定位"这一级，词表改造的收益被该级误差截断。

### 2.2 写时压缩 vs 读时抽象

caption 是**写入时刻**在**未知未来问题分布**下的一次单采样有损压缩：算子先验来自对 p(问题) 的猜测，且只产出一个码字；查询分布一旦偏离该猜测，被丢弃的成分不可恢复。原始像素交付等价于**延迟抽象**——把量化与抽象推到查询时刻执行，此时 p(任务|查询) 已可观测。延迟抽象的三项收益可分离：信息收益（不做无谓丢弃）、分布收益（不再赌未来分布）、算力收益（预算可按边际信息量重新分配）。但它不是无条件正确的：GroundingPI 的 20× 框压缩不伤 mIoU 是反例——当算子对齐任务族的**充分统计量** `(label, box)` 时，压缩相对该任务族近似无损。故统一判据是两条：压缩是否**相对任务** lossless；压缩决策是否放在**任务信息最大化**处。

### 2.3 D2 超加性的机制

串联系统每一段都是 AND 关系：一段不成立，整链不通。收益因此取最小而非相加——只补一个短板，新开出的通路立刻被其余短板截断，实测增益远小于该段理论增益。像素盖章单独 +1.33、文本编号单独 +3.08、合起来 +10.97，只能由此解释：任一单项都建不成通路。机制落在**寻址方式的替换**上：内容寻址要求下游先重建出可比表示再比对，跨模态比对本身就是一段极易失效的 AND 段；地址寻址改为一侧发稳定标识符、另一侧按号取值，"像素盖章 + 文本编号"于是构成跨模态解引用链——像素承载不可被文本压缩掉的证据，编号承载可寻址句柄，模型的动作从"重述"变为"指认"。

### 2.4 相关性排序销毁时间信号

按相关性排序交付是一次**投影**：相关性是查询条件化的排序键，顺序与时序是先验的、与查询无关的维度。以前者作为唯一排序键，就是把后者投影掉——这是交付层的主动销毁，而非检索失败。DeliverMem 的处置值得记住：必须用 `[seen #k of N]` 把"第几次看到/共几次"显式重注入。推广：凡下游依赖非相关性维度（时序、因果次序、被观察次数、来源身份），该维度都必须被**升格为显式 token**，否则它不会随召回率一起被救回。

### 2.5 GroundingPI 的两处机制

**词表即编码**：BPE 对数字的切分是病态的——1024 与 1025 在 token 空间里不保距，坐标被切成若干 subword，模型必须用注意力重建一维有序语义。量化专用词表 <0>–<999> 把数值压进单 token，把领域的序与邻近性写进表示层，换来 +2.47 mIoU 与约 4× 速度：收益来自**表示与领域语义对齐**，不是来自更多算力。**任务充分统计量**：20× 框压缩不伤精度，说明 `(label, box)` 对定位任务族充分，压缩只是换了坐标系。**OCR 是催化剂**：它同时提供文字自标注（识别结果自带监督，无需人工标注）与最小空间目标（"这个字在哪"是空间配准的最小可判定单元），从而逼出精确配准机制。

### 2.6 统一为五条可迁移原则

1. **瓶颈律**：先定位被钳制的那一级再优化；任一级的收益上界由其余级决定，且瓶颈位置只能由上界实验判定。
2. **延迟抽象**：压缩决策放在任务信息最大化处；写入侧保原文，抽象推到查询时刻，除非能证明算子相对任务族充分。
3. **显式索引优于内容寻址**：给稳定地址（编号、标识符、来源、轮次），让下游按号取值而非重建内容再比对。
4. **表示与领域语义对齐**：把领域结构（序、邻近、类型）压进表示层，不留给注意力重建。
5. **注意力经济**：交付预算是有限资源，按边际信息量分配，并清掉不承载知识的块。

## 三、灵枢现状对照：五条原则落在哪

证据边界：本次读取 `src/hooks.ts`（分段，共 776 行）、`src/lib/prompt_safety.ts`（全文 164 行）、`md_cg/mdcos.py`（115–184 段，文件 5712 行）；`md_cg/mcp_server.py` 与 `src/` 下关键词 grep 由编排侧补执行，补正见 §7.4。行号按读取锚点与范围给出。

**(a) 交付层一等公民 token。** 时间线块条目格式恒为 `- [layer] preview`（`src/hooks.ts:300-308` 的旧实现，分级渲染沿用同一行格式：`src/hooks.ts:345-354`）；窗口块为 `[role] body`（`src/hooks.ts:395-406`）。故一等公民只有 layer 与 role 两个维度。时间信号是**隐式**的：无 `t` 字段进入文本，仅由条目次序承载（新→旧，窗口渲染再反转成旧→新，`src/hooks.ts:377-383`、`405`）。无序号、无条目总数 N、无节点 id、无来源会话；唯一显式标头是两块的标题 `【灵枢最近记忆】` / `【本会话近期对话】`（`src/hooks.ts:642-646`、`663-667`）。相对 2.4 的差距即"时间重注入缺失"；相对 2.3 的差距即"地址句柄一侧缺失"。

**(b) 预算分配策略。** 客户端两级。时间线轨为**分级递减**：`budget = max(24, round(160 × 0.9^tier))`，`tier = floor(rank / 1)`，整块硬上限 1400 字符（`src/hooks.ts:345-349`、`322`、`352-354`）。窗口轨为**等宽**：单条 120 字、整块 800 字，逐条整放或整弃、裁剪保最新（常量区 `src/hooks.ts:362-371`，使用点 `395-403`）。服务端为 token 预算装包加单条摘录（`md_cg/mdcos.py:146` `est_tokens` / `:157` `excerpt_tokens` / `:67` `DEFAULT_BUDGET=1200` / `:70` `DEFAULT_MAX_ITEM_TOKENS=250`），默认预算与单条上限常量在 `md_cg/mdcos.py` 常量区（行号未取证）。窗口块取的 600 是**整包**预算，与 notes/goals/tasks/self_state 共享（`src/hooks.ts:362-366` 自述，引注服务端裁剪循环 `md_cg/mdcos.py:3546-3566`（注：`src/hooks.ts:364` 注释记为 3351-3362，系行号漂移，实测见 §7.4））。判定：位置先验 + 等宽，均属查询无关的静态分配，未按边际信息量、也未按查询相关性。

**(c) 双轨与截断位置。** 双轨成立：原文轨是窗口（`_recent.jsonl` 原文追加）与 recall 装包正文；抽象轨是 preview 前缀切片加省略号（`src/hooks.ts:350`、`396-397`）。截断发生在**交付时**而非写入时——写入侧只脱敏，且纯凭据消息整条跳过（`src/hooks.ts:590-591`、`720-721`、`285-291`）。丢弃粒度不同：窗口轨是**整条丢弃**（`src/hooks.ts:400-403`），服务端装包是**摘录纳入**并标 `truncated`，仅当剩余预算不足最小摘录才跳过（`md_cg/mdcos.py:1973` 起 `recall()`，装包循环 `:2043-2085`；常量见 `:67`/`:70`）。这与 2.2 一致，缺口在抽象算子本身：它按位置前缀截断，不按任务条件、也不做语义压缩。

**(d) R 级成熟度与判据缺口。** 成熟度证据：六路并行召回与 RRF 融合（lexical/bucket/entity/graph/chain/temporal，`md_cg/mdcos.py` 的 `search_rrf`，行号未取证）、候选池的分层与角色/会话/分支/时效过滤（`_candidates`，行号未取证）、资格裁决四态（`judge_qualification`，行号未取证）、读路径的访问记账与预热（`src/hooks.ts:726-738`）。但这些只证明 R 做了很多，不证明 R 不是钳制点。**判据缺口：未见检索上界实验**——仓内没有"R 换成 oracle、其余级不变"的对照读数，因此"R 是否已非瓶颈"在现有证据下不可判定。

**(e) W 级写入形态。** 节点存**原文**：写入前只过 sanitize（`src/hooks.ts:722-725`、`744-747`、`754-757`）。CCG 六要素（功能名/生效条件/子功能/执行/验证方式/不适用条件）属**写时抽象**，由写入侧或挖掘器在写入时刻生成（`md_cg/mdcos.py` 的 `_ccg_field` / `_declared_conditions`，行号未取证）。与 2.2 的张力最大处在此：该抽象是未知查询分布下的单采样。可辩护的一点是条件槽（生效条件/不适用条件/condition_space）记录的是**适用域**这一可判定结构，比 caption 式语义摘要更接近任务充分统计量。`doc_ref` 承担「卡片 → 真源」的可回读指针：写侧唯一入口在 `md_cg/refindex.py`，`md_cg/docindex.py` 负责切块 → 渲染 CCG → 把 `frontmatter.doc_ref` 指回原文区间并做回读漂移判定（编排侧补取证，见 §7.4）。

**(f) 消费者能力面。** 编排侧已补执行 grep：`src/` 下 `read_image` / `attachment` / `multimodal` / `image_url` / `image` **零命中**，`src/` 仅 7 项（`lib/` + 6 个 .ts），无图像或附件模块——「交付面纯文本」由「零命中 + 目录清单」双重取证。宿主是否**接受**图像 part（`assembly.contexts` 的载荷形态）仍**未取证**。已取证读数：`src/` 目录仅 7 项（lib/ 与 bridge.ts、cli.ts、hooks.ts、index.ts、init.ts、tools.ts，无图像或附件模块）；内容抽取只取 text 块；两块注入载荷均为纯文本（`src/hooks.ts:642-646`、`663-667`），不可信边界亦为文本标记（`src/lib/prompt_safety.ts:159-164`）。判定：本仓交付面是纯文本，"像素盖章"一侧不可复现，2.3 的跨模态解引用链只能迁移其"编号"一半——而现状连编号也未落进注入文本（见 (a)）。

**(g) 五条原则逐条判定。**

- 瓶颈律：**部分满足**——工程重心明确压在交付层（分级预算、双轨、脱敏、不可信边界、按块名独立注入），但缺上界实验，瓶颈位置未被测量确认。
- 延迟抽象：**部分满足**——写入保原文、抽象推至交付时刻（(c)），但抽象算子为前缀截断，非任务条件化；CCG 六要素仍是写时抽象（(e)）。
- 显式索引优于内容寻址：**完全未覆盖**——注入文本只有 layer/role，无节点 id、无序号、无 `[seen #k of N]`（(a)）。
- 表示与领域语义对齐：**部分满足于库侧、未覆盖于交付侧**——库侧有条件槽、层、角色、会话归因等结构化字段，交付侧把一切压回自由文本 preview。
- 注意力经济：**部分满足**——有分级递减、整块上限、永久层排除（anchor/self 不自动注入，`src/hooks.ts:311-324` 常量区）与单条摘录，但分配依据是位置先验而非边际信息量，且无条目级去重与语义压缩。

## 四、优化设计：按瓶颈律排序的四层改造方向

本章的排序律：交付层 D > 检索层 R > 写入层 W，而预算分配是前三者的约束面。凡涉 D1（原始像素交付）的论断依据为使用者裁定「下游是具备识图能力的视觉模型」；凡触及宿主持有能力而我未取证的，逐处标注「未取证」。只到「方向 + 判据 + 生效条件 + 不适用条件」粒度，不写实现补丁。

### 4.1 交付层 D·显式索引升格

**改造方向**：凡检索会打乱的隐式结构（时序、来源、层级、轮次、命中路径）都显式写进 token 流，形态为行首结构化前缀。建议形态：块一每条 `- [seen #k/N | t=Δ | layer | path=rrf:lexical#3+graph#7 | id=…] preview`；块二每条 `[turn #k/N | t=… | role] body`。

缺字段的具名位置（可核）：①`formatTimelineDecayed`（src/hooks.ts:333-355）只取 `layer` 与 `preview`（:340、:350），把载荷自带的 `id`/`start`/`end` 全丢弃（载荷形状见同文件 `formatTimeline` 注释，位于 :300 之前），于是模型拿到无锚点散文，既不能引用、也不能二跳解引用（4.3）、也判不出新旧；②`formatSessionWindow`（src/hooks.ts:384-406）只渲染 `role` 与 `text`（:393、:399），丢弃服务端 `recent` 段本就带的 `t`；更硬的一点是 `recent` 段**结构上没有 id**（md_cg/mdcos.py 的 `pack["recent"] = [{"role","text","t"}]`），故窗口块当前**不可指针化**——这不是渲染疏漏，是取数面缺字段；③轮次锚全缺：宿主「每步都 push、内容不变不追加」的稳定性契约（src/hooks.ts:596-606）不承载步序，`[seen #k of N]` 的 N 只能由插件注入（宿主是否暴露步序：**未取证**）；④来源缺：写侧已落 `session`/`UNASSIGNED_SESSION`（src/hooks.ts:698），读侧按会话过滤（:632-635），但注入文本不含会话标识——单会话注入与 `session="*"` 汇总在文本上不可区分；⑤层级有名无价：`[layer]` 在，importance、judge 四态与 `boundary_hit`（md_cg/mdcos.py 的 `search_rrf` 已产出）全不进注入面。

**判据**：注入块能否支撑「引用—校验—再取」三步——(a) 模型能否引用具体条目（需 id）；(b) 引用可否判真伪（`path_fingerprint` 已在 `search_rrf` 的 meta 中、可确定性复算）；(c) 连续两轮注入能否让模型区分新旧（需 k 与 N）。三条全否即当前态。

**生效条件**：autoRecall 开（src/hooks.ts:607）即生效；字段均来自已在手的载荷，不新增检索能力。

**不适用条件**：下游对行首前缀产生格式模仿（把 `[seen #3/9]` 抄进回复），或宿主对 context 文本做长度敏感的严格校验——此时降级为**单块头部一行**（`本块 N 条，新→旧，编号 #1 最新`）。若 4.4 原图轨落地且图内自带可读编号，逐行前缀可让位图内锚。

### 4.2 预算分配改为按边际信息量

**改造方向**：把「按位置分配」换成「按边际信息量分配」。现状是纯位置律：`RECALL_BASE_CHARS=160` 逐档 ×0.9、下限 24、整块 1400（src/hooks.ts:315-323、:345-352），窗口块单条 120、整块 800（:369-371），服务端整包 `WINDOW_BUDGET_TOKENS=600`（:367）。三个可判据缺陷：(i) 递减只认排名不认内容，第 9 位的高价值节点被压到 24 字符；(ii) 预算被**不可交付段**吃掉——`session_recall` 把 notes/goals/tasks/self_state 与 recent 并入同一 `tokens` 计数并按预算交替裁剪（裁剪循环见 md_cg/mdcos.py:3546-3566（注：src/hooks.ts:364 注释记为 3351-3362，系行号漂移，实测见 §7.4），经 src/hooks.ts:363 注释转述），而注入面**只渲染 `recent`**（src/hooks.ts:384-406）：非 recent 段花了预算、最后不进场；(iii) 切在条目中间（`preview.slice(0, budget)`，:350）会切掉常含答案的尾部。

替代策略方向：先算**价值标量**再按价值贪心装包，价值 = f(检索分, 条件命中, 新鲜度, 层级, 未被提及惩罚)。三处现成输入：检索分与命中路径（`search_rrf` 的 RRF 分与 `provenance`/`per_path`）、条件证据（`judge_qualification` 四态）、新鲜度（`_path_temporal` 已用 `created_at` + `time_core.cred_factor` 确定性核，`TEMPORAL_SCORE_FLOOR` 兜住缺 `created_at` 的老节点）。装包按价值降序逐条给足，整块上限作为**停止条件**而非逐条上限。

**判据（新策略何时算更好）**：同批查询对照跑三量——①答案条目席位不变或前移；②整块 token 数与现状持平或更低（`est_tokens` 确定性口径：CJK 0.6/字 + 其余 /4，md_cg/mdcos.py）；③被切条目数降为 0。三量同向改善才算更好；若①降而②升，判为「用召回换预算」，不采纳。

**生效条件**：注入前能拿到每条的分数与元数据（现已具备：`timeline` 带 `id`/`layer`/`start`/`end`，`recent` 带 `t`），无需改检索。

**不适用条件**：下游对**顺序**敏感而对完整度不敏感，或块内条目同质（价值方差近零）——贪心与位置律等价，本条无收益，不追加投入。

### 4.3 指针化与跨模态解引用链

**改造方向**：把「文本编号 ↔ 图内盖章」映射为「记忆条目 id ↔ 原始载体位置」。灵枢已有确定性映射基座：索引条目带 `path`，md_cg/mdcos.py 的图路以 `e["path"].split("/")[-1][:-3]` 从文件名反推 id，节点为 md 文档，故「id → 文件 → 行/锚」是既有能力；缺口只在**注入面不传 id**（4.1）与**缺区域级锚**（图片区域、行区间）。形态：条目前缀带 id；工具面按 id 取原文（`mdcg_get` / `cg(op=read)`）；跨模态时 id 指向「载体 + 区域」，区域以确定性归一坐标或 md 行区间表达。

**超加性从何而来**：文本编号只给寻址，图内盖章只给定位，两者相加仍无法解引用；只有「编号在文本、盖章在像素、两侧可用同一 id 反向解析」同时成立，模型才能完成「读符号 → 跳图中区域 → 读回细节 → 回文本续推」的闭环——这一跳的信息量不由任何单侧提供。超加性=一次跨模态跳转的可用性，非两条信息之和。

**前置条件（缺一即失效）**：①模型能可靠 OCR 图内小字——「小字/密集标注下的识别可靠性」**未取证**（使用者只裁定具备识图能力），需 OCR 对照实验；②id 两侧同源且写入侧不重写 id；③图内锚与文本锚共用坐标系；④解引用不越权：`cg(op=read)` 有密级/会话可见性闸（md_cg/mdcos.py 的 `_readable`、`_note_visible`），图内盖章不得成旁路。

**判据**：给一张含盖章的图与一段含编号的文本，模型在无额外提示下能否取回正确区域并回答一个**需图文两侧**的问题；对照组（只有编号 / 只有盖章）应显著更差。

**生效条件**：4.1 的 id 注入先落地，且工具面存在按 id 取原文的稳定出口（工具面清单本身未逐条取证：docs/mdcg/灵枢MCP工具总表_v3.4.md 与 docs/mdcg/README详细版_v0.4.10.md 在库但本席未读入正文）。

**不适用条件**：载体为纯文本、无跨模态面；或前置条件①不成立——此时翻转为「不做区域锚，改图旁文字转写 + 编号」。

### 4.4 图像/附件交付通路（D1 落地设计）

**改造方向**：文本与原始载体**双轨**。**原图轨**（D1）：开放式中未来问不可知，抽象必丢信息，故交原始像素/附件；**摘要轨**：封闭任务族、问域已知，交摘要省预算。判据=问题时域可否枚举：可枚举（「这张表 A 行的值」）→ 摘要 + 指针；不可枚举（「看看这张图有什么问题」）→ 原图。

**注入面如何承载**：现状两块注入均为纯文本（src/hooks.ts:642-646、:663-667，`contexts.push({name, text})`），且文本必经 `escapePromptBraces` 与 `renderUntrustedMemoryBlock`（src/lib/prompt_safety.ts）——两者只接受字符串，图像载荷既不能被 `{{` 转义，也进不了 `<untrusted-memory>` 边界。故图像通道必须**另设一格**：文本轨照旧走两块（含转义与不可信边界），图像轨走独立附件槽、带自己的边界声明与来源标注。宿主 `assembly.contexts` 是否接受 image part、工具结果面能否回传图像：**均未取证**；未取证前，「已可交付图像」的表述不成立。

写入侧缺口更大且已取证：`extractText` 只收 `block.type === 'text'` 的块（src/hooks.ts 的 `extractText`，被 :718 与窗口判定调用），非文本块**入口即蒸发**——图像既不进知识面也不进窗口；且既有脱敏 `desensitize` 只作用于文本（`sanitize` 单点），图像走旁路会绕过「写入前脱敏」的既有纪律，故图像通道必须自设脱敏判据。

**写时与读时抽象的边界**：写时**只登记与切分**（保原文/原始载体 + 最小元数据：来源、时间、会话、载体指针），读时按当前问域现算摘要且可重算——写时的问域是猜测，读时的问域是事实。

**判据**：①同一张图对两个不同问题都能作答（写时抽象会锁死一个问域）；②原图交付的 token 代价可被预算容纳（图像计费口径**未取证**）。

**生效条件**：宿主附件通路取证通过，且写入面新增非文本装载判据与图像脱敏判据两条。

**不适用条件**：问题域完全封闭且已固化（摘要轨更省）；或图像在载体中仅是装饰（原图轨无收益）。

### 4.5 检索层 R 与写入层 W 的「不追加投入条件」

**R 的追加判据（满足其一才继续投）**：①**召回未充分**——目标条目已知但未进榜或排位靠后，用 `search_rrf` 的 `per_path`（各路候选数）与 `provenance`（每条被哪几路、排第几）区分「某路没捞到」与「融合把强路 top-1 挤掉」；`path_fingerprint` 的三段（selection/recursion/paths）与 hash 使两次调参可逐位对拍。②**模态错配**——目标信息只在图像/附件，文本路恒不命中，此时投 R 是无效投入，转投交付面（4.4）。反向停止判据：目标已在榜且 `judge_filtered`／`early_stopped` 显示无残余不确定性，或各路已有命中而排序仍错——后者属预算与交付问题（4.1、4.2），不是召回问题。

**W 的最小改造：延迟抽象**。现状是写入即抽象——抽文本（只取 text 块）+ 脱敏 + 定值 `importance`（user 用 `opts.importance`，assistant ×0.8、tool ×0.6，src/hooks.ts:722-725 及其后两条分支）后立刻 `remember`，一次成型不可回退。最小改造为**原文保留 + 多粒度摘要并存**：原始载体（文本全文／附件指针）保真落盘，摘要分层且可重算；`importance` 由写时定值改为可复算读数——md_cg/mdcos.py 的 `remember_gated` 已落 `importance_source`（"hint"|"heuristic"），具备「落分带来源」的既有形态。

**判据**：任一摘要可删除而原文无损（可重生成）；同一条记忆能对两个不同问域给出不同粒度摘要。

**生效条件**：写入面已落 `session`/`role`/`tags` 与 `_forgetting.jsonl` 的去向留痕，延迟抽象不新增不可审计路径。

**不适用条件**：存储或合规禁止保留原文（脱敏后原文已不可复原）——此时翻回写时抽象，并显式接受问域被锁死。

## 五、瓶颈定位实验规格：两个 oracle 先于任何优化

现有证据能指出"端到端不高"，但指不出"不高在哪一级"。同口径 QA 里检索臂 17.2%、full_context 臂 16.4%（docs/eval/端到端LoCoMoQA同口径对照_v1.0.md §1），而检索面自然问句 hit@10 只有 40.2%（同文件 §2 A 口径）——两个数字之间的落差究竟落在检索召回、交付截断，还是写入表示，当前口径无法分离。两个 oracle 就是为这道分离而设的前置实验，先于任何架构优化动工。

**5.1 两个 oracle 的可操作定义**

- **完美检索上界（R-oracle）**：绕过 `cg.search` 全链路，不走路由、不做四路 RRF 融合、不做 top-k 截断；直接按答案键"必要采分点 ↔ 支持片段位置"映射，取该题全部相关节点原文，按原文时序拼接，喂给同一 reader。约束三条：证据集覆盖率须达 100%（《秤》§3.4 覆盖判据，纯机械可查）；非 gold 节点零注入；生成器、提示词、temperature 与系统交付臂逐字相同。
- **完美交付上界（D-oracle）**：保留系统真实检索结果（同一节点集、同一顺序），只替换交付层——不做写时抽象、不做渲染模板、不做预算裁剪与截断，把命中节点原文原样交出。它把交付层 D 从检索层 R 中摘出来，回答"检索给对了，是不是被交错了"。

两者共同的口径纪律：oracle 只允许替换被测的那一级，其余环节冻结。第三方验证报告已示范过反面代价——用 LLM 替灵枢做归一，会把生成器的能力记进系统账上（docs/eval/第三方验证报告_LoCoMo_灵枢_.md §四·2）。

**5.2 复用《秤》v2.1 的对照条件**

在既有六条件（闭卷 / 原文参照 / 足量证据对照 / 呈现对照 / 系统交付 / 写入探针）上增设**原文交付臂**：系统检索结果 + 原文全文直交，不经现有渲染与预算裁剪。它与 D-oracle 的区别在于，原文交付臂保留系统的真实检索误差，D-oracle 把检索误差也一并抹掉，二者差值即检索层的净损失。

必须写明：**"原文参照条件"不是理论上界**。这是规范的自我修正（《秤》§2）。全文输入受上下文预算、注意力分布与提示词共同限制，本仓已有本地实证——同一 25.4k 字场景，仅改拼装顺序，gold 位于前部 3/3 稳定答对、位于中部 5/5 稳定拒答（端到端对照 §3）；更直接的是 full_context 16.4% 反低于 retrieval 17.2%。全文直读是一个参照坐标，不是天花板。任何"我们接近原文参照了"的宣称都先把参照误读成了上限。

**5.3 读数与判据**

命基线为闭卷条件，取三个差值：Δ_sys = 系统交付 − 闭卷，Δ_doc = 原文交付 − 闭卷，Δ_R = 完美检索 − 闭卷。全部用题目级配对分数差，区间取依赖簇为重抽样单位的自助法（《秤》§7.1）。解读表：

| 形态 | Δ_sys | Δ_doc | Δ_R | 归因 |
|---|---|---|---|---|
| 一 | ≈0 | ≈0 | ≈0 | 瓶颈在写入/表示：库内无可用节点，或表示丢了时间/否定/条件（写入探针的结构保真维直接验证） |
| 二 | 低 | 高 | 低 | 瓶颈在交付层 D：证据已进到手里，被渲染、摘要或预算裁掉 |
| 三 | 低 | 低 | 高 | 瓶颈在检索层 R：召回缺失，交付无条件可谈 |
| 四 | 低 | 高 | 高 | R 与 D 叠加，按两差值之比排序投入，不可笼统称"记忆不行" |

判读纪律两条：其一，数值用四态表述，无交付抽象层的系统（纯全文库）在 D 维记"**不适用**"而非"失"，观察不到接口的系统记"**不可观察**"（《秤》§4）；其二，只报聚合与典型样例，不逐题定罪。

**5.4 最小可行版本与能红条件**

题池直接复用 LoCoMo-zh-500 与 `md_cg/bench_e2e_locomo_qa.py` 的既有管线，答案键复用上游 gold 与 zh_queries，避免重建标注。最小可行版取 100 题自然问句子集（三臂各一次生成，约 300 次 reader 调用）；全量 500 题在最小版方向成立后再跑。**能红条件**（什么样的读数推翻"瓶颈在 D"）：

1. Δ_doc − Δ_sys ≤ 3pp。3pp 取自本仓已实证的改写噪声量级（端到端对照 §2 D 口径 +3.0pp）——小于噪声的交付增益不是增益；
2. Δ_R > 0 而 Δ_doc ≈ 0：说明检索结果本身就在把错节点交给交付层，交付层无辜；
3. 加入原文交付臂后 answer 上升，但拒答数同步上升——这是提示词/格式变化而非证据变好，须回查。

**5.5 前置门**

必须先过《秤》的校准零号试验（§6）：甲无记忆、乙坏写入、丙坏检索、丁坏呈现、戊正常。通过判据是各系统指标下降方向与预注册一致，且乙≠丙≠丁在剖面上可区分。理由很直接——本实验的全部效力，就建立在"读数能分辨坏检索与坏呈现"这一条上。如果《秤》在受控破坏面前分不开丙与丁，那么原文交付臂与完美检索臂的差值同样分不开 R 与 D，两个 oracle 就成了两次昂贵且无法归因的采样。效度先于规模，这道门不通过，本实验不进正式实施。

## 六、诚实边界：这些结论何时会翻转

**一、"完美检索只 +2.31"只在基线召回已高时成立。** 该读数的正文出处本轮未取证，其前提必须写清：若被测口径的召回已接近饱和（如中文五槽层 hit@1 96.8% 量级，第三方报告 §二·口径一 A_zh5），检索确实不再是瓶颈；一旦换到自然问句形态（hit@10=40.2%），检索缺口重新成为主项。模态错配更彻底——英文原文零加工 hit@1 仅 15.8%，此时检索层是决定性瓶颈，"+2.31"不可外推。

**二、原始像素/D1 路径胜出，依赖消费者具备足够强的视觉编码器。** 本仓 LoCoMo QA 的 reader 是文本通路（deepseek-chat），像素交付要先过 VLM/OCR 编码再进语言空间，误差叠加而无额外信息优势，D1 在此不可行；正确做法转向最小化写时失真。像素臂的保真度若以 mIoU 之类指标衡量，还需消费者侧解码质量并入同一账，不能只报压缩比。

**三、指针机制依赖模型能可靠 OCR 图内小字。** 第三方报告已证静默错译存在（`scavenger hunt` → 食腐动物/猎取、`shelter` → 庇护，mapped 路径 52.8% 直译无护栏）。OCR 小字比词典直译更脆：小字号、低对比、手写、表格线任一出现即错，且报错静默——指针不会自证指错。故指针机制必须带"指回原文可逐字校验"的回路，否则不成立。

**四、20× 与 4× 是两套分母，引用时不得混用。** 20× 是对照特定冗余格式（字段重复、可推导结构）得到的；4× 是速度对照口径"量化坐标 vs 文本坐标"（BPE 计数基准）。混用等于把"格式冗余消除"记成"坐标量化收益"。两条读数的正文出处本轮均未取证，对外引用前须回源。

**五、灵枢自身的边界：本仓库未做检索上界实验。** 明确写"未做，属缺口"，不许暗示已有结论。现有最接近的两组数字都不是上界：full_context 16.4% 是全文直读（是参照），retrieval 17.2% 是系统交付（是被测）；第三方报告的 96.8/99.8/99.8 是检索命中口径，不含生成，不能当端到端上界。因此当前任何"瓶颈在 D"或"瓶颈在 R"的说法都是假设，唯有第五章的两个 oracle 跑完才可升级为结论。

**六、单 reader 下的归因不能外推。** 本仓既有读数几乎全部来自同一生成器，生成器交换矩阵（《秤》§8 复核档）未做，甲乙两系统在不同生成器下强弱反转的情形未被排除；双语文料留出复测同样未做。此外 oracle 臂的令牌与 KV cache 消耗远高于系统交付臂，须入成本附录单列（《秤》§7.3），否则"完美检索抬得动"会被误读为应无条件上全文交付——准确率与延迟是两个坐标。
