# 原生任务双层记忆

任务卡继续记录目标、计划和状态。`cg(op=task)` 新增三个动作，把一次会话的任务结果
与可复用经验分开保存：失败或受阻也能留下结果；没有经验时返回空经验层。

本实现参考腾讯 Hy-Memory 的双层草稿、独立合并、事实替代链和经验溯源设计，使用灵枢
自己的 Markdown、权限、派生关系、依赖失效与资格判定。没有新增 SDK 或模型依赖。

## 使用

先通过既有入口登记任务：

```json
{"op":"task","action":"open","name":"search-timeout","goal":"修复搜索超时"}
```

会话结束或取得实质进展后，由宿主 Agent 提交一条结果及零或多条经验草稿。`record_id`
是调用方给这一段结果的稳定编号，重试必须保持编号与内容一致；有新进展时使用新编号。

```json
{
  "op": "task",
  "action": "record_memory",
  "name": "search-timeout",
  "memory": {
    "record_id": "attempt-1",
    "fact": {
      "statement": "已定位连接池耗尽；缺测试环境，尚未验证修复",
      "subject": "src/search.py:request",
      "outcome": "blocked",
      "details": "保留原始命令、错误、数值和产物引用，不能用摘要猜测这些内容。",
      "files": ["src/search.py"]
    },
    "experiences": []
  }
}
```

经验草稿要求 `task`、`solution`、`conditions`、`boundary`、`verification`，可附最多五条
`search_keys`。宿主负责判断有没有值得复用的方法；本模块只检查结构，不调用 LLM
替用户作出价值或真实性裁决。诊断和明确的失败经验也可以是候选。只询问参数、尚无
实质操作时只写结果，不提炼“如何询问用户”这类经验；草稿先忠实记录本次证据，再按
明确任务身份建立关联，不能为迁就旧经验而改写本次发生了什么。

```json
{
  "task": "排查搜索请求超时",
  "solution": "先比较连接池占用与超时，再检查重试放大；记录实际测量和反例。",
  "conditions": "使用连接池的搜索请求超时",
  "boundary": "不适用于数据库文件损坏",
  "verification": "在目标环境回放 timeout 回归用例",
  "search_keys": ["连接池耗尽", "timeout diagnosis"]
}
```

查任务的当前结果与经验，两个桶各有独立的 `limit`：

```json
{"op":"task","action":"recall_memory","name":"search-timeout","limit":5}
```

`query` 可选，使用任务内词面召回；未实现向量或跨任务语义路由。原始 `details` 不参与
词面排名，也不在召回时重复注入；结果给出 `details_ref`，用以下动作完整回读：

```json
{"op":"task","action":"get_memory","node_id":"替换为 details_ref"}
```

新结果明确取代同一主体的旧结果时，在 `fact.supersedes` 中传旧 `fact_id`。旧文件保持
原样；默认只返回当前结果，`include_history=true` 同时显示旧结果。不同任务或主体
不能互相取代，也不会仅因语义相似自动覆盖。

## 存储与信任

- 任务身份继续使用已有稳定任务卡，在同一记忆根内隔离。
- 结果节点落 `contextual`，经验候选落 `knowledge`；两者初始均为 `unverified`。
  写下“回归通过”或填了 `verification`，均不会自动升级为已验证。
- 两种节点均继承任务卡的密级与既有会话权限；草稿不能自选身份或降低密级。
- 写前复用既有审核策略，检查正文与完整持久化元数据；策略不可用时拒绝写入。
  经验被策略拒绝时，已提交的任务结果保留，返回部分失败，拒绝内容不落入候选节点。
- 经验由结果派生，并声明 `depends_on`；来源被证伪时复用既有信任机制标为存疑。
  同内容经验复用原节点，新结果通过 `experience_ids` 关联，召回给出可见来源。
- 任务范围、可见性、历史状态和经验资格先于 Top-K；被拒经验不会占用返回名额。
- 完整草稿与关联保存在节点正文的版本化 JSON 载荷，`task_memory` frontmatter
  只含格式、类型、任务标识和校验值；回读从获权解密后的正文还原，不新增业务数据库。
- private/secret 在原生写入派生路由元数据之前先调用既有密封钩子，避免原始内容及
  私有不适用条件进入明文 frontmatter/索引；缺少原生加密写者时拒绝私有写入。
  本工具在获权解密后仅于内存补齐边界，再调用原生资格判定；通用明文索引不含这些私有词项。
- 这不是跨节点事务：先提交结果，再逐条写经验。经验失败时返回
  `ok=false, committed=true, partial=true` 和逐项 `errors`；相同请求可补齐缺项。
  不把“请求受理”当成整批成功。

## 验证与边界

```bash
python -X utf8 -m md_cg.test_task_memory
python -X utf8 -m md_cg.test_task_memory --mutate
python -X utf8 scripts/verify_task_memory.py
```

基线对照可运行同一探针：

```bash
python -X utf8 scripts/verify_task_memory.py --repo BASELINE_CHECKOUT --expect absent
```

新增动作是显式工具调用，未自动改写现有 hook、会话采集或睡眠调度；不是腾讯整套
Chat/System 2、跨域归纳、模型训练或代码 diff 链的移植。测试证明原生入口与存储行为，
不代表真实模型抽取准确率、生产数据收益或模型效果比较。
