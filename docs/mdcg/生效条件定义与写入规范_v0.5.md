# 「生效条件」的定义与写入规范（v0.5）

> 2026-10-31 · 起因：issue #722「条件闸门按字面匹配，自然问法普遍判 DEFER」
> **本版结论有实测支撑**（全库 32,842 节点抽样 2000 + 逐条抽看 20 条条件词项），不是推断。
> v0.1–v0.4 四版架构（文本来源 / 弱态 / S3 图扩散 / 主题面）与「跳过模板词」实测全部无效。

## 一、实测基线（可复现）

**查询「我不想你被换掉」· 取样 300 节点**：

```
DEFER      217  (72.3%)   ← 生效条件未命中
BLINDSPOT   82  (27.3%)   ← CCG 要素不全
ACCEPT       1  ( 0.3%)
```

**同一查询·跳过「本地文档仓」后**：四态分布**逐位不变**（217/82/1）——跳完剩的仍是技术描述。

**条件词项的实际形态（抽样 2000 + 逐条看 20 条）**：

| 形态 | 条数（20 条抽样） | 例 |
|---|---|---|
| `本地文档仓 \| 大域=xxx \| md` | **14** | 纯元数据 |
| 函数级前置条件 | 3 | 「`position` 可被 `_spec` 解析且其 spec 含 `"primary"` 键时返回该值」 |
| 工程操作 | 2 | 「载体=仓内 dsh」「或 `WRITER_ROLE_MAP` 命中」 |
| **用户会怎么说** | **0** | —— |

**语义路覆盖率为 0**：`MDCG_SEMANTIC` 未开、`semantic_on() == False`、**0/500 节点有 `semantic` 字段**。

## 二、根因

> **「生效条件」这个槽被当成了「文档元数据」来填，而不是「什么时候该用这条记忆」。**

| 实际填的 | 它回答什么 | 检索需要它回答什么 |
|---|---|---|
| `本地文档仓（大域=whitebox_kb）` | 这条放在仓库哪 | 什么时候该想起它 |
| `md（章节切分，level≤3）` | 用什么方法索引的 | 同上 |
| `全时窗` | 时间维不限制 | 同上 |
| `position 可被 _spec 解析…` | 函数的前置条件 | 同上 |

⇒ 填的是「这条数据**怎么来的**」，而检索要的是「你**什么时候会需要**它」。两个问题域完全不同。

**旁证**：#722 报告人把条件改成「他说"不想你被换掉""别消失""舍不得"时」后即 ACCEPT——
他做的不是"补同义词"，是**把条件从元数据改成了触发场景**。

## 三、规范：生效条件写「触发场景」

### 3.1 定义

```
生效条件 = 在什么情况下，这条记忆应当被想起
```

**必须是触发场景**，形如「当用户说 X / 遇到 Y 情况时 / 在做 Z 的时候」。

### 3.2 元数据写哪里

| 现在塞进生效条件的 | 应当写在哪 |
|---|---|
| 载体/位置（`本地文档仓`、`大域=xxx`） | `doc_ref` / `tags` / 索引 |
| 时间窗（`全时窗`） | `condition_space.time_window` |
| 方法（`md 章节切分`） | `tags` / 索引元数据 |
| 函数前置条件 | `# 执行` 或 `# 子功能` |

### 3.3 判据（可执行的检测）

一条生效条件算「合格」，当且仅当**至少一个词项不含下列元数据特征**：

```
元数据特征：本地文档仓 / 大域= / 全时窗 / 任意时刻 / 章节切分 / md（ / md( / 载体= / 仓内
```

⚠️ **注意（实测教训）**：仅"跳过元数据词项"**不能**改善判定——跳完剩的仍是技术描述。
所以本条**不用于判定**，**只用于写入把关**。

## 四、写入守卫（warn 优先，不阻断）

复用 #708 的 `write_gate` 三档（off/warn/enforce）：

| 档 | 行为 |
|---|---|
| `off` | 不检查 |
| **`warn`（默认）** | 写入成功，但计数 + 提示「本条生效条件是元数据，不是触发场景」 |
| `enforce` | 拒绝写入，要求改写 |

**判据单点**：`md_cg/nodefile.py` 或 `writegate.py` 加 `cond_is_metadata(cond_text) -> bool`，与 `_cond_terms` 的元数据词表**同源**（不复制语义）。

## 五、旧数据（明确不重写）

32,842 节点的条件重写**不现实**。现实路径：

1. **新写入**按本规范（守卫 warn 起步）；
2. **旧节点**：不重写、不改判定；靠 `aliases`（已合入 #719）补召回；
3. **可观测**：`cg(op=info)` 透出「条件为元数据的节点数」，作为改进基线。

⇒ **承认旧数据的条件在检索上不可用**，不为它设计复杂机制。

## 七、不适用条件

1. **不解决"旧节点捞不出来"**——只防新增；
2. **不改判定算法**（实测证明改了无效）；
3. **不要求 `semantic` 落地**（覆盖率 0，且是另一条工程线）；
4. **不覆盖 `# 子功能`**（原文有理由：那是依赖清单，不取）。

## 八、实测记录（2026-10-31，判据四次修正）

本规范的判据经**四次实测修正**才定稿，留痕防重蹈：

| 版 | 判据 | 失败原因 |
|---|---|---|
| ① | 正向「所有词项都含元数据特征」 | 条件含「源文档 a/b/c.md」时被 `/` 切成路径片段（`knowledge`、`x.md`），`all()` 恒 False ⇒ 元数据判出 **0 条** |
| ② | 加短词表（`md` 等精确匹配） | 仍 0 条——路径片段问题未解 |
| ③ | 反向「不含任何场景标志词」 | 单字标志词「**时**」被「全**时**窗」误触发 |
| ④ **定稿** | **结构化槽标签**：同时含 `载体/位置` 类与 `约束/方法` 类标签 | ✅ 通过（5/5 用例 + 120 抽样 **76.5%**） |

**教训：自然语言启发式判据（按词义猜）不可靠；结构化判据（按槽标签）才稳。**
