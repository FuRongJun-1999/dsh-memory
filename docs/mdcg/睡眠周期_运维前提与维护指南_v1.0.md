# 睡眠周期 · 运维前提与维护指南（v1.0）

> **这一页回答一件事：开了睡眠周期之后，你的记忆库多了什么、在哪里、怎么维护、怎么关、怎么退。**
> 依据：`docs/plans/睡眠与自迭代_功能优化设计_v0.4.md`（规格冻结版）§四 / §4.7。
> 使用者裁定（2026-10-01，第三轮）：「进行登记，让用户知道怎么维护记忆」。

---

## 一、睡眠周期是什么（一句话）

灵枢的**自迭代**（八步闭环的第 5 固化 / 6 记录 / 8 方向性自检）与**睡眠整理**合成一条周期引擎：在**睡眠时段**内，用**一个副本**做归纳 / 升层 / 巩固 / 权重与索引重建，完成后**周期性合并**回主库，并**留下修改历史**。

**为什么用副本**：整理期间主库的**真源面**（八个层目录下的 `.md`）逐字节不变——长驻进程（serve / 蜂巢 / 会话）继续正常读写，整理结果只在合并那一刻以**受闸门约束**的方式落回。

---

## 二、版本库在哪里（唯一的"新增物"）

| 项 | 位置 | 说明 |
|---|---|---|
| **版本库（git 目录）** | `<state_root>/sleep/lib.git` | **在数据根之外**。用 `git --git-dir` 显式指定，**不在你的记忆库里放 `.git`** |
| **影子工作树** | `<state_root>/sleep/shadow` | 整理实际发生的地方；每轮以 `git worktree` 建在分支 `sleep/<时间戳>` 上 |
| **台账** | `<state_root>/sleep/` 下的轮次记录 | 每轮九步的逐步读数、语义差异集 Δ、冲突清单 |

**版本库只覆盖真源面**：那八个层目录下的 `.md`。以下**结构性进不去**（用显式路径白名单而非 ignore 面保证）：
`_keys.json`（密钥信封）· `_access.log` · `_index.json` · `_index_log/` · `*.tmp`（临时件）· `*.lock`（锁件）。
⇒ **密钥与运行态从设计上就不可达**，不是"记得排除"。

## 三、维护动作（你要知道的四条）

### 1. 看历史

```bash
git --git-dir=<state_root>/sleep/lib.git --work-tree=<root> log --oneline
```

一条睡眠周期 = **两个提交**：先是**内容提交**（语义重放落主库的那一刻，台账里记作 `round_commit`），随后是 `--no-ff` 的**合并提交**（只记拓扑，其树与内容提交同）。

### 2. 看某一轮改了什么

```bash
git --git-dir=<state_root>/sleep/lib.git --work-tree=<root> show <round_commit>
```

逐节点的 before/after 另有 `_maintain.jsonl` 同族留痕（与权重重算共用一套）。

### 3. 回退（**只提供 `revert`**）

```bash
git --git-dir=<state_root>/sleep/lib.git --work-tree=<root> revert <round_commit>
```

**要 revert 的是该轮的「内容提交」**（台账 `phases.merge.round_commit`）——合并提交只是拓扑记录，对它 `revert -m 1` 对内容零影响（git 会报 nothing added to commit）。

**裁定（第三轮）：只给 `revert`，不提供 `reset --hard`。** 理由：`revert` 出一个**新提交**——历史不丢、可追、可再次审计；`reset --hard` 会抹掉历史，与「留下修改历史」的裁定相反。
回退是**显式发起**的动作，睡眠周期**永不自动回退**。

### 4. 冲突怎么处理

合并阶段若发现**主库与影子改了同一个 id**（或命中保护闸 / tombstone 闸 / 生命周期闸），该项**挂起**：**不自动解决**、**不写入主库**，出一个冲突清单等人处理（与蜂巢工作记忆 `hive/wm.py` 的既有裁决同款：冲突手交人工）。

> 一句话：**git 只做记录者，准入由仓内既有闸门裁决**。所以「合并成功」不等于"git 没冲突"，而是"过了语义四闸"。

## 四、开关与可调项（全部可调）

| env | 缺省 | 语义 |
|---|---|---|
| `MDCG_SLEEP` | `1`（开） | 睡眠周期总开关；设 `0` 即整条周期不再启动 |
| `MDCG_SLEEP_INTERVAL` | `3600` | 周期（秒），缺省一小时一次 |
| `MDCG_SLEEP_WINDOW` | `23:00-07:00` | **睡眠时段**（本地时间）；**支持跨午夜**；留空 = 全时段；**窗口外只记账、不迭代** |
| `MDCG_SLEEP_MERGE` | `auto` | 合并策略：`auto`（自动执行四阶段）/ `ask`（合并前询问）/ `never`（只留副本不合并）。**`auto` 下冲突仍挂起** |
| `MDCG_SLEEP_GITDIR` | 空 | 覆盖版本库位置（缺省 `state_root()/sleep/lib.git`） |
| `MDCG_SLEEP_SHADOW` | 空 | 覆盖影子工作树位置（缺省 `state_root()/sleep/shadow`） |
| `MDCG_SLEEP_SCRUB_APPLY` | `0` | 第④步「去污染实改」的闸门；**缺省只盘点不落盘** |
| `MDCG_TEMPORAL_GAMMA` | `ln2/30天` | 时间邻近度的衰减率（半衰期 30 天，与既有 `links.py` 同刻度）；可调 |
| `MDCG_SUSTAIN` | `1` | 常驻自维持循环总开关（睡眠周期挂在它上面） |

> **整条关掉**：`MDCG_SLEEP=0`；**连常驻循环一起关**：`MDCG_SUBSTAIN=0`。

## 五、自动的边界（哪些永不自动）

| 动作 | 可自动 | 依据 |
|---|---|---|
| 归纳 / 升层 / 权重重算 / 索引重建 | ✅ | 确定性、可预演、可回滚；索引是派生物 |
| 去污染**实改** | ⚠ 缺省关（`MDCG_SLEEP_SCRUB_APPLY=0`） | 在副本上可放行，合并前可复核 |
| **任何依赖 LLM 的固化** | ❌ **永不自动** | 依赖 LLM 的动作交人工另批 |
| **任何不可回滚的删除** | ❌ **永不自动** | 五环承诺：遗忘只能由显式 `cg(op=forget)` 发起 |
| 方向性自检 | ✅ 只产**记录** | 理论纪律：自检结果**不自动触发修改** |

**「合并前可复核」在缺省配置下由什么保证**：缺省 `MDCG_SLEEP_MERGE=auto` 会在**同一轮**内把已过闸的改动一并落主库，所以严格的「合并前人工看一眼」窗口只由 `MDCG_SLEEP_MERGE=ask` 提供。另外**去污染实改缺省就是关的**（`MDCG_SLEEP_SCRUB_APPLY=0`），所以缺省配置下最具侵入性的那一档根本不会落盘——要用它，请显式开启并配 `ask` 档。

**窗口值写错了会怎样**：`MDCG_SLEEP_WINDOW` **留空**＝全时段（这是唯一的显式全时段入口）；**非法形态**（例如 `23:00-99:99`）按同表 `INTERVAL`/`MERGE` 的既有回落口径**回落缺省 `23:00-07:00`**——不会因为打错字而变成全天迭代。

---

## 六、健康读数（每轮都留）

每轮睡眠在台账里留：①盘点候选数 ②本轮语义差异集 Δ 的大小 ③过了四闸多少、挂起多少 ④是否空轮（候选 0 ⇒ 只记账不动手）⑤九步逐步读数（未接线的步骤显式标 `skipped`）。

`cg(op=sustain, action=status)` 可看到最近几轮。

---

## 七、前提一句话总结

> 睡眠周期会在 `<state_root>/sleep/lib.git` 建一个**只覆盖真源面**的版本库，用它做**副本迭代 + 周期合并**，合并准入走仓内既有语义闸门（不是 git 的文本合并），回退只给 `revert`，冲突挂起等人处理。**密钥与运行态结构性进不去这个版本库。**
