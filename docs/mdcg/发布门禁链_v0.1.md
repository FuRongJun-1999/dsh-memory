# 发布门禁链 v0.1

> **背景**：第三方验证 v17 报告（§5.6）指出一个结构性窗口——**门禁写好了却不接进发布链，等于没有**。
> 仓库已有 5 道门禁脚本，但 `prepublishOnly` 只挂 3 步，`cogmap_sync.py check` 等未接入；
> 同一失效模式因此在 2026-09-15 与 v17（`4e2a9fc`）复发两次。

## 三层防线

| 层 | 触发 | 跑什么 | 行为 |
|---|---|---|---|
| 本地 pre-commit | `git commit` | `python scripts/cogmap_sync.py build` | **自动重挂**行号，并把两份投影文档一并暂存 |
| 发布链 | `npm publish` | `prepublishOnly`：build → test → **`npm run gate`**（五道门禁，见下） | 任一步失败即阻断发布 |
| CI | push / PR | `cogmap-check.yml`：`cogmap_sync.py check` + `link_check.py` | 远端兜底红灯 |

## 为什么本地钩子跑 build 而不是 check

行号锚只能由管线从真源 AST 现算（`cogmap_sync.py` 纪律：**禁止手工书写行号锚**）。
v17-1 实证：真源位移按区域取 +8/+9/+15/+18/+37/+56/+87（**不是常数**），手工施加位移必然翻车——
那一次 32/32 处统一偏 −1，把 CI 门禁踩红。故本地做「**自动修**」（build 重挂），
发布链与 CI 做「**报错拦**」（check）。

## 安装（一次性 · 仓库级本地配置 · 不入库）

```bash
git config core.hooksPath scripts/git-hooks
```

撤销：`git config --unset core.hooksPath`

钩子真源：[`scripts/git-hooks/pre-commit`](../../scripts/git-hooks/pre-commit)
（该文件必须为 LF，已由根级 [`.gitattributes`](../../.gitattributes) 钉死）。

## 发布门禁清单（`npm run gate`）

`prepublishOnly` 在 build + test 之后调用 `npm run gate`，五道门禁与 CI 同形：

| # | 命令 | 守什么 | 对应 CI |
|---|---|---|---|
| 1 | `python scripts/check_publish_artifact.py` | 发布件内容政策（凭据 / 私有数据 / 隐私文本 / 非追踪件） | `publish-artifact-check.yml` |
| 2 | `python scripts/cogmap_sync.py check` | 认知图行号投影与真源一致 | `cogmap-check.yml` |
| 3 | `python scripts/link_check.py` | 全库 md 相对链接可达 | `cogmap-check.yml` |
| 4 | `python scripts/workspace_index.py --check` | 工作区索引不陈化（第 18 条） | `workspace-index-check.yml` |
| 5 | `python scripts/verify_discipline.py --allow-missing` | 纪律真源 ↔ 各端产物一致 | `discipline-check.yml` |

> **依赖提示**：第 5 道经 `render_discipline` 解析 `docs/discipline/harnesses.yaml`，需要
> **PyYAML**（CI 里显式 `python -m pip install pyyaml`）。本机缺 PyYAML 时 gate 会硬失败——
> 那是门禁正常工作，装依赖即可，不是误报。

发布前可单独跑 `npm run gate` 自检。

## 不适用条件

本地钩子依赖 `core.hooksPath` 一次性配置；**未配置时该层不生效**，此时仍由发布链
（`prepublishOnly`）与 CI 两道兜底。本页不覆盖：非 md 文档的行号（本链只管认知图投影）。
