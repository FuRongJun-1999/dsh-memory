# CSRE 索引与负条件修复 · 2026-10-12

本轮在独立工作区修复旧白箱 CSRE 的两个可复现问题：不适用条件没有参与候选筛选；索引没有绑定来源，缓存也不会检查内容变化。改动定位为正确性修复。严格检查增加了耗时，没有宣称加速或提升默认 RRF 的召回率。

基线为 `76a1b7ba0579e8ce589e5f079b853e574735f822`。正式插件、真实记忆、主项目均未修改；工作尚未提交或推送。前一轮 Memory-RSI 的论文核对、合成与公开语料结果保留为历史记录，本报告记录后续修复。

## 行为变化

`md_cg/whitebox_kb/wisdom/csre.py`：

- `top_units_in_domain` 在 Top-K 截断前应用不适用条件，拒绝后仍可补入后面的候选。检查文本包含 question 与显式 `neg_terms`；命中数达到正数 `neg_gate` 时拒绝。`neg_gate<=0` 保留关闭门控的能力。
- 空白、非字符串和清洗后为空的负条件不计票；重复负条件去重。`limit<=0` 返回空列表。
- 原 NPZ 派生索引升级到格式 2，保存来源种类与路径身份哈希、nodes schema 哈希、知识卡完整行哈希和负条件。没有创建第二套知识库。
- `ensure_loaded()` 保留 bool 返回值；每次检查当前来源。已经加载到内存的实例也不例外。`rank_domains` 和 `top_units_in_domain` 使用前都会检查。
- SQLite 通过只读 URI 打开，缺库不会创建空库。MD 模式新读一份 `MdConn` 快照，避免其进程缓存隐藏文件更新。
- 文件不兼容、过期、串库、损坏或来源不可读时清空旧矩阵，返回 False；`index_info()` 提供上一次检查的状态。该方法自身不会刷新来源。
- 只在显式 `build_index()` / `save_index()` 时重建或保存。保存前再次核验，NPZ 不含 object/pickle 数组，临时文件完整写入后原子替换；保存失败保留旧文件。

`navigate.py` 的域先验复用原缓存对象，但调用的 `rank_domains` 会重新验证来源。无有效索引时返回 None，继续既有的检索/全扫回退，不使用陈旧域先验。

状态包括 `ready`、`index_missing`、`legacy_index`、`source_mismatch`、`stale_index`、`invalid_index`、`source_unavailable`。来源身份采用解析后的路径；内容相同的另一库/另一 MD 根也不共用索引。移动来源需要显式重建。

## 同数据正确性与成本对照

脚本 `md_cg.bench_csre_correctness` 可指定可信的修复前 `csre.py`，固定 100 / 1000 张合成知识卡、每档 20 个查询、一次预热和 7 轮计时。两侧 fixture 哈希相等，来源源码前后未变；原始每次耗时均保存。计时在启动完整测试组前串行完成。

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| 每档违反负条件的查询 | 9/20 | 0/20 |
| 接受另一份内容相同数据库的索引 | 是 | 否 |
| 接受内容已变的旧索引 | 是 | 否 |
| 显式重建包含新条件 | 是 | 是 |
| 只读检查改写缓存文件 | 否 | 否 |

每个计时样本包含 `rank_domains` 和 `top_units_in_domain` 两次调用，修复后也包含两次完整来源检查：

| 卡数 | 修复前 p50 / p95 | 修复后 p50 / p95 |
|---:|---:|---:|
| 100 | 0.104 / 0.133 ms | 2.465 / 2.707 ms |
| 1000 | 0.893 / 1.138 ms | 7.217 / 8.134 ms |

这是温热、本地 SQLite 的诊断，不是生产时延分布、盲测或严格随机交错的速度比较。完整内容指纹为 O(N)，MD 模式还需重读文件。修复后的成本更高，不能称性能优化。导航单次域先验只调用一次 `rank_domains`，其开销没有由上表单独测量。

没有用只看计数、mtime 或短 TTL 的方法替代内容验证，因此可发现同大小更新和 WAL 提交。未来若优化来源检查，应先证明不会漏掉更新，再独立比较成本。
