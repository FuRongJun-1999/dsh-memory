# 工具名迁移（0.9.9 起）

## 变化

| 版本 | 工具名 |
|---|---|
| ≤ 0.9.8 | lingshu_cg / lingshu_stg / lingshu_mdcg_reflect |
| ≥ 0.9.9 | cg / stg / mdcg_reflect |

原因：此前按 serverName 拼前缀，导致「同一个 MCP 服务、不同端看到不同工具名」的识别错误。
serverName 仍用于内部 provider/日志标识。

## 影响面（issue #634）

升级时**正在运行**的长会话/Agent 编排/脚本，若按旧名硬编码，升级后立刻 unknown tool；
新开会话不受影响。宿主与插件日志都显示注册成功，报错只在调用方——这是最难排查的部分。

## 迁移

1. 调用侧：把 lingshu_ 前缀删掉（lingshu_cg -> cg）；
2. 配置侧：profile 里的 tools 选择表匹配的是 MCP 侧原始名，写 lingshu_cg 与 cg 都不影响选择结果；
3. 兼容：0.9.12 起默认同时注册 lingshu_* 别名（描述标「已弃用别名」，指向同一实现）；
   设 toolAliases: false 可只保留裸名。

## 为什么不长期保留别名

两套名字会让「同一个工具有两个身份」进入模型上下文，也会让审计日志出现两种写法。
别名只作为升级缓冲，计划在一个 minor 周期后移除；届时会在 README 与本页标注。
