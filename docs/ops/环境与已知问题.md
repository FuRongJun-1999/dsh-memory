## 一、DSH Desktop 的启动告警（宿主侧，不在本仓修复范围）

**现象**：每次启动有一条 `migration failed`（约 2.6 秒）与 `profile maintenance frozen`，日志写
`@deepseek-ai/schemastery does not resolve from the installation closure`。

**机制**（可复核）：DSH Desktop 的 `installer.mjs` 先把 generation 里所有 `@deepseek-ai/*` 提走当**宿主单例**
（`hoistHostSingletons`），随后**又按该 generation 目录**做依赖闭包校验——「先删掉、再按原处校验」这对规则，
对任何把宿主包声明为普通依赖的插件都必然判「解析不到」。

**功能影响**：**无**。运行期宿主的 `host-module-fallback` 会把 `@deepseek-ai/` 前缀的 import 兜到宿主自带副本上
（记忆写入/召回、`cg(op=info)` 全部正常）。

**为什么不改包声明**：改成 `peerDependencies` 会让「裸 npm 安装后 import」直接失败（issue #222 的原始缺陷，
`test/issue222_optional_peer.test.ts` 守着这条契约）。两条契约在当前依赖形态下不可兼得；本插件面向 DSH **网页端**，
故维持现状、记录在案（分析见 issue #660，上游已记录为 deepseek-harness 讨论区 #10940）。

## 二、体积与部署：不是「拷几个 .py 就能跑」

`md_cg/` 是**整目录耦合**：代码 + 资产（`whitebox_kb` / `lexicon` / `semantic` / `knowledge`）同处一棵树。
MCP 模式还依赖**包根**的 `utf8_boot.py`。

| 项 | 实测（v0.9.13 main） |
|---|---|
| `md_cg/` 合计 | **71.9 MB / 2765 文件** |
| `whitebox_kb/` | 20.8 MB / 580 文件 |
| `lexicon/` | 1.6 MB |
| `semantic/` | 1.2 MB |

**判据**：只复制部分模块会在 import 期就抛 `ImportError: cannot import name 'nodefile' from partially initialized module`
（`mdcg.py` 顶层 `from . import (nodefile, protect, routing, subgraph, chain, provenance, pooling, …)`）。
要么整目录，要么等分包（issue #672 已登记评估项）。

## 三、落盘时机：节点文件同步、索引派生物异步（#677 P2）

一次 `cg(op=write)` 的落盘分**两层**，时机**不同**（设计取舍，不是缺陷）：

| 层 | 时机 | 语义 |
|---|---|---|
| 节点文件 `<root>/<layer>/<id>.md` | **同步**（返回前已落盘） | 真源；权威数据 |
| 内存索引（检索可见性） | **同步**（`_stage` 同钩） | 「写完立刻能检索」**不降级** |
| 索引派生物 `_index_log/` 分片日志（阈值触发的那次 flush） | **异步**（后台线程 `mdcg-index-flush`） | 派生数据；可由节点文件重放重建 |

**为什么异步**：那次 flush 要在 `FileLock` 下逐条 append 并开关分片句柄，是 RPC 返回路径上的
主要耗时。客户端 60s 超时衡量**整条链**，于是「已落盘但没回话」被读成失败，重试就产生重复条目
（issue #677 三条实证）。把这段搬出返回路径后，「超时 ≠ 失败」的概率大幅收窄。

**异步的对价与三条出口**（缺任一条就退化成「静默降级」）：

1. **要「确定已落盘」** → `cg(op=maintain, action=flush)`：显式**同步**把待落盘索引写完
   （返回 `{ok, action:"flush", async, pending_dirty, worker_alive, last_error}`）；
   `cg.close()` / 进程正常退出同样同步落盘（关闭语义不变：返回即已落盘）。
2. **要看「索引派生物是否落后于盘面」** → `cg(op=info)` 的 `os.index_flush`
   （`{async, pending_dirty, worker_alive, last_error}`）。后台落盘失败**必留痕**
   （`last_error` + 一次 stderr 告警），不会只存在于异常里。
3. **要关掉异步（回逐位旧行为）** → 环境变量 `MDCG_ASYNC_FLUSH=0`。

**由此派生的既有形态**：同一进程里 `del cg; gc.collect(); shutil.rmtree(path)` 之后目录可能
**被重建**（文件时间戳为删除那一刻）。测试里清理临时库请**另起进程**（`subprocess` / 单独脚本），
或在退出前显式 `cg.close()`。

## 四、超时 ≠ 失败：先查后写（#677 P1/P3）

写面的**超时不代表没写进去**。超时后的正确顺序是**先查后写**：

```js
try { write({ content, dedupe: true }) }   // dedupe：同层同内容复用既有节点（opt-in）
catch (e) {
  const hit = await route(intent);         // ① 先看落没落盘
  if (!hit) write({ content, node_id });   // ② 确认没有再写，且**自带固定 node_id**
}
```

- **幂等的两种办法**：自带 `node_id`（同 id 覆写 = 天然幂等）；或 `dedupe: true`
  （按「同层 + 内容指纹」短路复用既有节点，返回 `deduped: true` 与 `content_sha`）。
- **缺省都不做**：不传 `node_id` 时由服务端生成，重试即新增节点——既有契约，未改。
- 判据位置：`md_cg/writepipe.py`（幂等闸在链首短路，早于引用解析/建边）。

## 五、Windows + Python 3.12 的 `rmtree` 怪癖（属 Python，不属本仓）

`shutil.rmtree(root)` 抛 `FileNotFoundError`，但 `os.path.exists(root)` 为 `False`（其实已删干净）。
多层目录 + 锁文件的组合更容易触发。**处置**：忽略该异常即可，不要当成删除失败去重试写盘。

## 六、设计取舍：看起来像 bug，其实是契约

### 5.1 `importance` 的默认值与来源

写入面 `importance` 有默认值（库层 0.5、插件提示面常用 0.6），并会把来源标在 `importance_source`（如 `hint`）。
**这不是「库很脏」**——自动记忆面按「值得记住」的默认档写入，靠后续的 `scrub` / 校准收敛。

### 5.2 `importance >= 0.7` 是**硬保护**，写错了也改不掉

`md_cg/scrub.py` 原文：**受保护节点（self/anchor/importance≥0.7/显式保护）跳过；永不删除**。
单点常量是 `protect.AUTO_PROTECT_IMPORTANCE = 0.70`。
**含义**：把重要度写高＝申请不可遗忘保护；写错想删需显式 `override`。

### 5.3 `calibration` 只给建议，不自动施加

校准输出形如 `{suggested_offset: -0.15, applied: false}`：
`suggested_offset` 是**建议值**，`applied` 恒为是否真的被施加（默认**不自动改**置信度）。
**这是「人类在环」的取舍，不是「知道却不改」的 bug**；要施加须显式传 `apply`。

### 5.4 `validity` 只排「已过期」，不排「未生效」

`search` / `search_rrf` 的 `validity` 语义是**排除已过期**（`not_yet` 保留），名字容易读成「只给有效的」。
现在两条读路径都在 `meta.validity_scope` 里如实透出：`expired_only`（启用）/ `off`（未启用）。

### 5.6 最低分门槛：`0` 与 `-1` 都是「关」

两个门槛开关的**缺省值不同**，容易误读：

| 变量 | 缺省 | 语义 |
|---|---|---|
| `MDCG_MIN_SCORE` | `0` | 融合面 / T3 出口的最低分门槛；**0 = 关**（不过滤） |
| `MDCG_RECALL_MIN_SCORE` | `-1` | 召回面（token 预算装包）的最低分门槛；**-1 = 关**，设 `0.01` 才启用 |

**判定口径统一为 `> 0` 才算启用**：设成 `0` 或负数一律视为「关」，
而不是「门槛为 0（等于全都够格）」——后者看似等价，实际会让「被 S5 降到 0 分的真候选」
与「零分兜底」的差别消失。

非法值（非数值 / `nan` / `±inf`）**回落缺省并记账**：读面 meta 里出现 `min_score_input=invalid` 就说明设错了。

顺带说明一处历史口径差异（已统一）：融合面曾用 `>0`、召回面曾用 `>=0`，
于是 `MDCG_MIN_SCORE=0` 在两边一个关一个开、`-0.0` 还会开闸。现在两处都走同一个解析单点。

### 5.5 孤立节点必须能被兜底召回

`edges` 为空、`access_count: 0` 的节点会被 `T2_global_like`（全局词法兜底路）命中，**这是契约要求**：
`md_cg/routing.py` 原文「该节点留在 ORPHAN/兜底池（**S1 收敛时必须能被兜底召回**，见契约 §3 S1 不变量）」。
想要「只给高置信结果」请用资格裁决档（`judge` / `cg(op=route)`），而不是给兜底路加门槛。
