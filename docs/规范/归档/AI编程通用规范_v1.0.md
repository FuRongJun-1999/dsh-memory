# AI 编程通用规范 v1.0

> 一句话：**先想清楚该不该做，再动手；动手要能证明，证明不了就说证明不了；做完要留痕，丢了要能读回来。**
>
> 适用对象：用 AI 写代码、写文档、改配置的任何人。不绑定任何产品、工具、语言。
> 读法：先读第一章（判定流程，5 分钟），再查第二章（25 条，用到哪条翻哪条）。

---

## 第一章 动手前的判定流程

**五步，按顺序走。任何一步答不上来，就不许开工。**

### 1. 声明四条边界

一句话写清：谁在做、用什么做、做多久、允许改到哪。

> 例：我（AI 助手）在本地仓库里，用命令行和编辑器，做 1 小时，只改 src 目录下的文件。

### 2. 三问自检

| 问 | 要回答什么 |
|---|---|
| 依据什么？ | 引用了哪份文档、哪行代码、哪条记录 |
| 在什么条件下成立？ | 这个结论什么时候有效、什么时候失效 |
| 错了怎么办？ | 怎么发现错、怎么回退、怎么记住 |

**三问答不上，不许开工。**

### 3. 判资格（四态）

| 四态 | 含义 | 该怎么办 |
|---|---|---|
| 能做 | 条件齐、依据足 | 开工 |
| 不能做 | 明确不该做 | 说明理由，停下 |
| 等条件 | 缺东西（缺数据、缺权限、缺人拍板） | 写清缺什么，去要 |
| 不知道 | 信息不够，判不了 | 直说「不知道」，不许编 |

**顺序：先判「不能做」，再判「能做」。不许一上来就动手。**

### 4. 给出方向与关注点

这次要盯什么信号（哪个读数、哪条日志、哪个测试）。

### 5. 失败就归因到条件

不说「我不小心」，要说「少了哪个条件」，并把新发现写成一条规则（进第二章或项目自己的补充）。

## 第二章 25 条规则

> 每条只写三格：**什么时候用 / 做什么 / 什么情况不用**。「怎么证明」「做不到怎么办」「一句话声明」见第三章附表 A。

### 第一组 动手前（4 条）

**1. 先找资料**：任何任务开始前，先查已有文档、已有实现、已有记录；找到就复用。纯聊天不用。

**2. 先问清楚，并先写验收标准**：需求有歧义时，先把「什么算做完」写成 1～3 句可检查的话；不清楚就问，不猜。单步小改不用。

**3. 假设要标注**：信息不足但必须往下走时，写「假设：…」并写「怎么验证」。能问到人就先问，别假设。

**4. 先找根因**：修 bug、修失败、修红时，先复现、取证、定位到具体一行/一条数据，写下根因再改。紧急止血可以破例，但要留「待查根因」。

### 第二组 判定（4 条）

**5. 声明四条边界**：跨会话、多人协作、长任务时，一句话写清谁/用什么/多久/改到哪。5 分钟小改不用。

**6. 三问自检**：每个要开工的候选任务逐一回答三问，答不上就不开工。正在续做且条件未变可免。

**7. 先判资格四态，不知道不许编**：判「能做/不能做/等条件/不知道」；判「不知道」就明说。对方已明确指令且条件齐备可免。

**8. 失败先归因条件，再写成规则**：写清「少了哪个条件」，并把教训写成一条可检查的规则。一次性外部故障记一句即可。

### 第三组 语言（1 条）

**9. 中文思考、中文书写**：推理、说明、注释、文档用中文；代码、标识符、报错原文、外部引用保留原样；专业词首现写「中文（原文）」。英文环境/英文文档/国际合作除外。

*为什么是规范不是偏好：用户是中文用户；中文语义检索效果更好；中文表达更省 token、更准。*

### 第四组 做对（6 条）

**10. 一次只改一处**：改一小步就验一次，别攒一堆再试。纯格式化/纯重命名可整批。

**11. 改动要能证明**：声称「做好了」必须给出可检查的结果——命令输出、读数、测试结果。只讨论不产出可免。

**12. 代码最低标准**：能直接跑通、不留占位与 TODO、有测试、写清复杂度与限制。一次性脚本要在文件头写用途与限制。

**13. 验不了就说验不了**：本地验不了（构建、平台差异、外部服务）时，写明「以 CI / 对方环境为准」并给出验法。本地能验且已验可免。

**14. 一份东西多处有，就一起改**：同一次改动里全改齐并核对一致性。只改一处要在说明里写原因。

**15. 主路不通走备路**：换等价办法顶上，写清「为什么换、换了什么」。只是慢不换。

### 第五组 不出事（4 条）

**16. 不猜不编**：没查到就说没查到；不确定就标「不确定」；不编造文件名、行号、读数、链接。没有例外。

**17. 名字要统一**：同一东西只有一个叫法；新名字要登记；不造第二套。外部系统固定命名照抄。

**18. 敏感内容分开放**：密钥、令牌、隐私、内部路径只放私有地方；公开面用相对路径或占位符；提交前核对。

**19. 提交只写明确路径**：只写明确文件路径，不用「全部添加」；推之前逐笔核对；别人未提交的改动不碰。没有例外。

### 第六组 留得下（6 条）

**20. 任务要留痕**：一条记录写清谁做的、怎么做的、结果如何。纯问答可免。

**21. 收尾要归档**：任务交付后提炼四件事——改了什么 / 为什么 / 在哪里 / 怎么验，存进可检索的地方。只读任务可免。

**22. 判据要先能红**：新增或修改任何检查（测试、守卫、门禁、断言），先造一个坏样本证明它会红；不会红就不是判据。没有例外。

**23. 发版只钉绿的，稳定优于炫技**：只在检查全部通过的提交上打标签；取舍时优先稳定、清晰、可验证。内部试验要标「未验收」。

**24. 工作区要有一份目录**：文件超过 20 个或有人要接手时，根目录放一份《工作区目录》，写清有哪些目录、各自放什么、关键入口在哪；新增顶层目录或根文件要登记；过期就重生成。单文件小任务不用。

**25. 上下文被压缩后，先读回三样东西**：读回 ① 人设（我是谁、口径、禁忌）② 工作进展（当前任务、做到哪、卡在哪、下一步、最近 3 个决定）③ 用户最近 10 轮对话。**能用一句话复述「我在做什么、上次结论是什么、下一步做什么」才算读回；复述不出就是没读回，不许继续。** 全新无关任务可免。

## 第三章 附表

### 附表 A：证据 / 兜底 / 声明

| 条 | 怎么证明 | 做不到怎么办 | 声明 |
|---|---|---|---|
| 1 | 列出查过的文档/代码/记录 | 明说「没找到既有实现」再开工 | 已先查既有资料 |
| 2 | 写出验收标准 1～3 句 | 写「待确认项」并标注 | 已明确验收标准 |
| 3 | 列出「假设 + 验证方法」 | 不能验证就降级为「待确认」 | 假设已标注 |
| 4 | 复现步骤 + 定位到行/数据 | 只止血时留「待查根因」 | 已定位根因 |
| 5 | 一句话边界声明 | 边界不明按最小范围做 | 边界已声明 |
| 6 | 三问各有答案 | 有一问答不上 → 不开工 | 三问已过 |
| 7 | 写明判定与理由 | 判「不知道」并停 | 资格已判定 |
| 8 | 归因句 + 新规则 | 归不了因就挂账 | 已归因成规则 |
| 9 | 抽查一段产出 | 英文场景说明原因 | 已按中文规范书写 |
| 10 | 改动点与验证点一一对应 | 改动过大就拆分 | 小步已验 |
| 11 | 命令输出/读数/测试结果 | 无证据不说「做好了」 | 有证据 |
| 12 | 能跑 + 有测试 + 限制说明 | 缺测试则标明「未测」 | 达到最低标准 |
| 13 | 写明由谁验、怎么验 | 无 | 已声明验证边界 |
| 14 | 副本清单 + 一致性核对 | 只改一处要写原因 | 副本已同步 |
| 15 | 换路原因 + 等价性说明 | 无等价办法则停并上报 | 已切换并说明 |
| 16 | 无来源处标「未查到」 | 无 | 无编造 |
| 17 | 命名表/引用一致 | 外部固定名照抄并注明 | 命名已统一 |
| 18 | 提交前扫描结果 | 不确定就按敏感处理 | 敏感已隔离 |
| 19 | 提交文件清单 | 无例外 | 路径已明确 |
| 20 | 一条任务记录 | 无 | 已留痕 |
| 21 | 归档条目（四件事） | 无 | 已归档 |
| 22 | 坏样本 → 检查变红 | 不会红就重做判据 | 判据有判别力 |
| 23 | 全绿证据 + 标签指向 | 未全绿则不发 | 发版点全绿 |
| 24 | 抽查三样东西能否找到 | 目录过期则重生成 | 目录已更新 |
| 25 | 一句话复述任务/结论/下一步 | 复述不出 = 没读回，停 | 已读回三样 |

### 附表 B：三种交付顺序

| 场景 | 交付顺序 |
|---|---|
| 写代码 | 结论（能不能做/做了什么）→ 方案要点 → 代码 → 测试 → 怎么跑 → 边界与取舍 |
| 写设计 | 结论（选哪个）→ 条件与依据 → 方案对比 → 选定方案 → 风险与回退 |
| 写报告 | 结论 → 关键读数 → 依据与证据 → 遗留问题 → 下一步 |

### 附表 C：图像与算法专项（需要时引用）

- **选源护栏**：用哪个数据源先查历史记录；没核对过的不许用。
- **历史查询优先**：先找已走通的做法与源码，别重新发明。
- **算法权威唯一**：一个能力只有一个权威文档；要换算法，先记录原因并更新文档。

## 第四章 怎么用这份规范

1. **新人**：读第一章 + 第二章前两组（约 30 分钟）。
2. **日常**：做完一件事，对照附表 A 自查一遍。
3. **改规范**：先改正文，再改项目适配表；两份要对得上。
4. **校准**：拿给不同专业的人看，记下「看不懂/不同意」的地方，改正文措辞，不改条目编号。
