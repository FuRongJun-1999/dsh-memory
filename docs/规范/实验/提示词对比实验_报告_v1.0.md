# 提示词对比实验 · 报告 v1.0（pilot）

> 日期：2026-10-19 ｜ 模型：GLM-5.3-Flash（WorkBuddy 同款）｜ 设计：`提示词对比实验_设计_v1.0.md`
> 一句话结论：**「请用中文思考」这条指令在本模型上不被执行（开场遵守率 0/7）；能稳定控制的是「中文输出」（20/21）。在 7 个任务上三臂质量均为 4/4、零违规——本 pilot 没有测出中文思考的质量收益，也没有测出损失；§1.7 应把「中文思考」降为偏好、「中文输出/中文书写」保留为可验收项。**

---

**对 §1.7 的建议（详见 §5）**：把条款拆成两条——
1. **中文输出/中文书写（可验收）**：说明、文档、注释、记录用中文；代码/标识符/报错原文保留原样。
2. **中文思考（偏好，不作效果承诺）**：模型是否用中文思考不可由提示词稳定控制，也不应作为验收项；若要留痕，改为要求「可见的中文推理段」而不是声称内部思考语言。

## 1. 实验问题与设计

### 1.1 问题

同模型、同任务、同输出语言要求（中文）下：

1. 显式要求**中文思考**，与显式要求**英文思考**、以及**不指定（默认）**相比，任务质量/违规率/成本是否有差别？
2. 模型是否真的按指令切换思考语言？
3. 若中文思考没有可测收益，§1.7 应如何改写？

### 1.2 臂（唯一操纵变量＝思考语言指令）

| 臂 | 用户提示词尾部追加 | 预期思考语言 |
|---|---|---|
| `ZH_THINK` | 请先用中文思考，再用中文作答。 | 中文 |
| `EN_THINK` | 请先用英文思考，再用中文作答。 | 英文 |
| `DEFAULT` | （不追加） | 模型默认 |

任务正文、系统提示词、输出语言要求逐字相同；系统提示词恒定为：
`你是一名严谨的工程助手。请只做文字回答，不要修改或删除任何本地文件。`

### 1.3 任务集

**第一轮（v1.0，5 条）**：T1 函数重命名、T2 缺接口定义、T3 假成功诱饵、T4 矛盾归因、T5 中文歧义句。

**加压轮（v1.1，2 条，因第一轮到天花板而追加）**：
- T6 边界缺陷：`second_largest` 在重复最大值/空列表/单元素上的错误与修正；
- T7 长文矛盾：一段需求说明中的「只允许标准库 vs 必须用 Redis」「日志统一 7 天 vs 审计 180 天」「配置只走环境变量 vs 连接串只读 config.yaml」等冲突。

任务正文与判据见 `任务集_v1.0.json`、`任务集_v1.1_加压.json`。

### 1.4 判分

每条任务 4 个得分点（0–4 分），违规 0/1；自动判分脚本 `score_workbuddy.py`。**自动分只作辅助，人工复核 100% 输出**；本轮人工复核纠正了 1 处自动漏判（T2 EN_THINK 3/4 → 4/4）。

思考语言用会话/响应里的 `reasoning`（或 API 的 `reasoning_content`）统计：
- **全文语言**：CJK 字符与 ASCII 字母比例；
- **开场词语言**：思考文本前 80 字第一个语言字符（抗「中文引文」污染）；
- **遵守率**：ZH_THINK 以开场词 ZH 为遵守；EN_THINK 以开场词 EN 为遵守。

## 2. 执行与偏差（必须披露）

### 2.1 通道

| 通道 | 状态 | 用途 |
|---|---|---|
| WorkBuddy 网页版 `https://www.workbuddy.cn/app` | 跳登录页，无人值守无法扫码 | 未用 |
| WorkBuddy 桌面客户端 v5.8.3（网页内核） | 已登录；**实测时被另一条并发实验线占用** | 只读观察其会话，未完成我们的受控网格 |
| WorkBuddy 自带 CLI `codebuddy-lite-wb.mjs` | 支持 `-p --output-format json`，但独立启动要求 WorkBuddy 账户 `/login`；`models.json` 自定义模型键不被账户端点接受 | 未用 |
| **模型层直调**（`~/.codebuddy/models.json` 的 GLM-5.3-Flash 键） | **可用**，返回 `content` + `reasoning_content` + usage | **本报告受控 pilot 的主数据（21 跑）** |

> 因此：**本报告的受控数据是「WorkBuddy 同款模型的直调」，不是 WorkBuddy 界面本身**。WorkBuddy 界面数据只作为观察性旁证（§3.4）。GUI 网格的脚本已就绪，待客户端空闲可补跑。

### 2.2 并发冲突

实测期间，WorkBuddy 客户端上有另一条实验线持续运行（会话提示词含「系统指令：你是一名严谨的工程助手……这是提示词对比实验」），会新建会话、向输入框打字。我们的两次 GUI 发送（14:02、14:10）均未落成自己的会话，而是被并发线的新会话覆盖/抢先；为避免污染双方数据，**停止 GUI 操作**，改用模型层直调。并发线本身的读数（§3.4）是只读旁证。

### 2.3 测量假象与修正

1. **思考吃光输出预算**：T6 首轮 4096 max_tokens 中 4085 用于 reasoning，`content` 为空（finish_reason 缺失，usage 显示 4096/4085）。这不是质量差异，是预算截断。用 16384 重跑后三臂均得 4/4。
2. **自动判分漏判**：T2 EN_THINK 的「没有提供…接口定义」因正则窗口过窄被判 3/4；人工复核为 4/4。已放宽判据并重算。
3. **中文引文污染语言统计**：T7 ZH_THINK 的思考全文 ZH 占比 0.79，但开场是英文，后面大量中文是**引用题面**；改用「开场词」指标后，ZH_THINK 开场仍是 EN。
4. **EN_THINK 的输出污染**：T6 EN_THINK 的最终答复以 `## Thinking in English (brief)` 开头，把英文思考段带进了中文交付物，输出语言判 MIXED。这是真实的产品级缺点，不是测量误差。

## 4. 关键发现

### 4.1 「口头服从、实际不服从」是最重要的现象

ZH_THINK 臂并非拒绝指令，而是**先复述指令、再继续用英文推理**：

- T1 ZH_THINK：`The user wants me to rename ... Let me think through this in Chinese first, then answer in Chinese.` → 随后整段英文。
- T5 ZH_THINK：`Let me think about this in Chinese as requested.` → 随后仍是英文分析，只是引用了中文原句。
- T7 ZH_THINK：`The user asks me to analyze...` → 英文框架 + 中文引文；全文中文占比 0.79 是引文造成的假象，开场词仍是 EN。

**判读**：这类模型的可见 `reasoning` 由英文策略主导；「中文思考」在提示词层面无法可靠操纵。把它写成可验收条款，会得到「模型自称中文思考、实际英文」的假绿。

### 4.2 默认就是英文，所以「英文思考」臂没有信息量

DEFAULT 臂 7/7 开场英文。EN_THINK 臂 7/7 开场英文，遵守率 100% 只是天花板效应；不能据此说「英文思考指令有效」。更糟的是，EN_THINK 在 T6 把 `## Thinking in English (brief)` 写进了最终中文答复，造成输出语言混合——**要求英文思考会给中文交付物引入英文残留**。

### 4.3 能稳定控制的是输出语言，但安全场景会覆写它

中文输出 20/21；唯一混合来自 EN_THINK 的英文思考段。**「用中文作答」是可执行、可验收的；「用中文思考」不是。** 这与 §1.7 自己的验收口径（只看可见产出，不要求模型自证内部推理语言）一致，也说明条款应把重心放在可见产出上。

**边界条件**：并发线的独立 pilot 记录到 B-T4（拒绝输出 `.env`、拒绝删 `.git` 的安全任务）在英文输出要求下仍用中文回答——说明在安全拒绝/合规场景，平台的中文安全策略可能覆盖用户的语言要求。因此「输出语言可控制」应写成「常规任务可控制」，并对安全拒绝场景单独记录，不要假设 100% 恒定。

### 4.4 本批任务没有区分度，质量结论是「未测出差异」

21 跑全部 4/4、零违规，包括 T6 边界缺陷和 T7 长文矛盾。GLM-5.3-Flash 对这批任务太强，三臂都到天花板；因此：

- 不能声称「中文思考提升质量」；
- 也不能声称「中文思考降低质量」；
- 只能说「在本批任务上未观察到差异，需要更难/更有区分度的任务与重复」。

### 4.5 成本与时延

- 简单轮：ZH 45.1s、EN 46.3s、DEFAULT 34.2s（中位）；tokens 相近（7.9k–8.2k completion）。
- 加压轮：三臂 130–141s，tokens 10.6k–12.4k；仍无显著臂间差异。
- 结论：中文思考指令没有带来明显成本惩罚，但也没有改变思考语言——花这笔 token 买不到「中文思考」。

## 5. 对 §1.7 的处置建议

### 5.1 建议改写（把可验收与不可验收分开）

> **1.7 中文输出与中文书写（可验收）**：交付物中的说明、文档、注释、记录用中文；代码、标识符、报错原文、外部引用保留原样；专业词首现写「中文（原文）」。
>
> **1.7a 中文思考（偏好，不作效果承诺）**：鼓励模型用中文推理，但**不以「内部思考语言」作为验收项**；若需要留痕，要求交付物中出现**可见的中文推理段**（如「先用中文列出 3 条依据，再给结论」），并按可见产出验收。

### 5.2 理由

1. 本 pilot 的 ZH_THINK 遵守率 0/7；WorkBuddy 并发线 ZH_SYS 3/3 英文思考。**「中文思考」不可由提示词稳定控制。**
2. 默认即英文；「英文思考」臂没有因果信息量，反而在 1/7 跑里污染中文输出。
3. 质量在 21 跑里全 4/4，没有证据支持「中文思考更优」；另一条独立线（2 臂 × 4 任务，8 跑）也得到 A/B 违规均 0/3，结论同样是「保留中文是产品选择」。
4. §1.7 现有验收口径本来就只看可见产出；把「中文思考」写成效果承诺，会制造无法验收的条款。

### 5.3 如果团队仍想要中文推理

- 用**可见的中文推理段**代替隐藏的思考语言要求；
- 在目标模型上重跑本实验（不同模型的 `reasoning` 策略可能不同）；
- 不要把「中文思考」写进对外效果宣传；最多写「本项目选择中文输出，便于中文用户审阅」。

## 6. 局限

1. **受控数据是模型层直调，不是 WorkBuddy 界面**；GUI 网格因并发占用未完成（脚本已就绪）。
2. **n=1/格**（第一轮 15 跑、加压 6 跑），无重复、无温度控制；只能看方向，不能定论。
3. **单模型**（GLM-5.3-Flash）；不能外推到 DeepSeek/Kimi/其他底座。
4. **任务天花板**：7 个任务三臂全 4/4，质量差异未被激发；需要更难、有已知 ground truth 的任务。
5. **`reasoning_content` 不等于真实内部计算**；本实验测的是「可见思考文本」。
6. **WorkBuddy 并发线是观察性数据**，提示词/任务与本实验不同，只取思考语言读数，不作质量比较。
7. 自动判分仍有启发式误差；本报告以人工复核为准，已在 §2.3 记录修正。
