## 二、为什么必须先修 B（避免把预算花在错误的地方）

当前 `index_code` 的产出**在检索路径上是残废的**：

```

  第 1 步：ccg_completeness(content) 不全  →  直接返回 BLINDSPOT
           ↑ codeindex.render 不产 CCG 标记（codeindex.py:80-88）

             尽管 mcp_server.py:1508 已正确填了 verification_basis="compiler"
```

同仓已有两个正确范式可抄：目标节点**按 CCG 格式渲染**（`mdcg.py:513-519`，注释直写「保证 judge_qualification 能给出 ACCEPT 而非 BLINDSPOT」）、legacy 记忆走 `ccg_exempt`（`mdcos.py:313-316`）。

**结论**：索引层的第一个 PR 不是「加更多后缀」，而是**让渲染产物符合 CCG 5 要素**。否则索引量涨 10 倍，可用性仍是 0。

1. **回得去**：任何一条被检索到的节点，都能给出行级可定位的位置——
   代码 → `<path>:<lineno>-<end>`；文档 → `<path>#<heading-path>:<lineno>-<end>`。

## 四、设计：统一 ref 协议

沿用 `code_ref` 的形状，扩成 `ref` 协议，作为 frontmatter 一等字段（`nodefile` 已支持任意 JSON 值，无需改格式层）。

```jsonc
// 代码节点
"code_ref": {"path":"md_cg/mdcg.py","name":"MdCG.add","kind":"def",
             "lineno":383,"end":462,"lang":"py","hash":"9f2c1ab3de44"}

// 文档节点
"doc_ref":  {"path":"docs/认知图_MD目录方案_v0.1.md","heading":"9. 分阶段实施（稳健）",
             "heading_path":["9. 分阶段实施（稳健）"],"level":2,
             "lineno":491,"end":513,"anchor":"9-分阶段实施稳健","hash":"41ab77c0e1d9"}
```

**不变量（写进代码注释与测试）**
- 正文**永不复制实现/全文**——只存「索引块 + ref 指路」（对齐 `codeindex.py:4-6` 的既有纪律）。
- `hash` = 被引用行的 sha1 前 12 位，用于漂移判定（不是内容寻址，是变更探测）。
- 索引是派生物：`_refindex.json` 丢了/坏了，能从源文件全量重建。
- 源文件**只读**：索引一轮后源文件 mtime 全不变（对齐 P0 的 mtime 只读断言）。

**CCG 渲染模板（修 B 的关键）**

代码节点（`功能名/子功能/执行/验证方式/不适用条件` 五个必需标记齐 → `complete=True`）：

```
# 功能名：{name}（{kind}）
# 生效条件：大域={top_dir}；检索「{name}」或「{path}」
# 子功能：{所属模块/类} · {docstring 首段≤120字}
# 执行：{sig}
# 验证方式：compiler（AST 已解析，非人工声明）
# 不适用条件：其它大域的同名符号
```

文档节点：

```
# 功能名：{heading}
# 生效条件：文档={rel_path}；检索「{heading}」或正文关键词
# 子功能：{父 heading 路径}
# 执行：{首段摘要≤200字}
# 验证方式：data（原始文档为准）
# 不适用条件：其它文档的同名标题
```

> 取舍：docstring/首段进 `子功能` 行而不另起 `# doc:` 行，是为了让**单条节点的全部可检索信息都在 CCG 结构内**，避免出现「检索能命中、判定看不见」的字段。

## 七、验收（`test_p26_refindex.py`，对齐既有 `test_pNN` 脚本式 `check()` 风格）

1. **ref 落盘**：代码/文档节点的 `frontmatter.code_ref`/`doc_ref` 五字段完整，且 `loads` 往返不丢（`nodefile.py:73`）。
2. **CCG 合规（修 B 的守门断言）**：`ccg_completeness(content)["complete"] is True`；`judge_qualification(...)["state"] != BLINDSPOT`。
3. **回读一致**：`read_ref(node_id)` 返回的区间文本与该文件当前内容**逐字相同**（非「看起来对」）。
4. **漂移检测**：在目标文件插入 1 行 → `ref check` 报 `stale`；删除该符号 → 报 `dangling`；两者都不抛异常、都不改源文件。
5. **只读契约**：索引一轮前后，被索引的 `.py`/`.md` **mtime 全不变**、源文件 hash 不变。
6. **幂等**：同一目录索引两次 → 节点数不变、`node_id` 稳定、`_refindex.json` 不膨胀。
7. **不复制正文**：代码节点 content 内「函数体语句」0 命中（如断言不含 `return ` 之外的可执行行）；content 长度 ≤ 阈值。
8. **截断诚实**：`max_files=1` 时 `truncated is True` 且给出建议值。
9. **文档切块**：heading_path 与行号可定位；正文含 `---` 分隔线不污染 frontmatter（`nodefile.py:19-23` 的既有纪律不回归）。
10. **权限**：`op=ref` 走 `tokens` 校验；无权限 actor 读取越权层的 ref 应被拒。
11. **新 op 注册**：`tokens.ALL_OPS` 与 `mcp_server` 的 op 枚举一致（防漏改）。

## 十、诚实边界

1. **本计划是「可索引」，不是「可理解」**：doc/code 索引仍是**确定性静态索引**，不含语义蕴含；跨表述的「这段代码其实实现了那段文档的意思」不解决（与 `memory_score.md:36` 「有意剔除神经嵌入」一致）。
2. **索引质量上限 = 源文件注释质量**：白箱路线的固有代价。没有 docstring 的函数只能索引到签名。
3. **`hash` 不是内容寻址**：只做变更探测，不保证「内容相同即同节点」。
4. ~~R0 有一个待闭环疑点~~ → **已在 §十一 闭环**。「`test_p1` EXIT 1 且输出仅 165 字节」的根因与 `test_p0` 同一类：受管环境下 `os.remove` 被环境 shim 接管，
   删除量越阈即中断进程；且失败形态是**静默截断 + 非零退出**，不是一条 FAIL。现已改为不清空目录（原子覆盖 + 等号守门），并全量复跑验证。
5. **当前工作区未提交**：`docs/认知图_MD目录方案_v0.1.md`、`bench_p0.py`、`census.py`、`test_p0.py`、`test_p1.py` 已改，`md_cg/corpus.py` 未跟踪——R0 应先收口提交，再动索引层。

### 14.2 三个真实缺陷（首轮实测 39 通过 / 6 失败 → 修后 45/0）

首轮失败不是断言太严，而是**实现确实错**，逐条留证：

1. **巡检把一切都误判成 `dangling`（严重）**：`Ledger.record()` 没记源大域，`check_refs` 拿 `ledger.root`（= 认知图根）去拼 `root/rel`；而源在别处（如临时目录 / 任意被索引的大域），于是**文件永远找不到**。实测：改源一行后 `stale=[]`、`dangling=[alpha.py,beta.py,...]`，`sustain.diagnose` 因此报 `ref_dangling` 而非 `ref_stale`。
   → 逐文件记 `root`，巡检用**每个源文件自己的 root**；且键改绝对路径。
2. **水位不会遗忘死根**：键若按 `rel`（或虽按绝对路径但从不清理），源大域整个搬迁/删除后条目永久残留。因 `node_id` 与绝对路径无关，`nodes` 过滤挡不住这些幽灵条目，巡检会报**永不消失的 dangling**（`heal` 也治不好，因为条目不在任何会被重建的 root 下）。实测：连跑两次用例 → 水位 `files=4`（含上一轮已删临时目录的 2 条），`重跑后 dangling 消除` 失败。
   → 新增 `prune()`（剪掉源大域已不存在的条目，真悬空由节点自带 ref 兜底）+ `reconcile(root, kind, seen)`（一次**完整**索引后，本 root 下没扫到的旧条目剪掉）。**截断的索引不对账**——没扫完 ≠ 剩下的都消失了。
3. **落盘字节抖动**：`updated_at`/`ts` 用 `time.time()` 全精度浮点，`float` 最短 repr 的小数位长度会变 → 重跑 3 次体积 `1156 → 1157`，「不膨胀」判据假失败。→ 时间戳压到 **1 位小数**（`_now()`），体积稳定（实测 `1504 → 1504`）。

### 14.3 增量（修 F）：未变文件不重切

- `_refindex.json` 按 `(size, mtime)` 双等判「未变」，`incremental=True` 时**不读盘**直接跳过，计入 `skipped_unchanged`。
- 实测：首轮全量 `indexed=6 / files=2`；第二轮 `incremental=true` → `skipped_unchanged=2 / indexed=0`，**节点数不变（幂等）**；不传 `incremental` 时 `skipped_unchanged=0`（默认仍全量，保证不漏召回）；两轮 `id` 集合稳定。
- 水位键 = **源文件绝对路径**：一份认知图可索引多个大域，只按 `rel` 记会在 `alpha.py` 这类同名文件上互相覆盖（静默丢水位）。

### 14.4 漂移 / 悬空（修 D）：唯一判定实现

- 回读与巡检**共用 `probe_ref` / `codeindex.region_hash`**，杜绝「回读说没漂、巡检说有漂」。`stale` 判据是**内容哈希**，不是 mtime——只 `touch` 不改内容，报 `ok` 才对（段⑧ 首版用例正是写入了与索引**相同**的正文，属用例缺陷，已改为第二个真实漂移变体）。
- 实测：改源一行（`lineno 5..7` 区间）→ `check` `ok=false`、`stale=[alpha.py ×2]`；重跑 `index_code` → `stale=[]`；删 `beta.py` → `dangling=[beta.py ×2]`；恢复源并重建 → `dangling=[]`。
- **只读契约**：巡检前后被索引源文件 `mtime` 不变；`heal` 也不修改源文件（源里仍是改后的正文）。
- **快路径**：ledger 判「未变」的文件不读盘直接判 ok；变了的才读一次按记录区间重算哈希。ledger 覆盖不到的节点再回退逐节点探测（`only_tagged=True` 只扫带 `code`/`doc` 标签者）。

### 14.5 截断不静默 + 接入 sustain

### 14.8 诚实边界（R3 新增）

1. **`stale` 只承诺「可检出」，不承诺「自动定位到改了哪一行」**：报的是区间哈希不匹配 + 原区间坐标，不做行级 diff。
2. **水位是派生物缓存，可随时删除**：`prune`/`reconcile` 让它有界，但语义上它只是提速；删掉后巡检退回逐节点探测，结论不变。
3. **多根同名文件**：键为绝对路径，同名文件分属不同大域**互不覆盖**；但同一文件被两个大域同时索引时，`nodes` 会指向同一组 id，最后写入者胜（与索引自身语义一致）。
4. **`max_files` 截断时不对账**（§14.2-2），因此截断轮次后水位会短暂保留未扫文件的旧条目——这是**保守**选择：宁可多留，不可误删。
