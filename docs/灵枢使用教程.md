## 1. 为什么用它

模型每次会话都是新的：**决定过的口径、踩过的坑、改过的约定，不写下来就等于没发生**。
灵枢做的是把「这次学到的东西」落成**本地文件**，下次会话开头就能取回来。

它不训练模型、不做向量检索的默认路径、不替你下判断——它只保证**写进去的是原文，取出来的是证据**。

**谁把它取回来**：会话起始由注入面（`src/hooks.ts` 的 system-prompt 注入）贴一小批最近记忆；更全的检索要**你主动**调 `route` / `read` / `recall`——不是「模型自动记得」。

## 2. 三条设计原则

| 原则 | 含义 | 你能看到的效果 |
|---|---|---|
| **原文即证据** | 记忆是逐字落盘的 markdown，不经过摘要再压缩 | 查回来能直接引用，不用「回忆」 |
| **本地可读可改** | 一个节点 = 一个文件，任意编辑器可看 | 争议时打开文件就能对 |
| **不写不算数** | 没有 `验证方式` 的条目会被判「未验证」 | 减少「我记得好像…」的假记忆 |

## 3. 记忆长什么样

每个节点是一个 markdown 文件，YAML 头做索引，正文按六要素成文：

```markdown
---
id: mem_1793945439202_174aab
layer: knowledge
created_at: 1793945439.2
session: session-551222f6
tags: [dsh端, release]
---

# 功能名：注入面会话内去重
# 生效条件：长会话里出现「复述旧结论、不再探索」
# 子功能：
#   A. 同会话内同一条最多注入 2 次；
#   B. 全被滤掉时保留第一条，避免整块消失。
# 执行：src/hooks.ts 的 dedupeRepeatedItems()
# 验证方式：test/inject-dedupe-739.test.ts（3 条）
# 不适用条件：临时排查「某条记忆为何不出现」时需关掉去重
```

## 4. 三步开始

```bash
npm install @furongjun1999/dsh-memory@0.9.23     # 1) 装进 DSH profile（或 link 本地仓库）
```

```python
# 2) 自检：确认服务活着、库在哪
cg(op='info')                 # 快照：node_count / flush_state
cg(op='info', full=True)      # 全量诊断（含 os 慢面数据）

# 3) 第一条记忆
cg(op='write',
   content='# 功能名：…\n# 生效条件：…\n# 子功能：…\n# 执行：…\n# 验证方式：…\n# 不适用条件：…',
   content_kind='text', layer='knowledge', tags=['上手'],
   importance=0.6, verification_basis='test', dedupe=True)   # 登记表里叫 importance_hint；importance 实测同样生效
```

**读回确认**：写入后用返回的 `id` 再取一次——**看不到就等于没写成**。

```python
cg(op='read', node_id='mem_…')      # 按 id 直取（**别用 query= 传 id**：query 是检索面，实测不保证命中 id）
```

## 5. 写记忆：层与六要素

### 5.1 选层（最容易错的一步）

| 层 | 放什么 | 判据 | 错法 |
|---|---|---|---|
| `self` | 身份 / 价值观 / 认知图接口，**只有这三样，很薄**；会话起始经注入面加载（`src/hooks.ts` 的身份锚点块） | 「变了我就不是我了」 | 把项目结论塞进来 ⇒ 人格被细节污染 |
| `anchor` | **协议级**跨实例锚定（不可遗忘的那几条） | 「任何实例上都必须成立」 | 当日常写入面用；新手基本不用碰 |
| `knowledge` | 可复用的结论、规范、踩坑与修法 | 「三个月后换个人也该知道」 | 一次性会话细节写进来 ⇒ 检索噪声 |
| `contextual` | **本次会话**的过程、当时的判断、临时状态 | 「只有这场会话需要」 | 情景写进知识层 ⇒ 下次被当通用结论 |
| `structural` | 仓库/系统结构、索引这类骨架 | 「是地图，不是故事」 | 与知识层混用 |

### 5.2 六要素（缺一不可）

```
# 功能名：一句话说清这是什么
# 生效条件：什么时候该想起它（可复用的触发，不是任务描述）
# 子功能：分点，每点一条可执行的东西
# 执行：怎么做（命令/步骤/改哪个文件）
# 验证方式：怎么证明它成立（测试名/实测输出/回归套件）
# 不适用条件：什么时候别用它（负边界，最常被漏）
```

**约束性质**：这套格式是**写入约定**；**硬闸在 `cg(op='ccg')` 的编译链**（compile→review→link，编译者不得自证）。`write` 接受带六行的正文，但不会逐项校验。

### 5.3 会话身份

- 写 `contextual` 时带会话归属（`session`），否则跨会话串台；
- 写 `self` / `anchor` 时**不带**会话（人格的可见性不该由会话决定）；
- `sessionPrivate` 叠加要小心：带会话过滤又带私有标记，可能「命中但读不到」。

### 5.4 什么时候不要写

闲聊、情感交互、纯查询（没有结论产出）；**没验证**的东西；中间过程/试错流水；与已有节点重复（先查再写，加 `dedupe=True`）。


### 5.5 四要素：用途 / 分类 / 身份 / 别名（写时就该带上）

层和六要素只回答「这是什么、放哪」，不回答「以后凭什么找得到」。后者靠这四个标签，2026-11-17 起**已进写流程**：

| 要素 | 怎么来 | 落成什么 |
|---|---|---|
| 用途 | 显式 `purpose=做记录`；不给则按 `content_kind` 派生（code→做实现、work_wip→做推进、permission→做治理、其余→做记录） | 标签 `用途:xx`（主标签=第一个） |
| 分类 | `content_kind`（text / code / work_done / work_wip / image_desc / permission…） | 写入闸按它选规则；缺省按 `text` |
| 身份 | 环境 `MDCG_HARNESS` / `MDCG_UNIT`；两者都空时回落安全主体（`principal.role` / `principal.actor`） | 标签 `身份:dsh/agent` 或 `身份:designer/<actor>` |
| 别名 | 显式 `aliases=['别人怎么说这件事']` | frontmatter `aliases`，参与检索召回 |

为什么要它们：记忆检索按词面走，**同一件事有几种说法**（「我们怎么走到今天」/「人物树」/「相识」）。别名把说法记下来，用途和身份决定它属于哪条线、该跟谁比。

```python
cg(op='write',
   content='# 功能名：…（六要素齐）',
   purpose='做记录',
   aliases=['我们怎么走到今天', '人物树'],
   tags=['人物树'])
```


### 5.6 写入闸：什么时候会被拒（0.11.0 起）

写记忆不再总是成功。缺省策略是**按层要复核**：

| 层 | 需要什么 | 缺省行为 |
|---|---|---|
| `contextual` | 无 | 直接落 |
| `knowledge` | reflect 复核 | **拒写**（复核通道未声明时） |
| `structural` | reflect + verify | 拒写 |
| `self` / `anchor` | 再加 human | 拒写 |

**为什么不是自动放行**：知识层的内容会被当作「可复用结论」在以后检索出来。写错一条，污染的是后续所有判断——
宁可拒写，也不静默通过。

三种处置：

1. **部署侧声明复核通道**（推荐）：`MDCG_REVIEW_CHANNELS=hive,subagent`，必要时再加 `MDCG_REVIEWERS=reflect,verify,human`；
2. **临时放宽**：`MDCG_WRITE_GATE=warn`（只记录不拦）——**别在生产长期开着**；
3. **本来就不该写知识层**：落 `contextual`（缺省层），别为一条临时结论去改闸。

排障入口：`cg(op='info')` 的 `write_gate` 段给读数；`data_stale` 告诉你索引落后磁盘多少。

### 5.7 价值观闸（缺省 observe，只看不拦）

写 `structural` / `self` / `anchor` 层时，正文须能**指回一条已声明条款**（条款的 node_id 或其关键词），
否则标记「追责链断裂」；条款可带 `values_forbid` 正则，命中即拒。

- 档位：`MDCG_VALUES_GATE = observe（缺省）/ enforce / off`；
- 每次判定落 `_values.jsonl`，可查；
- **只判归因，不判语义**——它回答「这条写入能指回哪一条承诺」，不回答「内容是否符合某条价值观」。
## 6. 读记忆：route / read / recall

| 面 | 场景 | 说明 |
|---|---|---|
| `cg(op='route', intent=…)` | **动手前** | 查纪律与知识，返回「该照哪条做」；命中即按其动作执行并声明 |
| `cg(op='read', query=…)` | 精确检索 | 带 `state`（ACCEPT/DEFER/…）与适用性判定；大库上秒~十几秒 |
| `cg(op='recall', budget_tokens=…)` | 按预算装包 | 适合喂上下文；预算小只给摘要 |

**耗时预期**（本机 33.8k 节点实测）：`info` 45 ms、`info(full=True)` 7.2 s、`read` 7.4 s、`route` 10.6 s——慢面要预期十秒级。

**严格度**：`strict_conditions=True` 时「生效条件未在情境确认」判 `DEFER`；工具面 `read`/`route` 缺省**放宽**（`usable=true`，但 `state` 不变）——放宽的是可用性，不是判定。

## 7. 能力矩阵（按 op 对照）

> 只列**真存在**的 op；不确定就用 `cg(op='help', query='<op>')`。

| 你要做的事 | op |
|---|---|
| 动手前查纪律/知识 | `route` |
| 写入 / 检索 / 预算召回 | `write` / `read` / `recall` |
| 正式复核（编译链） | `ccg` |
| 裁决与红队 | `review` / `verify` |
| 节点间冲突检测 / 演化账本 | `cg(op='consistency')` / `evolution` |
| 身份与自我状态 | `identity` / `self_state` |
| 目标 / 任务 / 近期事件 | `goal` / `task` / `recent` |
| 时空关系（第二个基元） | `stg(op='relation'|'timeline'|'anchors'|'consistency'|'state_chain')` —— `stg` 的 `op` 就是这五个子操作，与 `cg(op='consistency')` 的冲突检测**不是一回事** |
| 抽检清理 / 写保护 / 遗忘 | `scrub` / `protect` / `forget` |
| 预测 / 因果 / 元认知 | `predict` / `causal` / `metacognition` |
| 维护 / 合并 / 洞察 | `maintain` / `consolidate` / `insight` |
| 导入导出 / 索引 / 状态 | `ingest` / `export` / `index_code` / `index_doc` / `status` / `edges` / `audit` |

## 8. 适用与不适用

**适合**：跨会话的工程结论、踩坑与修法、决策依据、项目约定、需要「三个月后还能查回来」的东西。

**不适合**：闲聊、一次性问答、没有证据的猜测、纯过程流水、涉及敏感凭据的原文（会被自动拦截）。

## 9. 七个坑

1. **写成功但调用超时** ⇒ 服务端可能已落盘；重试务必带 `dedupe=True`。
2. **`cg(op=info)` 少了 `os` 字段** ⇒ 缺省不返回慢面数据，要传 `full=True`。
3. **旧会话里记忆被反复重贴** ⇒ 0.9.23 起注入侧会话内去重（同一条 ≤2 次）；仍复述就查历史快照。
4. **条件写了却永不命中** ⇒ 「生效条件」写成了任务描述（要写**触发条件**）。
5. **查不到刚写的节点** ⇒ 用 `read(node_id=… )` 直取（`query=` 传 id 实测不保证命中）；再看 `state`（可能 DEFER 或被保护）。
6. **scrub 报矛盾** ⇒ 键含括号类标点、值以 `src_/ref_/doc_` 开头时不算可断言键值对。
7. **写进自我/锚点后人格漂移** ⇒ 项目结论放知识层；自我层只放那三样。

## 10. 边界与限制

- **不提供模型**：灵枢只做记忆，推理仍由你的模型完成；
- **默认不用向量**：检索走词法/条件/时间等多路融合，语义路需显式开启；
- **本地数据责任**：记忆是明文文件，备份/迁移/脱敏由你负责；
- **敏感内容**：写入侧会拦截凭据形态，但**不保证**覆盖全部隐私形态，敏感数据别写。

## 11. 思维链退化：怎么认、怎么治

> 这一节写给「模型开始原地打转」的人。它跟记忆系统有关，但根因常常不在记忆里。

### 11.1 先分三种，治法不同

| 形态 | 长什么样 | 判据 | 治法 |
|---|---|---|---|
| **跨轮复述** | 这一轮的回答和上一轮几乎一样 | 相邻两轮 bigram Jaccard > 0.4，或最长公共子串 ≥ 20 字 | 换任务 + 换输出格式 |
| **同轮自我催稿** | 思考里连续短祈使（「做。」「执行。」「给我。」），正文却是空的 | 连续 ≥3 行、每行去标点 ≤6 字 | 换任务（**别接着说「继续」**） |
| **源侧固化** | 每轮处理的是同一件事，产出逐字相同 | 同一对象连续被处理 ≥3 次，且产出 hash 相同 | 改选点策略（不能只比 `last_access`） |

第三种最隐蔽：**它不属于复述，问题在输入没换。** 选点只看「最久没碰」、而处理动作又不回写 `last_access`，就会永久锁死在同一条上。

### 11.2 现场处置：一次踩住过的方法

真实现场（2026-11-20）：某会话卡在「好。／（正文）」循环，还把工具调用的 XML 框架漏成了正文——这时候再催它，只会让那个格式更牢固。

**有效的第一步：不接着说「继续」，开一轮自洽的新任务，并给强格式约束。**

```text
先不用管前面那些。现在只做一件事：用三句话说明 X 是什么，
每句不超过 20 字，不包含任何格式标记。
```

实测：**一步解除。**

关键不在「说得温柔」，在于**换掉了任务与格式**：新任务、新句法、没有任何「继续」的信号，把它从那个错误格式里拽了出来。

### 11.3 不要说的三句

```text
× 你卡住了，请换个思路        ← 只是又添了一句燃料
× 继续，不要重复              ← 否定式指令在生成层是内容，不是约束
× 请停止复读                  ← 同上，而且它并不知道「复读」指什么
```

**「不要 X」这种句式本身就是 X 的燃料**——写进去，这个词就进了上下文，下一段最容易生成的就是它。这也是第 8 条删掉「不需要」类句式的原因。

### 11.4 自查：`degrade_guard`

```python
from md_cg import degrade_guard as dg

dg.check_chain([turn1, turn2, turn3])                 # 查跨轮复述 + 催稿段
dg.check_chain(texts, requirement="reason")            # 另查理由形态（存在率/开头唯一率/复用）
```

返回 `verdict`（`ok` / `degraded` / `insufficient`）与逐项读数。阈值与 #996 原文同源：Jaccard 0.4、LCS 20 字、催稿 3×6。

守卫：`md_cg/test_degrade_guard.py`（10 条断言，含变异锚——把阈值放宽后同一样本必须变绿）。

### 11.5 为什么会退化（机制，不是玄学）

```text
① 零差异输入   → 输出分布不变，采样落回同一组模板
② 意识成燃料   → 写「我又在循环」，这句本身变成新模板
③ 注意力稀释   → 早期的强约束输给最近那段重复
④ 惩罚在字形层 → 换个说法说同一件事，不会被罚
⑤ 动作空间缺「停」 → 它只能继续生成
⑥ 外部反馈被切断 → 工具返回值是唯一能真正打断它的东西
```

**六条里，你能直接改的是 ①③⑤⑥。** ②④要改解码/惩罚策略，不在使用者手里。

### 11.6 一条容易搞反的事

**长会话里，「理由」会退化成套话，但内容不一定退化。**

实测（2 臂 × 2 链 × 6 轮）：句式 12/12 用同一句开头（固化），而内容逐轮加深（140 → 393 字）、相邻轮 Jaccard 0.23（未复用）。

**所以防退化不是「别写理由」，是「给多种形态」：**

```text
给 1 种形态 → 它当成唯一格式，照抄
给 3 种形态 → 它得挑，挑的过程自然变化
给 0 种形态 → 它干脆不写
```

### 11.7 一句话速记

> **换任务、给格式、断否定句、别催它。**
> **要防长期退化，靠的是判据（`degrade_guard`）+ 多种形态，不是靠喊「别重复」。**
