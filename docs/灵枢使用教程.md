## 1. 为什么用它

模型每次会话都是新的：**决定过的口径、踩过的坑、改过的约定，不写下来就等于没发生**。
灵枢做的是把「这次学到的东西」落成**本地文件**，下次会话开头就能取回来。

它不训练模型、不做向量检索的默认路径、不替你下判断——它只保证**写进去的是原文，取出来的是证据**。

## 2. 三条设计原则

| 原则 | 含义 | 你能看到的效果 |
|---|---|---|
| **原文即证据** | 记忆是逐字落盘的 markdown，不经过摘要再压缩 | 查回来能直接引用，不用「回忆」 |
| **本地可读可改** | 一个节点 = 一个文件，任意编辑器可看 | 争议时打开文件就能对 |
| **不写不算数** | 没有 `验证方式` 的条目会被判「未验证」 | 减少「我记得好像…」的假记忆 |

## 3. 记忆长什么样

每个节点是一个 markdown 文件，YAML 头做索引，正文按六要素成文：

```markdown
---
id: mem_1793945439202_174aab
layer: knowledge
created_at: 1793945439.2
session: session-551222f6
tags: [dsh端, release]
---

# 功能名：注入面会话内去重
# 生效条件：长会话里出现「复述旧结论、不再探索」
# 子功能：
#   A. 同会话内同一条最多注入 2 次；
#   B. 全被滤掉时保留第一条，避免整块消失。
# 执行：src/hooks.ts 的 dedupeRepeatedItems()
# 验证方式：test/inject-dedupe-739.test.ts（3 条）
# 不适用条件：临时排查「某条记忆为何不出现」时需关掉去重
```

## 4. 三步开始

```bash
npm install @furongjun1999/dsh-memory@0.9.23     # 1) 装进 DSH profile（或 link 本地仓库）
```

```python
# 2) 自检：确认服务活着、库在哪
cg(op='info')                 # 快照：node_count / flush_state
cg(op='info', full=True)      # 全量诊断（含 os 慢面数据）

# 3) 第一条记忆
cg(op='write',
   content='# 功能名：…\n# 生效条件：…\n# 子功能：…\n# 执行：…\n# 验证方式：…\n# 不适用条件：…',
   content_kind='text', layer='knowledge', tags=['上手'],
   importance=0.6, verification_basis='test', dedupe=True)
```

**读回确认**：写入后按返回的 `id` 再 `cg(op='read', query=<标题>)` 一次——**看不到就等于没写成**。

## 5. 写记忆：层与六要素

### 5.1 选层（最容易错的一步）

| 层 | 放什么 | 判据 | 错法 |
|---|---|---|---|
| `self` | 身份 / 价值观 / 认知图接口，**只有这三样，很薄**，会话启动自动加载 | 「变了我就不是我了」 | 把项目结论塞进来 ⇒ 人格被细节污染 |
| `anchor` | **协议级**跨实例锚定（不可遗忘的那几条） | 「任何实例上都必须成立」 | 当日常写入面用；新手基本不用碰 |
| `knowledge` | 可复用的结论、规范、踩坑与修法 | 「三个月后换个人也该知道」 | 一次性会话细节写进来 ⇒ 检索噪声 |
| `contextual` | **本次会话**的过程、当时的判断、临时状态 | 「只有这场会话需要」 | 情景写进知识层 ⇒ 下次被当通用结论 |
| `structural` | 仓库/系统结构、索引这类骨架 | 「是地图，不是故事」 | 与知识层混用 |

### 5.2 六要素（缺一不可）

```
# 功能名：一句话说清这是什么
# 生效条件：什么时候该想起它（可复用的触发，不是任务描述）
# 子功能：分点，每点一条可执行的东西
# 执行：怎么做（命令/步骤/改哪个文件）
# 验证方式：怎么证明它成立（测试名/实测输出/回归套件）
# 不适用条件：什么时候别用它（负边界，最常被漏）
```

**约束性质**：这套格式是**写入约定**；**硬闸在 `cg(op='ccg')` 的编译链**（compile→review→link，编译者不得自证）。`write` 接受带六行的正文，但不会逐项校验。

### 5.3 会话身份

- 写 `contextual` 时带会话归属（`session`），否则跨会话串台；
- 写 `self` / `anchor` 时**不带**会话（人格的可见性不该由会话决定）；
- `sessionPrivate` 叠加要小心：带会话过滤又带私有标记，可能「命中但读不到」。

### 5.4 什么时候不要写

闲聊、情感交互、纯查询（没有结论产出）；**没验证**的东西；中间过程/试错流水；与已有节点重复（先查再写，加 `dedupe=True`）。

## 6. 读记忆：route / read / recall

| 面 | 场景 | 说明 |
|---|---|---|
| `cg(op='route', intent=…)` | **动手前** | 查纪律与知识，返回「该照哪条做」；命中即按其动作执行并声明 |
| `cg(op='read', query=…)` | 精确检索 | 带 `state`（ACCEPT/DEFER/…）与适用性判定；大库上秒~十几秒 |
| `cg(op='recall', budget_tokens=…)` | 按预算装包 | 适合喂上下文；预算小只给摘要 |

**严格度**：`strict_conditions=True` 时「生效条件未在情境确认」判 `DEFER`；工具面 `read`/`route` 缺省**放宽**（`usable=true`，但 `state` 不变）——放宽的是可用性，不是判定。

## 7. 能力矩阵（按 op 对照）

> 只列**真存在**的 op；不确定就用 `cg(op='help', query='<op>')`。

| 你要做的事 | op |
|---|---|
| 动手前查纪律/知识 | `route` |
| 写入 / 检索 / 预算召回 | `write` / `read` / `recall` |
| 正式复核（编译链） | `ccg` |
| 裁决与红队 | `review` / `verify` |
| 矛盾检测 / 演化账本 | `consistency` / `evolution` |
| 身份与自我状态 | `identity` / `self_state` |
| 目标 / 任务 / 近期事件 | `goal` / `task` / `recent` |
| 时空关系 | `stg(op=relation|timeline|anchors|consistency|state_chain)` |
| 抽检清理 / 写保护 / 遗忘 | `scrub` / `protect` / `forget` |
| 预测 / 因果 / 元认知 | `predict` / `causal` / `metacognition` |
| 维护 / 合并 / 洞察 | `maintain` / `consolidate` / `insight` |
| 导入导出 / 索引 / 状态 | `ingest` / `export` / `index_code` / `index_doc` / `status` / `edges` / `audit` |

## 8. 适用与不适用

**适合**：跨会话的工程结论、踩坑与修法、决策依据、项目约定、需要「三个月后还能查回来」的东西。

**不适合**：闲聊、一次性问答、没有证据的猜测、纯过程流水、涉及敏感凭据的原文（会被自动拦截）。

## 9. 七个坑

1. **写成功但调用超时** ⇒ 服务端可能已落盘；重试务必带 `dedupe=True`。
2. **`cg(op=info)` 少了 `os` 字段** ⇒ 缺省不返回慢面数据，要传 `full=True`。
3. **旧会话里记忆被反复重贴** ⇒ 0.9.23 起注入侧会话内去重（同一条 ≤2 次）；仍复述就查历史快照。
4. **条件写了却永不命中** ⇒ 「生效条件」写成了任务描述（要写**触发条件**）。
5. **查不到刚写的节点** ⇒ 先按 id `read`；再看 `state`（可能 DEFER 或被保护）。
6. **scrub 报矛盾** ⇒ 键含括号类标点、值以 `src_/ref_/doc_` 开头时不算可断言键值对。
7. **写进自我/锚点后人格漂移** ⇒ 项目结论放知识层；自我层只放那三样。

## 10. 边界与限制

- **不提供模型**：灵枢只做记忆，推理仍由你的模型完成；
- **默认不用向量**：检索走词法/条件/时间等多路融合，语义路需显式开启；
- **本地数据责任**：记忆是明文文件，备份/迁移/脱敏由你负责；
- **敏感内容**：写入侧会拦截凭据形态，但**不保证**覆盖全部隐私形态，敏感数据别写。
