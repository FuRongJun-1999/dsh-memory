## 六、副作用与归因（显式登记，不静默）

### 6.1 召回面扩大（本轮最大代价，已知且有量化）

| 口径 | 候选池 | LIKE 命中 P50 | P90 | **P95** | P99 | max | 均值 | 被 `GLOBAL_CAP=500` 截断 |
|---|---|---|---|---|---|---|---|---|
| 全量（含索引节点） | 6336 | 15 | 2348 | **2580** | 3437 | 5708 | 658.5 | **300/870（34.5%）** |
| 剔除 `code_`/`doc_` | 4523 | 13 | 1343 | **1380** | 1759 | 3895 | 347.5 | **247/870（28.4%）** |

**归因**：G2 的边际贡献 = P95 `1380 → 2580`（×1.87）、max `3895 → 5708`、截断率 `+6.1pp`（+53 条/870）。
**但截断的主体（28.4%）在 G2 之前就已存在**——这不是本轮引入的问题，本轮只是把它放大了约 1/5。
→ 处置建议（不在本轮）：索引节点应在**召回路由阶段**被降权或分池（`domain:` 标签已就位，可直接做域级路由），
而不是继续吃 `GLOBAL_CAP`。这是 G4/G5 的输入。

### 6.2 密级：**无降级**（观测工具失配，非事实变更）

盘上 `frontmatter`（真相源）复算：

| 口径 | private | internal | 说明 |
|---|---|---|---|
| 索引前 | 4525 | 1 | — |
| 索引后（盘上） | **4525** | **1814** | 旧节点 private 计数**完全不变**；新增 1813 全部 internal |
| `_index.json` | 4525 | 1814 | 与盘上逐字一致 |
| 层分布 | knowledge: private 4516 / internal 1814 ｜ self: private 5 ｜ anchor: private 4 | | 新节点全部落 knowledge |

**归因**：曾有 `op=info` 报 `sensitivity_counts={"internal": 6339}`，即「private 全变 internal」。经复算判定为
**常驻服务内存视图陈旧**（进程启动早于改造，`self.index` 为旧快照），**不是**密级降级：① 盘上 private 计数与索引前完全相同；
② `_index.json` 同口径复算一致；③ `mdcos._sensitivity_counts` 读取的正是 `index["nodes"][*]["sensitivity"]`，字段未丢。
→ 待定项：重启 MCP 服务以统一视图（§八）。
附：`body` 加密分布 `plain 6249 / enc 90`，未受本轮影响。

### 6.3 `node_id` 跨类同名归并（既有设计缺陷，本轮首次暴露）

`codeindex.node_id(item) = sha1(path + "::" + name)` —— 键**不含父类名**，故同一文件内跨类同名方法被归并为同一 id。
实测：登记 1847 → 唯一 1813，**冗余 34 条 / 27 个 id**（占 1.8%），分布：

| 源文件 | 冗余 | 已核实的同名 def |
|---|---|---|
| `md_cg/mdcos.py` | 12 | `__init__` `add` `_audit` `_candidates` `_neg_coverage` `search_rrf` … |
| `md_cg/signer.py` | 4 | `sign`×3 `verify`×3 `describe`×3 `public`×2 |
| `md_cg/sources.py` | 3 | `events`×3 `key`×3 `__init__`×4 |
| `md_cg/sustain.py` / `whitebox.py` | 2 / 2 | `summary`、`ask`、`remember` … |
| `md_cg/fsutil.py` / `security.py` / `test_p18_whitebox.py` / `src/index.ts` | 各 1 | `__init__` 等 |

**影响有界**：后写入者胜（同 id 原子覆盖），`_refindex.json` 保留全部区间；`ref check` 全部 `ok`。
**不本轮修**：改 id 键会破坏既有 id 稳定性与幂等，需单独立项（加 `parent` 入键 + 存量迁移，或同文件同名加序号后缀）。

## 九、诚实边界

1. **「触发词命中 P95 基线 89」无法同口径复现**：benchmark 自带的 `--ablate pool` 口径跑在**合成库**（1000 节点）上，
   实测中位 8 / max 366 / 截断 0/870，与真实库不同源。本轮真实库同口径（bench 同款查询集生成：`n=250, seed=7`，
   池 = `cg._candidates()` 读出集）复算得 P95=2580（全量）/1380（剔除索引节点）。
   → 结论：§6.1 的**相对归因**（1380→2580、+6.1pp）可信；**绝对值与「89」不可直接比较**，因为基线口径未固化。
2. **索引是「可索引」，不是「可理解」**：`code_`/`doc_` 是确定性静态索引，不含语义蕴含；跨表述的
   「这段代码实现了那段文档的意思」不解决（与「有意剔除神经嵌入」的既有裁定一致）。
3. **索引质量上限 = 源文件注释质量**：无 docstring/首段的符号只能索引到签名或标题。`docs/` 侧 `docs/` 下非 md
   文件（`.html`/`.png`/`.yml` 等 5 类）**显式列出**而非静默丢弃，但它们确实未被索引。
4. **cap 标签是「词面证据的保守子集」，不是能力证明**：阈值上调只把「明显不合格」挡在门外；0.8 档仍可能有个别误标
   （规则表含宽泛词），故 `cap_rollback` 是必备出口。它**不构成**「该节点具备该 op 能力」的充分证据。
5. **§6.3 的 27 个 id 归并意味着**：对同名方法，认知图里只能查到**一个**（后写者），另一处的正文虽在 `_refindex.json`
   有区间记录，但不在图里可检索。这是**已知覆盖缺口**，不是本轮回归。
6. **本轮无「dangling/unresolved=0」之外的漂移证据**：`ref check` 在索引完成的同一时刻测得，源文件此后若被改动，
   需重跑才能判 `stale`。巡检只承诺「可检出」，不承诺「自动跟随」。
