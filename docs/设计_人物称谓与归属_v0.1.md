## 1. 核心模型：人物 = 实体 + 一组称谓

一个人物节点 `profile-person-<主名>` 携带：

```yaml
person:
  canonical: 沈知夏            # 主名（最早出现的完整姓名）
  aliases:
    - {s: 知夏,   t: nickname,  first: 2026-05-03, ev: node_x1}
    - {s: 夏夏,   t: nickname,  first: 2026-06-11, ev: node_x9}
    - {s: 我,     t: self,      first: 2026-04-26, ev: node_n1}   # 自称（仅对 speaker）
    - {s: 沈编辑, t: title,     first: 2026-07-02, ev: node_y3}   # 职位称谓
    - {s: 妈,     t: kin,       first: 2026-05-20, ev: node_z2}   # 亲属称谓（需绑定）
  relation: {to: 角色, type: 本人}      # 与角色的关系
  attrs:    {年龄: [ {v: 24, t: 2026-04-26} ]}
```

**关键：检索与注入只认「称谓集合」，不认单一名字。** 任何 alias 命中 query ⇒ 注入同一张卡。

## 2. 称谓类型（枚举，决定绑定规则）

| type | 例 | 绑定判据（确定性，宁缺不错） |
|---|---|---|
| `full_name` | 沈知夏 | 自我介绍（我叫X / 叫我X / 名字叫X）⇒ 定为 canonical |
| `self` | 我 / 咱 / 本人 | **语言上即 speaker**：query 含自指 ⇒ 注入该 speaker 的角色卡（无需字面命中）|
| `nickname` | 知夏 / 夏夏 | 需显式信号（外号/昵称/大家都叫他X）或**人工别名表**；**不猜** |
| `title` | 陈编辑 / 苏编 / 满师傅 | 职位后缀（编辑/编/师傅/总/老师…）⇒ 该 surface 是某人的 title 称谓；与全名共现时绑定 |
| `kin` | 妈 / 爸 / 哥 / 姐 | 亲属词 + 同句/邻句出现姓名 或 「X 是我妈」⇒ 绑定；无证据则**单列待确认** |
| `honorific` | 老贺 / 小吴 | 前缀（老/小/阿）+ 姓氏；**只有在库内已存在该姓的人时才绑定**，否则单独成卡 |

## 3. 归属绑定：三档证据（越往下越不猜）

```
A 结构证据（最强）：diary.speaker / diary.participants / role 字段
B 显式语义：自我介绍、外号声明、"X 是我妈"、"和 X 说好"
C 共现推断：同一节点/邻接节点里「称谓 + 姓名」同时出现（只记 alias，不合并卡）
D 无证据：单独成卡，标 needs_review —— 不合并、不猜
```

**D 档必须存在**：宁可多一张"待确认"卡，也不要把两个人合成一个。

## 4. 注入判据（修 ② 的落点）

```python
def match(query):
    hits = set()
    for card in profile_cards:
        # ① 任一别名出现在 query 里
        for a in card.aliases: 
            if a.surface in query: hits.add(card)
        # ② query 是自指 ⇒ 命中 speaker 的角色卡
        if card.relation.type == "本人" and any(w in query for w in ("我", "咱", "本人")):
            hits.add(card)
        # ③ 亲属/职位提问（"我妈""我编辑"）⇒ 命中相应关系卡
        for rel in card.relations:
            if rel.vocative in query: hits.add(card.target)
    return hits
```

## 5. 与既有实现的关系（增量，不推倒）

| 已有 | 保留 | 新增 |
|---|---|---|
| `profile-role-*`（角色卡） | ✔ | 加 `aliases`（自称 + 一切指向该角色的称谓）|
| `profile-person-*`（第三人） | ✔ | 加 `aliases` 与 `needs_review` 标记 |
| 人名三闸 | ✔ | 闸只管"是不是人名"，**不管是不是同一人** |
| 注入（标签直取） | ✔ | 判据从"实体名 in query"扩到"**任一别名 in query**"+"自指规则" |

## 6. 落地顺序

1. **卡上加 `aliases`**（先只记，不做合并）+ 注入按别名匹配（**本批可做**）；
2. 自指规则（已在 #881 后的补丁里）+ 亲属/职位提问规则；
3. 外号/昵称的显式信号抽取（"外号叫X"）+ 人工别名表入口（`_aliases.json`）；
4. kin 绑定（"X 是我妈"）——**最后做**，因为最容易错。

## 7. 边界（不声称）

- 同名不同人（两个"老贺"）不消解；
- 跨会话的角色名变化（换角色扮演）不处理；
- kin 的传递推理（我妈的妹妹）不做；
- 别名自动发现（从上下文猜昵称）**明确不做**——只接受显式信号或人工表。
