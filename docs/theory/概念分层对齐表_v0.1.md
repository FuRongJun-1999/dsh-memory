# 概念分层对齐表 v0.1

> **定位**：外部评审（GPT）指出系统置信类概念在增殖——condition / evidence / trust / confidence / qualification / prediction confidence / source trust / execution confidence / consensus confidence——若不加约束会退化为 heuristic framework。本文档将既有置信面**严格对齐到五层**：Source Trust（来源信任）→ Evidence Quality（证据质量）→ Claim Confidence（断言置信）→ Execution Confidence（执行置信）→ Consensus Confidence（共识置信），盘点每层的代码落点、量纲与重叠冲突，作为后续概念收敛的共同参照。
>
> **边界（先读）**：本表是**文档层对齐**，不裁决任何工程面合并——凡涉及行为变更（改默认值、改排序、改判定序）一律另案，经验证单元与使用者终裁后才可落地。行号对齐 2026-09-15 工作区 HEAD；行号必腐化，以符号名为准绳。
>
> **理论锚点**：CTP 仓（仓外私有理论仓 `CommonTrustProtocol`）`智能论3.4.md`（下称「理论」）。

## 1 五层定义与判定标准

| 层 | 名称 | 一句话定义 | 判定问句 | CTP 理论锚点 |
|---|---|---|---|---|
| L1 | Source Trust 来源信任 | **谁**——来源（实例/写入者/通道）本身的历史行为可信度 | 这个来源过去的行为记录如何？ | 信任值=信噪比映射（理论 L4376）；T_total 第一性分量 P_trust（理论 L1678-1694）；compiler「德」寄存器=trust_value 名实一处 |
| L2 | Evidence Quality 证据质量 | **凭什么**——支撑断言的外部验证基底有多硬 | 断言背后是什么类型的验证？ | 理论无独立证据层；「验证单元独立复核」（理论 L4654）为最近对应；工程侧 verification_basis 两档口径为自建分级 |
| L3 | Claim Confidence 断言置信 | **这条断言**本身多可信、当前是否适用 | 这条记忆该不该用/有多可靠？ | 「概率负责可信度，条件负责资格」二分（理论 L1170）——资格（条件）与置信（概率）分离的理论根据 |
| L4 | Execution Confidence 执行置信 | **做事的预测**——某通道/路线继续做某事会成功的概率 | 这么做能成吗？ | 通道可信度 2.9.1a：「置信度=单次判断内部一致性；可信度=通道历史验证命中率」（理论 L1743-1746）；T_pred 为辅助分量（理论 L1520-1525） |
| L5 | Consensus Confidence 共识置信 | **多方是否一致**——多个独立来源对同一对象的一致程度 | 大家都同意吗？ | P_gap 宏观信息差（理论 L1737-1741）；蜂群阶段4触发 T_avg≥0.75 持续30天（理论 L2834） |

**归层判定问句**（给后续新增指标用）：先问「这个数回答的是谁/凭什么/该不该/能不能成/同不同意」中的哪一个，再入层；一个数同时回答多个问句的，标记为跨层混合点并在 §4 注记。

## 3 分层正确先例（代码内自声明，收敛的现成锚点）

概念收敛**不需要发明新原则**——四个关键分离代码里已有自声明，缺的只是给它们统一命名与显式分层：

| 先例 | 代码位置 | 自声明内容 | 对应分层 |
|---|---|---|---|
| 性能/资格正交 | `md_cg/mdcg.py:1254` | tier=怎么找到的（性能）/state=是否该用（资格），二者正交 | L3 资格 ≠ L4 检索性能 |
| 置信度≠可信度 | `md_cg/predict.py:322-326` | 置信度=单次判断内部一致性；可信度=通道历史验证命中率（P-T-73/74） | L3 断言置信 ≠ L4 通道执行置信 |
| 来源≠内容 | `md_cg/evidence.py:20-21` | 验证「证据来自该节点」≠「证据为真」 | L1 来源信任 ≠ L2/L3 证据与断言 |
| 定价≠资格 | `md_cg/autonomy.py:17-18` | score 只做排序不做资格 | 信号定价（非五层）≠ L3 资格 |

| L1 Source Trust | 半空缺 | 蜂群域有实现（trust/德/验签）；**记忆域只有身份无信任**——writer/session 已落盘（2026-09-13 归属落地）但 writer 不带信任分、不进检索排序 | 若补：writer 信任属 L1，排序消费属 L3/L4，跨层链路须显式设计 |
| L2 Evidence Quality | 半空缺 | verification_basis 是名义枚举，**无连续证据强度量纲**；REPRODUCIBLE_BASIS 五档是唯一分级；`bench_progressive.py:220` 已自我承认（「证据强度分离，另案」） | 分级（枚举）与强度（数值）是两种量纲，收敛时不可混称 |
| L3 Claim Confidence | 不空缺 | fm.confidence + 四态 qual + 降级链，链路完整 | 当前最厚实层之一 |
| L4 Execution Confidence | 不空缺 | predict.py 全套 + judge_ranking 换算通道 | 当前系统重心；理论对齐最好（P-T-73/74） |

## 6 术语漂移实录（GPT 所指增殖的词面证据）

| 词 | 现状 | 各处含义 |
|---|---|---|
| 信任 / trust / 德 | 三名一物 | CTP「信任值」=信噪比协作度量（理论 L4376）= swarm trust（L1）= compiler「德」寄存器——本层内部一致，但外部读者易读成「总体置信」 |
| confidence | 一词三用 | fm.confidence（L3 断言静态声明）、edge confidence（L4 结构置信）、SEMANTIC_CONF=0.4（语义诱导候选固定置信） |
| 可信度 | 最干净 | beta docstring 专指「通道历史验证命中率」（`predict.py:322-326`），与 CTP 2.9.1a 一致——建议保留为 L4 专名 |
| score | 一词四用 | autonomy proposals（信号定价）、检索相似度分、score_route composite、health score——四处同名异义 |
| qual / 资格 | 最干净 | judge 四态，名义非数值，自声明与 tier 正交——建议保留为 L3 专名 |

**收敛建议方向**（文档层）：每层一个专名——L1=信任（trust）、L2=证据（basis/strength）、L3=置信（confidence，断言面）+资格（qualification，query 面）、L4=可信度（reliability，通道面）、L5=共识（consensus）；其余同义词（德→trust 保留别名注记、score 按 §4-6/4-7 改名）逐步归位。
