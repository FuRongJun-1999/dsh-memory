## 〇 总览：从"给定前提"到"推导结论"

**出发点**：v0.1 把"任何组件都不可靠"作为公理接受；v0.2 修正为定理；v0.3 补全推导桥接与威胁模型。

**推导链**：

```
前提1（智能论 0.0.1 信息条件性）：
    每个信息差都依赖于条件空间，不存在绝对信息差。
前提2（智能论 0.0.3 局部不可知）：
    任何有限观测者在有限条件下都无法获取全局完备信息。
前提3（智能论 2.7 信息差增定律）：
    在没有持续干预时，信息差自然趋于扩大。

桥接命题（B 桥）：
    组件行为是其不完备信息的函数；其声明/预期即其自模型。
    条件空间不完备 ⟹ 存在模型外演化使实际行为偏离自模型。

推导：
    任何组件 c 都是有限观测者（有限资源、有限信息、有限处理能力）。
    因此 c 对自身状态和外部状态都存在不可消除的信息差。
    因此 c 在任意时刻可能以未被自身观测到的方式偏离其声明或预期。
    这种偏离即失效——包括最难防御的静默错误。

定理 T0（失效定理）：
    ∀ 组件 c、∀ 时刻 t：c 在 t 可能以其声明行为空间内的任意模式失效。
    （可能性版：仅用前提1+2）

强化版（引入前提3）：
    若不干预，偏离概率上界随时间单调升。
```

由此，整个框架的承诺发生一次根本转向：

| 传统可靠性观 | 本框架的可靠性观 |
|---|---|
| 可靠 = 组件不出错 | 组件必然出错（T0） |
| 目标：防止失效 | 目标：失效**可发现、可隔离、可恢复、可追溯**（四可，见 D4） |
| 失效是异常路径 | 失效是一等公民状态，失败路径先于成功路径设计 |
| 信任由权限授予 | 信任由验证链长度 × 独立性度量（D3） |

**一句话总纲**：

> **系统不承诺"组件正常"，只承诺"任何未经充分验证的结论，都不会被当成事实"。可靠性不是组件的属性，而是证据链的属性。**

**与智能论的关系**：本框架是智能论在系统层的投影，不是独立公理体系。T0 的效力等同于智能论推论三（局部不可知）在系统层的直接应用。因此本框架的合法性不来自"接受一个悲观前提"，而来自"智能论已被接受"。

## 一、定理层（T0–T2：由智能论直接推导）

### 【定理 T0】失效定理

> **∀ 组件 c、∀ 时刻 t：c 在 t 可能以其声明行为空间内的任意模式失效。**

**推导链**（见总览）。**威胁模型限定**：本定理覆盖自然失效与对手失效，但二者防御经济学不同（见 D2 威胁模型小节）。

失效分三类，危险性递增：

| 类别 | 形态 | 可观测性 | 防御手段 |
|---|---|---|---|
| ① 崩溃 | 不响应、进程消亡 | **可观测** | 重试 / 同轮重建 / 心跳超时 |
| ② 显式错误 | 报错但内容错 | 可观测（错误信号在） | 校验返回值 / 拒收 |
| ③ **静默错误** | 正常响应，内容错 | **不可观测** | **独立验证路径（T5）——唯一防御** |

> 第三类是本框架与常规容错设计的分水岭：常规容错面向崩溃，本框架**由静默错误主导设计**（T4）。

### 【定理 T1】观测者同罪

> **检测组件 c 失效的组件 d，自身满足 T0。不存在特权观测者。**

*证明*：d 也是有限观测者，也受信息条件性和局部不可知约束，故 d 也可能失效。∎

**修正说明**（v0.3）：删除 v0.2 中"若 d 被假设为'可信'，则 d 不满足 T0"句。d 被采信的资格由验证链度量（D3），而 d 自身的失效可能性不因被采信而消失——这正是 T10 对验证器同样适用的原因。

### 【定理 T2】消息不可信

> **任意两条消息之间可发生：丢失、重复、乱序、任意延迟、内容篡改。存储介质与信道皆然。**

*证明*：消息由组件产生、经信道传输、由组件接收。产生者、信道、接收者三者均满足 T0。因此消息的完整性不可假设。∎

**修正说明**（v0.3）：本定理的严格成立需要一条组合公理——**各组件失效模式可独立发生，不排除最坏组合**。这是保守化设计选择，不是逻辑推论。工程上取最坏组合作为设计上界。

## 二、公理层（A1–A4：本框架内的设计前提）

> 以下条目是**设计选择**，不是逻辑必然。它们可被替代，但替代方案必须显式声明其代价。

### 【公理 A1】真源唯一（工程取舍）

> **唯一可信终点是 append-only 落盘原文（事件日志 + md 认知图原文）。内存态、进程态、索引态、网络态均为易失派生物，其可信度恒 ≤ 真源。**

**修正说明**（v0.3）：真源**不豁免于 T0**。它不享有"可信"的特权，只享有**验证预算最集中的终点**这一工程地位。真源同样可能发生静默错误（磁盘位翻转、固件bug），且因其"最可信"，静默错误的穿透力最强——这正是 T4 的直接推论。真源验证由 T13（真源验证定理）独立保证。

**为什么是设计选择**：也可以设计"多真源"（如拜占庭共识），代价是通信复杂度和写入延迟增加。本框架选择"单真源 + 多验证"替代"多真源 + 共识"。

### 【公理 A2】时间不可信

> **墙钟可漂移、回拨、跳变。系统内事件次序只承认逻辑时序（先后关系 / 水位），墙钟仅作展示与粗排序。**

**修正说明**（v0.3）：删除"相对论双重否证"表述。相对论揭示的是时钟的**条件依赖性**（与 0.0.1 同源），工程实践（NTP 漂移、闰秒、回拨）揭示的是**不可靠性**。二者合起来支持本公理，但不构成"否证"。

### 【公理 A3】验证有成本

> **验证本身消耗资源，且验证器自身满足 T0。因此验证强度必须分级，按风险分配——100% 全量验证在理论与经济上均不可得。**

**工程含义**：本框架的承诺因 A3 而必然是**概率承诺而非绝对承诺**（见边界说明）。

### 【公理 A4】诚实公理

> **组件对自身状态的不确定必须可声明（BLINDSPOT）；声明不确定，永远优于编造确定。**

*与智能论的对应*：四态路由中的 BLINDSPOT 在此升格为公理——它不只是检索策略，而是系统在自身不可靠这一事实面前的**唯一诚实姿态**。fail-closed（T8）是 A4 在工程侧的镜像。

## 三、定义层（D1–D6）

| 编号 | 定义 |
|---|---|
| **D1 组件** | 任何可产生输出或改变状态的单元：进程、函数、存储页、网络跳、LLM 调用、人。 |
| **D2 失效谱与分级假设** | 失效谱从 fail-stop（只崩溃不撒谎）到拜占庭（含静默错误）。**分级采用**：存储层按 fail-stop 设计，但校验和检测到内容错即升级按拜占庭处置（隔离）；计算层——尤其 LLM 输出——**一律按拜占庭设计**（内容不可信，须验证）。**威胁模型**：自然失效（介质老化、时钟漂移、宇宙射线）服从 hazard 分布；对手失效（定向篡改、自适应攻击）会学习未验证窗口。二者防御经济学不同，T10 的成立依赖此区分。 |
| **D3 信任度量** | 信任 = 验证链长度 × 各环节独立性。验证链闭环（自己验自己）= 零信任，无论链多长。 |
| **D4 四可** | 可发现（detectable）、可隔离（isolatable）、可恢复（recoverable）、可追溯（traceable）。**本框架对系统的全部承诺即四可，不承诺"不失效"。** |
| **D5 合法态与自稳定** | 状态空间中满足全部判据的子集称合法态；系统在任意瞬态扰动后可仅凭真源与协议在有限步内回到合法态，称自稳定。 |
| **D6 幂等** | 操作 op 应用一次与应用 N 次效果相同。实现基准：以内容哈希为幂等键。 |

## 四、定理层（T3–T14：由 T0–T2 + 公理层导出）

### 【定理 T3】无特权裁决定理

> **不存在组件 c\*，其裁决可免于独立验证而被采信。**

*证明*（v0.3 修正，直接由 T5 导出）：若 c\* 可免于独立验证被采信，则对 c\* 的采信不存在不经过 c\* 的验证路径，与 T5 矛盾。∎

*工程推论*：任何裁决（包括四层证据防火墙的终排、双实例互验的判定）必须可被**不经过裁决者自身**的证据链复核。

### 【定理 T4】静默错误支配定理

> **系统的安全设计必须由静默错误主导，崩溃恢复是必要非充分。**

*证明*：由 T0 三分类，崩溃与显式错误均可观测，重试/重建可处置；唯静默错误不可观测，其唯一防御是独立验证路径（T5）。面向①②的设计对③无证明力。∎

*工程推论*：评审优先级反转——**失败路径与静默错误路径的测试，证明力高于成功路径**。

### 【定理 T5】独立验证定理

> **不经过被验组件自身的独立验证路径，是采信为事实的必要条件；采信强度是路径独立性、链长与复验频率的函数（D3/T10）。**

*证明*：若一切验证路径都经过该组件，则该组件静默错误时验证结果与其一致（T1：验证器与被验者同一失效域），验证无判别力；反之，独立路径提供判别力。∎

**修正说明**（v0.3）：v0.2 用"当且仅当"，超出证明力。独立验证路径是**必要条件**，非充分条件——路径自身也可能静默失效。同时声明：本定理实际针对的是**自洽静默错误**（被验者错误时其关联自检同样错误且一致）；不自洽失效即使在闭环链内也可检测。

*工程推论*：验证链**不得闭环**；验证器与被验者必须故障不相关（不同实例、不同代码路径、不同数据副本）。

### 【定理 T6】真源恢复定理

> **真源 + 确定性重建协议 + 端到端判据 ⇒ 可自恢复（充分条件）。本框架选择唯一真源以换取写入路径的简洁，代价见 A1。**

*证明*：真源在，派生物按 A1 可弃可重建；重建过程须由 T12 端到端判据兜底 + 失败重放，才能闭环。∎

**修正说明**（v0.3）：v0.2 用"充要条件"，双向过强。⟸ 方向忽略重建者本身也是组件（T1）；⟹ 方向反例——多等价载体互为真源也可自恢复。唯一真源是工程取舍，不是逻辑必然。

### 【定理 T7】幂等必要性定理

> **在 T2 下，若合法态判据要求幂等等价（D5），则非幂等写操作必然（在消息重复场景中）导致状态损坏。**

*证明*：T2 允许重复投递；非幂等 op 对重复消息应用 N>1 次的效果 ≠ 应用 1 次，状态偏离合法态。∎

**修正说明**（v0.3）：显式引用 D5，删除"偷运"的断言。

### 【定理 T8】fail-closed 定理

> **验证不可用时，输出必须落向"声明不可用"，而非"跳过验证继续"。**

*证明*：跳过验证继续输出 = 以静默错误为代价换取可用性，违反 T4。∎

### 【定理 T9】自稳定定理

> **对真源可恢复的故障类（真源未损，或真源可由外部锚重建），满足 A1 + T6 + 幂等（D6）+ 水位对账的系统，在任意瞬态故障后可有限步回到结构合法态（D5）。内容合法性由 T12 独立裁决。**

*证明*：真源未损 → 重放重建派生态（T6）；重复消息被幂等键吸收（T7）；乱序/延迟由逻辑时序与水位对账收敛（A2/T2）；重建目标即结构合法态。∎

**修正说明**（v0.3）：①陈述加入"真源可恢复故障类"前提；②明确"结构合法 ≠ 内容正确"——若真源写入时已携带静默错误，重建会忠实重建错误，内容正确性须由 T12 独立保证。

### 【定理 T10】信任衰减定理

> **在定向对手模型下（对手会学习未验证窗口），数据可信度是"距最近一次独立验证的时间"的单调不增函数。在纯自然失效模型下，需假设累积损伤机制（老化、磨损、位翻转累积），结论同样成立。**

*证明*：数据所处环境持续满足 T0/T2；未复验区间越长，"当前仍正确"的概率越低。∎

**修正说明**（v0.3）：v0.2 缺 hazard 假设。补入定向对手模型为主、累积损伤模型为辅。

### 【定理 T11】多样性定理

> **N 个相同实现的副本，对系统性（共模）错误的防护为零。**

*证明*：相同实现对相同输入产生相同错误（含静默错误）；N 个一致的错误结果在互验中相互印证，伪装为正确。∎

*工程推论*：双实例互验必须审计**实现多样性**（不同代码路径 / 不同算法 / 不同实例身份）。

### 【定理 T12】端到端定理

> **错误检查必须在端到端层面（真源 ↔ 最终输出）成立；低层校验只能降低成本，不能替代端到端判据。**

*证明*：低层校验只覆盖各自层内失效模式；跨层组合失效只有端到端判据能捕获。∎

*工程推论*：最终判据永远落在**原文子串 / committed / HMAC**上，不落在"组件说成功"上。

### 【定理 T13】真源验证定理（v0.3 新增）

> **真源内容的可信度同样遵循 T10；外部锚（离线审计副本、跨机快照、人）的复验间隔即真源的信任半衰期。真源不豁免于 T0。**

*证明*：真源是组件（D1），满足 T0。若真源无独立验证路径，则其静默错误穿透力最强（T4），违反 T5。因此真源必须由外部锚构成独立验证路径。∎

*工程推论*：外部锚调度从运维备注升格为框架构件；矩阵中"真源验证"空格由此补全。

### 【定理 T14】LLM 派生物重建条件（v0.3 新增）

> **含 LLM 的派生物须钉死模型版本 + prompt 版本 + temperature 0，或将其排除在"可重建派生态"之外、升格为二级真源（带独立验证）。**

*证明*：temperature>0 或模型/prompt 版本变化会破坏"确定性重建"（T6 的 ⟸ 与 T9 的重放对该类派生物失效）。∎

*工程推论*：重建管线本身是 LLM 时，多样性审计（T11）要覆盖它。

2. **WAL-HMAC**：Python 侧逐条验签 `swarm/rust_swarm.py`（verify_wal_signatures，hmac.compare_digest 交叉复核）+ Rust 侧纯 std 实现 `swarm/rust_runtime/src/hmac.rs`；第三方复现报告（LoCoMo 独立复现、灵枢 vs dejavu 统一评分 v7）覆盖的是检索质量评测，未触及本机制——实验判定据此降级。
3. **T13 外部锚 🟡 的"部分"依据**：审计分片轮转（`md_cg/mdcos.py` audit_archive）与 git 远端留痕（互验产物入库同步）；跨机快照与外部锚复验调度无实现。

## 七、边界说明（诚实口径）

1. **概率承诺**：由 A3，四可是概率承诺，不是绝对承诺。框架不解决"全部验证器同时被攻破"——那需要外部锚：离线审计副本、跨机快照、或人。外部锚的调度属运维协议，不在本框架内。
2. **共模残余风险**：T11 的上界——两个独立实现仍可能共享同一个上游错误。理论残余风险不可消，只能靠多样化维度（代码、算法、人）压缩。
3. **拜占庭共识的取舍**：swarm 为半封闭小规模节点集 + 真源单写点，引入 PBFT 类全时拜占庭共识的成本高于收益。本框架用"真源单写点 + 独立验证链 + 互验"替代；若未来开放多方写入，再议 quorum 方案。
4. **T0 的证伪方式**：T0 作为从智能论推导出的定理，其前提由智能论接受。因此 T0 不需要独立证真——它继承智能论的前提效力。可检验的是它导出的机制。**若智能论前提修订，本框架须版本联动（T0 继承前提效力，也继承前提风险）。**
5. **LLM 派生物的确定性重建**：T14 声明其条件——钉死版本或升格二级真源。未满足条件的 LLM 派生物不纳入"可重建派生态"。
