## 1. 从理论推出的四条（不是从 Cteno 抄的）

### P1 降熵定理是**准入判据**，不是赞美词

> 「协议的效力不依赖于设计者的权威，而依赖于其降熵效率」（0.7）

推论：**任何新增结构必须自证降熵**。在记忆系统里，降熵的可观测代理就是
"协作不确定性下降" —— 我们已有的代理是 B 类（检索到位仍答错）题数。
timeline 之所以成立，正是因为它把 B 类 19 → 9（可观测降熵）；
而"七维类型化"**自证失败**（B-非时间 = 0，没有可下降的量）。

同时 5.3 的 `K_π`（结构成本，含导航税/验证成本）说明：**不降熵的层是纯成本**。

### P2 信息差增定律要求"结构可生长但必须廉价"

> `d(D_meta)/dt ≥ 0`，D_meta 持续供给 D_task 来源 → "认知永远有活干"（2.7.0）

推论：记忆系统**必须能长期加层**，但每次缩小信息差都要消耗 K。
所以新层不能是"又一套持久库"，而应是**可重算的投影**（算得起、丢得掉、可复算）。

### P3 资格判断不是相似度排序

> 「传统检索解决『哪个答案最像』；条件路由解决『哪个候选有资格执行』。
> 相似度可以产生候选，但不能单独授予执行资格——**资格由条件证据裁决**」（6章.2）

四态：**ACCEPT / REJECT / DEFER / BLINDSPOT**。

推论：三列表里 A 类归零 = "候选生成本身已经不是瓶颈"；
B 类 9 题不是"候选不对"，而是**缺"资格证据"** ——
具体缺的是「这一条凭什么是当前值」的证据。这正是下面 P4 的内容。

### P4 stable 租约 + 混杂系统 = 终态求解的理论形态 ★

> `stable(S, t_verified, TTL)`；
> `S ∈ stable ⟺ (t − t_verified) < TTL ∧ ¬conflict(Ŝ_pred, S)`
> 触发条件：TTL 超时 **或** 第六感预测与 stable 记忆显著冲突 → 自动降级 weak 重新验证（3.2.2）

> 混杂系统：连续流 `dc_i/dt = −γ_i(c_i − c_baseline)`、`dTTL/dt = −1`；
> 离散跳变 `guard(V_hit, t>TTL, conflict) → transition → reset(P, S, C)`（5.2）

**这是本轮最关键的一条**：终态**不是"最新那条记录"**，而是一个
**在 TTL 内、且未被冲突推翻的 stable 值**。记录只增不改；状态可以被降级重验。

而且 3.2.2 明确规定（P1-003）：

> **确认度降级作用于状态，不作用于记录** —— 不得把 "stable→weak 降级" 误实现为 "删除记录"。

灵枢当前的 soft delete（trash + `_deletions.jsonl`）恰好符合这条；**但"终态"这一层整体缺失**。

## 3. 设计：一个账本 + 一个求值器 + 两个投影

**不做七维图。** 理论给的形状是「账本 → 状态 → 投影」，不是「类型化实体图」。

```
         ┌───────────────────────────────┐
记录层   │ _state_events.jsonl（只追加） │  ← 不可遗忘，不修改不删除
         └───────────────┬───────────────┘
                         │ 确定性求值（无 LLM）
         ┌───────────────▼───────────────┐
状态层   │ stable 求值器（TTL + conflict）│  ← 5.2 连续流 + 离散跳变
         └───────────────┬───────────────┘
                         │
         ┌───────────────┴───────────────┐
投影层   │ timeline（已做） / state_view  │  ← 按需算，可丢可复算（K_π 廉价）
         └───────────────────────────────┘
```

### 3.1 账本（事件，不是状态）

每行一个事件，**只追加**：

```json
{"t": 1794231503.0, "subject": "meeting_plan", "slot": "time",
 "op": "set", "value": "2026-07-21 15:00",
 "evidence": "node_abc123", "source": "session_x", "conf": 0.8}
```

**op 闭集**（只四种，够用且可判）：

| op | 语义 | 对状态的作用 |
|---|---|---|
| `set` | 声明"槽位 = 值" | 候选新值；**不直接改终态** |
| `corroborate` | 再次确认同值 | `t_verified ← max(t_verified, t)`，`repeat_count++` |
| `conflict` | 声明另一值 | 触发 `guard`：有证据 → transition；无证据 → 降级 candidate |
| `retract` | 撤回某次声明 | 该事件不再是证据（**不删行**，加 `retracted_by`） |

> 为什么 `set` 不直接等于终态：P14 那题的失败模式正是"第二次提到新日期就把旧值覆盖"。
> 理论要求**有证据才 transition**（`guard(V_hit, t>TTL, conflict)`）。

### 3.2 求值器（纯函数，可复算）

```python
def eval_state(events, now, ttl_of) -> {slot: Stable}:
    for (subject, slot), evs in group_by(events):
        cur, t_ver, reps = None, None, 0
        for e in sorted(evs, key=t):
            if e.op == "corroborate" and e.value == cur:  t_ver = e.t; reps += 1
            elif e.op == "conflict":
                if e.conf >= CONFLICT_MIN:   cur, t_ver, reps = e.value, e.t, 0   # transition
                else:                        pending = e.value                    # candidate
            elif e.op == "set":              pending = e.value                    # 候选，不改终态
        alive = (now - t_ver) < ttl_of(slot) and pending is None
        yield Stable(subject, slot, cur, t_ver, reps, weak=not alive)
```

三个关键点，全部来自理论：

1. **`weak` 不是删除**（P1-003）：值仍返回，只标记"需重验"；
2. **TTL 与 `valid_until` 共享同一衰减核 `exp(-γt)`**（3.2.2 耦合声明 DEV-005）——不引入第二套时间语义；
3. **`pending` 存在则降级**：这正是"改期已提出但未确认"的中间态，也是 DEFER 四态的落地。

### 3.3 `state_view` 投影（同主题全部槽位联合给）

```json
"state_view": [
  {"subject": "meeting_plan",
   "slots": {"time": {"value": "2026-07-21 15:00", "t_verified": "2026-07-18", "weak": false},
             "place": {"value": "城西咖啡馆", "weak": false},
             "participant": {"value": "老贺", "weak": false}},
   "pending": {"time": "2026-07-25 10:00"}}
]
```

**为什么要"联合给"而不是逐槽位给**：P12-NEW-009（周五下午 + 谁收 + 放哪）是
"多要素同时在场"，模型需要一次看到同一 subject 的全部当前值 —— 分开给就又要它自己做合成。

## 4. 与 Cteno 四层的对照：我们不是照抄，是"投影化"

| Cteno | 灵枢本设计 | 理论依据 |
|---|---|---|
| 原始记录（append-only） | `_state_events.jsonl`（节点仍为可变件，但**状态变更**走账本） | 3.2 记录单元 + P1-003 |
| 记忆笔记（砍掉） | 不设；CCG 六要素已在节点本体 | K_π：不新增层 |
| Wiki（可重建，模型整理） | **确定性投影**（`timeline` / `state_view`），无 LLM 参与 | 6章.2「条件判断必须交给稳定的确定性机制，LLM 只负责提供候选假设」 |
| 索引 | 已有（`_index` / bucket / `_reach_index`） | — |

**差别就是理论优势**：Cteno 的 Wiki 是"整理出来的"，会随模型变而变；
我们的投影是"算出来的"，**同样的账本 + 同样的求值器 ⇒ 逐位相同的终态**（可验证、可复算）。
这也顺带解决"换模型要不要重建 Wiki"——我们不需要重建。

## 7. 必须声明的盲区（含引用理论自身的盲区机制）

| 盲区 | 说明 | 处置 |
|---|---|---|
| **TTL 取值无理论依据**（对应盲区 7：置信概率的样本依赖） | γ 与 TTL 怎么定？理论只说"由验证单元按条件空间校准"，未给数 | 先给缺省（按时段：日期类 30d / 事实类 180d），用 9 题验，再调 |
| **账本格式定版后改动要迁移**（对应盲区 50：跨版本一致性） | 事件 schema 一旦落盘，改字段要写迁移 | v0.1 先只落最小字段，预留 `extra` |
| **账本与节点双写一致性**（本设计新增盲区） | 事件写了节点没写 / 反之，会撕裂 | **单一入口**：只在 `write`/`verify`/`state_event` 三个 op 里产事件，禁止旁路 |
| **冲突阈值 `CONFLICT_MIN` 是拍脑袋** | 什么算"有证据"？ | 先取 0.7（与 `importance_hint` 同档），用 9 题校准 |
| **规则抽取的召回上限** | 正则抽不出"明天陪爸开药→4月2日"这种相对时间 | 已有 `timeboost` 相对日期解析，复用；抽不出的记 BLINDSPOT 而非猜 |

## 8. 实施路径（三档，需使用者裁）

| 档 | 内容 | 代价 | 能验什么 |
|---|---|---|---|
| **A（最便宜）** | 只加 `state_view` 投影，靠现有节点 `created_at` + 同主题分组做"伪终态"（不改写入面） | ~半天 | 对"改口"可能有效；对"改期终态"大概率无效（没有事件语义） |
| **B（中）** | 加 `_state_events.jsonl` + 求值器 + `state_event` op；**写入面暂不自动产事件**，由调用方显式写 | ~2 天 | 拿 9 题手工灌事件，直接验"账本齐了能不能到 5/9" |
| **C（重）** | 写入面自动产事件（`write`/`verify` 自动推断 subject/slot/value） | ~1 周 | 端到端；但抽取准确率先会成为新瓶颈 |

**我的建议：先 B，不先 A 也不先 C。** 理由：
- A 缺"事件语义"，P14/P01 这类题**结构上就解不了**，跑完大概率证明不了什么；
- C 的瓶颈在抽取准确率，会把"账本是否有效"这个变量污染掉；
- B 能**隔离变量**：手工灌 9 题的事件，只测"求值器 + 投影"这一层。

## 9. 一句话结论

**理论不要求"更聪明的类型化图"，要求的是"记录只增不改 + 状态可降级重验 + 终态由证据裁决"。**
B 类 9 题缺的正是第三件。所以下一步做「事件账本 + stable 求值器 + state_view 投影」，
用那 9 题当验收（0/9 → 5/9 成立）。
