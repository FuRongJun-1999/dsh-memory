## 2. 命名规范

```
{层级前缀}_{功能主干}
```

- 层级前缀：knowledge 层固定 `kn`
- 功能主干：2–8 汉字语义名，禁空词（知识/内容/信息/数据），禁 `/ \ : * ? " < > |` 与空格
- 四问全过为合格；不可起名（正文为空/纯元数据）如实返回 `new_name: null`

## 3. 执行架构（蜂巢 v0.2）

| 参数 | 值 | 落点 |
|---|---|---|
| 子代理 LLM | `deepseek-flash`（DeepSeek-V4.1-Flash） | spec.model |
| 思考 | `{"type":"enabled"}` + `reasoning_effort: high` | spec.thinking / spec.reasoning_effort |
| 上下文预算 | 300,000 tokens（执行器保守估算，超限 fail fast 不白跑 API） | spec.context_budget_tokens |
| 硬超时 | 600s | spec.timeout_s |
| 温度 / 输出上限 | 0.3 / 4096（思考链计入） | spec.temperature / max_tokens |

子代理任务设计：**一个 job = 一个节点的命名裁决**（单轮 chat/completions，读单节点 md，回单行 JSON）。
系统提示词（唯一真源）：`hive/plans/naming_gov/system_prompt.txt`。

## 4. 记忆协议（本项目核心约定）

1. **子代理零记忆写权限**——system_prompt 明示；认知图/知识图谱/词表一律不写。
2. **唯一写入口 = 主代理**：读 `result.json` → 查重（与 194 强锚名、同批已分配名冲突则打回下一轮修正 job）→ 写入本计划批次表 + 命名映射表。
3. **映射表是最终产物**：`hive/plans/naming_gov/mapping_batch<N>.json`，每行
   `{"old_id", "new_name", "confidence", "reason", "q2_aligned"}`——审计留痕，认知图回写（是否/何时执行）另行裁定，不在本项目范围。
4. 失败/超时 job 如实记录 `error`，绝不假装 done。

## 6. 运行手册（key 就绪后）

```cmd
set HIVE_API_KEY=<DeepSeek密钥>
set HIVE_API_BASE=https://api.deepseek.com
cd /d <本仓根目录>
python hive\plans\naming_gov\gen_specs.py --bucket cond_感知系统_d94e90d2 --limit 10 --submit
:: serve 未启动时 submit 自动拉起（MCP 路径）；CLI 需先： target\release\hive.exe serve
target\release\hive.exe poll
```

成本预估（试点）：10 job × ≈2k tokens 输入 + 思考/输出 ≈ 0.05 元级。全量 6,645 job 约 15–30 元（deepseek-flash 空闲时段更低）。
