## 4. 诚实结论与建议

1. **S1b 是一个「快模式」**：约 **7–8 倍更少扫描、4–6 倍更快**，但**不保证与全表扫描同结果**。
   因此它必须保持 flag 默认关（现状如此），且**不建议**作为唯一检索路径启用——
   这正是「域收敛不得丢召回」这条不变量在真实库上的边界。
2. **要同时拿到速度与等价召回**，缺的是一层**廉价高精度候选生成器**：即把「词 → 命中节点」做成
   **倒排/发布表**（词项索引），这样不必读遍所有文件就能取出词法命中，再交给既有路径排序。
   契约 §7 允许「倒排只作 S1/S3 之后的候选内加速」——这是该层的正确定位（不是用它替代认知路径）。
3. 该倒排层的建设成本在**索引 schema + 写入/重建维护**，属下一个里程碑级别的工作；
   在它落地前，建议 S1b 只作为**可选加速**（默认关），并在启用时把 `meta.gates.s1b` 与
   `covered_neg` 一并暴露给调用方，让调用方知道「本次是加速模式」。
