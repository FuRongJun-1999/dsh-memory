# 检索算法口径对照 v0.1（批次 15）

> 2026-09-23 使用者口径定案：**统一翻译为中文 → 中文归一化到标准中文集（atoms 词表）→ 检索**。
> **2026-09-30 使用者裁定收窄作用域**：归一层**只对英文内容做翻译归一，中文内容原样不动**。
> **2026-09-30 使用者裁定翻缺省**：`MDCG_UNIFY_QUERY` 由「默认开」翻为「**未设即关**、
> 显式 `=1` 才开」——本层本职是让英文 query 命中中文节点，对中文检索池是纯开销
> （locomo-zh-500 实测缺省关态 lexical hit@1 96.4% / lexical+fuzzy 97.2%，
> 开态 95.8% / 96.6%）；两侧三态判据同语义。
> 本文是该口径的两侧实现对照与残留差距真源——两侧实现以本文为准，改动检索口径先改本文。

## 一、统一管线（两侧同构）

```
query（任意语言）
  │  MDCG_UNIFY_QUERY=1 可整体开（**默认关**——2026-09-30 裁定：本层只服务英文 query）
  ▼
[统一归一层 unify] —— 作用域（2026-09-30 收窄）：**只译英文内容，中文原样不动**
  ├─ 分段判据单点：中文 = CJK 统一表意文字基本区 U+4E00–U+9FFF
  │     Python `semantic/canonical.py::is_zh_char` / Rust `text.rs::is_zh` 同判据
  ├─ query 无 ASCII 字母 → 原样返回（纯中文零变更纪律，不 strip）
  ├─ 中文段 → **逐字保留、绝不切分、绝不送 segment**
  ├─ 含 ASCII 字母的非中文段 → en 形态归一（小写/停用词/时态归零）
  │            → en→zh 词表映射（en_zh_map.json，28478 词，CEDICT 全链派生）
  │            → 未登录词原样保留（unknown_keep = 词表边界，非错误）
  │            → 映射产物经 segment 贪心最长匹配（zh_keys 204 标准原子，键长降序）
  ├─ 不含 ASCII 字母的非中文段（数字/标点）→ 原样保留
  ├─ 各段按原顺序单空格 join；空白（段内/段间）一律折叠为单空格
  ├─ 归一产物为空（折空白后）→ **回退原入参本身（含首尾空白，不 trim）**——
  │     两侧同语义：Python `return text` / Rust `query.to_string()`（见 §六）
  ▼
标准原子序列（空格 join，如 "我 吃 牛肉 昨天"；
             中夹英 "领养 LGBTQ 群体" → **Python 侧**原样，旧口径会切成
             "领 养 LGBTQ 群 体"；Rust 侧对未登录大写词的产物是
             "领养 lgbtq 群体"——**两侧既有非对称**见下「一之补」表第 ① 条）
  ▼
检索各路（lexical / bucket / entity / graph，RRF 融合）
  —— doc 侧正文不动（真源+原始双保留纪律），只有 query 侧归一
```

**为何收窄（2026-09-30 定因，实测）**：旧口径「query 含任一 ASCII 字母即整条
归一」会把**中夹英** query 的中文部分逐字切开（「自我接纳」→「自 我 接 纳」、
「慈善跑」→「慈 善 跑」）。locomo-zh-500 公开题池（567 池 / 500 题，
`eval_common` jaccard + GLOBAL_CAP 解除，k=5）：现状 lexical hit@1 = 94.4% /
lexical,fuzzy = 87.2%；收窄后 **95.8% / 96.6%**；归一层全关 96.4% / 97.2%。
500 题里含 ASCII 字母的 145 条**全部**也含中文（题池无纯英文 query）。
复现：`python -X utf8 -m md_cg.bench_locomo_zh_public`。
**2026-09-30 翻缺省后**：缺省态（= 归一层关）即取 **96.4% / 97.2%** 这一行，
显式 `MDCG_UNIFY_QUERY=1` 才回到 95.8% / 96.6%。
（以上为本次收窄的定点实测读数，仅作口径变更的证据——仓库对外参考值/
README 数字不因本任务变动，数字回流由编排侧另行核。）

### 一之补 · 两侧既有非对称（非本次收窄引入，2026-09-30 实测）

下表三条是两侧实现的**既有分歧**，非 2026-09-30 收窄引入、也非本清理批次引入——
**收窄前对照实测同分歧**（收窄前 = `HEAD~1`：Python 侧按
`git show HEAD~1:md_cg/semantic/unify.py` 的整条归一路径
`" ".join(query_atoms(t))` 实跑；Rust 侧用 `git archive HEAD~1 rust` 导出到临时目录、以临时
cargo 工程（独立构建目录，不碰仓库 `rust/target/`）重建后实跑 `Atoms::unify`）；该提交亦**未触碰**
`en_normalizer.py`（`git show --stat HEAD` 可见）。读数取法：Python 走
`md_cg.semantic.unify.unify_query`，Rust 走 `atoms.rs::Atoms::unify`
（两侧消费同一份 `en_zh_map.json`）。

| # | 形态 | Python 产物 | Rust 产物 | 根因（各自实现内） |
|---|---|---|---|---|
| ① | 未登录**大写**英文词 | `领养 LGBTQ 群体` → `领养 LGBTQ 群体`；`AI 记忆 系统` → `AI 记忆 系统`（保留原 case） | `领养 lgbtq 群体`；`ai 记忆 系统` | Python：未登录词 unknown_keep 原样；Rust：先经 `normalize_en`（一律 lower）再查表，未命中以 lower 形占位 |
| ② | 命中词表的**专名** | `Paris 报告` → `Paris 巴 黎 报告`（原词 + 译词**双原子**） | `巴 黎 报告`（只出译词） | Python `en_normalizer` 的 `is_proper` + 词表命中 → `proper_mapped_both` 双原子；Rust 无该分支 |
| ③ | 字母与数字**同段** | `beef 2024 报告` → `牛肉 报告`（**丢数字**） | `牛肉 2024 报告`（**保数字**） | Python `normalize_en_query` 分词类 `[A-Za-z\u4e00-\u9fff]+` 不含数字；Rust 侧 ASCII 数字词元保留、未登录则原样占位 |

**为何 fixture 避开这三类形态**：`md_cg/semantic/unify_fixture.json` 是**两侧钉同一期望值**的
逐位对拍件（Rust 侧 `include_str!` 编译期嵌入），上表三条两侧产物不同 ⇒ 钉不出同一期望值，
故该文件只登记「两侧同构」形态，`_caveat` 亦指向本节（正文为真源）。**是否把某一侧改成另一侧
口径，见 §七 待裁定项——本文不自行定方向。**

## 二、词表真源单侧化（架构决策）

| 资产 | 真源 | 产物 | Rust 消费 |
|---|---|---|---|
| en→zh 映射 | `md_cg/semantic/en_normalizer.py`（EN_ZH 人工层 + COMPOUND_ZH + CEDICT 链） | `en_zh_map.json`（`export_en_zh_map.py` 生成，28478 词条） | `rust/src/atoms.rs` 查表 |
| 标准原子键 | `md_cg/semantic/zh_en_atoms.py`（ZH_EN，204 键） | 同上文件 `zh_keys` 字段 | segment 贪心匹配 |
| OOV 审计基准 | `md_cg/semantic/atoms.json`（815 标准概念，zh+en 双语条目） | —— | （写入侧摘要合法性，检索不消费） |

**为何不移植词典到 Rust**：双词典真源 = 版本敏感漂移（同词面不同版本映射不同 →
两侧分数漂移）——正是弃用外部分词器（jieba 等）的原因。词表更新后重跑
`python -m md_cg.semantic.export_en_zh_map` 再生成，两侧永不漂移。

**为何不用标准分词器**：中文无空格分词天然标准；jieba 词典版本敏感且 rust 侧
无同源实现。bigram + 词表映射零依赖、确定性、可逐位对拍。

## 六、变更纪律

- `MDCG_UNIFY_QUERY` **默认关**（2026-09-30 使用者裁定，由「默认 "1"」翻为「未设即关」）；
  两侧三态判据同语义，**唯一开态 = 显式 "1"**：
  未设 → Python `unify_on()` `False` / Rust `Atoms::from_env()` `None`；
  `"0"` → 同上（关）；`"1"` → `True` / `Some(Atoms)`（开）。
  两侧同一 env，判据落点：Python `md_cg/semantic/unify.py::unify_on`
  `os.environ.get("MDCG_UNIFY_QUERY", "0") == "1"`；
  Rust `rust/src/atoms.rs::Atoms::from_env`
  `std::env::var("MDCG_UNIFY_QUERY").as_deref() != Ok("1") → None`。
  三态守卫 `md_cg/test_unify_default_off.py`（含两侧一致性与定点变异自证）。
- **归一层作用域（2026-09-30 收窄）**：只对英文内容做翻译归一，中文段逐字保留
  ——中文判据单点两侧同区间（`canonical.is_zh_char` / `text.rs::is_zh`）；
  逐位对拍 fixture `md_cg/semantic/unify_fixture.json`（两侧钉同一份期望值），
  改任一侧实现必先同步另一侧并跑两份守卫。
- **中文判据边界**：Python `is_zh_char` **仅长度恰为 1 的串可为真**（空串/多字符串
  一律 False）；Rust `is_zh` 收 `char` 天然同语义。两侧边界约定写在各函数 docstring。
- **空产物回退**：归一产物为空时两侧**原样返回原入参（含首尾空白，不 trim）**
  ——Python `unify_query` 尾行 `return text`，Rust `Atoms::unify` 的
  `query.to_string()`（2026-09-30 清理批次乙1 修正：此前 Rust 误为 `query.trim()`）；
  fixture「空产物回退·原样返回原入参（不 trim）」例钉住。
- **两侧既有非对称三条**（§一之补）**尚未统一**——改任一条都属**改语义**，须先由
  使用者裁定方向（§七 待裁定项 2），再两侧同改 + 更新本节与 fixture。
- 词表再生成：`python -m md_cg.semantic.export_en_zh_map` → 两侧自动同源。
- 对拍命令：`python scripts/rank_parity.py --dataset scripts/retrieval_dataset.json --ab`
  （A/B 证据）+ 同命令去 `--ab`（逐位对拍）。

### 2. §一之补 的三条两侧既有非对称统一到哪一侧？

**后果读数**（2026-09-30 实测）：locomo-zh-500 公开题池（池 567 / 题 500，
`eval_common` jaccard + GLOBAL_CAP 解除，k=5），Python 侧用**进程内 monkeypatch**
量（不改仓库文件；patch 包在 `en_normalizer.normalize_en_query` 外层，随后跑与
`python -X utf8 -m md_cg.bench_locomo_zh_public` 同一口径；池与结果均落临时目录）：

| 态 | lexical hit@1 | lexical,fuzzy hit@1 | MRR（lexical / lex,fuzzy） |
|---|---|---|---|
| 现状（Python 保留原 case、字母数字同段丢数字） | **95.8%** | **96.6%** | 0.9755 / 0.9821 |
| 把 Python 的未登录大写词改 lower（= 向 Rust ①侧靠） | 95.8% | 96.4%（−0.2pp） | 0.9755 / 0.9811 |
| 把 Python 的字母数字同段改为保数字（= 向 Rust ③侧靠） | 96.2%（+0.4pp） | 96.6%（持平） | 0.9775 / 0.9821 |

读数边界（如实声明，勿外推）：
- 「大写 lower」patch 的判据是「term 含 ASCII 字母即 lower」⇒ 它同时覆盖第 ① 条
  **与第 ② 条的原文原子大小写面**（`Paris`→`paris`），但**未动** ② 的双原子结构；
- 「保数字」patch 把数字串**追加在该段原子序列末尾**（段内原位插入会略改 bigram
  组合），属近似实现；
- **第 ② 条「专名双原子」未单独量**（需改 `is_proper` + 词表命中分支，patch 面更大）
  ——缺读数即声明缺，不填猜测值。

⇒ 结论：两条可量项都**未达「明确该改」的强度**（①向 Rust 靠在这两路不增益甚至
fuzzy −0.2pp；③向 Rust 靠 lexical +0.4pp、fuzzy 持平），且两条都动两侧共享语义面
（Rust 侧改需同步改 `normalize_en` 的 lower 语义或新增双原子分支）。**故本批只披露
读数，统一到哪一侧由使用者裁定；裁定后两侧同改 + 更新 §一之补 / fixture / 守卫。**
