# 检索算法口径对照 v0.1（批次 15）

> 2026-09-23 使用者口径定案：**统一翻译为中文 → 中文归一化到标准中文集（atoms 词表）→ 检索**。
> 本文是该口径的两侧实现对照与残留差距真源——两侧实现以本文为准，改动检索口径先改本文。

## 一、统一管线（两侧同构）

```
query（任意语言）
  │  MDCG_UNIFY_QUERY=0 可整体关回退（默认开 = 口径定案转正）
  ▼
[统一归一层 unify]
  ├─ 纯中文 → 原样（bigrams 去空白后与原文等价，零变更纪律）
  ├─ 含英文 → en 形态归一（小写/停用词/时态归零）
  │            → en→zh 词表映射（en_zh_map.json，28478 词，CEDICT 全链派生）
  │            → 未登录词原样保留（unknown_keep = 词表边界，非错误）
  ├─ 中文段 → segment 贪心最长匹配（zh_keys 204 标准原子，键长降序）
  ▼
标准原子序列（空格 join，如 "我 吃 牛肉 昨天"）
  ▼
检索各路（lexical / bucket / entity / graph，RRF 融合）
  —— doc 侧正文不动（真源+原始双保留纪律），只有 query 侧归一
```

## 二、词表真源单侧化（架构决策）

| 资产 | 真源 | 产物 | Rust 消费 |
|---|---|---|---|
| en→zh 映射 | `md_cg/semantic/en_normalizer.py`（EN_ZH 人工层 + COMPOUND_ZH + CEDICT 链） | `en_zh_map.json`（`export_en_zh_map.py` 生成，28478 词条） | `rust/src/atoms.rs` 查表 |
| 标准原子键 | `md_cg/semantic/zh_en_atoms.py`（ZH_EN，204 键） | 同上文件 `zh_keys` 字段 | segment 贪心匹配 |
| OOV 审计基准 | `md_cg/semantic/atoms.json`（815 标准概念，zh+en 双语条目） | —— | （写入侧摘要合法性，检索不消费） |

**为何不移植词典到 Rust**：双词典真源 = 版本敏感漂移（同词面不同版本映射不同 →
两侧分数漂移）——正是弃用外部分词器（jieba 等）的原因。词表更新后重跑
`python -m md_cg.semantic.export_en_zh_map` 再生成，两侧永不漂移。

**为何不用标准分词器**：中文无空格分词天然标准；jieba 词典版本敏感且 rust 侧
无同源实现。bigram + 词表映射零依赖、确定性、可逐位对拍。

## 三、两侧实现对照

| 环节 | Python | Rust | 对齐守卫 |
|---|---|---|---|
| 统一归一入口 | `semantic/unify.py::unify_query`（三处 search 入口接线） | `atoms.rs::Atoms::unify`（`engine.search` 单点接线） | rank_parity 逐位对拍 |
| en 形态归一 | `en_normalizer.strip_tense` | `text.rs::strip_tense_en`（golden 对齐测试） | golden_python_alignment |
| en→zh 查表 | normalize_en_query 查链（extra→EN_ZH→CEDICT） | en2zh 查表（键=strip 后原形，lower） | 同一 en_zh_map.json |
| segment | `zh_en_atoms.segment` | `atoms.rs::segment`（键长降序贪心） | atoms 三测 + rank_parity |
| 词法打分 | bigram 集合交（`inter/len(qb)`） | `text.rs::bigrams`+`overlap_count` | golden 对齐 |
| 融合 | `search_rrf`（RRF_K/PATH_TAKE/weights） | `retrieval.rs::fuse` | rank_parity |

## 四、A/B 转正证据（2026-09-23，`scripts/rank_parity.py --dataset --ab`）

数据集：`scripts/retrieval_dataset.json`（30 节点中英混合 + 10 query，两侧同源）。

| query tag | unify=off top-1 | unify=on top-1 | 判定 |
|---|---|---|---|
| beef noodles lunch | ds_en_02（错位） | **ds_zh_00 牛肉面** | 跨语修复 |
| soul hub hot cache | ds_en_02（错位） | **ds_zh_02 灵枢热缓存** | 跨语修复 |
| token verification / database migration / piano practice | 英文原文档 | 中文同义文档 | 同义翻转（无退化） |

结论：跨语增益真实（off 的跨语 top-1 全部错位）；单语场景排序有 tie 翻转
（中英文档同义时 top-1 可能互换）——**口径变更的如实代价**，靠 judge 终排与
path_weights 调优消化。

## 五、登记残留（未施工，按优先序）

1. **S1b 中文 query 桶收敛失效**（批次 15 发现）：桶键英文（如
   `swarm-dispatch`）时，中文 query 经 `bucket_key_readable`+`domain_similarity`
   恒 no_key_match → 不收敛。恰击中 S1b 设计目标场景（真实库 91.1% 中文节点）。
   方向：桶键双语化 / domain_similarity 中文面。
2. **对拍逐位残留**（issue #29 未清项的精确化）：unify=0 基线 9/10、unify=1
   8/10。差异集中于两侧 terms 展开对英文保留词的处理与 graph 路种子——两侧
   lexical 路细节差，归一层无关（基线态已现）。
3. **CEDICT 低置信错译**：dispatch→「结果」类第一义项直译（LoCoMo 报告发现 5
   同模式）。en_zh_map 保留 CEDICT 层（覆盖面）+ low_confidence 观测，错译随
   用随修进 EN_ZH 人工层。
4. en 归一规则差：Python en_normalizer 有内嵌短语扫描（COMPOUND_ZH_PHRASES），
   Rust 端短语经 map 键直接覆盖（"soul hub" 等已入键），长句内嵌扫描未移植。

## 六、变更纪律

- `MDCG_UNIFY_QUERY` 默认 "1"（转正）；`=0` 显式关回退，两侧同一 env。
- 词表再生成：`python -m md_cg.semantic.export_en_zh_map` → 两侧自动同源。
- 对拍命令：`python scripts/rank_parity.py --dataset scripts/retrieval_dataset.json --ab`
  （A/B 证据）+ 同命令去 `--ab`（逐位对拍）。
