# 检索收敛口径实测与 S1b 设计（真实库 12,149 节点，只读）

> 目的：为「重接检索线路」的价值边界提供**实测**依据，并据此确定下一个核心任务（S1b）。
> 全部为只读测量（`MdCG(真实库)` + 抽样分类），未对真实库做任何写入。

## 1. 两条收敛口径的实测对比

| 口径 | 键 | 覆盖率 | 收敛强度 | 证据 |
| --- | --- | --- | --- | --- |
| **粗：14 大域**（本轮 S1 已落地） | `big_domain_classify`（关键词表） | 已标注 **58.3%**；无域信号 41.7% | 域内 ∪ 未标注 ≈ **44%~52% kept（约 2 倍）** | 240 节点抽样：binary 140 / tier2 +6 / 仍无标签 94 |
| **细：路由桶**（写入侧已建好） | `bucket_dir(route_key(...))` | **91.1% 节点有非 orphan 桶**（11,063 / 12,149） | **期望扫描 2.1%**（1,066 桶，最大桶 10.1%） | 全库统计 |

细口径的桶形如 `cond_感知系统_d94e90d2`、`cond_letta-code_f5190c71`、`cond_graphrag_f0f8d2e7` —— 是
**来源/项目级域**（来自 `domain:` 标签或 `observation_position`），比 14 大域精细得多。

## 2. 现状（代码事实）

`MdCG.search()` **已经有 T0/T1 桶路**：当调用方传入 `context` 时，
`route_bucket = bucket_dir(route_key(ctx, ctx.get("tags")))`，优先只在同桶内 LIKE 检索（T0），
不足再桶内全扫（T1），仍不足才落 T2/T3 全库。

**缺的只有一环**：不传 `context` 的普通 `search(q)` 没有桶 → 直接全表扫描。
（审计「偏差 5：桶路由依赖人工标签」在**自动沉淀的库**上成立；本真实库 91% 有桶，桶路是健康的。）

## 3. S1b 设计（下一个核心任务）

**目标**：让 `search(q)` 在**没有 context** 时也能吃到细口径收敛。

1. **桶规模表**（索引内即可构建，缓存）：`bucket → 节点数`（本库 1,066 桶）。
2. **query 侧键推断**：把 query 扩展词与每个桶的可读前缀做 `domain_similarity`（已有：包含取长度比 + bigram Jaccard），
   取 top-k 个键（`MDCG_BUCKET_TOPK`，默认 3）且要求 `sim ≥ MDCG_BUCKET_MIN_SIM`。
3. **收敛**：候选 = 命中桶内节点 ∪ **orphan/无桶节点**（召回安全，本库 orphan 仅 8.9%）∪ 未标桶节点。
4. **兜底**：命中不足 `min_results` → 回退全库（与 S1 同款规则）。
5. **开关**：`MDCG_GATE_S1B_BUCKET`（默认 0、显式 =1）；审计 `meta.gates.s1b = {keys, kept, dropped}`。

**预期收益（按本库实测推算）**：query 命中具体桶时 kept ≈ 该桶(期望 2.1%) + orphan(8.9%) ≈ **11%**
→ 约 **9 倍**；命中大桶时 ~19% → 5 倍；命中不到任何桶时自动回退（不劣化）。

## 4. 边界

- 不改写入侧（桶已由 `route_key` 在写入时建好）；
- 不放松召回安全：orphan/无桶节点恒留兜底，命中不足即回退；
- 与 S1（14 大域）可叠加：S1 先按大域收敛，S1b 再按桶收敛（两者都有兜底）。
