## 三 设计裁决（白箱三问判定单）

格式：依据（锚点）｜条件（适用范围）｜错后（失败如何被记录修正）｜裁决。

### D-1 完成语义：done ≠ verified，验收锚在盘面

- **依据**：A2（元公理3——不可验证的共识等同于无共识）+ A12（验证分层）。现状「done」只代表执行器自报成功（result.json 无 error 字段）；`expect_*` 只覆盖确定性分支。
- **条件**：适用于一切 LLM 任务收口；确定性任务由 expect_* 即达成快速验证档。
- **错后**：若验证任务本身造假，回退到 wm merge 主代理人工审查 = 维生终裁（理论位置：3.3 验证与反思不一致时维生裁决）。
- **裁决：ACCEPT（语义先行，代码后随）**——本轮起文档统一口径：`done`=执行完成、`verified`=通过验证档；P0 不改代码；验证档落地 = C7/M5 收口裁决 + C15 验收矩阵。

### D-2 恢复判据：产物说了算，判据前移

- **依据**：A2 + A14（意义=被记录、被验证、被锚定的路径——恢复时盘面产物就是已锚定路径）。`D:\2_ai` 实锤：`recover_orphans`（`scheduler.rs:124-158`）不信产物，而 `classify_exit`（`:284-312`）信产物——同一代码两套判据。
- **条件**：对「产物即证据」的任务充分；需要新鲜结果的任务必须显式声明 `rerun_on_recover:true`（D1 裁决），**系统不猜**（条件空间声明：本判据不作新鲜性保证）。
- **错后**：误认陈旧产物 → result 留痕（旧 result 更名 `result.json.recovered-<ts>`）+ 测试反向对照（注释产物判据必须报红，`D:\2_ai` M1 验证判据）。
- **裁决：ACCEPT**——M1（P0）照 `D:\2_ai` 设计稿施工，理论无异议。

### D-3 决策与验证分层：三层任务 × 三档验证

- **依据**：A11 + A12（PROP-DECISION-LAYER-003 + 3.11）。映射：

| 任务层 | 判据（成本-收益-风险） | 验证档 | 蜂巢形态 |
|---|---|---|---|
| L1 确定性 | 零 LLM、秒级、可逆、产物可断言 | 快速 | `model="cmd"` + commands + expect_*（现状已有） |
| L2 常规 LLM | 中风险、部分可逆（有 wm revert） | 完整 | 执行完成 + 编排者收口裁决（C7/M5 落地后含出处计数）或独立验证子任务 |
| L3 不可逆高风险 | 改仓库/推远程/发发布件 | 协同 | 双实例互验 + 维生（使用者）终裁（现状：第 17 条改状态必派发+留痕，推送等由使用者确认） |
