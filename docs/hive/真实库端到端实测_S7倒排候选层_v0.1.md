## 3 等价证据（这是 S7 存在的理由）

以「逐条 (id, 分数, 次序)」为判据：

- **`RESULT_PARITY 6/6`**：`results` 与全表扫描**逐条相同，含次序**。
- `pre_cap`（命中集规模）与 `cap/candidates/tier/cut_order` 亦一致。
- 唯一允许的差异是 `scanned`（正是加速本身）。

两个必须点名的**真实缺陷**（均已在本次落地中修掉，并有不通过即红的用例）：

1. **并列同分的次序**：候选曾按`集合`迭代序取出，而集合迭代序随进程哈希随机化而变
   → 同分同重要性的条目次序会与全表不一致、甚至**逐个进程不同**。
   修法：窄化时**保持索引原序**（候选集是过滤，不是重排）。
   *证据*：`test_retr_s7` 第 12 节（3 个同内容同重要性节点，断言次序一致）。
2. **组合退化（S7×S3）**：S7 曾把`窄化后的 entries`当作 S3 扩散的 allowed 集，
   而 S3 的目标恰恰是「词面无交集、只沿 edges 可达」的节点 → S7+S3 会把 S3 的扩散清空。
   修法：S3 的 allowed 恒取「S1/S2 门控后的全量候选」；S7 只做 T2 的加速器。
   *证据*：`test_retr_s7` 第 11 节（临时还原该行 → 用例立即红：`expanded 2→0`）。

**独立复核（编外验证单元）REJECT 的三条，均已修并补直接证据：**

3. **组合退化（S7×语义路）**：`MDCG_SEMANTIC=1` 时「frontmatter 有 semantic 的节点」在
   `_like` 之外**无条件入池**，而该标志**只在节点文件里**（索引快照无此键）→
   候选阶段无法识别 → 窄化会漏读语义节点、丢召回。
   修法：语义路开启时 S7 一律不窄化（`reason=semantic_on`，审计可见）。
   *证据*：`test_retr_s7` 第 13b 节（含"无词面交集的语义节点 s2 仍入池"断言）。
4. **自证式断言**：第 7 节原有一句 `check(..., True)`（恒真，等于没断言）。
   修法：改为真断言「全量有命中 ∧ 0 < 候选数 < 全量命中数」——
   该用例必须真的走在"窄化后命中不足 → T3 恢复全量"的路径上。
5. **根目录自污染（根级节点）**：`_postings*.json` 就写在库根目录；
   若用"根目录 mtime"判过期，快照刚建就被自己的写入改旧。
   修法：根级路径（path 无目录）改为**逐文件记 mtime**（`file_mtimes`），
   `dir_mtimes` 不再含空目录键。*证据*：`test_retr_s7` 第 15 节
   （自身派生文件写入后仍新鲜；改写根级节点 → `root_file_touched`）。
   （注：现行 `_scan_nodes` 只扫 `<layer>/**.md`，根级节点本不会进索引；
   此修复是**防御性**的，成本为零。）

## 5 设计要点

1. **候选 ⊇ 真命中**：每词取其**全部 bigram 的发布列表交集**，各词并集；
   再交既有 `_like` 精确过滤 → 召回与全表一致（契约 §7「候选内加速」定位）。
   实测反证：某查询 `cands=934`、真命中 873，`hits - cands = 0`。
2. **快照指纹**（节点数 + 节点目录 mtime + 索引文件 mtime / 0.064s）：
   节点写入走 `fsutil.atomic_write`（temp + `os.replace`），目录 mtime 必然变化，
   故 O(目录数) 次 stat 即可判定过期。
3. **T3 兜底还原**：T2 未达阈值时强制恢复全量候选，并把 `scanned` 口径还原为
   「从未窄化」（弃读量另记 `attempted`，诚实计量）。
4. **抽样构建不算新鲜**：`--limit` 只索引部分节点，故**不写**快照指纹
   → 检索一律回退（防「静默漏召回」）。

## 6 诚实结论与局限

1. **收益与查询选择性成正比**：`贝塞尔 曲线 工程 应力` 4.4× 更快（0.45s vs 2.00s）、
   `graphrag 图谱 检索` 1.4×；而 `whitebox 白箱 条件` 只降 6%（该查询含极常见 2-gram
   「条件」，11,499 个节点确实含它——候选集**本来就是**真命中集，不是实现问题）。
2. **无 IDF 加权**：候选是「各词并集」，任一常见词就会把候选推到接近全库。
   下一步可加「按词稀有度分层 + 提前剪枝」，但**不得**改为交集（`_like` 是任一词命中）。
3. **单字词会让整条查询回退**：如「感知系统 记忆 节点」经同义词组展开得到单字词「库」
   → 无法用 bigram 表达 → 整查询回退全量（安全但不加速）。
   要覆盖单字词，需要字符级索引（下一里程碑）。
4. **持续写入的库上会频繁过期**：批量改写期间 S7 落回基线；这是**正确性优先**的取舍，
   不是失效。要长期吃到加速，需要**写入路径的增量维护（dirty 集）**——v1 未接
   （每次写都 load+save 75MB 不可接受），当前用 `--if-stale` 重建守候。

## 7 开关与审计

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |
| `MDCG_RETRIEVAL_PIPELINE` | 关 | 父开关（不开则 S7 代码路径不进入） |
| `MDCG_GATE_S7_POSTINGS` | 关 | S7 子开关，**必须显式 =1** |
| `MDCG_S7_FRESHNESS` | `auto` | `skip` 仅供离线对照实测（跳过指纹校验） |
| `MDCG_SEMANTIC` | 关 | =1 时 S7 自动让位（`reason=semantic_on`）：语义节点面无法在候选阶段识别 |

审计：`meta.gates.s7`，键位 `cands`（窄化后候选数）/ `in`（门控后全量）/ `terms`（查询词数）
/ `reason`（`single_char_term` / `no_index` / `no_module` / `no_snapshot` / `no_candidate`
/ `semantic_on`（`MDCG_SEMANTIC=1` 时不窄化）
/ `stale_index:<dir_touched|node_count_changed|dirs_changed|index_touched|no_meta|root_file_touched|root_files_changed>`）
/ `fallback`（`full_scan` / `no_candidate` / `t3_full`）/ `attempted`（T3 兜底时被弃读量）。

运维：`python -X utf8 -m md_cg.build_postings --root <库根> --if-stale`（过期才重建，供守候环调用）；
`--stats` 打印规模与 `stale_reason`。发布表是**派生索引**，可随时删除/重建，不影响节点。
