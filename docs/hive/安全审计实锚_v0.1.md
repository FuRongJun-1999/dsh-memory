## 读权限分级（批次 27，使用者需求落地；表述经使用者 2026-09-24 澄清）

**private 的体系语义正名**：private ≠ 个人隐私保密，而是**错误处置标记**——
工作区内容因错误相关、验证未过、待排查而被标记私有，目的是限制向平级/
下级扩散。可见性是**故意的冲突设计**：平级/下级限读，但错误处置链路
（**设计者、上级节点、验证单元**）必须可读。缺口已于批次 28 按使用者裁定
**分型治本**：新增 `restricted` 档（阶梯
public<internal<**restricted**<private<secret），错误处置标记用 restricted
——可见性按**错误处置链路角色集**（designer/orchestr/verify，或
can_admin）判定而非纯 rank；**不加密**（不在 ENCRYPTED_LEVELS——链路要
明文读）。private 回归纯隐私/会话绑定语义（加密、仅归属会话+设计者
豁免）；verify 的初版 cap=private 豁免被分型取代、回滚 internal——
验证单元不读真隐私。

**新发现——信封加密的第二层墙（批次 28 实验实锤）**：private/secret 节点
落盘即加密（encrypted_levels），provision_dek 为每个 actor 发独立 DEK、
节点用**写入者 DEK** 加密——跨 actor 读取解密失败静默空（实验：另一
designer 读 seed 的 private 节点亦空）。即 cap 豁免只过密级闸，跨 actor
的 private 实际可读还需 **DEK 共享机制**，三选项待裁定：①DEK 信封共享
（写者 DEK 用读者身份再包信封——改 seal/envelope 结构）；②设计者代查
通道（designer 解密后受控转述）；③private 分型（错误标记 vs 隐私加密
拆开）。不在本批擅自改加密结构。

| 身份 | 文件读面（read_file） | 认知图读面（lingshu_cg read） |
|---|---|---|
| 设计者/主代理 | 全路径（2026-09-19 裁定）+ 部署可选 `HIVE_READ_ROOTS`；文本内容过 **PII 脱敏**（跳过个人敏感信息不入明文） | 其密级上限内全量（designer=secret：public/internal/private） |
| 子代理（worker） | **fail-closed 白名单**：工作区（job_dir）+ 定制工作目录（`spec.workdir`）+ 额外定制目录（`spec.read_roots`，新增）——其他会话/越界拒读；无根即无文件读权限 | 默认密级 **internal**（原 secret 降级）：可读 public/internal，**错误处置标记（private）与 secret 拒读**——平级不消费未证实/已知有误内容 |

实现：`hive/exec.py` `_worker_scope`/`tool_read_file(scope_roots=)`/`_redact_pii`
（邮箱/手机号/身份证/私钥块/API key 样式；正则脱敏是概率防线，新增类别在
`_PII_PATTERNS` 扩展）。编排器派生令牌（`_PRINCIPAL_FACTORY`）身份由调用方

## P2-14 根源分析（批次 32，使用者要求查明根源）

**堆积链路**：新版 Windows 移除 wmic.exe → ind_bootstrap_procs 的
subprocess 抛 FileNotFoundError → except: pass 吞掉返回 [] → main
停转分支把 [] 解读为「确认无进程」→ **不 kill 旧 loop 直接 restart** →
每轮叠加一个新进程（堆积）。

**三层根源**：
1. 组件层：wmic 已从新版 Windows 移除（本机实测 wmic.exe 存在且可运行
   ——堆积在本机未发生；风险面向新部署）；
2. **语义层（真根因）**：探测失败（未知）被压平为「确认无进程」——
   fail-open 的错误处理。修复 = 三态探测：成功返回 list / 失败返回
   **None（未知）**，调用方对 None 跳过 kill/restart（fail-safe：不确定
   就不动）；
3. 历史层（实证）：watchdog 日志 1316 条 100% 是 no_log——
   ind_bootstrap_procs 在本机历史中从未执行过（bootstrap_log.jsonl
   不存在，no_log 分支短路），堆积从未发生。

**报告断言修正**：①「taskkill 模糊匹配误杀」不成立——kill_procs 是
/PID 精确击杀，find 的行过滤也必须含 bootstrap_loop.py；②「判活恒失败」
在 wmic 存在的机器不成立（no_log 短路根本不进判活）。

**修复落地（批次 32）**：find_bootstrap_procs 升级 CIM 枚举
（Get-CimInstance+CSV，wmic 依赖消除）+ 三态返回（None=探测未知）；
main 两个分支（degraded/停转）对 None 一律跳过 kill/restart、状态记
probe_unknown。行为验证：CIM 实测 []（当前无 loop 进程）、枚举故障
mock → None。顺带发现：loop 未部署的机器上 watchdog 每 10 分钟刷一条
no_log 噪声日志（1316 条）——调度侧应停用未部署机器的 watchdog 任务。
