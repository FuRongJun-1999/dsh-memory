# 灵枢使用教程 v0.1

> 面向：第一次给灵枢写记忆、或写了却查不回来的人。10 分钟读完。
> 取向：**规则只有几条，但坑不少**。每条规则后面都跟「常见错法」。

## 0. 三十秒上手

`cg` 是灵枢的唯一入口（DSH 里是内建工具 `lingshu_cg`/`cg`；MCP 面是同名工具）。下面都是它的 `op`。

```python
# 1) 动手前先查：命中纪律/知识就照做
cg(op='route', intent='给检索加一个过滤开关')

# 2) 有结论就写（参数面以 cg(op='help', query='write') 为准）
cg(op='write',
   content='# 功能名：…\n# 生效条件：…\n# 子功能：…\n# 执行：…\n# 验证方式：…\n# 不适用条件：…',
   content_kind='text', layer='knowledge', tags=['检索'],
   importance=0.7, verification_basis='test', dedupe=True)
```

真实范例（可直接照抄结构）：

```
# 功能名：注入面会话内去重（同一条记忆最多注入 2 次）
# 生效条件：长会话里出现「复述旧结论、不再探索」；或怀疑注入面重复贴同一批条目时
# 子功能：
#   A. 按 layer|preview 计次，同会话内同一条 cap=2；
#   B. 全被滤掉时保留第一条，避免整块消失导致宿主多追加快照。
# 执行：src/hooks.ts 的 dedupeRepeatedItems(payload, seen, cap=2)，挂在 system-prompt/assemble。
# 验证方式：test/inject-dedupe-739.test.ts（3 条）+ 实测 session-c28c8589 注入 362 次→18 条去重后。
# 不适用条件：临时排查「为什么某条记忆不出现了」时需临时关掉去重。
```

## 1. 写哪一层？（最容易错的一步）

| 层 | 放什么 | 判据 | 错法 |
|---|---|---|---|
| **self（自我）** | 身份 + 价值观 + 认知图接口，**只有这三样，很薄**，会话启动自动加载 | 「变了我就不是我了」 | 把项目结论塞进自我层 ⇒ 人格被细节污染 |
| **anchor（锚点）** | **协议级**跨实例锚定（不可遗忘的那几条） | 「这条必须在任何实例上都成立」 | 当日常写入面用；新手基本不用碰 |
| **knowledge（知识）** | 可复用的结论、规范、踩坑与修法 | 「三个月后换个人也该知道」 | 一次性会话细节写进来 ⇒ 检索面噪声 |
| **contextual（情景）** | **本次会话**的过程、当时的判断、临时状态 | 「只有这场会话需要」 | 情景写进知识层 ⇒ 下次被当通用结论引用 |
| **structural（结构）** | 仓库/系统结构、索引这类骨架 | 「是地图，不是故事」 | 与知识层混用 |

**一句话**：知识层回答「以后怎么做」，情景层回答「这次发生了什么」，**自我层回答「我是谁」**（薄且少写），锚点层回答「跨实例必须成立的是什么」。

## 2. 六要素（CCG）——写记忆请按这个格式

```
# 功能名：一句话说清这是什么
# 生效条件：什么时候该想起它（可复用的触发，不是任务描述）
# 子功能：分点，每点一条可执行的东西
# 执行：怎么做（命令/步骤/改哪个文件）
# 验证方式：**怎么证明它成立**（测试名/实测输出/回归套件）
# 不适用条件：什么时候**别**用它（负边界，最常被漏）
```

**约束性质要说清**：这套格式是**写入约定**；**硬闸在 `cg(op='ccg')` 的编译链**（compile→review→link，编译者不得自证）。`write` 面接受带这六行的正文，但**不会**逐项校验——所以「写了六行」不等于「过了编译」。

**最常漏的是「不适用条件」**：没有负边界的记忆，会在不该用的时候被召回，比没有更糟。

## 3. 会话身份：让记忆「跟会话走」

- 写**情景层**时带上会话归属（`session`），否则跨会话串台；
- 写**自我层/锚点层**时**不带**会话（人格的可见性不该由会话决定）；
- `sessionPrivate` 叠加时要小心：带会话过滤又带私有标记，可能「命中但读不到」。

## 4. 什么时候**不该**写

- 闲聊、情感交互、纯查询（没有结论产出）；
- **没验证**的东西（跑通了再写，`verification_basis` 才立得住）；
- 中间过程/试错/调试流水（写核心结论，不写过程）；
- 与已有节点重复（先 `route`/`read` 查，再 `dedupe=True`）。

## 5. 读：route / read / recall 三面

| 面 | 用途 | 注意 |
|---|---|---|
| `route(intent=…)` | **动手前**查纪律与知识，返回「该照哪条做」 | 命中即按其动作执行并声明 |
| `read(query=…)` | 精确检索，带 `state` 与适用性判定 | 大库上偏慢（秒~十几秒） |
| `recall(query, budget_tokens=…)` | 按预算装包，适合喂上下文 | 预算小只给摘要 |

**严格度**：`strict_conditions=True` 时「生效条件未在情境确认」判 `DEFER`；工具面 `read`/`route` **缺省放宽**（`usable` 为 true，但 `state` 不变）——放宽的是可用性，不是判定。

## 6. 常见的七个坑

1. **写成功但调用超时** ⇒ 服务端可能已落盘；重试务必带 `dedupe=True`。
2. **`cg(op=info)` 少了 `os` 字段** ⇒ 缺省不返回慢面数据，要传 `full=true`。
3. **旧会话里记忆被反复重贴** ⇒ 0.9.23 起注入侧会话内去重（同一条 ≤2 次）；仍复述就查历史快照。
4. **条件写了却永不命中** ⇒ 「生效条件」写成了任务描述（要写**触发条件**）。
5. **查不到刚写的节点** ⇒ 先按 id `read`；再看 `state`（可能 DEFER 或被保护）。
6. **scrub 报矛盾** ⇒ 键含括号类标点、值以 `src_/ref_/doc_` 开头时不算可断言键值对。
7. **写进自我/锚点后人格漂移** ⇒ 项目结论放知识层；自我层只放那三样。

## 7. 一页速查

```
要动手前        → cg(op=route, intent=…)，命中即照做并声明
有可复用结论    → write, layer=knowledge, 六要素, verification_basis, dedupe=True
只有这场会话要  → write, layer=contextual, 带 session
关于我是谁      → write, layer=self（薄、少写）
跨实例必须成立  → write, layer=anchor（协议级，慎用）
忘了怎么用      → cg(op=help, query='write')
要过正式复核    → cg(op=ccg) 编译链（compile→review→link）
```
