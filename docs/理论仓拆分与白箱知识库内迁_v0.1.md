## 0. 三条动作

| # | 动作 | 一句话 |
|---|---|---|
| **A** | 理论仓（CTP）功能拆分 | 去掉 `aeis/` 工程库，CTP 只留「灵」（协议 / 文档 / 账本 / 测试集） |
| **B** | 灵枢插件主仓改为使用 `md_cg` | 主桥默认从 `python -m aeis.mcp.server` 收敛为 `python -m md_cg.mcp_server`，不再依赖 pip 装 `aeis` wheel |
| **C** | 白箱知识库改为主仓自带 | CTP 的 `wisdom/` + `knowledge/` + `seed_knowledge/`（+ `skills/`）迁入 `dsh-memory` |

**关键现状（决定顺序）**：插件当前启**两个 Python 子进程**——

```
LingshuBridge  → python -m aeis.mcp.server    ← pip 安装的 aeis wheel（来自 CTP）
MdcgClient     → python -m md_cg.mcp_server   ← 本仓 md_cg/（需 PYTHONPATH 指向仓库根）
```

即 **「大脑」目前物理上住在理论仓**：npm 包 `files` 白名单只含 `lib/src/README/cordis*/docs`，**不含 `md_cg/`**。所以 B 与 C 必须**同时成立**才不产生功能回归。

### 3.2 功能缺口（必须逐项裁决）

实测工具定义数：`md_cg/mcp_server.py` = **33**，`aeis/aeis/mcp/server.py` = **84**。

`md_cg.mcp_server` 默认只暴露 kernel 2 基元（`cg`/`stg`），`MDCG_MCP_SURFACE=full` 才补 29 个细粒度工具。**差额约 50 个工具**（角色扮演 / 世界模型 / 身体视觉 / 洞察 / 生命周期 / 智慧之书族）。

每一项须落入三选一：

| 处置 | 含义 |
|---|---|
| **迁入** | 该能力本质属于大脑（如白箱族）→ 在 `md_cg` 内实现或包一层 |
| **移身体** | 依赖设备/模型/宿主（如 `see`/`device_call`/`run_command`）→ 身体仓，插件侧作为可选扩展挂载 |
| **废弃** | 已无下游调用（如 `lingshu-whitebox` provider 已下线）→ 删除并留痕 |

> 未裁决先切默认 args = 静默丢功能（工具不再注册，Agent 侧表现为「工具不存在」）。

## 4. 动作 C：白箱知识库内迁

### 4.1 搬迁映射

| 源（CTP/aeis） | 目标（dsh-memory） | 体积 |
|---|---|---|
| `wisdom/` | `md_cg/whitebox/`（引擎+资产同目录） | 26.5 MB |
| `knowledge/` | `data/whitebox/knowledge/` | 8.6 MB |
| `seed_knowledge/` | `data/whitebox/seed/` | 1.4 MB |
| `skills/` | 顶层 `skills/`（随包分发） | 1.1 MB |
| `harness/` | `harness/` 或并入 `src/` 桥 | 0.3 MB |

### 4.2 实测阻断点：wisdom 依赖 `aeis.core`

`wisdom/` **不是自包含的**，硬依赖如下（实测）：

- `from aeis.core import ...` —— **11 个文件、约 25 处**：`SpacetimeMemoryEngine` / `ConditionSpace` / `MemoryLayer` / `EdgeType` / `STNode` / `LayeredStore`
  - 涉及：`wisdom_cloud.py` `wisdom_book.py` `semantic_translate.py` `pattern_separation.py` `causal_discover.py` `scene_reconstruction.py` `spatial_qa.py` `card_validator.py` `neural_retrieve.py` `answer_spec_anchor.py` `danmaku_bridge.py`
- `from aeis.api import Agent` —— 3 处（`spatial_qa` `causal_discover` `danmaku_bridge`）
- 平铺导入：多数文件 `sys.path.insert(0, __file__ 目录)` + `from wisdom_book import ConditionDex`（非包相对），**同目录搬迁即可存活**，但改名会破坏
- **`md_cg` 侧无对应类**：实测 `md_cg/` 内 0 处定义 `ConditionSpace`/`MemoryLayer`/`STNode`/`SpacetimeMemoryEngine`（md_cg 用 plain dict 表达 `condition_space`）

**两条路径**

| 路径 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A 兼容层**（建议先行） | 在 `md_cg/` 内建 `aeis_compat.py`，提供上述 6 个类名 → 映射到 md_cg 原生模型；wisdom 只改 import 前缀 | 小（一个 shim + import 替换） | 语义漂移：`ConditionSpace` 字段口径须逐字段对齐，须回归测试 |
| **B 收敛重构** | 把 wisdom 的 `aeis.core` 用法改写为 md_cg 原生 API | 大 | 高回归面，需全量白箱测试 |

### 4.3 新增裁决点：37.6 MB 知识资产怎么分发

| 方案 | 优点 | 缺点 |
|---|---|---|
| 随 npm 包 | 一条命令装齐 | npm 包从 <1 MB 涨到 ~38 MB，安装/更新变慢 |
| 随 Python 包（wheel） | 与 pip 生态一致 | 需要主仓产出 wheel（当前无 pyproject） |
| 首启下载 / 按需拉取 | 包最小 | 离线首次不可用，与「开箱可用」冲突 |

> 建议：**引擎随包、大资产（`.db` / `.npz`，合计 ~18 MB）单独发资产包**，首启校验并落 `data/whitebox/`；这需要你裁决。

## 6. 总验收

1. 主仓 `python -m md_cg.mcp_server` **独立可跑**，不依赖 pip 装的 `aeis`。
2. 主仓 `grep -r "aeis" md_cg/ src/` 仅剩「兼容层 + legacy 迁移脚本」两类豁免命中。
3. 白箱知识库自洽：迁入后 `knowledge/` 247 md + `seed_knowledge/` 118 md，数量与 CTP 侧一致。
4. CTP 内无工程实现（仅协议/文档/账本/测试集）。
5. 工具面差额表逐行闭环，无静默丢失。
