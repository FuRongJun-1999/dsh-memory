## 3. 可学习优点清单（按建议优先级排序）

### ④★P0 记忆演化 fork（最高价值——条件论反事实的实验场）

- **pi 机制**：会话是 entry 树，任意历史节点可 fork；两种 scope（`branch` 只拷贝某分支路径 / `tree` 拷全树），运行态一律不复制（`session/types.ts:562-602`、`jsonl/repo.ts:146-196`、`fork-policy.ts:56-63`）；被放弃旁支由 branch_summary 归档（2048 token 定长摘要，`branch-summarization.ts:87-118,274`），切回时提供上下文。
- **灵枢现状**：认知图是**单一演化线**（`_evolution/ledger.md` 2,650 行账本），没有假设分支。条件论的「负条件/反事实显式化」在记忆层没有实验场。
- **建议落点**：`md_cg/mdcg.py` 新增 fork 层（节点 frontmatter 加 `branch_id`/`branched_from`；派生索引记分支 tip），`stg.py` 支持分支时间线；新增 `branch_summary` 节点类型（复用 `NEG_MEMORY_MARKS` 式的必填 MARKS 模式）。语义：大规模改写/遗忘策略变更前先 fork 推演，验证通过合并回主支（合并=按 `derived_from` 溯源回写），失败归档 branch_summary 教训节点。
- **验收**：fork→改写→合并后主支节点 `derived_from` 链完整可回溯；放弃分支不污染主支检索（召回主支时 branch 节点零命中）。

### ⑥★P0 写入路径钩子化（闸门即扩展）

- **pi 机制**：全生命周期事件总线，每个钩子可改变行为——`before_agent_start` 改提示词、`context` 每次 LLM 调用前改消息、`tool_call` 阻断/改参、`session_before_compact` 整体替换压缩（`docs/extensions.md:277-349,452-475,780-848`）。闸门/路径保护/审批全是以扩展形态叠加的，核心没有硬编码策略。
- **灵枢现状**：写入侧闸门族已经是管线形态——role 作用域闸（`mcp_server.py:1434`）→ 冲突闸（:1656）→ 审核闸（:1707）→ 校验闸（:1715）→ 主动遗忘闸门（`forgetting.assess` 三问四态）→ writelimit（写侧限流+同构聚合，`writelimit.py`）→ canonical 语义归一（`semantic/canonical.py`）。**次序与启停硬编码在 write 路径里**，加一道闸要改核心代码。
- **建议落点**：`md_cg/mcp_server.py` 写路径重构为拦截器链：`before_write(ctx) -> verdict`（可 ACCEPT/MERGE/DROP/DEFER/改写）与 `after_write(ctx)` 两个挂载点，现有六道闸全部改注册为拦截器（行为不变，回归护航），token 角色校验保留在链首**不可卸载**（见 §4 反面清单——不学 pi 的全权信任）。
- **验收**：全部既有写入测试（`test_md_writepath.py`/`test_writelimit.py`/`test_verify_answer.py` 等）零改动通过；新增/移除一个拦截器不改核心文件。

### ①P1 上下文经济学：工具面与纪律的分层驻留

- **pi 机制**：system prompt 约 150 词骨架（`system-prompt.ts:127-144`）；工具只以**一行 snippet** 常驻系统提示，完整描述只进 API tools 字段（`system-prompt.ts:82-84`）；8 个内建工具默认只激活 4 个（`agent-session.ts:2831-2834`）；skills 只驻留「name+description+path」三元组 XML 索引，正文由 agent 任务匹配时自己 read（`skills.ts:355-383`）。
- **灵枢现状**：MCP 工具（cg/stg）的 op 参数空间全量 schema 常驻；16 条工作纪律全文常驻 AGENTS.md。
- **建议落点**：`md_cg/mcp_server.py` 工具 schema 瘦身（一行职责+`docs/工具详细说明.md` 按需引用）；纪律/技能分层（索引常驻、正文文件化按需读）；评估工具子集按 profile 启停（对齐已有 `tools: 'core'|'brain'|'all'` 三档，做到档内再分层）。
- **验收**：瘦身前后工具描述 token 数对比产物（目标 ≥50% 削减）；检索/写入功能回归零变化。

### ②P1 记忆节点显式生命周期状态机

- **pi 机制**：运行操作 = 13 叶子显式状态机（`session/types.ts:315-329`），drive 循环按 `at` 分发；一轮无任何进展抛 `SessionInvariantError`（`drive.ts:101-104`）——非法迁移在结构上不可能。
- **灵枢现状**：节点生命周期状态**散落**：writelimit 的 `tidy:converged` 标记、forgetting 的 importance 降权、`_evolution/ledger.md` 账本、`protect` 的 protected 标记——没有一个统一状态字段，迁移合法性无校验。
- **建议落点**：`nodefile.py` frontmatter 新增 `state` 字段（建议集：`active → converged → demoted → archived`，受保护节点单独豁免），`mdcg.py` 写入时校验迁移合法性（非法迁移拒绝，负路由）；存量节点默认 `active`，一次性回填。
- **验收**：非法迁移用例被拒且回归零变化；`_index.json` 索引快照带 state（免读文件可查）。

### ③P2 写入两段式提交（intent/结果对账）

- **pi 机制**：工具调用先持久化 intent+参数（status=effect_pending）再执行，完成后原子写结果；崩溃后 `replay:"safe"` 工具重放，否则合成 interrupted 结果——消息永不缺失（`drive/tools.ts:187-227,515-540`）。
- **灵枢现状**：`_audit.jsonl` 已是追加式操作日志（coggraph 会话串链的数据源），但只有 op=add 事后记录，**没有写入意图的先行持久化**，崩溃时无法区分「写了没落盘」。
- **建议落点**：`md_cg` 写路径在闸门通过后先落 `_audit.jsonl` intent 事件（含 content_hash），写入完成落 outcome 事件；启动时对账（有 intent 无 outcome 的写入做 content_hash 校验补账）。工具幂等声明可后置（md_cg 写入天然可重放：同 hash 幂等）。
- **验收**：kill -9 模拟半途写入后重启，对账报告正确补账/标记；`test_lock.py` 回归通过。
- **落地状态（2026-09-16 · CodeBuddy 端）：✅ 已落地**。`md_cg/twophase.py`（新，两段式真源）+ 两条真实落盘路径接线（`writepipe.py`：链尾执行器 / `_gate_gated` 替代落盘路径各自 begin→commit）+ 库层门面（`mdcg.reconcile_writes` / `pending_writes`）+ MCP 启动自动对账（`mcp_server.py`，失败不阻塞启动但必须 stderr 上报）。**偏离建议**：账本落**独立文件** `_write_2pc.jsonl` 而非本文档建议的 `_audit.jsonl`——理由见 `twophase.py` docstring（`_audit.jsonl` 已被当作单一语义流消费，混入三类事件会扰动既有断言口径；本仓已有 `protect.py/_protected_audit.jsonl` 独立审计惯例）。**边界（如实）**：对账只做「补账 / 如实标记」，**不重放写入**；`append_jsonl` 在 Windows 非原子（对账是增益、不是「保证不丢」）；`_gate_audit` 的 REJECT 负记忆与各闸 propose（无落盘动作）不在覆盖面内。验收：`python -m md_cg.test_twophase` 10 组 35 项全绿 + 全量回归零新增失败。

### ⑤P2 conformance：数据健康不变量的周期巡检

- **pi 机制**：`session/testing/conformance/`（storage 920 行 + session-repo 1185 行）把存储承诺写成断言：事务原子提交、seq 严格递增、非法写被拒且状态完全不变、close/reopen 状态保持、重放确定性。
- **灵枢现状**：机制测试 60+ 套件很强；但**数据健康不变量**没有周期断言。2026-09-15 审计（灵枢 node_26b0973a）发现的存量问题：knowledge 层索引节点混层 57.9%、role 存量 99.99% 为空、evidence_count 仅 6 条、精确重复 90 条、闸门 DROP/DEFER=0、召回率 7%——全靠人肉审计发现。
- **建议落点**：`md_cg/census.py` 产品化：把审计脚本（临时位置 `Temp/audit_write_effect.py`，可向 ZCode 端索取）改写为断言集（混层比例阈值/重复度阈值/字段覆盖率下限/闸门四态分布），挂 `sustain` 周期巡检；超阈值告警不自动改数据（治理另走 tidy/merge，永不删除）。
- **验收**：census 断言集可一键复跑；对当前真源产出首份基线报告（以上数字应复现）。

## 4. 反面清单（不学什么，与灵枢哲学冲突）

| pi 做法 | 为什么不学 | 灵枢对应原则 |
|---|---|---|
| 无 sandbox/无审批，扩展以用户全权运行（security.md:35 自述有意设计，隔离外包 OS/容器） | 信任必须**结构强制且可复算**，不能靠文档告诫+一道 project trust | 位置效应、写权限互斥、凭据六角色（designer/reflection/verifier/recorder/output/sustain/guest） |
| No MCP 立场（CLI+README 替代协议） | 灵枢保持双形态接口：MCP 服务 MCP 阵营（资格闸服务端强制），CLI 形态补「md 目录直改设防」后再开；协议哲学见荣 2026-09-15 纲领（唯一协议=智能论，字节层放开） | 智能论=唯一行为协议 |
| 子进程模型（OASIS 式批处理/每工具一进程） | md_cg 主链路常驻+Rust `--serve` 检索形态已占优 | 记忆真源唯一+多端共享 |
| 会话即全部记忆（无跨会话沉淀） | pi 的 session 文件就是它的全部记忆；灵枢的认知图蒸馏（16 条闭环）是**灵枢独有的维度**，绝不为对齐 pi 而弱化 | 记忆闭环（第 16 条） |
