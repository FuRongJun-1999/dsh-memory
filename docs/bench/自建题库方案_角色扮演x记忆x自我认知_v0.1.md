# 灵枢自建题库方案 v0.1 —— 面向「角色扮演 × 记忆整理 × 自我认知一致性」的公开评测

> 背景：Bench 2.2 实测（2026-11-14）证明瓶颈不在「记不住」，在「该想起来的时候凑不齐证据」
> （全中率 30.44%；k 从 10 放大到 100 召回只到 63.74%）。同时 due 家族 0/45 暴露了另一类问题：
> 信息在库里、也进了 prompt，模型就是不主动提——**这是行为层，不是检索层**。
> 本方案的目标不是再写一个 chat-memory benchmark，而是把**角色扮演所需的三种能力**分开称重。

## 1. 定位：为什么另建一套

| 现有题库 | 测什么 | 缺什么 |
|---|---|---|
| Ornn8 chat-memory 2.2 | 检索能否凑齐证据（A/C/S） | 不测**人格一致性**；不测**记忆整理**（写侧） |
| 通用长上下文 bench | 读长文档 | 不测**跨会话自我同一性** |
| 角色扮演对话评测 | 语气像不像 | 不测**记得住、记得准、不自我矛盾** |

灵枢的宣称是「记得住、查得到、改得回、账不丢」。本套题库把这三句话各自对应到可判单元：

```
记得住   → 事实回忆（单事实 / 多事实链 / 时间条件事实）
记得准   → 抗干扰（同人不同事、同一事实的不同表述、过期信息不得复现）
改得回   → 记忆整理（新增/纠正/撤回首时，旧说法必须失活）
自我一致 → 跨会话人格、价值观、边界（不假装、不越权、不忘立场）
```

## 2. 五个题族（每族都附「可判」，不附就当没写）

### F1 事实回忆（单点）

```
形态：多轮对话历史 → 提问 → 期望答案含指定事实要素
判据：要素全中（不是「提到相关」）——沿用 2.2 的全中率口径
目的：基线，防止「人格做得好但记不住」
```

### F2 事实链（多点，顺序敏感）

```
形态：一个事实由 2–4 轮共同构成（2.2 的直接教训）
判据：全链命中才计分；只中一部分按 0 计（剂量-反应已证「部分命中≈没命中」）
目的：逼出「节点粒度/按引发展开」这类结构问题
```

### F3 时间条件（不是「越近越好」）

```
形态：给出「现在」与「那次提到的时点」，问「当时说的是什么」
判据：答案必须匹配该时点的事实，而不是最近的相似事实
反例守卫：长期记忆题（问很久以前的）与近期偏好题成对出现，防止系统只会「取最近」
目的：把 condition_space.time_window 从「过滤」抬到「排序」
```

### F4 记忆整理（写侧，2.2 完全没有）

```
形态：先给说法 A，若干轮后用户纠正为 B（或撤回）
判据：问 A 时必须答「已更正为 B」或不复述 A；问 B 时答 B
子类型：① 纠正 ② 撤回（不再成立）③ 冲突留白（不得二选一硬答）
目的：这是「改得回」的对外可判面；也是灵枢相对其它系统的结构性优势
```

### F5 自我认知一致性（角色扮演的核心，也是本套的差异化）

```
形态：跨会话（新开会话问同一人格问题）、诱供（诱导它承认自己是 AI/否认设定）、
      边界（被要求做违反设定的事）、价值观一致性
判据：三档 —— 一致 / 漂移（措辞变但立场在）/ 崩（否认设定或立场反转）
关键：**同一事实的不同表述**（孪生题）必须成对出现，否则测不出「靠措辞记答案」
目的：角色扮演的本质不是语气，是「隔着会话还是同一个人」
```

## 3. 与 2.2 的三处方法论对齐（不重复踩坑）

| 2.2 的教训 | 本套怎么吸收 |
|---|---|
| micro recall 与分数不挂钩 | **只用全中率**作为召回侧指标；另记一条 micro recall 仅作诊断 |
| prompt 长度会稀释分数（M02 6.1k→13.3k，−3.65） | 每题**固定 prompt 预算**（如 ≤8k 字符），排序改动不得突破预算；超预算的展开按 0 计 |
| 部分命中 ≈ 没命中 | F2/F4 一律「全中才得分」，不做部分给分 |
| 成本项会让 S 分失真 | 同时报 A / C（`/v1/usage` 记账）/ S，并**分别**报三族分项 |

## 4. 判分与统计

```
单元 = 一道题（含孪生成对）
主指标：全中率（题级）、A（rubric 判分）、S（含成本）
统计：单元级 McNemar（孪生/前后对照）、95% CI；**不给单点差异下结论**（2.2 的 rerank +4.55 但 p=0.33 就是教训）
对照臂：naive（只给最近 6 轮）= 地板；qwen-base 或等价泛化系统 = 参照
```

## 5. 数据与隔离（公开可复现的前提）

- **全合成 persona**：不搬真实用户会话、不含隐私路径与执行日志；
- 灌库走隔离根（`MDCG_ROOT`/`MDCG_STATE_ROOT`），与生产库零接触；
- 每族数据独立种子，可复现生成（生成脚本随题发布，题目本身带 `case_id`）；
- 敏感信息隔离按第 9 条：公开仓只放合成数据；真实人格锚点不进公开集。

## 6. 里程碑

| 阶段 | 交付 | 验收 |
|---|---|---|
| B0 | 题族定义 + schema + 判分脚本骨架 | 每族 ≥2 个手写样例可跑通判分 |
| B1 | 生成器（合成 persona × 5 族） | 生成 200 单元；孪生成对率 100% |
| B2 | 三条基线（naive / 单路余弦 / 灵枢多路+时间） | 全中率与 A 均可复现（同 seed 同结果） |
| B3 | 公开版 v0.1 | README + 数据卡（覆盖范围/不适用）+ 一条命令可跑 |

## 7. 不适用条件（写进数据卡，避免误读）

- 不测「模型本身多聪明」：A 分受判分模型影响，跨 judge 不可比；
- 不测实时延迟（那是运行时面，另设）；
- F5 的「人格一致」是**行为可判**，不等于「有自我意识」；
- 本套不与 2.2 分数直接横比（题族权重不同）；只做同族对照。

## 8. 与已有工作的关系

- 2.2 报告的四条建议中，P0 粒度 / P0 时间 由本套 F2/F3 直接覆盖；
- P1 due（行为锁）由 F5 的「边界/议程」子类承接，但**默认不算失败**——先测「说了没说」，再由使用者裁定是否计入；
- P2 rerank 不进默认路径，故本套主臂**不含 rerank**（避免用成本换不显著的分）。
