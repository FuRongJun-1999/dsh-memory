> 使用者当场定性与裁定：「**这又是理论和工程脱节**」「这个节点数限额是我自己提的……当时提的
> 还附带了条件，遇到更多的检索节点，应该要**建立索引**，**明确检索条件**，和**不适用条件**，
> 而**不是扩大节点数**」。

> 同样适用于本稿——stg 索引只做**条件维的收敛**，不替代认知路径。

## 一、背景与定性

**#52 的工程事实**（已实证）：`md_cg/stg.py::_scan` 按 `list(index["nodes"].items())[:max_scan]`
在**条件过滤之前**做 id 字典序切片——限额被实现成「静默砍尾巴」，使用者当年附带的三件事
（建立索引 / 明确检索条件 / 明确不适用条件）**一件未落地**。

**定性（「理论/工程脱节」的第 n 次现身，同族形态谱）**：

| # | 理论（已设计） | 工程（实际） | 处置 |
|---|---|---|---|
| 1 | S1–S6 逐级收敛（检索路径契约） | 认知结构入库但检索不调用（审计五偏差） | 已修（门控接线 issue #25 / C-8） |
| 2 | 六要素全要素为检索面服务 | 验证方式/不适用条件两行未进默认检索 | 已修（0.7.0 §5.4） |
| 3 | 限额＝「该建索引/细化条件」的压力信号 | 限额＝字典序切片（本项 #52） | **本稿 + 第 1、2 层** |

共同主线（审计原文）：「认知结构被实现成『数据结构』而不是『计算路径』」；本项的变体是
「**设计约束被实现成实现细节**」——5000 的语义是「超限该收敛」，工程把语义丢了、只剩数字。

## 二、第 1、2 层（另批，不属本稿）

条件过滤先于截断（「明确检索条件」落到实现）、截断可观测（`truncated` + 提示 + 近期优先兜底）。
本稿设计以「第 1 层路径（全量快照遍历 + 条件过滤）」为**正确性基线**：索引路径必须与它逐位一致。

## 三、第 3 层设计（本稿主体）

### 3.1 目标形态

契约 §2 在 stg 三接口上的落地：「触碰节点数从 N(全库) 降到 域内 ∩ 条件匹配 ∩ 邻域」——
查询条件（session / layer / time_window）经**结构化倒排直取子集**，不再逐条遍历快照。

### 3.2 索引形态（主案：装载期内存倒排 + 写路径增量维护）

**主案**：不改任何磁盘格式，索引是**内存派生结构**：

- **构建**：`MdCG._load_index()` 完成后的首次 stg 访问时，一次 O(N) 快照流生成三张表：
  - `by_session: {sid | None: [ids]}`（`None` = 无会话归属，即 `unassigned` 兜底桶）；
  - `by_layer: {layer: [ids]}`；
  - `by_time: [(t, id)]`（有序，`t` 经既有 `trust.epoch_seconds` 归一；无有效时间戳的进 `_untimed`）。
- **维护**：与既有桶计数**同一写钩**（`_set_index_entry` / `_remove_index_entry` 处增量增删）。
- **不变量**：三张表恒为快照 keys 的划分（同源维护）；任一表缺失/代际不符 ⇒ **回退第 1 层全量遍历**
  （安全降级且**可观测**，与 postings「宁可慢，不可丢召回」同纪律）。
- **跨进程**：各进程装载时自建，无共享过期问题；多实例内存各持一份（1.7 万节点 ≈ 三张小表，可接受）。

**备选（记录不采纳理由）**：
- *快照内倒排*（`_index.json` 加段）：改最核心文件的 schema，装载/校验/compact/rebuild 全链兼容负担大；
- *独立文件*（走 postings 的指纹+重建模式）：引入跨进程过期面与重建时机问题，而本索引的源数据
  （快照字段）本就在内存——独立文件无增益。

### 3.3 读侧直取

- `timeline(session=X)`：`by_session[X]`（+ 既有的「x 会话不匹配」过滤语义逐位不变）→ 子集走既有排序链；
- `anchors(time_window)`：`by_time` 区间截取（二分）→ 子集；
- `consistency(layer)`：`by_layer[l]`；
- 截断语义与第 1、2 层完全一致（`truncated` / 近期优先）——索引只改「取数面」，不改「语义面」。

### 3.4 条件资格进 stg（「明确不适用条件」）

- 复用 read 面唯一单点 `judge_qualification`：对 stg 返回条目做资格判定（生效条件命中 /
  不适用条件拒绝 / 无从判定），结果随返回体带出（`qualification` 字段，语义与 read 面同口径）。
- **首验形态：只上报不过滤**（行为零变化，`MDCG_STG_QUALIFY=1` 显式开）；
  **次验形态（硬过滤，与 read 面同权）另立裁定**——因为 stg 的语义是「遍历视图」而非「召回 top-k」，
  过滤改变视图完整性，需设计者拍板。

### 3.5 flag 与回退（契约 §4 纪律）

- `MDCG_STG_INDEX=1` 显式开；默认关时＝第 1 层路径。
- **两条路径结果逐位一致**为等价性准入判据（同 postings 的「候选内加速、召回与全表一致」先例）。
- 收敛读数（`meta` 分阶段计数：子集大小 vs 全量 N）供编外复核逐项核对。

### 3.6 与既有机制的关系

- **postings（词法 bigram）**：正交可叠加——词法先收词、stg 索引收条件维；
- **桶（routing.bucket_dir，域级）**：正交；`route_key` 的 `observation_position` 一档与 layer/session 不同维；
- **refindex（`_refindex.json`）**：形态参考，非复用对象。

## 四、验收判据

1. **等价性**：flag 开/关，三接口返回体（除 `meta` 计数）逐位一致（快照对比）；
2. **收敛性**：`meta` 读数显示「实际遍历/触碰」从 N 降到子集（目标 ≤ 条件命中量级）；
3. **不劣化**：既有 stg 套件 + 第 1、2 层新守卫全绿；在役对照（timeline(session) 的 count 与条目集）不改；
4. **可观测**：索引命中/回退（表缺失/代际不符）均有 `meta` 计数与 reason；
5. **守卫与定点变异**：索引增删钩、回退路径、等价性各有断言与变异自证。

## 五、边界（不做的事）

- 不改默认启用（先 flag，逐项验证，再讨论默认开启）；不改 `max_scan` 数值与第 1、2 层语义；
- 不做 FTS 替代、不引入第二套时间/条件解析（复用 `trust.epoch_seconds` / `_view_session` / `judge_qualification` 单点）；
- 不动写入侧磁盘语义（索引是内存派生 + 同钩维护）。
