# 真源索引（通用机制）· N203 的替代路线 v0.3

> 状态：**裁定齐备，可开工**（三条裁决 + 一条简化指示，均 2026-09-28 使用者给出）
> 生效范围：v0.3 取代 v0.1/v0.2（v0.2 的两条待裁决按本条指示**撤回**，见 §12）。
> 使用者裁定与指示原文：
> · 「203 我们不改 dsh 的日志，我们单独建立记忆索引，同样使用认知图读，然后通过索引找日志。
>    这个方案是通用的，任何信息真源都能这样索引。」
> · 「①指针落点：真源身份指向 zstd 日志、区间指向确定性转写。②旧节点处置：按 §5 第 3 步软退休。
>    ③一次把外部真源也纳入首期，文本，图像，语音，视频…所有的文件都可以兼容，建立索引。」
> · 「索引使用文件名，路径，类型即可。任意文件通用，可读文本内容才细化摘要简介和补 ccg 条件检索，
>    而且这些多模态文件，往往会伴随可读文本简介。」

## 0. 为什么这条路比修 id 更对

N203 的现象是「日志索引节点 id 位置化 ⇒ 中途插话即永久错位 + 静默丢索引」。但位置化
id 只是**症状**：真正的根因是那条路**把真源正文拷进节点**（`scripts/dsh_log_index.py:575`
自陈「节点 id = dsh-log-<派生标识>-<章节序号>」，且模块头注明**不写 `doc_ref` / 不登记
Ledger**）。既然节点是正文的**拷贝**，它就只能靠「序号」这种脆弱身份认领自己；真源一变，
拷贝与身份一起失效，而 `if nid in nodes: skip`（`:611-613`）把失效表现成静默。

改 id 只是在拷贝模型里打补丁。使用者给的路线是换模型：**节点不存正文，存指向真源的索引
条目**——真源零改动，索引可重建，读的时候经索引回到真源。

**旁证（现场发现）**：`scripts/dsh_log_index.py:575` 的 docstring 自陈「节点 id =
`dsh-log-<派生标识>-<章节序号>`（**内容寻址**，跨重启幂等）」，而 `:610` 的实现是
`nid = f"dsh-log-{token}-{i:04d}"`——**同一条句子里「章节序号」与「内容寻址」互相矛盾**：
意图本就是内容寻址，落地退化成了序号。本方案等于把它真正做实（id 交给
`docindex.node_id`，内容寻址不再是措辞）。

## 1. 机制在仓内已存在（关键事实，勿重造）

`md_cg/refindex.py` 已经是这套东西的通用实现：

| 能力 | 现成实现 |
|---|---|
| 统一 ref 协议（指向真源的指针） | 节点 frontmatter `code_ref` / `doc_ref`（path / root / heading / level / lineno / end / anchor / **hash**）——`refindex.py:399-419` 两组 `_ref()` 构造 |
| 内容寻址的节点 id | `docindex.node_id(it)` / `codeindex.node_id(it)`（`refindex.add_items` 内统一调用） |
| 区间哈希（漂移判定） | `codeindex.region_hash(lines, lineno, end)`（`refindex.py:453`） |
| 按区间**回读真源**（单点） | `read_ref(ref, root=…)` → ok/stale/dangling + `text`（`refindex.py:470-484`） |
| 漂移 / 悬空巡检（只读、不抛、不改源） | `check_refs(cg, ledger=…)`（`refindex.py:490+`）；状态集 `ok/stale/dangling/unresolved/error` |
| 增量水位（不全量重扫） | `Ledger` + `<root>/_refindex.json`（源文件绝对路径为键，记 size/mtime + 区间） |
| 切片 | `docindex.extract(source, path, suffix)` → 每项自带 `lineno/end/hash/heading/anchor/level` |

⇒ **本方案不新造协议，只补一层「源适配器」**：把「任意真源」变成 refindex 能吃的「带区间的可寻址材料」。

## 2. 三层结构（本方案）

```
① 源适配器（Adapter）      真源 → 可寻址材料 + 区间表
   发现 discover() / 身份 identity() / 物化 materialize() / 密级 sensitivity()
② 索引（认知图 ref 节点）   一条 ref = 一个区间；id 内容寻址；正文可留摘要/标题（不留全量拷贝）
③ 回读（单点）             read_ref(区间) → 真源正文；check_refs → stale/dangling
```

**两层定位（本方案相对普通 doc_ref 的唯一扩展）**：日志的真源是 zstd JSONL，而可读区间落在
**确定性转写**上，所以 ref 要同时记：

- `src_*`：真源身份 —— 真源绝对路径 + 会话 uuid + workspace + **真源哈希**（staleness 判在真源上）；
- `span`：可读载体区间 —— 转写文件的 `lineno/end/hash`（回读落在转写上，复用既有 `read_ref`）。

这样「真源被删/被改」能报 `dangling/stale`，「转写重新生成」也不会让节点认错自己。

## 3. 为什么这同时消灭 N203 的两个后果

| N203 后果 | 新机制下的表现 |
|---|---|
| 中途插话 ⇒ 序号平移 ⇒ 整段错位 | **防静默不靠 id**：`docindex.node_id` 是 `path#heading_path` 寻址（`docindex.py:294-299`），同标题换正文时 **id 不变而 hash 变**（P1 实跑 `md_cg/test_logref.py` 守卫②）⇒ 判据必须是「hash + 行位全等才算已索引」。旧节点：**真源层**保留 `doc_ref.src.file_hash` 水位、可判 stale；**转写层**同 id 按 hash 覆写并计数（转写是同路径暂存物，被重生成后旧区间不保留） |
| `if nid in nodes: skip` ⇒ 静默丢索引 | 重跑幂等的判据从「id 撞了就跳」改成「区间哈希 + 行位全等才算已索引」；不一致即覆写并在报告里计数（不再静默）——变异回「id 撞即跳」后 `updated==0` 而区间哈希复核出现不一致，守卫必转红 |

## 4. 通用化边界（使用者要的「任何真源都能这样索引」）

| 真源形态 | 适配器 | 区间落点 | 状态 |
|---|---|---|---|
| 代码 / 文档（仓内文件） | 已有（codeindex / docindex） | 文件行区间 | **现成** |
| DSH 会话日志（zstd JSONL） | 新增（复用 `dsh_log_index` 的转写与章节切分） | 转写文件行区间 + 真源身份 | **本方案** |
| 工作区文档（大域） | 已有（`workspace_index.py` / doc_ref 多 root） | 文件行区间 | 现成 |
| 外部真源（URL / API / 远端库） | 需新适配器（拉取 → 本地缓存 → 行/字段区间 + 内容哈希） | 缓存物化件区间 + 远端身份（ETag/版本） | **后续**（未含在本方案首期） |
| 不可寻址真源（一次性管道 / 无稳定路径） | 不适用 | —— | 见 §8 不适用条件：退回拷贝模式 |

## 5. 迁移（真源零改动，节点面三步）

1. **新建**：按 §2 建立 ref 索引（首批 = 现有 DSH 会话），写进**临时库**先对账，不碰在役库；
2. **对账**：同一批会话在「旧位置化节点」与「新 ref 节点」上做内容比对（区间回读文本 vs 旧节点正文），确认零遗漏、零错位（这一步是 第5条 的固化解）；
3. **退休**：对账过后把旧位置化 `dsh-log-*` 节点**软退休**（`forget` 移 trash + 留痕，可 restore），不物理删除；**DSH 日志本身及其摄取脚本的读写语义不动**。

## 6. 守卫（新机制必须自带判别力）

守卫落成件：`md_cg/test_logref.py`（P1 起并入 `scripts/linux_verify.sh` 门禁）。

| 守卫 | 判据 | 红基线做法 |
|---|---|---|
| 幂等 | 同源重跑 → `updated == 0`、**节点 `doc_ref` 与当前源区间逐条一致**（区间哈希全 ok） | 定点变异把「hash+行位全等才算已索引」改回「id 撞即跳」→ 在**内容已变**的源上 `updated==0` 而区间哈希复核出现不一致 ⇒ 必转红（守卫①②） |
| 插话场景（两代构造） | v1 旧式 → 插话 v2：`missing/misplaced/roundtrip` 全 0、`updated == updated_expected`；**剔除根章**（最外层章 end=全文行数，任何改动都让它变）后旧式错位槽 ≥ 2——为 0 即报「对账无判别力」并失败 | 构造插入版源（插入点必须在**首条 user 消息之后**，否则改 `derive_session_token` 的 basis 会换掉旧式 id 空间），断言零静默跳过（守卫③） |
| 悬空 | 删**真源** → src 层 dangling；删**转写** → 区间层 dangling 而 **src 层仍 ok**（两层解耦，各自独立可判）；带 `regenerable` 的节点不被 `prune_dangling` 列入（计数透出），非 regenerable 的悬空节点**必须**被列入 | 临时目录删源/删转写，断言状态迁移与清退名单（守卫④） |
| 回读逐字节 | `read_ref(区间)` 的文本 == **转写**同区间切片 | 与 `docindex.extract` 同源断言（守卫③） |
| 密级跟源 | 索引节点密级 == `docindex.sensitivity_for(src["path"], None)` 的**真源路径判**（不得因索引而放宽，且不低于 internal）；落进 `crypto.ENCRYPTED_LEVELS` 时**报告必须出现加密告警计数**（否则 v1.0「误标 private → 加密 → 检索零命中」会静默复现） | 私有提示路径的合成真源 → 节点必须 private 且计数 > 0（守卫⑤） |
| path 口径 | `doc_ref.root` == 转写根、path 为**相对**路径；同 sid 跨 ws 时裸文件名口径必撞 id、`<ws>/<sid>/<sid>.md` 口径零撞（绝对 path 当 rel 在 `probe_ref` 里仍 status=ok = 既有实现不拦，故口径必须由落库侧写死） | 合成同 sid 跨 ws 夹具，断言零撞 id（守卫⑥） |

## 7. 分步落地（每步可独立验收，可停）

| 步 | 内容 | 验收 |
|---|---|---|
| P0 | 适配器接口 + 真源身份/区间表（纯函数，不写库） | 单测：给定日志 → 区间表；篡改一处 → 哈希变化可判 |
| P1 | ref 索引写入（临时库）+ 对账脚本 —— 落地件：适配器 `srcindex.session_src_id`/`log_units`、桥与读路径 `md_cg/logref.py`、入口 `scripts/_mdcg_reindex_dshlogs.py`（`--reconcile {off,generation,full}` / `--repair 1` / `--src-path {abs,rel,hash}`，**只写 tempfile 库**） | 与旧式位置化节点两代比对报告：新增 > 0、遗漏 = 0、错位 = 0，且旧式错位槽（剔根章）≥ 2（判别力）；守卫 `md_cg/test_logref.py` |
| P2 | 读路径接通（检索命中 → `read_ref` 回读真源区间）—— 落地件：`mcp_server._ref_call` 的 `read/get` 分支对带 `doc_ref.src` 的日志节点改走 `logref.read_index_node`（**区间文本仍由 `refindex.read_ref` 取**，只补 span 状态机与再生指路；非日志节点逐字不变），`with_src` 显式开真源身份层探针 | 端到端：问句 → 命中索引 → 取回原文区间（`md_cg/test_logref.py` 守卫⑦：逐字节 + 幂等 + 插入场景，含生产读面 7l-7n） |
| P3 | 守卫五条 + 红基线 | 上表全绿且变异必红 |
| P4 | 旧节点软退休 + 在役库切换 | 退休可 restore；检索面无回退 |

## 8. 不适用条件与诚实边界

- **不适用于不可寻址真源**（无稳定路径/一次性管道）：那时只能退回拷贝模式，并接受拷贝模型的错位风险——本方案不假装覆盖它。
- **不适用于跨机真源**：指针含绝对路径，跨机失效；要么改用「工作区锚 + 相对路径 + 内容哈希」的自洽校验，要么重新索引。
- **不解决真源本身的语义漂移**：索引只保证「指得准、读得到、改了知道」；真源内容里的事实是否过期，靠既有 `verification_state` 面，不在本机制内。
- **不引入外部服务**：仍零第三方依赖，仍走认知图与既有 op 面。
- **不是「不改 dsh 的日志」的豁免面**：本方案确不动 DSH 日志与其摄取脚本的读写语义；但**新索引路径要新增代码**，这属正常落地，不等于「零改动」。

## 10. 多模态推广（v0.3 按指示简化）：**通用层 + 细化层 + 伴随文本**

关键简化：**不必为每种模态设计 locator**。任意文件先用「文件名 / 路径 / 类型」进通用层；
只有当真源**本身可读文本**时才细化（摘要简介 + CCG 条件检索）；而多模态文件**往往自带可读文本
简介**，语义面就走那条伴随文本，无需解码器、无需模型。

### 10.1 通用层（任意文件，零解码、零模型、零第三方依赖）

```
条目 = { path, name, type, size, mtime, file_hash, reader=原文件 }
span      = whole（整文件粒度）
text_view = 文件名 + 路径 + 类型（+ 若有伴随可读文本，一并挂上——见 §10.3）
```

- **类型**判据＝扩展名 + 魔数嗅探（几十字节前缀即可，零依赖）；类型只进检索面与分组标签，
  **不决定「能不能索引」**——任何文件都能进通用层。
- 这一层覆盖文件索引的绝大多数用法：「我知道那个文件叫什么 / 在哪 / 是什么类型」。
- 哈希用文件级 sha256 ⇒ `stale`（真源被改）与 `dangling`（真源被删）都判得出来，复用 `check_refs`。

### 10.2 细化层（仅当真源含可读文本）

- **章节切分**：`docindex.extract` → 每节一条 ref（line 区间 + 区间哈希），并产**摘要/简介**；
- **补 CCG 条件检索**：正文含 `# 生效条件：` 一类 CCG 行的，走既有 `condition_space` 同源机制
  （`refindex.add_items` 已支持），让条件面参与检索与路由——这正是「可读文本才细化」的落点；
- 不可读文本（图像/音视频/二进制）**不强行细化**：它们停在通用层，靠 §10.3 的伴随文本获得语义面。

### 10.3 伴随文本：多模态的语义通道（替代 v0.2 的模型路线）

多模态文件在实践中**总是伴随可读文本**（使用者原话：「往往会伴随可读文本简介」）：

| 伴随形态 | 例 |
|---|---|
| 同名 sidecar | `a.png` ↔ `a.md` / `a.txt` / `a.json` / `a.caption` |
| 目录级说明 | 同目录 `README.md` / `_index.md` / 清单文件 |
| 文件内嵌文本段 | EXIF/XMP 的 Description/UserComment、ID3 标签、容器 title/comment |
| 项目清单 | 生成该媒体的脚本/配置/提示词（prompt 文件本身就是最好的简介） |

处理方式：**伴随文本本身就是真源**（有自己的路径与哈希）⇒ 照常索引（通用层 + 细化层照走）；
媒体条目与伴随文本条目**互相关联**（同一 `group`/目录锚）。于是语义检索由此进入：
查「海边日落视频」命中其伴随描述或 prompt 文件 → 经关联回到媒体文件本体。

### 10.4 撤回（v0.2 的两条待裁决，按本条指示不再需要）

- ~~媒体解码器（ffmpeg）~~ → 通用层是**整文件粒度**，首期不按时间点/区域切片 ⇒ 不需要解码器；
- ~~为媒体调模型产「派生文本」~~ → 语义面走**伴随文本**（真源自带）⇒ 首期不需要模型；
  仅当某媒体**确无任何伴随文本**又需要语义时才另议（列入 §12 后续可选，不进首期）。

## 11. 落地顺序（v0.3）

| 步 | 内容 | 验收 |
|---|---|---|
| P0 | 契约层：单位（`whole` / `line` 两类即可）+ `src_id`（路径+文件名+类型+文件哈希）+ 适配器接口 | 单测：任意文件可入通用层；改一字节 → 哈希变化可判 |
| P1 | 文本/日志细化：章节 ref（区间哈希）+ 摘要简介 + CCG 条件面 | 与旧节点对账：遗漏/错位 = 0 |
| P2 | 读路径：检索命中 → `read_ref` 回读（整文件 / 区间） | 端到端：问句 → 命中 → 取回 |
| P3 | 通用层全类型扫描（含图像/音视频/二进制走整文件条目） | 覆盖计数与不落项如实报出 |
| P4 | 伴随文本关联（sidecar / 目录说明 / 内嵌文本段 → `group` 关联） | 关联命中率对账 |
| P5 | 守卫五条（幂等 / 插话 / 悬空 / 回读逐字节 / 密级跟源）+ 红基线 | 变异必红 |
| P6 | 旧位置化节点**软退休**（可 restore）+ 在役切换 | 检索面无回退 |

## 12. 后续可选（非首期，明确不入本期实现）

1. **按时间点/区域切片回读**（音视频时间段、图像区域）：需解码器/图像库，属「粗粒度不够用」时再加；
2. **无伴随文本媒体的语义化**：可用 hive 委托模型产派生文本（派生文本亦是真源、照常索引，密级随真源）；
3. **跨机真源**：指针含绝对路径，跨机须改「工作区锚 + 相对路径 + 内容哈希」。

## 13. 不适用条件（沿用 §8，补两条）

- 不适用于**不可寻址真源**（无稳定路径/一次性管道）——退回拷贝模式并承担错位风险；
- 不适用于把「不改 dsh 的日志」读成「零改动」（新索引路径要新增代码，仅真源与既有摄取脚本读写语义不动）；
- **不适用于要求「索引即全量正文」的场景**：本机制存的是定位与文本面（文件名/路径/类型/摘要/条件），
  正文按需回读——这是「索引 + 真源」的分工，不是缺陷；
- 不适用于**无文件实体**的真源（纯流式/内存对象）：须先物化成有路径的文件。
