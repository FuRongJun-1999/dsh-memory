> **定位**：协作架构 v0.2 的**唯一真待定项**（群聊形态）的落地协议。
> **编制原则（使用者指示）**：**不需要完全原创**——QQ 群聊是现成的成熟工程，**照搬其成熟语义**；只改**两处**（见 §三）。
> **上游**：协作架构 v0.1 §五（群聊章，已逐条对照 DS Bot）／v0.2（§五：仅群聊形态待定）。

## 一 借什么：QQ 群聊语义 → 我们的落法

**核心洞察**：**QQ 群本身就是一个 append-only 消息流 ＋ 角色模型 ＋ @ 传唤**——与 v0.1 要的群聊**高度同构**。故**照搬**，不重造。

| QQ 成熟语义 | 我们的落法 | 改动 |
|---|---|---|
| **群**（群号／群名／成员／**群主·管理员·成员**三级角色） | `crew.json`（群 id／名／成员／角色） | **照搬** |
| **消息流**（时间序、只增） | `chat.jsonl`（append-only） | **照搬**（它天然同构账本） |
| 消息字段（发送者／时间／内容／类型） | `{ts, from, text, kind, refs}` | 加 `refs`（待决项／issue／job 引用） |
| **@ 定向传唤** | `@name` → **必须带待决项** | **加约束**（v0.1 已定） |
| 群公告 ／ 精华消息 | 团队 **L0**（`L0.md`） | **照搬** |
| **撤回** | **记撤回事件**（不删原文） | **改**（见 §三·A） |
| **自由发言** | **显式发言令牌**（租约 ＋ 到期） | **改**（见 §三·B） |
| 禁言 ／ 踢人 | 权限动作（**记事件**，不改成员表） | **照搬**（落成事件） |
| 群文件 | 交付物（指向 `job_id` ／ issue） | **照搬** |
| 消息漫游 ／ 检索 | 按 `ts`／`from`／`refs` 检索 | **照搬** |

⇒ **十项里八项照搬，只改两项。**

## 二 消息格式（照搬 QQ，加一个 refs）

```jsonl
{"ts": 1791514708.79, "from": "admin", "kind": "text", "text": "@dev 请核 issue#7 的删除闸", "refs": ["issue:7", "job:h_dsh端_协作架构_输出单元_0004"], "id": "msg_<sha1前12>"}
```

| 字段 | 语义 | 约束 |
|---|---|---|
| `ts` | 时间（epoch 秒，浮点） | 单调递增（同秒内按写入序） |
| `from` | 发送者 | 须在 `crew.json` 成员表内 |
| `kind` | `text`／`pass`／`system`／`retract`／`token` | 闭集 |
| `text` | 正文 | `pass` 可为空（但**事件必须存在**） |
| `refs` | 引用（待决项／issue／job） | **@ 传唤时非空**（见 §三·C） |
| `id` | 消息指纹（内容 sha1 前 12） | 同内容幂等去重（同账本纪律） |

## 三 只改的两处（＋ 一处从 v0.1 继承）

### A. 撤回 → **记事件，不删原文**（改）

QQ 的撤回是**删除**；我们**不删**——追加一条 `kind=retract` 的事件，带 `refs=[msg:<被撤消息 id>]`。
**理由**：与账本 append-only 铁律一致（v0.1 已定「PASS 也要落盘，否则「没说话」与「没参与」不可区分」）；**删除会让审计面出现空洞**。

### B. 自由发言 → **显式发言令牌**（改）

QQ 群**谁都能说**；我们**加互斥**——主持人发放令牌（含到期时间），超时即收回。
**理由（v0.1 已论证）**：DS Bot 靠「上一人 posted 或 passed」隐式推断发言权交还，**成员崩溃或长时间思考时无法区分「在说」与「死了」**；改为显式租约后，与蜂巢 `claimed.lock`、悬赏站 `lease` **同构，一套机制三处复用**。

### C. @ 传唤必须带待决项（**继承 v0.1**）

@ 必须携带 `refs`（待决项或信息缺口）；**无理由的传唤按噪声记账在发起者头上**——对齐悬赏站「被拒命令记在尝试者头上」的防刷单口径。
**理由（v0.1 已论证）**：否则群聊退化成广播风暴，注意力预算被无差别消耗。

## 四 与蜂巢的接驳（v0.1 §5.1 的边界，一字不改）

**人可以对群聊说话，群聊不可以对蜂巢下调度指令。** 群聊唯一的出口是 **spec**——由 admin 写成 `spec.json` 并走 `hive_spawn`／`submit`（工作纪律第 17 条）。

| 层 | 可做 | **不可做** |
|---|---|---|
| 群聊（本协议） | 澄清意图、展示状态、记待决项、发放令牌 | ❌ 不产出 `claimed.lock`、不产出 `depends_on`、不写账本 |
| 蜂巢（执行面） | 进程／DAG／群体三层调度 | ❌ 不读群聊自然语言作调度依据 |
