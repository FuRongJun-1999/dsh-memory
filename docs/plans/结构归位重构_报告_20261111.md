### 2.1 shim 为什么**不能**写成一行 `from .govern.x import *`

这是本轮踩得最深的一个坑，值得单列。星号导入**复制名字、不绑定模块**，于是：

* `audit.VERIFIERS[k] = fn`（注册表写入）、`audit.default_policy_path = lambda: ...`
  （测试注入策略定位）这类**重新绑定**会被钉在 shim 局部，真源看不到 ⇒ 注入静默
  失效。实测后果极其严重：`test_issue43_default_policy` 的 `_dfl_policy` 注入失默后，
  **策略闸按真实包内策略放行**，本该 fail-closed 的场景静默变成正常写入（G3a/G3b/G3e
  三红 + `test_mr_m2` C4b 红）。
* `audit.ACCEPT` / `REJECT` / `DEFER` / `BLINDSPOT` 是**元组解包常量**，机械按「首字符
  非下划线」枚举 `__all__` 会漏掉它们（它们在 `a, b, c = ...` 的 Tuple 目标里），而
  调用点确实按模块属性访问（`if st == audit.ACCEPT`）⇒ `AttributeError`。

因此 shim 采用 PEP 562：`__getattr__` 转发（读取落在真源上）、`__setattr__` 对
**已存在的真源名** fail-loud（不静默失效）、`__doc__`/`__all__` 显式绑定成真源的
（模块字典里已有这两个键，PEP 562 对它们根本不触发）。

### 2.2 搬家真正的炸药：`__file__` 深度

`audit.package_root()` 与 `conformance.DEFAULT_ROOT`/`whitebox_kb` 都是
`os.path.dirname(os.path.dirname(abspath(__file__)))` —— **数 dirname 次数**。
迁入子包后深了一层，于是：

* `audit` 把包内随发的策略定位成 `md_cg/data/policy.json`（不存在）⇒ **全仓每一次
  写入都被 fail-closed 判成 `policy_unavailable`**（实测：20 个 audit 测试里 19 个红，
  `test_auditview` 26 处红）。
* `conformance` 把 `DEFAULT_ROOT` 算成 `md_cg/data/mdcg`、把白箱目录算成
  `md_cg/govern/whitebox_kb`——两者都**静默指空**（不抛错，只是数据面变空，巡检读不到
  任何节点却仍出报告）。

修法：两处都改为「向上找到名为 `md_cg` 的那一层」（结构性判定，搬家不再改变结果），
并在注释里写明事故现场。

### 2.3 同型第二炸药：**读源码型守卫**对着 shim 判据

21 个测试文件用 `md_cg/x.py` 路径串或 `x.__file__` 读源码做断言。迁移后这些路径指向
**零逻辑 shim**，于是：数量类断言恒得 0（恒红）、否定类断言恒真（**假绿**）。
更隐蔽的是 `inspect.getsource(consistency)`（`test_cons200`）与 AST 扫 `_KD` 字面量
（`test_issue472`）。

处理原则：**源码面读真源（`govern/`），行为面继续用 shim（等价）**。逐件处理了
14 个测试文件（见 §7.3），其中 3 处需要「历史路径 ≠ 当前路径」的分叉处理
（`test_issue190` / `test_issue294` 的 `git log -S` 必须扫历史路径、`git show HEAD:`
必须扫当前路径）。

### 2.4 一处行为变更（有意为之，需审阅）

`govern/revise.py::_write_new` 原为 `from ..mcp_server import _cg_dispatch`
（函数内）。迁入 `govern/` 后这条被 `_verify.py` 判成 **govern 反向依赖 adapter**

解除属第二阶段（写入链下沉 kernel/iface）。

## 5. 任务 5：测试目录重整 —— **判定：不动**

### 5.1 先读收集约定（任务要求）

`md_cg/run_tests.py:85-88` 的收集面是：

```python
for f in sorted(glob.glob(os.path.join(_REPO, "md_cg", "test_*.py"))):
    stem = os.path.splitext(os.path.basename(f))[0]
    out.append(("md_cg", f"md_cg.{stem}",
                [[sys.executable, "-X", "utf8", "-m", f"md_cg.{stem}"]]))
```

即收集面**只认 `md_cg/` 目录直属的 `test_*.py`**，并以 `-m md_cg.{stem}` 运行。
`scripts/run_tests.py:132` 的 `_discovered_files()` 用的是 `md_cg/**/test_*.py`
（recursive），**两个入口的收集面已经不一致**——这一点本身就是不能贸然移动的理由。

### 5.2 实测的风险面（这是「不动」的实证依据，不是推测）

| 依赖面 | 实测数量 | 挪动后的后果 |
|---|---|---|
| 测试里 `__file__` 出现次数 | **651** | 许多用于定位仓根/夹具目录 |
| `dirname(dirname(__file__))` 或 `parents[1]`（定位仓根） | **382** | 搬进子包后全部指向 `md_cg/` 而非仓根 |
| 测试内相对导入（`from . import X`） | **754** | 搬进子包后需全部补深一层 |
| 指向 `md_cg/test_*.py` 的**路径串** | **324** | 字符串不会随 `git mv` 更新 ⇒ 静默失效 |
| 测试内 `-m md_cg.test_*` 调用点 | **100** | 改收集面即全部失效 |
| **无显式被测面**（无相对导入）的测试 | **336 / 631** | 挪动后连「它测谁」都无从判断 |
| **跨多个层**的测试 | **219** | 「按层分目录」无法落地（一个测试测多层） |

另外两条结构性问题：

* `tests/`（复数）已有一套 **shim 机制**：27 个文件是薄转发（
  `from md_cg.test_bm25_pool_view import run_guard, MUTATIONS`），而
  `scripts/run_tests.py::ROOT_TESTS` 只收**具名裁决清单**的 3 件。也就是说仓内已经
  有过一次「把测试搬出去 + 留转发」的尝试，并且**留下了两条收集入口不一致**的现状。
* `run_tests.py:224-228` 有「零选中拒绝以 0/0 通过收场」的 fail-closed 门。把 631 个
  测试从收集面移走，会让它先报 `rc=2`（看起来像坏了）而不是「搬成功了」。

### 5.3 结论与替代产出

**不搬。** 移动的收益（目录整洁）远低于代价（631 个文件的历史与路径语义、两条收集
入口、`tests/` shim 双重机制、336 个无被测面件静默失效风险）。任务书明确允许
「若移动风险高于收益，写清楚为什么不动，并提供映射表替代」。

**替代产出**：`docs/plans/测试到模块映射_20261111.md`（631 行），对每个测试给出
被测模块与归属层。它同时是一份**第二阶段拆分的安全网**：拆分 `mdcos` / `mdcg` /
`mcp_server` 时，改哪个模块该跑哪些测试，可以直接查表。

**建议（第二阶段做，不在本轮）**：
1. 先把**两条收集入口统一**（`md_cg/run_tests.py` 的 glob 与
   `scripts/run_tests.py::_discovered_files()` 对齐到 `recursive=True`），再谈移动；
2. 按「被测面唯一且单层」的测试先搬（可用映射表筛：跨层 219 个先不动，剩 412 个里
   挑单层件）；
3. 迁移时**同时**改路径串（324 处）与 `-m` 调用（100 处），并保留 `tests/` 式转发。
