### 1.3 六要素与索引

**（a）六要素本来就有"图的索引角色"** —— `docs/theory/智能论3.4.md:3053-3059` 表头「要素 \| 标记 \| 内容 \| **图的索引角色**」，**只有 4 行**（功能名/生效条件/子功能/执行）。配套 `:3043-3045`「**注释 = 节点的名（以名举实）：图的检索 = 条件词 → 节点**……无注释 = 节点无名 = 图断裂」；`docs/theory/白箱智能是什么？.md:423/804` CCG =「以『条件词 → 节点』为检索面的代码能力索引」。

**（b）条件空间是 4 维**（`docs/mdcg/认知图_条件空间合成与生效条件口径_v0.1.md:4`）：载体/位置 · **时间** · 方法 · 约束。**因果不在其中。**

**（c）时间与因果的现存身份**：时间 = 条件空间 4 槽之一 + 双时间轴 `valid_from/valid_until`（**已入索引**但**只在显式 `validity=True` 时过滤**）；因果 = `edges` 的 `relation=="causal"` + 时空图 `temporal_coordinate`/`sequential` 边（**不进索引、不进默认检索**）。

**（d）索引现状**：`_index.json = {nodes, buckets, _fingerprint}` 扁平快照（`md_cg/mdcg.py:1646-1651`）；与条件空间有关的只有 `time_window`(:1572) 与 `observation_position`(:1590) 两个标量。**无六要素轴、无时间轴、无因果轴。**

**（e）结论**：「按六要素／按时间与因果重建索引」在文档里**零处** ⇒ 本设计是**新提案**；其合法性来自 §1.3(a) 那张表——**六要素本来就是"图的检索面"**，我们要做的是把表从 4 行长成 6 行、并把它从"注释即索引"落成真正的索引结构。

## 二、设计目标（可判）

1. **睡眠成为一条有真源步骤序列的周期**（本仓从"欠定义"到"有设计正身"）。
2. **自迭代获得驱动源**：只在纪律允许的范围内自动（确定性 + 可预演 + 可回滚；**LLM 依赖动作永不自动**）。
3. **按六要素的索引重建落地**：六要素从"4 行索引角色 + 只当资格门槛"升级为**6 行 + 真正的重建轴**；并补**时间**与**因果**两条图检索面。
4. **自动整理不碰主库**：一切改动先落在**影子副本**上，周期合并（裁定 1）。
5. **可观测**：每轮睡眠/自迭代都有台账与判据读数（补 `缺口矩阵 #27` 的"无治理前后数字"）。
6. **不破既有纪律**：索引仍是派生物、可重建、逐字节确定；不自动删节点；不改 `forget` 的显式语义。

## 四、副本迭代与周期合并（裁定 1）

> 裁定原话：「周期性改库不用担心。在开启时，使用一个副本进行迭代整理。完成后才周期性合并。周期设为一小时一次，且在睡眠时间开启，可由用户调整。」

### 4.1 形态：影子副本（shadow），不做原地整理

```
主库 <root>/                       ← 生产只读；睡眠周期绝不在此写
影子 <state_root>/sleep/shadow/    ← 每轮从主库物化的副本（含 _index.json 与 md 源）
合并 <root>/  ← 仅在「合并阶段」按差异集重放；每节点一条 before/after 留痕
```

**为什么是影子而不是"锁主库再整理"**：跨进程无互斥（§1.6 第 1 行）⇒ 原地整理会与生产写方并发改同一个 `_index.json`。影子把"整理"与"生产"在物理上分开，**结构上避开了并发面**（这正是裁定 1 的价值所在）。

### 4.2 四阶段协议

| 阶段 | 动作 | 判据 |
|---|---|---|
| **① 物化** | 从主库快照出副本（记录**基准水位**：`_index.json` 指纹 + `_index_log` 各分片 stat + `_deletions.jsonl` 偏移） | 副本可独立开库；主库零写入（可用主库文件 mtime 不变作判据） |
| **② 迭代** | 在副本上跑 §3.1 的 2–7 步（归纳/升层/去污染/权重/索引重建/记录） | 副本内 `_evolution` 台账完整；每步读数可出 |
| **③ 对账** | 算**差异集** `Δ = {节点 id → (before, after)}`，并逐项过三闸：<br>· 保护闸（`protect.py` 三层，衰减须有 floor，见 §七.3）<br>· tombstone 闸（主库在副本期间被 `forget` 的 id **不得复活**：读 `_deletions.jsonl` 增量）<br>· 并发闸（主库在副本期间被改动过的同一 id → **主库优先**，该 id 记 `conflict` 挂起，不合并） | 差异集为空 ⇒ 整轮跳过（零写入） |
| **④ 合并** | 按 Δ 逐节点重放到主库：写节点 + 标脏 + `evolution.record` 每条 before/after | **幂等**（同批只合并一次，批次 id 落台账）；**可回退**（沿用 `weights.rollback` 形态的反向 apply） |

### 4.3 合并要复用的既有三件套（不新造）

仓内已有"自动改库"的成熟形态，**合并层直接复用、不另起一套**：

- **预演**：`weights.recalc(apply=False)` 先出报表 + samples（`md_cg/weights.py:472-568`）。
- **逐节点留痕**：`_maintain.jsonl` 每节点一条（`:544-549`）+ `evolution.record` 的 `pattern/missing/action/state/evidence`（`md_cg/evolution.py:2-28`）。
- **反向 apply**：`weights.rollback`（按 batch 或 entry_ids 写回 `before`，自己再记一条 `importance_rollback`，`:572-616`）。

### 4.4 周期与睡眠时段（可由用户调整）

| env | 缺省 | 语义 |
|---|---|---|
| `MDCG_SLEEP` | `"1"`（**开**，对齐裁定"显式开启"） | 睡眠周期总开关 |
| `MDCG_SLEEP_INTERVAL` | `"3600"`（秒） | 周期，**一小时一次**（裁定 1） |
| `MDCG_SLEEP_WINDOW` | `"23:00-07:00"`（建议值） | **睡眠时段**（本地时间）；**留空 = 全时段**；支持跨午夜；窗口外只记账不迭代 |
| `MDCG_SLEEP_MERGE` | `"ask"`（建议值） | 合并策略：`auto`（窗口内自动合并）/ `ask`（只出差异集待人工放行）/ `never` |
| `MDCG_SLEEP_SHADOW` | `""` | 影子根（缺省 `state_root()/sleep/shadow`） |

> **缺省取向需裁定**：§十-1（合并是否缺省自动）。建议 `ask` 起步——理由：仓内纪律「未验证不固化」与「依赖 LLM 的固化永不自动」，且合并是唯一碰主库的动作。

## 五、六要素索引（裁定 2）

> 裁定原话：「『验证方式 / 不适用条件』是赋予索引角色，**以什么方式验证，什么条件下不适用。这是需要检索的。**」

### 5.1 把理论那张表从 4 行补成 6 行

| 要素 | 图的索引角色（理论 `智能论3.4.md:3053-3059` 原文） | 索引键（本设计） | 检索用法 |
|---|---|---|---|
| 功能名 | 条件节点（语义） | 语义符号 | 已有 |
| 生效条件 | 条件节点（when——路由门槛） | 条件词 | 已有（S2 门控） |
| 子功能 | 子功能节点（结构——可检索） | 结构词 | 已有 |
| 执行 | 执行词节点（how——机制检索） | 机制词 | 已有 |
| **验证方式**（新增） | —— | **后置条件词** | 「**是怎么验证的 / 用什么方法证明的**」——按验证手段检索 |
| **不适用条件**（新增） | —— | **拒绝域词** | 「**什么条件下不适用**」——按边界检索 |

### 5.2 一个必须处理的既有耦合（关键约束）

仓内检索面已有一条**负条件判据**：`md_cg/mdcg.py::judge_qualification` 会把 frontmatter 的 `non_applicable_conditions` **按空白切词、任一词命中当前情境即判 REJECT**。若把"不适用条件"同时做成**正面检索键**，两条语义会在同一个字段上打架。

**设计约束**：拒绝域命中**必须标记为"边界命中"**，与资格判定的 REJECT 分开计数、分开呈现——即：

- 检索"什么条件下不适用" → 该节点以 **`boundary_hit` 命中**（可召回、可展示）；
- 该节点的**正例资格**不受影响（不因边界命中就 REJECT 它）。

这条必须在实现前落成判据，否则会重现记忆里那次「检索面 REJECT 46→0」的返工。

### 5.3 重建协议（四条硬约束）

1. **幂等**：同源重建必得同一索引 ⇒ 以 `_fingerprint` 对拍。
2. **增量优先**：指纹未变则跳过（照抄 `csre_freshness`）。
3. **可回退**：重建只覆盖派生物，源面逐字节不变（可判）。
4. **可对拍**：守卫断言"重建前后合法次序逐位不变"。

### 5.4 与检索的关系

新增轴**默认不进默认检索路径**（守"默认链路零行为变更"）：以**新路**形态加入 `paths`（如 `six_elem`），由调用方显式开启或经睡眠周期出读数后再裁定转正。

## 六、图检索路：因果与时间（裁定 3）

### 6.1 定位（照调研结论写）

- **理论给授权，契约给模型**：照抄 `docs/hive/检索路径与认知结构契约_v0.1.md:21-53` 的 **S3** ——「以 (S1∩S2) 命中为种子，沿 edges 双向扩散 N 跳、按跳数衰减；**不走全表**」「**不得引入未通过 S2 门控的节点**」，**默认关**。
- **不新造遍历原语**：因果链遍历**已有完整实现**（`md_cg/chain.py`，含 14 类边权、`MAX_DEPTH=5`、`decay=0.9`），直接复用；**禁止**另写一套边权表（仓内"真源唯一"纪律）。

### 6.2 因果路（`causal`）

| 项 | 取值 | 来源 |
|---|---|---|
| 种子 | `ranked["lexical"] + ranked["entity"]`（复用既有口径）或改走 S3 口径 `(S1∩S2) 命中` | `md_cg/mdcos.py:1493`、`md_cg/mdcg.py:3482-3486` |
| 边权 | `chain.edge_weight()` = 类型 base × 边 confidence | `md_cg/chain.py:82-91`（表 `:28-47`） |
| 跳数/衰减 | `MAX_DEPTH_DEFAULT=5` / `decay=0.9` | `md_cg/chain.py:55`、`:283` |
| 打分 | `种子分 × 链累积权重 × decay^跳数` | `md_cg/chain.py:289`、`:311` |
| 融合位置 | `search_rrf` 的 `ranked` 字典，按 `w/(RRF_K+rank)` 融合 | `md_cg/mdcos.py:1481-1503`、`:1519-1525` |
| 融合口径 | 缺省 **`max`**（单路独有召回型，`sum` 会系统性低估） | 先例 `md_cg/mcp_server.py:3359-3362` |

### 6.3 时间路（`temporal`）

- **形态不同：时间天然是"1 跳"**，没有多跳语义 ⇒ 它更像 **S4 层级激活的同类（排名项）**，而不是扩散路。
- **边权（时间邻近度）目前零实现**；最小可选口径 `exp(-|Δt| / τ)`，τ 由 `time_axis` 校准——**注意：这是工程口径的类比迁移**，理论原文（`智能论3.4.md:2122-2125` 的 `exp(-γ·t)`）说的是 **confidence 衰减**，不是时间邻近度。**出实现时必须显式标注这一点**。
- 种子不能来自词法命中（时间类问句常词面零重叠）⇒ 取**时间算子/区间命中集**（把 `stg.anchors` 的 `during/contains/overlaps/equals` 语义改成从**索引标量**直读，不再 `_scan` 全库）。

## 七、权重刷新与衰减（裁定 4）

> 裁定原话：「**显然是分数**，被经常调用的记忆其权重被刷新，不被调用的记忆，其权重衰减。这个也是本来就有的理论设计。」

### 7.1 按裁定定形态

- **形态 = 分数乘子**（不是并列键）：`score ← score × w_refresh(node)`，其中 `w_refresh` 由"访问刷新 + 时间衰减"合成。
- **刷新来源**：`access_count` / `last_access`（现只记账、且**不在索引条目里** — §1.5(c) 卡点）。
- **衰减核**：**必须复用** `md_cg/whitebox_kb/aeis_core/time_core.py` 的 `credit` 族（该模块 docstring 明令「任何在它之外出现的衰减核实现都是 bug」）；形态与 `智能论3.4.md:2122-2125` 的 `exp(-γ·t)` 同族。
- **刷新/降权的门槛与步长**：照抄 AEIS `consolidate_cycle` 的既有取值（`rehearsal_threshold=0.7`、`degrade_threshold=0.2`、`gain=0.01`、`access_count % 10 == 0` 才 +gain），因为这些是本仓**已成文**的参数，不自行发明。

### 7.2 实现路径（取风险最小的一条）

**卡点先解**：把 `access_count` / `last_access`（或其派生的 `refresh` 分数）**加进索引条目**（与 `time_window`/`observation_position` 同为扁指标量的先例，`md_cg/mdcg.py:1572/1590`）——否则检索拿不到这两个数，只能读盘，违反"检索不写少读"。

**两段落地**：

1. **第一段（不动主分数）**：新路 `refresh` 参与 RRF（与 `causal`/`temporal` 同形）。**published 读数零位移**可判。
2. **第二段（动主分数）**：按裁定做成乘子。**必须先双侧同改**——Python `_score` 与 Rust `sort_path`（`rust/src/retrieval.rs:201-220`，对拍见 `docs/eval/优化第一批…_v1.0.md:218-221`），并加"合法次序逐位不变"的对拍守卫；**并如实披露 published 检索读数会变**。

> 建议：第一段先做（可用本件 §九 的验收判据量出"旧记忆干扰"的下降幅度），第二段等第一段读数出来再裁。

### 7.3 必须补的第二道闸（移植隐患）

AEIS 的 `decay_cycle` **没有 floor**，而 md_cg 的保护判定是**即时读 `importance ≥ 0.70`**（`md_cg/protect.py:135-151`）⇒ **衰减穿过 0.70 会让节点自动失去保护**。移植时必须：

- 给衰减项加 **floor**（照 `md_cg/weights.py:459` 的 `IMPORTANCE_PROTECT=0.70` 用法）；
- 保留 `weights.recalc` 已有的"`after ≥ 0.70` 自动补写 `protected`"（`:531-534`）行为；
- 记忆里那条语义边界：**不可遗忘 ≠ 不可覆盖**，衰减属"降级/搬迁"族，须走 `guard_move` 语义（`md_cg/protect.py:272-282`），且"降级不得误实现为删除记录"。

### 7.4 回滚与预演（照既有三件套）

`weights.recalc(apply=False)` 预演 → `_maintain.jsonl` 逐节点 before/after → `weights.rollback` 反向 apply。**衰减/刷新机制必须自带同款三件套**（AEIS 侧没有预演/回滚，这是移植时的净增工作量）。
