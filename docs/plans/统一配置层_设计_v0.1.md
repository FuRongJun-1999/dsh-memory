| 分层 | 三面（环境面／调参面／标定面）；环境面**不进用户配置文件**，只登记分类 |

## 1. 分层表（谁进用户配置文件）

| face（盘点口径） | 进 `~/.mdcg/config.toml` | 进 registry 调参序列 | 判据 |
|---|---|---|---|
| **环境面 ENV**（90） | **否** | **否**（只登记分类） | 部署与隔离必需：`MDCG_ROOT`／`MDCG_AUX_ROOT`／`MDCG_STATE_ROOT`／`MDCG_DATA_ROOT`／`MDCG_TOKEN`／`MDCG_MASTER_KEY`／`MDCG_BRAIN_PYTHONPATH`／密级／解释器／**写路径白名单**。改了会**换库或换身份**，不是「用户可调参数」 |
| **调参面 TUNE**（173） | 是 | 是 | 阈值／开关／预算／条数／超时（检索门控、缓存容量、限流、巡检间隔、插件 config 键） |
| **标定面 CALIB**（210） | 是 | 是 | 默认值本身需实验找较优；进配置文件但**必须带 `status`／`evidence`／`since`** |

**为什么环境面不进用户配置文件**：用户配置文件是「用户自己的偏好」面，而环境面
是「这一份部署是哪一个库、以什么身份、能不能写哪根」——把它交给用户配置文件，
等于让「换个用户」变成「换库/换身份」的静默事故源。环境面的正道是**部署期 env**
（CI／容器／服务单元），配合 `md_cg/datapath.py` 的优先级链。

机器可读形态：`md_cg/config_registry.py::LAYER_TABLE`；全量环境面名字分类登记：
`md_cg/config_registry.py::env_catalog()`（90 条，**只登记分类，不登记缺省值**）。

## 2. 单一用户落文件与优先级

### 2.1 文件

```
~/.mdcg/config.toml        # 用户配置文件（唯一）
```

`~/.mdcg/` **已是既有用户面**（`md_cg/datapath.py::aux_root()` → `DEFAULT_AUX_DIRNAME = ".mdcg"`，
逐字保留的历史默认；`md_cg/tokens.py::DEFAULT_TOKEN_FILE = ~/.mdcg/_tokens.json`；
另有 `~/.mdcg/master.key`、`~/.mdcg/_links.json`、`~/.mdcg/swarm/`、`~/.mdcg/sustain/`）。
把用户配置放进这里＝**零新概念、零新目录**，且天然与「仓外、0600」同一体例。

### 2.2 优先级（唯一口径）

```
① 显式 CLI / env 覆盖（进程级，最高）
        ↓ 未给时
② 用户配置文件 ~/.mdcg/config.toml
        ↓ 未给时
③ 标定默认（registry / 源码常量）
```

### 2.3 「env 是覆盖面，不是配置面」

**保留 env 全覆盖**（大量测试与 CI 靠 env 隔离；`md_cg/test_sleep_p1.py` 一类的
守卫显式改 env 做沙箱）。但须在文档与 `cg(op=help)` 层面明写：

> env 是**覆盖面**（override surface）——用于部署、隔离、测试与临时实验；
> 它不是**配置面**（configuration surface）——用户的长期偏好写进
> `~/.mdcg/config.toml`，不要写进 shell profile / 服务 env 文件。

### 2.4 文件格式与示例（草案）

TOML（无第三方依赖，`tomllib` 自 Python 3.11 起为标准库；本机解释器 3.12）：

```toml
# ~/.mdcg/config.toml —— 统一配置层（用户偏好面）
# 规则：只写「与默认不同」的项；缺省即用标定默认（registry）。
# 环境面（根路径/凭据/身份/密级/解释器/写路径白名单）**不放这里**。
schema_version = "0.1"

[tune]                      # 调参面
MDCG_SPREAD_HOPS = 2
MDCG_HOTCACHE = true
MDCG_HOTCACHE_MAX_NODES = 1024      # issue #28：池 567 节点 > 缺省 256
MDCG_READ_CACHE = true
MDCG_GATE_S3_SPREAD = false

[calib]                     # 标定面（改它 = 声明你接受「默认值是可标定项」）
MDCG_RETRIEVAL_PIPELINE = false     # 总闸：**保持缺省关**
MDCG_GATE_S1_DOMAIN = false         # 子闸缺省现为「1」开——见 §7 真问题 c
MDCG_REACH_TTL = 600.0

[meta]                      # 审计：谁在何时按什么依据改的（写入口自动维护）
MDCG_HOTCACHE_MAX_NODES = { since = "0.5.1", evidence = "bench:locomo-zh-500 n=567", by = "designer" }
```

**每个值域的校验**由生成件 `md_cg/config_validate.py` 提供：
`validate(name, raw) → (ok, coerced, err)`，`python -X utf8 -m md_cg.config_validate --name X --value V`。
未登记约束的参数**不臆造约束**（只做类型归一）。

## 3. 写入口：签名与权限矩阵

### 3.1 程序化写入口（**第二批实现**；本批只定签名）

```python
# md_cg/config_store.py（第二批）
def write_params(values: dict[str, object], *, by: str,
                 evidence: str | None = None,
                 confirm: bool = False,
                 dry_run: bool = False) -> dict:
    """把 values（键 = env 名）写入 ~/.mdcg/config.toml。

    契约：
      1) **值域校验**：逐个过 config_validate.validate；任一不过 ⇒ 整批不做
         （fail-closed，不部分写入）。
      2) **权限闸**：按调用者角色 × 参数类别查 ROLE_WRITE_MATRIX；不通过的键
         整批拒绝并逐键列明（不静默丢）。`security` 类须 confirm=True。
      3) **幂等**：写入后逐字节比对；值未变则**不写盘、不备份**（返回 written=False）。
      4) **改前备份**：真写时先把现文件复制到
         ~/.mdcg/backup/config.toml.<utc_ts>.bak（同目录、0600），再原子替换
         （写 .tmp + os.replace）。
      5) **审计**：更新 [meta] 段的 since/evidence/by（由 registry 的
         `status`/`evidence`/`since` 规格对齐）。
    返回 {"written": bool, "backup": path|None, "rejected": [(k, why)], ...}
    """

def read_params() -> dict[str, object]: ...
def explain(name: str) -> dict:   # 三来源合并视图：env?/file?/标定默认
    ...
```

判据与既有体例的关系：`md_cg/tokens.py` 已有「读-改-写临界区
（`_store_lock`，跨进程排它 + `TOKEN_LOCK_TIMEOUT` 超时 fail-closed）」与
「原子替换、0600」——写入口**复用同一套存储纪律**，不另造。

### 3.2 权限矩阵（沿用 `md_cg/tokens.py::ROLE_SPECS` 角色名）

| 角色 | deployment | tuning | calibration | security |
|---|---|---|---|---|
| `designer` | —（改它＝部署动作，不走本入口） | ✅ | ✅（`evidence` 必填） | ✅（须 `confirm=True`） |
| `orchestr` | — | ✖ | ✖ | ✖ |
| `record` / `reflect` / `verify` | — | ✖ | ✖ | ✖ |
| `guest` | — | ✖ | ✖ | ✖ |

* 收窄口径与 `tokens.py::_narrow` 一致：**子权限只能收窄**；本入口是**额外闸门**，
  不替代 `tokens` 的 `can_admin`/`can_write` 判据（两层各自 fail-closed）。
* 机器可读：`md_cg/config_registry.py::ROLE_WRITE_MATRIX` /
  `PARAM_CLASSES` / `CLASSES_REQUIRING_CONFIRM`。
* **本批不动 `security.py`**：写入口只约束「配置写入」这一动作，与路径白名单判据无关。

## 4. registry 字段规格与体例裁决

### 4.1 字段规格（`md_cg/config_registry.py::SCHEMA`）

| 字段 | 必填 | 说明 |
|---|---|---|
| `key` | ✅ | 稳定唯一 id：`dsh-memory-main::<文件>::<符号>` 或 `::env::<ENV 名>` |
| `name` | ✅ | env 名 / 源码符号名 |
| `face` / `layer` | ✅ | `ENV/TUNE/CALIB` 与 `env/tune/calib` |
| `kind` | ✅ | `env` / `const` / `table` |
| `tunable` | ✅ | 是否真「数值型可调」（枚举名与模板串为 False） |
| `value` | ⭕ | 缺省**快照**；定位不到字面量时为 `None`（**不用盘点文字顶替**） |
| `value_type` | ✅ | int/float/bool/str/tuple/list/dict |
| `semantic` | ⭕ | env 面有效缺省语义：`on`/`off`/`unset`/`fail-open`/`value`/`enum`/`conflict` |
| `env_name` | ⭕ | env 覆盖键 |
| `anchor` | ✅ | `{how, file, symbol, key?, files?}`——**符号锚，不写行号** |
| `status` | ✅ | `uncalibrated` / `calibrating` / `calibrated` |
| `evidence` | ✅ | 依据（读数／文档锚／源码复核口径） |
| `since` | ✅ | 哪个版本起生效；未核 `unknown` |
| `notes` | ⭕ | 备注（分叉标记等） |
| `repo` | ✅ | 第一批只登记 `dsh-memory-main` |

### 4.2 体例裁决：**扩成一张总表** 还是 **保留分区表**？

**裁决：保留分区表（`SLEEP_ENV_KEYS/SLEEP_ENV_DEFAULTS`、`AUTO_DEFAULTS/AUTO_ENVS`、
`AUTONOMY_ENV_KEYS/AUTONOMY_ENV_DEFAULTS` 三处不动），另立
`md_cg/config_registry.py` 作「上位登记真源」，两者之间由守卫强制相等；
共用的是 schema／生成器／校验器／守卫，不是表本体。**

理由（逐条对**硬化事实**）：

1. **分区表已被守卫机械钉死，合并会连带改读取出口**。`md_cg/test_sleep_p1.py`
   的判据是「全仓 `MDCG_SLEEP*` **带引号字面量只许出现在** `sleep.py` 的
   `SLEEP_ENV_KEYS` 里」——一张跨 20 个模块的总表会让这条判据的语义**当场失效**；
   同时 `sleep_env()` / `auto_from_env()` / `autonomy_env()` 这三个读取出口
   是各自模块的**唯一入口**，物理合并必然要改它们＝**动了读取点**，违反本批硬规则。
2. **三张表的读取语义各不相同**（`sleep_env` 返回原始字符串由具名包装解释；
   `auto_from_env` 把真源 bool 折成 `"1"/"0"` 再判非关断词；
   `autonomy_env` 非法值 fail-closed 抛错）。合成一张表就必须在表里表达三种解释口径
   → 表变复杂、且**单一真源**从「一处缺省」退化为「缺省 + 解释器绑定的双源」。
3. **局部纪律要有边界**。「改缺省只改这里」这条纪律的有效性，正来自它的作用域小
   （sleep 面的人改 sleep 只碰 `sleep.py`）。一张 300+ 行的总表会让跨模块改动变成
   日常动作，**放大误改面**。
4. **「一张总表」的好处可以全拿而不合并**：统一 schema（`SCHEMA`）、统一文档生成
   （`config_render.render_doc`）、统一校验器（`config_validate`）、统一守卫
   （`config_registry_guard` 的 G2 直接读分区表并逐位对比 registry 登记值）。
   拿到的是**单一视图与单一判据**，付出的只是「登记值 ≠ 表值 ⇒ 红」这一条守卫。

**代价与兜底**：多一处登记＝多一处可能漂移。兜底＝G2（表值 vs 登记值逐位相等）
＋ G4（分区表每个键都必须被登记，漏登 ⇒ 红）。**两条都是机械判据，已落地且经变异自证。**

### 4.3 registry 收录判据（**机械、无一例外**）

* **const 面**：盘点里 `kind=const_literal`、锚点形如 `文件 :: 「符号 =」`、
  该符号在**该文件**模块级确有赋值、且右值可**常量折叠**（含 `1 << 20`、`50 * 1024`、
  `10 ** 9` 这类表达式）者。取不出的（`OrderedDict(...)`、`refine.X`、
  `2.0 * DEFAULT_BEAT_INTERVAL`、含名字的元组）**一律不收录**，计数如实报告，不猜。
* **env 面**：只收**策展名单**（`scripts/gen_config_registry.py::CURATED_ENV_NAMES`）；
  对每个名字在 `md_cg/` 下 AST 扫「读取点 → 缺省」，四种形态全覆盖：
  `get("X", d)` / `get(NAME, d)`（NAME 为模块级 `= "X"` 常量）/ `(environ or os.environ).get(NAME)`
  / `_cap(x, "X", SYMBOL)` 与 `check_path_root(p, "X", what)`（助手式实参）。
  **生产面全部读取点缺省一致**才算解析成功；分叉者照实记 `conflict`
  （**不许静默取其一**——分叉本身就是待裁定证据）。
  只登记**生产面**（排除 `test_*` / `bench_*` / `probe_*` 前缀文件）。

### 4.4 与既有守卫的兼容（**硬约束，registry 必须服从**）

仓内已有三条**全局字面量守卫**，把「同一个 env 名不许有第二份带引号字面量」钉死：

| 既有守卫 | 判据 | 钉死的名字 |
|---|---|---|
| `md_cg/test_sleep_p1.py::g8` | 除 `md_cg/sleep.py` 外，`md_cg/*.py` 里零个 `"MDCG_SLEEP*"` 字面量 | 7 个 sleep 键 |
| `md_cg/test_auto_defaults.py::G3` | 生产源码里 `"MDCG_AUTO_TIDY"` 恰 1 处（在 `AUTO_ENVS`） | 4 个 auto 键 |
| `md_cg/test_autonomy_modes.py::g_g` | 全仓 `.py` 里带引号的档位 env 字面量只出现在 `autonomy_modes.py` | 1 个档位键 |

**因此 registry 必须服从它们**：`md_cg/config_registry.py` 的 12 条 `kind=table`
登记，**env 名从真源表取**（`getattr(mod, keysym)[key]`），**本文件不写字面量**；
`md_cg/config_render.py` 同样从表取（`_ENV_SLEEP_MERGE` / `_ENV_AUTONOMY_MODE`），
并令**生成件** `md_cg/config_validate.py` 以**变量表达式**（而非字面量）作这两个键
——否则生成件本身就是「第二处字面量落点」。

**代价（如实登记）**：这 12 条的 `env_name` 是运行期由真源表推出的，故 G2 对
`kind=table` 条目只判「表在、键在、值逐位相等」；`env_name` 的**唯一性**由既有三条
守卫自己保证（它们更强）。这是**刻意的服从**，不是遗漏。

## 5. 默认值须实验标定

### 5.1 流程（参数 → 可复跑基准 → 读数 → 回填 evidence）

```
① 挑参数：registry 里 status != calibrated 且 tunable=True 的项（按面分组）
② 定基准：选**可复跑**的基准与题池（检索面点名已公开的中文基准
          `hive-memory-bench`（184 题/23 章/可运行判分器，外部公开台账可逐格复算）；
          本仓另有 `md_cg/bench_lme_zh.py`、`md_cg/bench_locomo_zh.py`、
          `md_cg/bench6_*`，以及 `scripts/rank_parity.py`（打分模式对拍））
③ 跑两臂：默认臂 vs 候选臂（**只改这一个参数**），同机同批
④ 记读数：机械层优先（逐字率／保地基／写入耗时／命中率），判官层次之
⑤ 判方向：候选是否在**目标读数**上更优且**不劣化护栏读数**（护栏读数 = 与
          A2「new ⊇ old」类不变量相关的读数；本仓已有 `tests/test_retr_gates_prodpath.py`、
          `md_cg/test_unify_default_off.py` 这类不变量守卫）
⑥ 回填：registry 该条 status → calibrated，evidence = 「基准名 + 臂 + 读数 + 复跑命令」，
          since = 生效版本；**读数不可复跑者只能停在 calibrating**
⑦ 守卫：G2/G4 复跑全绿后再提交（默认值变更**本身**属第二批，须设计者裁定）
```

### 5.2 三条硬约束

1. **未标定一律标「保守／未标定」**：第一批 304 条里 `calibrated = 0`
   （`uncalibrated` 284 / `calibrating` 20）——**没有一条走完上面的流程**，
   故一条都不许标 `calibrated`。
2. **`evidence` 不许写「看起来合理」**：只许写读数、文档锚或**机制性理由**
   （如「为 A2 不变量在默认配置下精确成立而刻意默认关」——这是可检验的理由）。
3. **改默认值 ≠ 登记**：登记是第一批的事；改默认值必须走 ⑥⑦，且**归设计者裁定**
   （见 §7 与 §9）。

        md_cg/config_render.py（纯函数渲染：render_doc / render_validator）
                     ┌──────────┴──────────┐
     scripts/gen_config_doc.py    scripts/gen_config_validate.py
                     │                     │

**纪律**：生成件**不手写**；改生成件形态＝改 `config_render.py` 后重跑薄壳；

### 6.2 守卫判据（`md_cg/config_registry_guard.py`；任一条红 ⇒ 退出码 1）

| 判据 | 内容 | 为什么需要 |
|---|---|---|
| **G1** | schema/内部一致性：必填字段齐、分类取值合法、`key` 唯一、`tunable` 与 `value_type` 相容 | 防登记表自身腐化 |
| **G2** | **锚点可解 + 缺省逐位相等**：`const` → 锚点文件模块级赋值折叠后 == 登记值；`table` → 分区表键值 == 登记值；`env` → 按锚点形态复核（字面量缺省／助手缺省符号／无缺省开关／助手实参），**分叉条目必须仍分叉** | 防「登记与代码漂移」——本守卫的**核心价值** |
| **G3** | **生成件新鲜度**：文档参数表与校验器必须**逐字节等于**由真源重渲染的结果 | 防手改生成件／忘记重跑 |
| **G4** | **分区表覆盖完整**：三张既有真源表每个键都必须在 registry 登记 | 防新增键漏登 |

**基线纪律**（沿用 `md_cg/test_sleep_p1.py` 先例）：不以 git HEAD 为基线源；
「改动前形态」由**定点变异**复现；变异锚点找不到 ⇒ 退出码 **2**（ANCHOR-MISS）。
变异全程在**内存**改源码文本（`_SRC` 覆盖），**不落盘**。

## 8. 迁移与兼容

1. **既有 env 一律继续生效**（覆盖面不缩）。本批**不删、不改、不重命名任何 env**。
2. **既有 env 名与默认值不动**：registry 是**只读登记**，不是运行时来源；
   第一批没有任何读取点接入 registry ⇒ **零行为变更**。
3. **既有三张真源表不动**：继续是各自读取点的运行时真源；registry 只是「上位登记」。
4. **新增参数的三步走**（第二批起）：①改源码缺省/读点 → ②重跑
   `scripts/gen_config_registry.py` 或在 `config_registry.py` 手工补登记 →
   ③守卫 G1–G4 全绿。
5. **用户配置文件的引入是纯增量**：文件不存在 ⇒ 全部走标定默认（与今天完全一致）。
6. **敏感面不外溢**：`MDCG_TOKEN` / `MDCG_MASTER_KEY` / `AEIS_DESIGNER_KEY` 等
   敏感项**只出现在环境面分类登记**（名字 + 值域类型），**不含值**（且盘点件本身
   已按「敏感（不回显）」处理）。
