## 二、对接面盘点（读码级）

### 2.1 身体侧（`lingshu/world` 24 件）关键面

- **`scene_model.py`＝「语义时空图 ↔ 3D 场景绑定层」**——天然对接件：
  - store 协议：`get_nodes_by_tag(tag, limit)`（读）；节点带 `tags`（`spatial`＋`cat:<类>`＋`ent:<名>`）、`spatial_coordinates {x,y,z}`（米）、`state_attributes {"state": …}`；`ingest_scene` 写路径。
  - `load_world_from_memory(store)`＝世界重建（"记忆即缓存：场景＝记忆节点的实时投影"）——**理念与脑侧「事件是源、槽位是投影」同构**。
- `semantic_anchor_graph.py`：3D 语义锚点图（节点＝类别＋坐标；边＝关系；"事物是其关系的总和"）。
- `seven_layer_loop.py`：感知→记忆→理解→预测→验证→物理→决策（"记忆"层即对接位）。
- `spacetime_consistency / anchored_verification / anchor_verify`：时空一致性、锚定分级验证（多感知通道）。

### 2.2 脑侧（本仓）对应面

- `stg` 五 op（`timeline / anchors[2D bbox] / consistency / relation / state_chain`）；
- `state_events` 台账 ＋ `state_slots` 投影 ＋ `cg(op=state_event)` 写口 ＋ 两个《秤》探针；
- MCP 面（V3 smoke 已证跨进程全链）。

### 2.3 映射表与缺口

| 身体侧约定 | 脑侧对应 | 状态 |
|---|---|---|
| tags：`spatial` / `cat:` / `ent:` | 节点 tags（写侧可带） | 写 ✓；**读侧缺 tag 过滤维（缺口①）** |
| `spatial_coordinates {x,y,z}`（米） | `frontmatter.spatial.bbox`＝2D 图像坐标四元组 | **缺口②：3D↔2D 方案待裁**（见 §四.2） |
| `state_attributes.state`（每实体状态） | **槽位寄存器**（subject＝实体／slot＝state／value）＋状态事件台账 | **✓ 同构，直接对接**（世界模型的"状态追踪"＝本版新地基：记账→台账→投影） |
| `ingest_scene` 写 | `cg(op=state_event)` / `mdcg_remember`（经 MCP，已证） | ✓ |
| `load_world_from_memory` 读 | 需"按 tag 读＋坐标取回"的组合 | **缺口①③：标签过滤读；场景整体重建的组合接口** |

## 三、最小闭环（两条路线）

- **M1（读向·身体重建世界）**：给 `scene_model` 提供"**脑版 store**"（实现 `get_nodes_by_tag` /
  `state_attributes` 等 → 经 MCP `cg` 读＋台账投影取值）→ `load_world_from_memory` 零改动直接以脑为底。
- **M2（写向·身体观测入脑）**：`ingest_scene` 的写落到 `cg(op=state_event)`（状态变迁）＋场景节点
  （坐标入库）→ 由脑的投影/查询供任意端消费（**smoke 已证全链**）。

两条路线共用同一验证工具：`python -X utf8 scripts/body_e2e_smoke.py`（隔离库、零在役写入、退出码判据）。

## 四、四条裁决（2026-10-06 已裁，按各条推荐执行）

1. **适配器归属侧**：身体侧件（`lingshu/world/brain_store.py`，聚合仓工具面）vs 脑侧件（本仓）。
   推荐：**身体侧适配器**——章程口径"脑为包依赖、身侧件进身仓"，且 `scene_model` 零改动即插。
   → **已裁/已落地**：`lingshu` 仓 `fb4b98b`（含 intake 登记与双清单审计）。
2. **3D 坐标方案**：推荐 **`spatial.coords3d` 自定义键直存米制＋可选 bbox 投影**（不改既有
   `spatial.bbox` 的 2D 语义、stg 四 op 零位移）；不建议扩 bbox 为 3D（破坏既有语义）。
   → **已裁/已落地**：本仓 `e5d7f0c1`——`mdcg_remember` 两分支经单点 `_spatial_kw` 透传
   （**缺省不落键**，既有 fm 形态逐位不变）；守卫 `md_cg/test_spatial_coords3d.py`（15 断言，
   两处定点变异各自恰好命中 1 项）。
3. **tag 过滤读（缺口①）**：脑侧给 `read/search` 加 tag 维（小活，进脑）vs 适配器侧读后过滤
   （零脑改、性能略差）。推荐：**先适配器侧**（探针验证后再决定是否进脑）。
   → **已裁/已落地**：适配器侧过滤（`BrainStore.get_nodes_by_tag`：`cg(op=read)` 候选 →
   按 tags 过滤）；探针实测读面召回充足（三种 query 全命中场景节点且 tags 在场）。
4. **smoke 进门禁**：是否把 `scripts/body_e2e_smoke.py` 纳入发布链附加腿（与《秤》探针同列）。
   → **已裁：进**——`npm run gate` 链尾第 12 腿 + Linux 容器腿同步补登（发布门禁链文档已更新）。
