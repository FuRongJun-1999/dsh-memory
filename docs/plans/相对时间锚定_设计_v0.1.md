# 相对时间锚定 · 设计 v0.1（`MDCG_TIME_ANCHOR`，缺省关闭）

> 移植自灵枢独立仓的同名特性（lingshu `core/timeanchor.py`）。规则表同源，**架构按本仓重做**：
> 本仓没有 SQLite 派生表与触发器，事件区间落在节点 frontmatter 的派生字段里，查询侧作为
> `search_rrf` 的一条可审计的路，而不是独立的重排器。

## 1 意图

对话记忆里事件时间几乎都是相对写法：「昨天」「上周二」「last weekend」「two years ago」。
本仓节点只有**观测时刻**（`created_at`，说这句话的时刻）；`temporal`（事件时刻）要调用方显式
写，对话导入时几乎从不写。于是按日期点名的问句（「2023年5月7日 Caroline 做了什么」）：

* 字面检索落空——证据里写的是 *yesterday*，没有「5 月 7 日」这几个字；
* 时间算子（`start_time/end_time`，观察轴）落空——观测时刻是 5 月 8 日，且观察轴在 `temporal`
  缺失时回退的是 `condition_space.time_window`（观测窗），同样是 5 月 8 日。

## 2 做法（确定性、零 LLM、只用标准库）

### 2.1 文件与开关

| 文件 | 改动 |

| `md_cg/mdcos.py` | `MdCGOS.search_rrf`：开关开时解析**原问句**的日期；解析出区间才追加 `time_anchor` 路（`_path_time_anchor`），融合后把区间有交集者稳定前置；`meta["time_anchor"]` 留痕 |
| `md_cg/hotcache.py` | `_ENV_SWITCHES` 登记两个开关；`_KEYED_EXTRA` 登记 `time_anchor`（问句区间入缓存键——「上周二」随当天变化） |

开关：`MDCG_TIME_ANCHOR`（只认字面 `"1"`，与 `MDCG_RANK_CREDIBILITY` 同款）；
`MDCG_TIME_ANCHOR_TZ`（参照日时区，相对 UTC 的小时数，缺省 0，非法/越界回落 0）。

### 2.2 写入侧：派生字段 `temporal_anchor`

节点**没有显式 `temporal`** 时，以 `created_at` 所在日为参照，把正文里**第一个**可解析的时间
表达归一成闭区间，写进 frontmatter：

```
temporal_anchor: {"start": "2023-05-07", "end": "2023-05-07", "rule": "en.yesterday",
                  "span": [12, 21], "ref": "2023-05-08", "v": 1}
```

* **可审计**：`rule` 指认是哪条规则给的区间，`span` 是命中位置（字符偏移），`ref` 是参照日，
  `v` 是口径版本（规则语义变了就加一，存量据此判陈旧）。**不抄正文片段**进 frontmatter。
* **不覆盖**：fm 已有 `temporal`（用户显式写的事件时刻）或已有 `temporal_anchor` → 不动。
* **不猜**：规则全不命中 → 不写字段。
* **加密密级不派生**：`private`/`secret`（`crypto.ENCRYPTED_LEVELS`）的正文在盘上是密文，而
  frontmatter 是明文——派生等于把正文里的日期信息漏到明文面，故不派生。
* **不并入既有时间轴**：`trust.time_window_of` / `filter_by_time` / `stg` / `temporal` 路一个字没改，
  派生字段只被本特性的查询侧读取。理由：观察轴的语义是「`temporal` 优先，缺失回退观测窗」，
  把规则推断的区间塞进去会让既有时间算子的结果在开关开时悄悄变化，且推断 ≠ 用户声明。
* 派生字段**不进索引快照**（`_node_entry`/`_stage` 未改）：避免改动索引形态（N137 同款纪律）；
  代价是查询侧要逐条 `_read` frontmatter（见 §5）。

### 2.3 查询侧：`time_anchor` 路 + 交集前置

1. 开关开时从**原问句**（`unify_query` 之前——它会改写英文词形）解析日期：带年份的绝对日期优先
   （`2023-05-07`、`2023年5月7日`、`7 May 2023`、`May 7, 2023`、`May 2023`、`2023-05`、`2023年`），
   其次相对表达（以当前时刻按 TZ 折算的日期为参照）。
2. 解析不出 → 什么都不做：`ranked` 不出现本路，meta、`path_fingerprint.hash`、结果**逐位不变**
   （守卫 [5] 与基准「原题面逐位对照 228/228」）。
3. 解析出区间 → 在 `entries`（已过 `_candidates` 资格与 S1/S2 门控）上逐条取事件区间
   `node_interval`：**显式 `temporal` > 派生 `temporal_anchor` > 观测当日推定**。与问句区间有交集者
   进本路，分数 `anchor_score` = 1/(1+区间宽度天数)，观测当日推定再 ×0.5。本路照常参与 RRF。
4. 融合后**稳定前置**：档 0 = 显式/派生区间有交集，档 1 = 仅观测当日推定有交集，档 2 = 其余；
   档内保持 RRF 融合序（词面相关度仍起作用）。`judge_ranking` 分支同样前置。
   理由：问句点名的日期是**约束**，不是一路普通投票——只作为一路 RRF 时，词面强的无关 turn
   （点名问句只有「说话人名」可匹配，几百条 turn 同分）仍能压过证据。消融读数见 §4 末行。
5. `meta["time_anchor"] = {interval, rule, overlap, sources}`（不含正文）。

## 3 可信边界

**已验**
* 守卫 `md_cg/test_time_anchor.py`：74 通过 / 0 失败（规则表 27 例 + 问句 7 例 + 关闭零调用 +
  点名日期 top-1（英/中）+ 无日期逐位不变（含 meta 与 path_fingerprint.hash）+ 显式 temporal 不覆盖 +
  加密密级不派生 + TZ + 登记），5 个定点变异各自转红（读数见 §6）。
* LoCoMo（snap-research/locomo @ `cbfbc1dba6bc53d00625212a0f22d55ffee7c1fc`，`locomo10.json`
  sha256 `79fa87e9…ea698ff4`）category-2 中 gold 能解析成日期区间的 228/321 题，见 §4。
* 规则表与 lingshu 版在 LoCoMo 全部 5882 条 turn 上逐条对拍：只有 1 条结果不同（见 §7①）。

**未验**
* 中文规则只有单元用例；中文点名读数用的是**英文语料 + 中文写法的问句**，不是中文对话语料。
* 加密库（`MdCGSecure` + private 节点）上的端到端行为只验了「不派生」这一侧的纯函数；查询侧对
  private 节点按观测当日推定处理，未单独压测。
* 大库（10⁵ 节点以上）的查询延迟：本路逐条 `_read`，未测。
* 规则表在真实 DSH 会话日志上的误判率（如 "may" 之外的同形词）。

**不确定（是约定，不是事实）**
* 「上周 / last week」取参照日前 7 天的滚动窗口而非日历周；「this weekend」按说话星期推断过去或将来；
  缺年份的「5月7日」取不晚于参照日的最近一次；「for N years」按「N 年前」取区间（时长被当成起点）。
* 一条 turn 只取**第一个**时间表达；一句话里有两个事件时间时，第二个丢失。

## 5 污染声明

规则表照搬 lingshu 版。lingshu 版的规则在对话 0–4（dev）上调；但开发过程中看过一次全量（含 test）的
失败样例，此后加了 6 族规则：`on the Nth`、`in YYYY`、`for N years`、`<Month> last year`、`this month`、
`this year`（本仓 `timeanchor.POST_HOC_RULE_IDS`）。所以 **test（对话 5–9）不是干净留出**，表中
「去 6 族」一行（写入与查询两侧同时剔除这 6 族）是下界。本仓移植时**没有**再按 test 调任何规则或排序；
排序口径（交集前置、显式/派生先于观测推定）是在 §2.3 的单元场景上定的，之后才第一次跑基准。

## 7 与 lingshu 版的差异

1. **修了一个大小写 bug**：lingshu 版 `<Month> last year` 用 `MON[m.group(1)]`（未转小写），文本是
   「August last year」时 KeyError 被吞掉，退回 `last year` 整年。本仓转小写后给出 8 月整月。
   LoCoMo 上只影响 1 条 turn（test 日期正确率 79.6% → 80.6% 的来源），该规则属于 6 族，下界不受影响。
2. 「几天前」类规则去掉了 lingshu 里永远不会生效的「半」分支（`cn_num("半")` 本就返回 None）。
3. 没有内容时间表达的节点**不写**派生字段（lingshu 写「说话当日 src=0」）；查询侧再按观测当日推定，
   并把推定排在显式/派生之后。
4. 显式 `temporal` 优先（lingshu 无此概念）；加密密级不派生（lingshu 无密级）。
5. 查询侧是 `search_rrf` 的一路 + 交集前置，不是独立重排；读数里的「原题面」基线高很多
   （本仓多路 RRF：test 65.0% vs lingshu LIKE 路径 30.1%），两边点名检索读数不可直接横比。

## 8 不适用条件

* 内容不含时间表达、事件又不在说话当天（「我养它很久了」）——按观测当日推定，是错的。
* 问句用规则表外的写法（「国庆前后」「开学那周」「上上周」「in May」——情态动词同形，刻意不收）——不进新路径。
* 写入时 `created_at` 不是说话时刻（批量导入统一写成导入时间）——参照日错，区间整体错位。
* 跨时区用户且未设 `MDCG_TIME_ANCHOR_TZ`——临近午夜的消息会差一天。
* 时长型问题（「多久」「几年前」）——只给区间，不做时长推理。
* 已有存量节点：开关打开**不回填**，只有之后的写入（含覆写）才派生。回填需另写 backfill（未做）。
* 大库：查询侧逐条读 frontmatter，候选面大时延迟线性增长；如需上线应把派生字段入索引快照
  （须同步 `_node_entry` 与 `_stage` 两处，N137 纪律）。
