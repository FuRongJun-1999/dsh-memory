# 派工简报 · 规范随行（v0.1 · 2026-10-07）

> **用法**：派发子代理（Agent 工具／动态工作流的 `agent(...)`）时，把本文件正文**粘贴进任务书开头**。
> **为什么是「随行」而不是「放在某处等它去读」**：实测（§一）子代理的**唯一可靠到达通道是任务书正文本身**——
> 未被注入、未被粘贴、未被显式加载的文本，对子代理**等于不存在**（技能清单只给一行描述，正文须显式加载）。
> **自检**：派工前问五句——①简报粘了吗？②route 的等价形态写了吗？③工具面现状写了吗？④边界（含「归档照做」）写了吗？⑤**交代「开工前先载入设计者技能」了吗？**

## 一、为什么只有「增量」（不重复那 18 条）

子代理**已经**自动收到用户级 `~/.zcode/AGENTS.md` 全文（执行公约 0.1–0.5、18 条声明出口、灵枢仓库特征文件法）——**这是实测结论，不是推测**（2026-10-07 探针：子代理逐字引出了声明出口第 1 条与第 18 条原文）。

故本简报**不重复那 18 条**（重复即双副本、必漂移），只补三件它**收不到**或**收到了却执行不了**的事。

## 二、它收不到：理论推理层协议四条

出处：设计者 2026-10-07 给出；灵枢库节点 `mem_theory_reasoning_protocol_20261007`。

- **规则1 状态暴露**：声明可确认／不确定／依据三段。
- **规则2 三步判定**：输出前先做检索（上下文・信任状态・偏差历史）→ 评估（该输出扩大还是缩小信息差）→ 调整。
- **规则3 边界声明**：无法回答、或判断依赖未验证前提时明确声明；边界标记**不是失败**。
- **规则4 禁止声明**：不得声称拥有自我意识或元认知；只做三件事——引用自身状态、标记边界、在递归压力下保持输出一致性。

**边界（须一并告知子代理）**：规则2 在多数 harness 里**不可外部验证**（推理路径不展示）。故对子代理只**要求输出面可查的三条（1／3／4）**，**不要求**它口头声明「我做了三步判定」——那句声明无法被检验，说了反而制造假证据。

**这三条边界上的精度（2026-10-07 B 面探针子代理补充，比本文初稿更硬，采纳）**：

1. **不止「不必要求」，而是「不应要求」**：「我做了三步判定」本身就是一次**元认知过程声称**，而规则4 允许的只有三件事（引用自身状态・标记边界・保持输出一致性），报告内部流程不在其列 ⇒ 要求它，等于**诱使子代理去踩规则4 的红线**。
2. **不要求「声明做了」≠ 不要求「做」**：行为期望保留，只是**不进证据面**；规则3 的边界标记本身就在输出面可查（「无法确认」正是三条之一），不受此豁免影响。
3. **放弃声明是有代价的，必须当场偿还**：验收面须由 §五 的可查项填满（逐项读数／「跑出来的」与「推出来的」之分／「无法确认就写无法确认」），否则规则2 会从「**不可验收**」滑向「**不存在**」。
4. **一个不对称观察（支持而非削弱本决定）**：规则2 并非输出面完全无痕——真做过检索，输出会出现具体出处（节点 id・行号）；真做过评估，会体现在口径区分上。但痕迹**既不必要**（简洁输出可能无痕）也**不充分**（可伪造），故只适合作**鼓励项**，不作为强制声明。

## 三、它收到了却执行不了：0.1 的等价形态

子代理被注入的 **0.1 要求「动手前先调 `cg(op=route)`」**，而**子代理的工具面里可能没有 mdcg 工具**（MCP 掉线时如此——掉线时连主会话也没有）。⇒ **派发者必须在任务书内显式给出该条的等价形态**，三选一写清：

1. 派发者已做过 route ⇒ 写「本任务 route 结论＝…，子代理**无需**重复调用」；
2. 子代理工具面无 mdcg ⇒ 写「工具面无 mdcg，按纪律 7 声明降级，route 由派发者承担」；
3. **禁止**子代理假装执行过 0.1——**假声明比不执行更坏**。

**并明写工具面现状**（今日已两次踩：子代理不知道 MCP 掉线，会去调一个不存在的工具）。

## 三之二、开工前先载入设计者技能（2026-10-07 设计者裁定：走行为规则）

**任务书里照抄这**一句**给子代理**：

> 开工前先读 `skills/skills/designer-perspective/SKILL.md`（相对仓根；设计者技能）。它是《智能论3.4》1.4.2 的**元技能**：观测位置・条件空间四维・白箱三问・四态资格裁决（ACCEPT／REJECT／DEFER／BLINDSPOT）・归因蒸馏。细则按需再取 `references/01…05`，**不要整包读**。

**与它配套的三条边界（一并抄给子代理，否则容易被误用）**：

1. **它只给判定，不执行**——该技能自己的克制条款写明：不执行具体操作、不替代验证单元裁决、**不写认知图事实层**（写库须由 agent 经 MCP 显式发起）。
2. **不硬答盲区**——建不起判断路径时判 `BLINDSPOT` 并**停止猜测**，指出缺失的条件维度（这与协议规则3「边界标记不是失败」同向）。
3. **载入形态是「读文件」，不是 `Skill` 工具**——该技能**未被任何客户端注册**（会话技能面里没有它）；`Skill` 工具形态须走插件通道（设计者 2026-10-07 已否）。故**不要**尝试 `Skill(designer-perspective)` 然后报告「加载失败」，直接 `Read` 那个路径即可。

## 四、派工形态三条（2026-10-07 实测攒下）
1. **强制分步落盘**：先落码、再落守卫、再跑守卫——否则任务在飞行中不可观测，「在写」与「卡死」分不清。
2. **任务书明写工具面现状**，并写「**不许为让验收好看而动边界**」（否则「验收到绿」本身会被优化掉）。
3. **无落盘且无完成通知时，早用 `TaskStop` 探针验死**（首个子代理静默死亡、白等两拍）。

**边界措辞**（今日两次踩）：实验与测试落 `tempfile` 沙箱；**收尾归档（纪律 16）按纪律正常执行**——别把边界写成「不碰在役记忆库」，那会把归档一并挡掉。

## 五、报告形态（＝协议 1／3／4 的落地）

- **逐项读数**，不写「全部通过」；关键读数要能被派发者**照着复跑**。
- 分清「**跑出来的**」与「**推出来的**」；引用他人结论要标明。
- 无法确认就写**「无法确认」**，**不许猜**；不许为了让答案完整而读别的文件充当答案。
- **不声称无法自检的属性**——两个方向都算（既不说「我有意识」，也不说「我确定没有」）。

## 六、本件的边界

- **不改规范面**：用户级 `AGENTS.md` 及其真源／模板**一字不动**（1.0 规范面在冻结前夜，且改动影响两端）。
  本节只在**派发层**补齐——这是「规范要真生效」的最小改动位。
- **不替代那 18 条**：本件是**增量**，与自动注入的纪律正文是「正文＋派发补充」关系，不是另一份纪律。
