### 0.3 三个必须先知道的硬约束（决定方案形状）

1. **`mdcg.py` 顶层 import 数 = 0**（`mdcg.py:117-119` 只 import 了 `nodefile/protect/routing/...` 等
   16 个模块，`grep` 实测无 `from .mdcg import` 自引用）。而 `mdcos.py:54` 从 `mdcg` 导入 **31 个名字**，
   `mcp_server.py` 从 `mdcg`/`mdcos` 延迟导入。⇒ **`mdcg` 是依赖图的最底层**，拆它风险可控；`mdcos` 之上还压着 `mcp_server`。
2. **`MdCGSecure` 显式断言 `type(self)._seal_content is not MdCG._seal_content`**（`mdcg.py:4825`）。
   ⇒ 凡把类方法搬出原模块的拆分方式（mixin / 组合 / 外置函数）都会让这条「鸭子判据」静默失效，
   导致 **private 明文落盘不报错**（B2 密级一致性闸失守）。**这是全方案的一号禁区**。
3. **`mdcos.py` 的 `MdCGOS` 靠 override 钩住基类调用点**：`_candidates`(1202)、`_set_index_entry`(1074)、
   `_move_layer`(1079)、`_scan_nodes`(7114)、`add`(1093)、`judge_qualification`(1312)、`search`(1350) 等
   12 个方法被基类 `MdCG` 内部调用。⇒ 任何「把 `MdCG` 的方法搬到模块级函数」的做法都会**绕过 override**，
   变成静默行为变更。`mdcos.py:1073` 的注释自己写明了这条依赖链。

### 0.4 方案总纲：只拆三种东西（并给反例）

本方案**只允许**以下三种拆分动作，其余一律拒绝：

| 动作 | 说明 | 适用 | 收益度量 |
|---|---|---|---|
| **A. 纯符号搬家** | 无 `self` 依赖的模块级函数/常量 → 新模块 + 原位置 re-export | `mdcg` 的词法归一层、`mcp_server` 的校验层 | 行数直线下降，零行为风险 |
| **B. 表驱动分派** | 巨型 if/elif 链 → op→handler 映射表 | `_cg_dispatch`、`_dispatch` | 主函数降到 ≈90 行 |
| **C. 组合式内聚体** | 把一组**共享同一批实例属性**的方法搬进一个组合对象（`self._core`） | `MdCG` 的索引/落盘机制 | 类方法数 118→≈55 |

**明确不做**（反例，因为它们都会击穿 §0.3 的 2、3 条）：
- ❌ 把 `MdCG` 的方法改成模块级函数（`_seal_content` 判据失守 + `MdCGOS` override 全部绕过）
- ❌ 把 `MdCG` 的方法拆成 mixin 类（`type(self)._seal_content is not MdCG._seal_content` 变成恒 True）
- ❌ 把 `MdCGOS` 的 override 方法下沉到 mixin（`super()` 语义变化 + MRO 变化）
- ❌ 用 `__getattr__` 模块级代理（`from .mdcos import MdCGOS` 仍能用，但
  `test_c8_search_rrf_gates.py:466` 的 `itertools`/`inspect.getsource` 与
  `scripts/check_op_table_parity.py:157` 的 `from md_cg import mcp_server as ms` 语义漂移，见 §1.2 风险 R-3）

#### 1.2.3 分派表设计（M1 的核心，零风险）

```python

_SIMPLE_OPS = {
    "task":        _task_call,
    "recent":      _recent_call,
    "review":      _review_call,
    "goal":        _goal_call,

    "verify":      _verify_call,
    "forget":      _forget_call,
    "protect":     _protect_call,

def _cg_dispatch(cg, a):
    a = {k: v for k, v in (a or {}).items() if not str(k).startswith("_")}
    op = (a.get("op") or "read").strip().lower()
    ...
```

**为什么这不会触发 `check_op_table_parity` 红**（`scripts/check_op_table_parity.py:19` 自称
「`_OP_TABLE` 是唯一权威」）：该守卫的四条 AST 断言都指向
`mcp_server.py` 的 `cg` 工具字典描述串 / op 枚举串 / `_ACTION_SIGS` / `_ACTION_DEFAULT` **必须**从
`_ot.*()` 派生（`check_op_table_parity.py:313-357`），以及「`mcp_server.py` 内**不得**出现 op 枚举串字面量」
（`:359-365`，判据是「含 `route`+`read`+`write` 三词的类似枚举的字符串」）。

#### 2.3.2 组合对象 vs mixin：为什么必须选组合

`MdCGOS` 的 override 方法（`add`/`_candidates`/`_set_index_entry`/`_move_layer`/`search`/
`judge_qualification`/`_scan_nodes`）**必须留在 `MdCGOS` 类体内**，因为它们要被 `MdCG` 的方法
通过 `self.xxx` 调到。

但非 override 的域（G1 审计、G2 审核队列）可以走**组合**：

```python
class MdCGOS(MdCG):
    def __init__(self, root, autoflush=64, actor="system", async_flush=None):
        super().__init__(root, autoflush=autoflush, async_flush=async_flush)
        self.actor = actor
        ...
        self._review = _ReviewQueue(self)      # ← 组合：把 self 传进去
        self._audit  = _AuditFacade(self)

    # 13 个薄转发，保住公开签名不变
    def review_decide(self, *a, **kw):
        return self._review.review_decide(*a, **kw)
    def audit_records(self, *a, **kw):
        return self._audit.audit_records(*a, **kw)
```

**代价**：类方法数 148 → ≈85（**仍超 60 的阈值**），需要 `_ReviewQueue`/`_AuditFacade` 各自
≤60 方法（实际 27 / 15 ✅）。**这是本方案对 `MdCGOS` 能取得的最好结果**，因为
`MdCGOS` 的 60 方法单类上限在「保留 override 链」的约束下**不可达**——
必须如实标注这个缺口（§2.4 R-7）。

> **mixin 为什么不行**：把 G2 抽成 `class _ReviewMixin:` 再 `class MdCGOS(MdCG, _ReviewMixin)`
> 会让 `super().xxx` 在 mixin 内的解析目标变化（MRO 变成 `MdCGOS → MdCG → _ReviewMixin → object`，
> mixin 里的 `super()` 会跳到 `object`），且 `type(self)._seal_content is not MdCG._seal_content`
> **不受影响**（那是 `MdCG` 的属性），所以 mixin 的失效是**静默的 MRO 漂移**，比组合危险。

#### 3.2.4 最小可行第一步

**`_DirtyDict`（`:1733-1893`，161 行）→ `md_cg/dirty_dict.py`，原位 re-export。**

理由：独立类 + 单点外部 import + 零 `self` 与 `MdCG` 交错 + 有专项守卫
（`test_n230_dirty_replay` / `test_issue400_hive_dirty_args` / `test_verify_dirty_reconcile`）。

**但必须注意一处隐式契约**（`mdcg.py:1742-1744` 类自己的 docstring）：
> 「消费方纪律：flush/rebuild 清空必须走 `.clear()`（保住子类钩子），**不得** `self._dirty = {}` 直接换新 dict」

⇒ 搬运时若在某处写成 `self._dirty = {}`，「write_gen 恒 0、读缓存失效面随之失效」。
搬 `_DirtyDict` 是安全的；**但 S3 步（`_IndexCore` 组合）时若把 `self._dirty` 改成 property，
任何既有 `self._dirty = {}` 写法都会静默变成 `property` 的 setter 失败或绕过钩子** ⇒ 必须 grep 全仓
`_dirty =` 赋值点（实测 `MdCG` 内 2 处：`mdcg.py:1770` 附近与 flush 路径）并逐个确认。

### 4.2 shim 策略

#### 4.2.1 三种 shim 形态与选择规则

| 形态 | 写法 | 何时用 | 代价 |
|---|---|---|---|
| **S1 原位 re-export**（推荐） | `from .newmod import foo` 保留在旧模块顶层 | 被搬的东西是**函数/类/常量**且调用方 `from old import foo` | 旧模块仍需要 import 新模块（可能引入环） |
| **S2 模块对象替换** | `import sys; sys.modules[__name__] = newmod` | 想把旧模块整个变空壳 | ❌ **禁用**：`scripts/check_op_table_parity.py:157` 的 `from md_cg import mcp_server as ms` 会拿到新模块、`inspect.getsource` 全变 —— 破坏面不可控 |
| **S3 模块级 `__getattr__`**（PEP 562） | `def __getattr__(name): ...` | 想延迟加载、避免环 | ❌ **禁用**（同 §0.4 反例）：`ast.walk` 类守卫（17 文件）看不见符号；`hasattr` 会触发副作用 |

### 4.5 动态属性访问（会让拆分静默失败）

**结论：三个文件自身的 `getattr` 全部是「可选钩子」形态，不构成拆分风险；真正的风险在「测试按名 setattr 改写模块级常量」。**

#### 4.5.1 三文件内的 `getattr` 统计

| 文件 | `getattr` | `hasattr` | `__dict__`/`globals()`/`vars()` |
|---|---:|---:|---:|
| `mcp_server.py` | 51 | 10 | 0 |
| `mdcos.py` | 51 | 3 | 0 |
| `mdcg.py` | 22 | 0 | 0 |

形态说明（抽样）：
- `mdcos.py:760` `getattr(cg, "_attributed_session", None)` —— **可选钩子**（纯 `MdCGOS` 无该属性时回落）
- `mdcos.py:726` `getattr(cg, "index", None)` —— 防御式取索引
