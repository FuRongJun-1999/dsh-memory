# 灵枢三层拆分规划 v0.1

> 状态：规划稿（未执行任何文件搬迁）
> 日期：2026-09-10
> 范围：理论（灵）/ 大脑（brain）/ 身体（body）三仓职责分离与主仓库瘦身
> 性质：**本文只定义职责与顺序，不构成搬迁授权**；所有搬迁动作须先通过 Phase 0 裁决。

---

## 0. 背景与结论

### 0.1 现状问题

| 问题 | 表现 |
|---|---|
| 主仓库职责混杂 | `dsh-memory` 同时承载「记忆大脑」与「工程/身体运行时」（`docker/`、`scripts/` 看门狗、宿主启动脚本），二者依赖量级完全不同 |
| 同名不同物 | 历史命名中「AEIS」既指理论方（CTP）自带的工程副本，又指 `dsh-memory` 的 Python 大脑包，导致「aeis = 大脑」的旧语义债 |
| 跨库同步困难 | 同一份工程内容在多库各存一份，改动需人工同步，真源不清 |
| 断链 | `AEIS/tools/*` 指向 `dsh-memory\llm-adapter-poc`，该路径当前不存在（待 Phase 0 核实） |
| 交付面过宽 | 完整灵枢 = 理论 + 大脑 + 身体，体量巨大；理论难懂、身体重依赖，二者都阻碍了「大多数人只需大脑」这一主路径 |

### 0.2 结论（本次收敛）

**主仓库不再放工程内容的完整实现，只放「大脑」。**

- 完整灵枢 = **灵** + **脑** + **身**；但对外**默认只交付大脑**。
- 理论（灵）与身体（身）作为大脑的**可选下层 / 上层**，通过 README 分层入口引导，而非塞进主仓库。
- 分离的直接收益：消除跨库重复实现，真源唯一，降低同步成本。
- 面向人群：理论 → 研究者；身体 → 少数需具身者；**大脑 → 大多数人（默认入口）**。

## 1. 三层定位

| 仓 | 角色 | 内容边界 | 默认读者 | 依赖量级 |
|---|---|---|---|---|
| CTP / CommonTrustProtocol | **理论（灵）** | 协议、认识论、信任账本；**不含工程实现**（待剥离自带 `aeis/` 工程副本） | 研究者 | 无（纯文档/协议） |
| **dsh-memory（主仓库）** | **大脑** | `md_cg` 认知图内核 + MCP/npm 接口 + 记忆数据；**纯逻辑、零重依赖** | **大多数人（默认入口）** | 轻（标准库 + 轻量 npm） |
| AEIS / body | **身体** | 传感器、语音、执行器、docker 运行环境、模型权重、宿主看门狗 | 少数需具身者 | 重（设备/模型/容器） |

**一句话各自定位**

- 灵：定义「什么样的智能值得被信任」——协议与公理，不落代码。
- 脑：定义「记住什么、如何召回、如何自演化」——可在任意宿主上单独运行。
- 身：定义「如何感知与作用于世界」——可选，且可替换。

## 2. 主仓库（大脑）取舍清单

### 2.1 保留（= 大脑本体）

| 路径 | 内容 | 理由 |
|---|---|---|
| `md_cg/` | 认知图内核（98 py：consolidate / refine / pooling / provenance / whitebox / MCP server…） | 大脑核心，纯 Python |
| `src/` | MCP / npm 插件接口（8 ts） | 大脑对外唯一入口 |
| `test/` | 集成测试 | 大脑正确性保障 |
| `data/` | 记忆数据（**归位须待 Phase 3**） | 大脑资产，非工程副产物 |
| `package.json` / `tsconfig.json` | 构建定义 | 轻依赖 |
| `README.md` / `docs/` | 分层入口文档 | 需重写为三层入口（Phase 4） |

### 2.2 移出或降级（= 身体 / 工程）

| 路径 | 处置 | 去向 |
|---|---|---|
| `docker/` | 移出 | 身体仓（运行环境） |
| `dsh-web-start.bat` | 移出 | 身体仓（宿主启动） |
| `scripts/`（看门狗 ps1 / vbs） | 移出 | 身体仓（宿主守护） |
| 语音 / 模型权重 / 设备相关资源 | 移出 | 身体仓 |

### 2.3 断链修复（Phase 2 处理）

- `AEIS/tools/*` → `dsh-memory\llm-adapter-poc`（当前缺失）。
- 二选一：**补齐**该路径，或**声明废弃**并从文档/代码中移除引用。
- 原则：不允许存在「文档指向不存在路径」的悬空引用。

## 4. 贯穿全程的三条铁律

1. **先定职责、再定归属**——库名是历史沉积，不是功能声明。不得因为「名字里有 aeis」就归给理论方。
2. **接口冻结早于代码搬迁**——否则拆的是目录，不是耦合；耦合仍在，只是换了个地方报错。
3. **数据最后动且可回退**——`data/mdcg` 挪错是**静默失效**（写入只打 warn），6340 节点无法从代码重建。

## 5. 风险与回退

| 风险 | 触发条件 | 回退动作 |
|---|---|---|
| 记忆真源错位 | `mdcg.root` 落到错误目录，写入静默告警 | 恢复 `data/mdcg` 原位 + `mdcg.enabled: false` |
| 写入冻结期间数据丢失 | Phase 0 冻结但未建备份 | 冻结前先做全量备份（必须前置） |
| 契约冻结不彻底 | 身体侧仍直接读大脑文件 | 强制走契约能力名，禁止跨层直连 |
| 真源判断错误 | Phase 0 diff 结论有误 | 保留 diff 快照，可重判并回滚剥离 |

**迁移不可逆点**：Phase 3.2。进入前必须完成 Phase 3.1 回退演练。
