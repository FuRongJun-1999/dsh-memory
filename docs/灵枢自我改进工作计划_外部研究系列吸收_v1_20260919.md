—— 基于六篇外部研究与一份实践视频的系统化吸收 · v1.0

## 0. 元原则：计划自身的形态

本计划采用 Dream-RSI 的三段闭环作为**元结构**——每个阶段不是清单的
罗列，而是一个可独立验收的迷你循环：

> **改造 → 回放验证 → 量化 → 选拔 → 回归**

- **改造**：对灵枢记忆/协议/检索做一次结构性变更；
- **回放验证**：变更必须在**历史数据**上证明不劣化——用灵枢已有的
  完整留痕（会话记录、审核记录、回执、认知图真源）作为回放沙盘，
  新旧版本在全部历史查询上对比；
- **量化**：验收指标数值化（见 §7 指标体系），拒绝"感觉更好"；
- **选拔**：回放分不劣化（含旧版本作为候选 → 单调门 [DRSI]）才进入真源；
- **回归**：阶段完成后立即投入真实任务流（蜂巢运行），用真实使用
  暴露沙盘盲区，驱动下一阶段（[DRSI] 边界：回放不知未探索区域）。

零条改动绕过此循环。这是 Dream-RSI 对本计划的最大贡献：
**自改进的安全形态 = 回放沙盘 + 单调门 + 周期性回归真实**，
而非"文字教训注入"形态（[DRSI] 反直觉发现：文字指导一致拖累表现）。

## 1. 现状盘点：主战场与缺口

**已建成（主战场，不动摇）**：
五层认知图、CCG 六要素条件卡、四态判定（含 BLINDSPOT）、
D_norm 信息差、审核队列（DEFER → can_admin 裁决）、supersede/forget/
protect 撤回体系、蜂巢多实例互验（跨端验证协议 v0.1：水位/心跳/回执
逐字纪律）、hive 任务队列、三端 kernel surface（cg/stg）、渲染管线
（真源 → render → verify 防漂移）、白箱化纲领。

**外部对照后的两个缺口 + 一个盲区**：
1. **使用侧缺口**：检索为单步路由/读取，缺图遍历原语与时间算子
   （[RE][MA] 两篇独立证实这是数量级差距来源）；
2. **模型侧缺口**：事实无显式有效期，时间只是元数据而非推理维度
   （[GB][RE][MAGE] 三篇独立指向）；
3. **治理盲区**：治理强度从未被量化——supersede 传播率、矛盾处理率、
   过期取回率无数字（[MAGE] 给出三个现成指标定义）；
4. **自改进盲区**：evolve/consolidate 无回放沙盘与单调门（[DRSI]）。

## 2. 负面清单：明确不做的

防止吸收变成照搬。以下为**有意不采纳**的外部设计：

| 不做 | 理由 |
|---|---|
| per-language 原生索引器（[GB] tree-sitter 全语言 WASM，≈70MB）| 灵枢走统一语义归一路线；语言无关的结构化表示是本体，格式只是来源 |
| 把 insight/教训作为提示词常驻注入（[DRSI] 反例）| 文字指导 = 有损压缩 + 语义偏置；教训以可回放记录存在，按需派生 |
| 入库前放弃裁决改为事后撤回（[GB] 模式）| 事前裁决是灵枢信任模型的核心；GBrain 的事后账本可借鉴为**补充**而非替代 |
| surface 全量开放给所有 agent | 保持 kernel surface 收缩 + 阶梯 fail-closed（[GB] 阶梯设计本身采纳，默认档保持最小）|
| 记忆图静态单调增长（[MA] 自认局限）| 灵枢的更新/遗忘是主场，反向输出而非吸收 |

## 3. 阶段一：基础字段与冻结协议（数据模型升级）

**目标**：事实的生命周期与治理状态在数据模型上显式化。

### 3.1 双时间轴字段 [GB][RE][MAGE]
条件卡新增：
- `believed_at`（信念时间：体系何时确认此条——supersede/审核的锚）；
- `effective_from / effective_until`（效力时间：事实在任务世界何时有效）；
- `expired_at` + 过期查询语义（过期≠删除，是查询默认过滤）。
验收：全部历史条件卡回填后，按效力区间过滤的历史查询回放结果
与人工标定一致。

### 3.2 巩固字段一等公民化 [GB]
新增 `consolidated_at / consolidated_into`（自引用）——归并/insight
操作从流程记录升级为可追溯字段。
验收：任一合并后的条目可定位其全部前身。

### 3.3 裁决枚举扩为四类 [MAGE]
审核队列裁决从 ACCEPT/REJECT(+edit/merge) 扩为显式
**ADD / UPDATE / DELETE / NOOP**——NOOP（"已评估，判定不改变任何
现有记忆"）成为被记录的判定而非静默忽略。
验收：NOOP 有留痕、有统计（§6 指标输入）。

### 3.4 冻结动词协议 v1 [GB]
为灵枢 MCP 记忆工具面（kernel surface 的记忆相关操作）定义
《灵枢记忆动词协议 v1》：字段名与语义冻结、只增不破坏、
`protocol_version` 随行、**conformance 测试**钉死形状。
范围先行收窄：`route / read / write / supersede / forget` 五动词。
验收：三端（DSH/ZCode/CodeBuddy）按协议文档独立实现客户端，
conformance 全绿。

### 3.5 fence 真源绑定 [GB]
条件卡与 Markdown 真源之间加"往返列"（真源 slug + 行位），
实现 DB 行 ↔ 真源文件双向定位。
验收：任一条件卡可定位真源精确行；真源重排后按 reconciler 重建。

**回放验证**：全部历史条件卡与审核记录在新模型上重放
（route/read/write/supersede 逐条），结果与旧模型逐字节一致
（纯字段增列，不改既有语义）。
**风险**：低（增列不动既有语义）。**依赖**：无。

## 4. 阶段二：检索原语（使用侧补强）

**目标**：把 `cg` 的检索从单步路由升级为可组合的图遍历原语，
agent 端获得多步推演的能力面。

### 4.1 时间算子 [RE]
所有检索原语接受 `start_time, end_time, start_operator, end_operator`
参数——时间是一等检索参数且带比较算子（§3.1 的字段在此兑现）。

### 4.2 find_entity_contexts 式原语 [RE]
`subject / object / predicate + 时间条件 + limit / ordering / offset /
aggregation`——按三元组任意端与谓词反查。

### 4.3 tag 枢纽层 [MA]
cues（细粒度线索）与内容之间加"短标签"检索枢纽
（≤2 词，`query_tag_events` 式），先查 tag 再展开内容。

### 4.4 反向遍历 [MA]
`Content → (Cue, Tag)`——从已取内容反查来源线索、由线索激活
相邻记忆，暴露为独立检索动作。

### 4.5 f_route 式剪枝 [MA]
多步遍历中每步由 LLM 剪枝无关分支——[MA] 数据：剪枝使 token
118k vs 245k/632k（−52%~−81%），多步反而省。

### 4.6 能力探测降级 [GB]
检索入口探测能力：无 embedding 依赖时自动降级 BM25 式关键词——
零配置可用的底线体验。

**回放验证**：新原语在全部历史查询上对比单步基线——
召回集是旧法的超集（单调门），且引入的噪声由剪枝控制
（f_route 的准确率回放对比）。
**风险**：中（新原语的误用噪声）。**依赖**：§3.1（时间字段）。

## 5. 阶段三：治理量化（把主场变成可测的主场）

**目标**：灵枢最强的治理维度获得数字。[MAGE] 给出三个现成定义。

### 5.1 治理指标三件套 [MAGE]
- **修正传播率**：一次 supersede 之后，下游引用它的节点同步失效/
  更新的比例（MAGE 91.2%）；
- **矛盾处理率**：新证据与旧记忆矛盾时被正确裁决（取代/失效）
  的比例（MAGE 88.5%）;
- **过期取回率**：查询返回已过期信息的比例（MAGE 3.1%，越低越好）。

### 5.2 拒答/无知量化 [RE]
四态判定的 BLINDSPOT 获得 REMem 式量化：不可答问题的
拒答精确率/召回率/F1（REMem F1 64.0 为对照线）。
"显式表达无知"从设计变成可打分的能力。

### 5.3 公开基准体检 [RE]
以 LoCoMo（长对话回忆，与蜂巢会话场景最近）为首个外部基准，
灵枢记忆对标准流程跑分，与 Mem0/HippoRAG 2/REMem 公开数字对照。
仅测差距，不为其改架构。

### 5.4 BLINDSPOT 票据化 [WF]
BLINDSPOT 生成时追问"缺的是哪类信息"，自动生成对应类型消解票据
（research / prototype / grilling / task）挂入依赖图——
无知从状态标记升级为可分派工单。grilling 类型由既有 grill 工具承接。

**回放验证**：指标基线先在"不改动"的当前版本上测出
（这是基线定义，无单调门问题）；随后每次治理相关改动
对照基线报告三指标变化。
**风险**：低（测量不改行为）。**依赖**：§3.3（NOOP 枚举）。

## 6. 阶段四：角色化读取与超边形式化（蜂巢侧）

**目标**：蜂巢多实例的记忆读取按角色差异化；协作事件形式化。

### 6.1 角色化读取 [MAGE]
主代理读"结论与修正历史"，验证端读"判据面与环境陷阱"，
回执任务读"命令与预期输出"——同一记忆库，按角色过滤视图。
验收：角色化读取后各角色任务的 token 消耗与判据命中率
对照无差别全量读取。

### 6.2 超边形式化 [MAGE]
把"一次跨端验证"显式定义为超边类型：参与者集合、证据集合、
修正集合、时间范围——互验协议 v0.1 的文件组约定升级为
可被外部工具理解的正式结构（对齐 MAGE 的第一类超边）。
验收：任一历史验证回执可从超边完整重建。

**依赖**：§3 全部（超边字段引用双时间轴与裁决枚举）。
**回放验证**：历史互验记录全部迁移为超边后，水位/心跳/回执
语义逐字不变。

## 7. 阶段五：回放沙盘（自改进闭环，终局）

**目标**：灵枢的 evolve/consolidate/白箱自举获得 Dream-RSI 形态的
安全自改进。

### 7.1 历史留痕升级为可回放世界 [DRSI]
会话记录、审核记录、回执、认知图真源——这些本来就完整留痕的
历史，封装为**可回放世界**：任意记忆/策略变更，可以在历史上
全部真实查询与任务回执上离线重放。

### 7.2 单调门 [DRSI]
自改进候选（新词条、新路由策略、新归并规则）在回放世界上
与现役版本同台比试；候选集含现役版本 → **历史回放分单调不退化**
才被选拔。

### 7.3 周期性回归与盲区标记 [DRSI]
回放只覆盖已探索区域——沙盘选拔后周期性回归真实任务流，
新暴露的未探索区域以 BLINDSPOT 显式标记（§5.4 票据化承接），
驱动下一轮在线探索。

**回放验证**：本阶段自身的验收即 Dream-RSI 数字——自改进操作
历史回放分单调不退化 + 真实任务流上无回归 + Lasso 式成本节省
（对照：人工演进）。
**风险**：高（新机制）。**依赖**：§3–§5 全部 + 蜂巢历史留痕完整
（已满足：会话/审核/回执本就全留痕）。

## 9. 风险与边界

1. **回放盲区** [DRSI]：沙盘单调 ≠ 真实不退化——每阶段以真实任务流
   回归收口，新盲区以 BLINDSPOT 标记；
2. **上游提取质量** [MAGE 同款限制]：语义归一依赖 LLM 抽取——
   抽取失真会进库。缓解：来源留痕 + fence 往返（可审计回原文）、
   受控翻译（标识符白名单）；
3. **协议冻结的不可逆**：v1 冻结是单向门——字段命名与语义需在
   三端实测收敛后再冻结，冻结前允许破坏性调整；
4. **工程容量**：阶段四、五重（蜂巢改造 + 新机制），阶段一至三
   轻（字段 + 原语 + 测量）。顺序即风险排序。
