## 0. 一句话纲领

**不可理解的执行体不可信；可信 = 可理解 + 可复算 + 可溯源。** 白箱化就是把一切执行体（程序、记忆、智能体行为）转换为**统一中间表示**，使其可分析、可验证、可治理。今晚三个项目分别在**程序域**（Ghidra）、**协作域**（pi）、**质量域**（OCR）独立验证了这套方法——它们不知道彼此，却实现了与我们相同的方法论。这不是巧合，是收敛。

## 1. 纲领本体：白箱化四原理

| # | 原理 | 陈述 | 违反后果 |
|---|---|---|---|
| W1 | **统一表示** | 一切被分析/被执行的对象，先归一为小而正交的中间表示 | 异构对象各说各话，分析无法跨域复用 |
| W2 | **确定性内核** | 「不能错的」由确定性机制保证，概率性组件（LLM）只产候选 | 质量随 prompt 漂移，结果不可复算 |
| W3 | **显式化** | 隐式状态、隐式前提、隐式盲区必须显式展开；未知的显式占位，不静默丢弃 | 隐蔽腐化：错在心里看不出在哪 |
| W4 | **知识数据化** | 平台知识/规则/策略外置为可审查的数据（spec），引擎对知识零改动 | 加一条规则改一次代码，演进被代码锁死 |

**验证记录**（各原理的异域实现）：
- W1：Ghidra P-Code（74 正交操作码+Varnode 全状态编址，`PcodeOp.java:46`）；pi 事件溯源日志（13 叶子状态机+全局 seq，`session/types.ts:315`）；灵枢认知图（md 节点+frontmatter——**且多两维：条件化+信任化**，荣 2026-09-16「我们做统一中间表示，工具是智能论条件论」，灵枢 node_1a5d8a68）。
- W2：OCR 确定性五模块×Agent（同模型 Precision/F1 更高、token 仅 1/9）；灵枢蜂群 verifier 逐位复算、四闸门。
- W3：Ghidra UNIMPLEMENTED 显式占位（未建模指令不静默丢弃）+标志位展开为显式数据流；pi 错误消息显式标记不入上下文；灵枢盲区 BS 制度、条件空间卡。
- W4：Ghidra SLEIGH（新平台=新 spec，引擎零改动）；pi 扩展系统（工具/compaction 可替换）；灵枢 writelimit 规则、Pi 交接 D3 规则引擎（待建）。

> **MiroFish 关联**（世界模型方向，已完成分析归档）：作为反面样本佐证纲领——有智能（万人 LLM agent）无白箱（无验证闸/无 checkpoint/预测不可复算），恰是四原理缺失的完整标本。详见灵枢 node_36ec9560。

## 2. 三项目在纲领中的位置

| 项目 | 域 | 白箱化角色 | 它教我们的一句话 |
|---|---|---|---|
| **Ghidra** | 程序域（二进制） | **黑箱→白箱转换器**：把不可理解执行体还原为可分析表示 | 完备性=小而正交算子+全状态统一编址；新域=新数据不改引擎 |
| **pi** | 协作域（agent 运行时） | **白箱运行时**：一切行为落事件日志，状态可重放、可分支、可对账 | 核心最小化+显式状态机；工具面渐进披露；压缩可逆 |
| **OCR** | 质量域（代码评审） | **白箱质检线**：确定性硬约束筛选与定位，LLM 只裁语义 | 确定性工程让 LLM 提质 9 倍省 token；反思/定位模块分离 |

**三域合围即灵枢的完整图景**：灵枢大脑在认知域做同样的事（信息流→认知图 IR），且是三者中唯一把**观测条件（条件空间）与信任凭证（四态/evidence）编码进 IR** 的实现。三个项目是我们路线的异域印证；灵枢的增量维度是它们没走的下一步。

## 3. 统一方法论六条（交叉验证结论，方法论级可引用）

1. **小而正交的封闭算子集**优先于大而全的开放枚举（Ghidra 74 操作码六年稳定 ↔ 术数编译器封闭指令集）；
2. **隐式状态显式化是分析的前提**（Ghidra 标志位→显式数据流 ↔ 灵枢条件显式化/反思两问句）——不显式化，就只能猜；
3. **未知的显式占位**（Ghidra UNIMPLEMENTED ↔ 灵枢盲区 BS 制度）——「没分析过」与「分析过没问题」必须可区分；
4. **知识外置为数据，引擎对知识零改动**（SLEIGH/pi 扩展/评审规则库）——演进速度由数据决定，不由发版决定；
5. **确定性管线+可枚举变换序列**（Ghidra 反编译 Action 链/分析器确定性排序 ↔ 蜂群 BSP 确定性提交/评审 M1 机械层）——自由发挥只属于候选生成，不属于裁决与结算；
6. **一份核心多前端**（headless/GUI 共用管线 ↔ 一份大脑多 harness），前端是方言，核心是协议本体。

## 5. Ghidra 交接正文（防御面专项）

### 5.1 定位与许可
- 入区 `agi-architectures/ghidra/`（浅克隆 442MB，20,546 文件）；荣裁定：「矛盾是一体两面的，破解和防御都是对同一种机制的认知。**我们取防御面**。」
- 许可红线：核心 Apache-2.0；**根目录 `GPL/` 下模块另带 GPL/LGPL，代码严禁复制进本仓**；Ghidra 自身有已知安全公告（README Security Warning）——运行样本分析必须在隔离环境（容器/VM）。

### 5.2 防御面四对接点（能力储备，按需启用）
1. **供应链安全审计（二进制级）**：灵枢以 npm 包发布（@furongjun1999/dsh-memory），scanner CI 管 manifest 级，Ghidra 管原生模块/native prebuilds/可疑 so-dll——纵深补位；
2. **外部程序准入评审**：蜂群盲区 **BS-4 异构程序实例**——世界模型测试场接收外部术数程序/字节码时，headless 模式可脚本化批量审计「外来程序实际做什么」；
3. **保护线对抗纵深**：vision-protection 的攻击样本分析能力储备；
4. **工具链自防**：分析工具本身是攻击面（Ghidra 自己的安全公告为证）——自用工具同样过 scanner。

### 5.3 浅层调研结论（已完成，灵枢 node_1a77ad69）
- **P-Code**：74 正交操作码+Varnode 三元组（全状态地址空间化）；SLEIGH spec 数据化；lossless（UNIMPLEMENTED 显式占位）；反编译=固定 Action 序列；
- **插件管线**：Plugin/PluginTool+服务与事件两路解耦；Analyzer=可选步骤；6 队列 priority 确定性排序；扩展 zip 自动进管线；
- **Headless**：与 GUI 共用分析管线；可复现（确定性排序+无随机源）。
- **方法分析六条对照**全部与灵枢已有件同构（§1 验证记录+§3），Ghidra 无一件与我们路线冲突——收敛而非修正。
