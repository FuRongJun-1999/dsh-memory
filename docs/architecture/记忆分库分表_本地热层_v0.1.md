# 记忆分库分表（本地热层）v0.1

使用者裁定（2026-11-14）：**分库分表**——重要自我信息与短期记忆固化到**本地库优先检索**；
总库改为**每晚同步一次**，把短期记忆整理写入总库。

## 现状与实测（3.5 万节点生产库）

| 面 | 耗时 | 说明 |
|---|---|---|
| 载入总库 | 10.4s | 进程启动一次 |
| `cg read k=20` | **≈24s** | 全库检索本体（与本件无关，另议） |
| 建热层（冷缓存） | 3.1s ~ 93s | 取决于 OS 缓存；夜间跑无所谓 |
| 热层检索 | **0.14–0.17s** | 150x 快于全库 |

## 产物

```
<brain>/_hot/
  hot_nodes.json     精选节点（id/layer/importance/t/session/preview≤300）
  hot_postings.json  倒排（归一化词 → id）
  hot_meta.json      构建元数据（built_at / source_stamp / 计数 / layers / truncated）
```

**热层是派生物**：删掉 `_hot/` 不影响任何数据，随时可重建；`search` 在缺失时返回
`available=false`（不抛错）。

## 收什么（两遍优先级）

```
① self / anchor          —— 全部，**永不因上限被挤掉**
② 近 7 天 contextual     —— 短期记忆
③ importance ≥ 0.7       —— 少量高价值知识
上限 6000 条（防热层长成第二个总库）；超限记 truncated=true
```

检索时层加权：self 2.0 / anchor 1.8 / knowledge 1.2 / contextual 1.0 ⇒ **先看自己与近的**。

## 每晚同步（已注册）

```
计划任务：LingshuHotTierNightly  每日 02:30
命令：python -X utf8 scripts/sync_hot_tier.py --root <总库> --write
做的事：① 重建 _hot/   ② 把**当天** contextual 整理成一条日摘，写入总库
```

日摘规则（安全）

| 项 | 取值 | 理由 |
|---|---|---|
| 层 | `contextual` | 日摘不是知识，不能过知识层准入闸（#749/#913/#914） |
| node_id | `digest_YYYYMMDD` | **幂等**：同日重复运行不产生第二条 |
| 标签 | `daily-digest, regenerable, shortterm` | 可被 heal/regenerate 重放 |
| 回滚 | `forget digest_YYYYMMDD`（软删可 restore） | 不物理删除 |

## 开关与回滚

- 热层只在**显式调用**时使用（`md_cg.hottier.search`）；未接入默认检索路径，故**当前零行为变化**；
- 下一步（未做）：`MDCG_HOT_FIRST=1` 时让 `read` 先问热层再回总库（需改检索入口，另开 PR）；
- 全部可回滚：删 `_hot/` + 停计划任务即可回到原状。

## 不适用条件

- 热层检索是**词法**（归一化 token 倒排），不做语义/向量；答不上就应回总库，不假装完整；
- 不替代 `read` 的性能优化：24s 的检索本体仍在；
- 不搬敏感节点：热层按 layer/importance/时间选，**不绕密级**（正文仍回总库按密级取）。
