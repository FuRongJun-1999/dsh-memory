# 会话身份与「工作 / 日常」分离 v0.1

> 一句话：**同一个大脑，不同会话担任不同身份；身份决定「看得见哪些记忆」。**
> 本文是「解析不出身份」时的排查入口，也是判据的唯一口径来源。

## 1. 身份从哪来（唯一真源）

会话身份**不是一个新字段**，它就是会话标识的五元组第二段：

```
s5.<端>.<身份>.<工作区>.<创建时间>.<首条消息摘要前12位>
例：s5.dsh.maintainer.D_4_ai.1791340000.3f9a2b7c1d05
              └── 第二段 = 身份
```

设计出处：《会话身份五元组形态（s5）设计定稿》（设计者三项决定，2026-10-09/10）。
代码出处：`md_cg/identity_names.py`（中文名对照）、`src/hooks.ts` 的 `sessionUnitOf`。

## 2. 身份如何影响记忆可见性

| 身份类别 | 取值（机器形态） | 注入「最近记忆」时 |
|---|---|---|
| **工作身份** | `maintainer` `designer` `auditor` `verifier` `recorder` `reflector` `output` `sustain` | **可以看见**工作留痕（审核裁决记录等结构层条目） |
| **日常身份** | `agent` `roleplay` `user` | **看不见**工作留痕，只看见日常内容 |
| **未登记 / 解析失败** | 空串，或标识不是五元组形态 | **按日常处理**（安全侧降级），并在注入块尾部给出提示 |

判据代码：`src/hooks.ts` 的 `recallSkipItem(item, unit)`，顺序为

```
① self / anchor / rejected  → 任何身份都拦（前者走独立身份块，后者是否证记忆）
② structural（含审核裁决）   → 工作身份放行，日常身份拦
③ audit_trace / audit 标签  → 工作身份放行，日常身份拦（防它落到别的层）
```

> **顺序有意义**：若把「按层拦」写在「按身份判」之前，工作身份形同虚设。
> 守卫 `test/inject-by-identity-937.test.ts` 的 K2 就是钉这一条。

## 3. 「解析不出身份」怎么排查

看到注入块尾部有这句提示：

> 本会话身份未登记：标识非五元组形态，已按日常处理。

就是**注入面拿到的会话标识不是 `s5.` 开头**。排查顺序：

1. **看标识**：查该会话写入的任意节点，`frontmatter.session` 是否为 `s5.…` 形态；
   - 若是 `session-<uuid>` 或 `sess_<hex>`：属于**旧形态**，本仓按纪律**不回填**，新会话才会用五元组；
2. **看端侧接线**：端（DSH / zcode / CodeBuddy / Codex）是否在会话起始算出五元组并注入；
   - 未注入 ⇒ 标识保持旧形态 ⇒ 身份恒空 ⇒ 恒按日常处理；
3. **看身份段取值**：若第二段是未登记值（如 `ops`），注入行为等同工作身份判断失败，
   需在 `md_cg/identity_names.py` 的 `UNIT_NAMES` 增补条目（**不猜**，由维护者裁定）；
4. **刻意要工作留痕时**：确认本会话标识第二段在工作身份清单内，或改用对应身份的会话。

## 4. 不适用条件

- 不覆盖**存量旧标识**节点：它们不回填身份，也不因此被删改；
- 「按日常处理」是**安全侧降级**（宁可少看见，不可多泄露），不是能力缺失；
- 中文展示名只影响界面；库内形态永远是小写段值，跨端可复算。

## 附：用途标签约定（2026-11-14 起）

写入时若会话标识可解析出身份，会在标签里追加 `用途:<中文值>`（如 `用途:修缺陷`、`用途:扮演`）。

| 项 | 约定 |
|---|---|
| 形态 | `用途:` 前缀 + 中文短词（冒号为半角） |
| 来源 | **会话身份派生**（五元组第二段），不读内容、不看关键词 |
| 缺省 | 旧形态标识或身份未登记 ⇒ **不打标签**（不猜） |
| 已登记的取值 | 修缺陷 / 做设计 / 跑审计 / 做验证 / 做记录 / 做反思 / 做输出 / 做维生 / 扮演 / 日常 |
| 新增取值 | 必须先在 `md_cg/identity_names.py` 的 `UNIT_PURPOSE` 登记，否则不出标签 |
| 幂等影响 | 无：写入幂等闸（`_gate_dedupe`）按**同层 + 内容指纹**比对，**不看 tags** |
| 分桶 | `bucketindex.build` 统计 `purposes` 副键（纯增量，不进词表、不改桶名） |

## 附二：三层分类（2026-11-14 定稿）

| 层 | 取值来源 | 缺失时 |
|---|---|---|
| **主归属 · 项目** | 写时标签 `项目:<名>` | 不建项目桶，计数 0（不猜项目名） |
| **副键 · 用途** | 会话身份派生 → 写时标签 `用途:<中文>` | 不打标签，计数 0（不猜用途） |
| **检索标签 · 学科** | 既有大域分类（big_domain） | 允许缺失，只作过滤维度 |

**实现位置与性质**

- 三者都只在 `bucketindex.build()` 里做**计数**（`purposes` / `projects`），
  **不进词表、不改桶名、不落新文件** ⇒ 既有检索打分与桶形态零变化；
- 项目与用途**都没有独立输入源**：节点无 `workspace` 字段、会话归属在写入路径也不落盘，
  所以只能读**写时标签**。这是实测结论，不是设计偏好；
- 守卫：`md_cg/test_purpose_bucket.py` P1–P7（含 P7 负例：无标签时两副键必须为 0）。
