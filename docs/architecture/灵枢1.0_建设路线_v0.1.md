# 灵枢 1.0 建设路线 v0.1（解耦 · 纯记忆系统）

> 依据：《灵枢记忆系统 · 统一架构 v1.2》（外部设计仓文档，未随本仓分发；L 轴五层 / 四 KPI）、PR #593（三重同构 ⇒ 记忆必须显式化）、PR #594（八条原理移植）。
> 本文只做**归位与切分**，不新增理论。

## 0. 一句话

**1.0 = 一个不依赖任何宿主、不生产智能、只负责「记得住、查得到、改得回、账不丢」的纯记忆内核；宿主（DSH 插件 / hive / 其它）只能通过四个接口接入。**

## 1. 目标与非目标

| | 内容 |
|---|---|
| **目标** | ① 依赖单向（内核不知道宿主存在）；② 接口只有四个；③ 四个 KPI 各有可判门禁；④ 单模块可独立测试（不拉起插件）|
| **非目标** | 答得更准/更快/更省（bench 已证归模型）；兼容历史内部函数名；保留 `mdcos.py` 的「什么都干」形态 |

## 2. 解耦分层（内核 · 治理 · 接口 · 适配；依赖只能自上而下）

```
适配层   dsh 插件 / MCP server / hive worker      ← 只调 D2，不碰 D1/D0
接口层   四个契约（Write / Read / Govern / SelfCheck）
治理层   生命周期四档 · 审计台账 · 回滚/2PC · 资格判定（DEFER/BLINDSPOT）
内核层   节点存储 · 索引 · 检索打分 · 锁/WAL
```

**禁止项（违反即判耦合）**：
- 内核/治理层不得出现 `from ..dsh`、不得读环境变量决定行为（除路径根）；
- 接口层不得依赖任何 HTTP/MCP 类型，只吃 dict/JSON；
- 适配层不得直接读写存储文件。

## 3. 四个接口契约（最小签名）

| 契约 | 签名（示意） | 不变量 |
|---|---|---|
| **Write** | `write(node_id, content, conditions, provenance) -> {id, state, receipt}` | 必须带 `provenance`（依据链）；写失败必须留账 |
| **Read** | `read(query, context) -> [{id, score, why, state, evidence_ref}]` | `why` 必填（依据什么命中）；`state` 只来自治理层 |
| **Govern** | `revise / retire / rollback / audit(ts_range)` | 任何修订可回滚；回滚**覆盖正文**（已实现，见 §4 注） |
| **SelfCheck** | `status() -> {counts, lag, drift, wal_ok}` | 必须能在不读全部节点的情况下答「我坏没坏」 |

> 原文「回滚面不含正文（#573 实测）」判断有误，予以订正：
> - **#573 与本条无关**：该 issue 标题为「0.9.6 第五批：把『环境造成的红』与『真缺陷』分开」，正文只讲 `HIVE_EXEC_PY` 未设导致 16 个任务全落 error，**全文无「回滚」字样**（仅 1 处「回退成 exec.py」，指执行器回落）。
> - **实现早已覆盖正文**：`md_cg/rollback.py` 的 `rollback_mutation` 走 `method="preimage"`，按执行时点前像覆写正文，并给出 `bytes_equal_preimage` 读数；B 合并类另走 `strip_aggregate_lines` 定向剥离。该能力随 `00824721`（10-17）落地，早于本文档首版 `388fe4a6`（10-20）**3 天**。
> - **本仓自带用例已断言**：`md_cg/test_mutation_rollback.py` 在文档首版时即含 Q 组「回滚：逐字节比对前像 = True」「回滚后盘面逐字节 == 前像」。
> - **独立复核**（不引用仓内测试辅助，直接读盘面）：建节点含 `8080` → 变更单接受改写为 `9090` → `rollback_mutation` 返回 `ok=True, method=preimage, bytes_equal_preimage=True` → 盘面 `含8080=True / 含9090=False`。
>
> ⇒ 结论：正文面回滚**不是缺口**，W2 无需重新开发；四契约里 `Govern.rollback` 只需在接口层**声明**该语义（契约骨架见 W1）。

> **§6 注（R1「当前共用一把锁」前提不成立 · 事实核查订正）**
> 原文 R1 行断言「写路径与读路径**当前共用一把锁**」，并据此把 W3 定为「拆锁」。
> 三条运行期读数均不支持该前提，予以订正：
>
> 1. **读路径根本不取锁**（`scripts/probe_w3_read_write_lock.py --mode lock`，运行期给
>    `fsutil.FileLock.__enter__` 装计数器，沙箱库根实测）：建库 120 节点取锁 **242 次**；
>    随后 `search` ×5 与 `search_rrf` ×5 合计取锁 **0 次**。读写之间无共用锁可拆。
> 2. **写入 P95 不受并发检索影响**（`--mode p95`，读者在独立进程、排除 GIL）：
>    放大 **1.05–1.18x**（5 轮）。「读长尾拖慢写」不成立。
> 3. **首版结论曾误判，已自查纠正**：首版只测「线程内并发检索」得写入 P95 放大 43.78x，
>    看似锁争用确证；但把读者换成**纯 CPU 忙等（一行 md_cg 代码都不碰）**，放大到
>    **838.05x**——一个不取任何锁的对照组比实验组慢 19 倍，说明 43.78x 主要来自
>    CPython GIL 争用。把读者挪到独立进程后即降到 1.05–1.18x。**不做该对照组，就会把
>    一个错误前提写进本文档。**
>
> **但耦合确实存在，方向是反的**（`--mode read`，写者在独立进程；写者固定 id 覆写以
> 恒定库规模，排除「库越大重载越慢」的混淆项；每臂 200 次查询）：
>
> | 臂 | 唯一差异 | 读 P95 放大 | 并发期整库重载 |
> |---|---|---|---|
> | flush | 写者改索引签名 | **16.58–21.02x** | **200 / 200 次** |
> | noflush | 写者不改签名（对照） | 1.13–1.25x | 0 / 200 次 |
>
> - **机制**：读者每次查询都在读路径上探测索引签名（`mdcg.py::_maybe_reload_index`），
>   他进程 `flush()` 改变签名 ⇒ 读者**整库重载**（`_load_index`）。即**写影响读**，
>   不是「读影响写」。
> - **生产缺省即此形态**：`MDCG_RELOAD_MIN_INTERVAL` 缺省 `'0'`（应急闸关闭），
>   且 MCP serve 本体就是 `autoflush=1 只 flush 不 close` 的长期写方。
> - ⇒ **W3 照原判据（写入 P95）拆锁，拆的是不存在的东西**；真实可拆物在
>   **读侧整库重载**，不在锁。W3 判据已相应改写（见 §9）。

## 7. #593 推论 C 的架构约束

凡要求独立核验的场合，记忆载体必须**显式、可枚举、可脱离模型读取**。落到 1.0：
- 节点必须是**离散文件/行**，不得只存在参数或内存缓存；
- `Read` 返回必须带 `evidence_ref`（可定位到节点/行）；
- 「依据链」必须能层层指认到上游条目（否则 T 维不成立）。

## 8. 不适用条件

- 不覆盖“模型内部推理质量”（归模型，不归记忆系统）；
- 不承诺与历史内部函数签名兼容（只承诺接口契约与数据格式）；
- 不在本路线内改 `hive` 调度语义。
