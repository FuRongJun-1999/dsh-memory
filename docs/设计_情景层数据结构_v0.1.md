# 设计：情景层数据结构（日记式）v0.1

> 使用者 2026-11-12：**从角色扮演与身份交流看，用户名就是角色名；实体名错误是不应该的。**
> 原始材料按「对话片段」组织本身有问题——角色与 AI 的对话，存入记忆**本就该按日记写进情景层**。

## 0. 一句话结论

**角色名不是抽出来的，是写进来的。** 把「谁说的」从正文里用正则猜，是把结构信息降级成文本噪声；
场景下说话人是**闭集**（用户角色 / AI 角色），完全可以在写入时就确定。

## 1. 问题取证（外测档 1 验收）

```
要素在 pack：2/19 → 2/19（建卡前后无变化）
卡确实进了 pack（19 题里 17 题有 profile- 卡，每题 16–30 张）
但命中的是错卡：profile-person-号你（正确卡 profile-person-沈知夏 存在却未被选中）
另有整题 cards=0（该实体卡根本没建）
```

三层排除：不是 session 归属（±过滤同值）、不是卡没进（16–30 张）、**是卡错/卡碎/卡淹没**。
其中 `profile-person-号你` 这条不是「抽取规则差一点」，而是**方向错**：名字根本不该被猜。

## 2. 情景层数据模型（日记条目）

情景层每条 = **一幕**（一段连续对话或一个事件），frontmatter 增加 `diary` 结构体：

```yaml
diary:
  date: "2026-04-26"            # 事件日（不是写入时刻；与 created_at 分离）
  scene: "收摊后，店里"          # 可选：一幕的标题
  speaker: "沈知夏"              # ★角色名（闭集：用户角色）
  listener: "满师傅"             # ★AI 角色名（闭集）
  participants: ["老贺"]         # 第三方（引述/在场者）
  place: "江北咖啡店"            # 地点轴
  objects: ["画册"]              # 辅助面
  mood: "累"                     # 辅助面
```

三处关键分离：

| 分离 | 为什么 |
|---|---|
| `diary.date` ↔ `created_at` | 事件发生日与记账时刻是两件事（#804/内容日期之乱的根源） |
| `speaker/listener`（结构）↔ 正文 | 角色名是**声明**，不是从文本里抽 |
| 核心（人/地/时/事件）↔ 辅助（物/情绪） | 前者建轴追踪，后者只做检索 facet |

## 3. 资料卡按「轴」聚合（不是按文本猜名）

```
角色卡：profile-role-<角色名>      ← speaker/listener 聚合（本人视角）
人物卡：profile-person-<第三人>    ← participants 聚合
地点卡：profile-place-<地点>       ← place 聚合
事件卡：profile-event-<日期>       ← 同日 scene 聚合
```

角色卡是**必然存在**的（每个库只有两三个角色），因此「用户基本信息」类题的第一步
不需要任何抽取：卡的存在性由写入契约保证。

## 4. 抽取降级为「只补第三人 + 辅助面」

| 来源 | 手段 |
|---|---|
| 角色名 | **写入声明**（零抽取）|
| 第三人 | 抽取 + **已知人名 registry**：首次登记，后续需过形态校验（2–4 字、非代词/语气词、带称谓或出现 ≥2 次）|
| 地点 | `place` 声明优先；缺失时按处所词尾抽 |
| 物品/情绪 | 只进 facet，不建树 |

`profile-person-号你` 这类错名会被三道闸挡住：代词表 + 长度/形态校验 + registry 确认。

## 5. 兼容与迁移（不推倒重来）

| 节点 | 处理 |
|---|---|
| 新写入 | 带 `diary` 字段（摄取面声明 speaker/listener/date）|
| 存量 | 按老路（抽取）建卡；能补 `diary` 的回填（从 `session`/`role`/`created_at` 推 speaker 与 date）|
| 判据 | 卡上标 `card_source: declared` / `extracted` —— **两种来源不许混报** |

## 6. 落地顺序（最小改动优先）

1. `diary` 字段 + 写入参数（`speaker`/`listener`/`participants`/`place`/`date`）；
2. `profiles.build`：**先读 `diary`，缺则回落抽取**；角色卡必建；
3. 人名三闸（代词表/形态/registry）+ registry 文件 `_entity_registry.json`；
4. 资料卡配额：pack 里资料卡 ≤5 张、按与 query 的实体匹配度排序（避免 16–30 张淹没）；
5. 迁移脚本：存量节点回填 `diary`（能推的推，推不出留空，不猜）。

## 7. 验收判据（不变）

**19 题「要素在 pack」比例（现 2/19）**；附加两条：

- 错名率：`profile-person-*` 里非法/非人名的比例（当前至少 1 例 `号你`）；
- 配额命中率：19 题中「正确卡在 pack 且未被无关卡挤出」的题数。

## 8. 边界（不声称）

- 别名/昵称合并（沈知夏 vs 知夏）需人工别名表，本设计不做自动消歧；
- 事件卡的「一幕」边界仍需人定（一次会话 ≠ 一幕）；
- 存量回填只能补「能从结构推出的」（speaker/date），第三人仍需抽取。
