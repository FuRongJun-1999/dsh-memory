## 2. 接线点候选（关键）

**问题**：谁、在什么条件下，以 `bypass_gain=True` 调 `explore`？

> 先厘清「通电」的语义：缺口 a 的病是**生产路径不可达**（无挂载点），不是「没人自动跑」。按 #25/#28 的修复先例，「通电」＝**让开关在生产挂载点可见、默认关**，而非「让它自动运行」。因此**接线点（谁调）**与**是否自动（进不进心跳）**是两个正交问题——候选 A/B/C 回答前者，§2.4 单独讨论后者。

### 2.1 候选 A · 显式触发（手动 / 命令行 / MCP op 参数）

- **形态**：为既有生产入口 `insight act="explore"`（`md_cg/mdcos.py:3931-3937`）**新增一个透传参数** `bypass_gain`（缺省 `False`），并在 MCP schema 暴露；等价地提供一条 CLI 显式入口（如 `python -X utf8 -m md_cg.autonomy ...` 或经既有 `insight` 命令面）。形态与 `goal action=generate`（`md_cg/mcp_server.py:2489`）同构——**显式调用、默认零副作用**。
- **风险**：**最低**。调用者是显式主体（`actor` 字段可归因）；不改变任何默认路径；不引入无人值守行为。
- **可审计性**：**最高**。`_explore.jsonl` 已落 `bypass_gain`（`autonomy.py:294`）＋`actor`（`:290`）；可加 `budget` 字段（见 §3）。
- **与裁定第 8 条的关系**：**一致**。第 8 条要求「首版不进心跳（opt-in 显式调用）」，候选 A 正是 opt-in 显式调用——与 `goal_gen` 走同一道门。
- **我的判读**：**推荐（首版唯一入口）**。

### 2.2 候选 B · sustain / sleep 周期触发（常驻 tick）

- **形态**：仿 `md_cg/sustain.py` 的第六档 tick（`_tick_evolve`／`_tick_sleep`，见 `sustain.py:26-33` 与 `sleep.py:8`），新增一个周期性 `_tick_curious`，按 env 开关（如 `MDCG_CURIOUS=1`）与周期预算触发。
- **风险**：**中**。无人值守自动探索：会写 `_explore.jsonl` 并可能经 `learn_blindspots(apply=...)` 回写 `gap_hint`（`autonomy.py:277`）——**写面扩大**；且与自愈/演化的资源竞争。
- **可审计性**：中。留痕经 `_sustain.jsonl`（tick 台账）＋`_explore.jsonl`。
- **与裁定第 8 条的关系**：**精神上冲突**。第 8 条的判据是「阈值未标定前自动化＝制造噪声」——探索预算同样**未标定**，同一判据适用。若首版就进周期 tick，等于在未标定预算上自动运行。
- **我的判读**：**不作为首版接线**；可作为「预算标定后」的第二阶段（届时沿用同一开关，仅换触发源）。

### 2.3 候选 C · 心跳触发（宿主 5 分钟巡检 / cron）

- **形态**：由**宿主侧**心跳（zcode/DSH 编排层）周期性以 `bypass_gain=True` 调生产入口。
- **风险**：**最高**。心跳是**最外层**编排，触发频率最高、归因最弱（易与「设计者直连通道」抢注意力）；且 md_cg 自身不拥有心跳（心跳在宿主侧，见纲领 §七）。
- **可审计性**：中。跨进程调用，留痕仍落 `_explore.jsonl`，但触发者身份在库外。
- **与裁定第 8 条的关系**：**直接冲突**。第 8 条明确「首版不进心跳」。除非编排侧显式改裁，否则不应在首版接入。
- **我的判读**：**首版排除**（与第 8 条同门）。

### 2.4 关于「是否沿用裁定第 8 条的门控」（明确讨论，不默认）

- 第 8 条原文（`设计者首批裁定_v0.1.md:31`）针对 **W2 目标发生器**，依据是「阈值未标定前自动化＝制造噪声；**对齐 `explore`/`tickets` 的既有 opt-in 现状**」。
- **关键旁证**：该条依据把 `explore` 列为「既有 opt-in 现状」的样板——即**裁定自身已认定 `explore` 属 opt-in 一族**。好奇线是 `explore` 的豁免通道（同一个 `explore` 函数、同一个调用面），因此**沿用门控是自洽的，不是外推**。
- **反方观点（需并陈）**：好奇线若要真正成为「与威胁并行的第二驱动力」，迟早要脱离纯手动。若永远 opt-in，则「好奇」的系统性展开仍依赖外部唤醒——与 §2.9.3.1「不是任务策略的待命形态」有张力。
- **我的倾向**：**首版沿用第 8 条（不进心跳、不进周期 tick），只开显式入口**；把「自动化触发」列为 §9 待裁项，并附带**前置条件**（预算上限须先标定出保守缺省）。理由：缺口 a 的病是「不可达」而非「不自动」；先闭合可达性 + 声明预算，再谈自动化——与第 8/10 条「先观察、后自动化」同节奏。

## 3. 预算上限的设计选项

**背景**：真源 L1846–1848 要求「预算内不经 Gain 筛选（豁免），**预算耗尽即回到任务定价**；预算上限是**设计决策**，须**显式声明并可审计**，**不从第零定律推导**」。故本节的产出是**声明位**（env 名 + 缺省 + 超限行为 + 审计字段），取值本身留编排侧拍板。

**不拍板**，给三选项。三条共用的设计原则：
- **单位取「提案条数（explore 提案数）」**——与既有 `limit` 同量纲（`autonomy.py:244`），不新造量纲（对齐 W4 设计「复用既有常量、不新造量纲」的纪律）。
- **超限行为三选**（每选项标注）：①**拒绝**（hard reject，返回 `refused` + reason，零副作用）；②**排队**（降级为任务定价，即回落 `enforce_gain=True`，本轮仍可产生 deferred）；③**降级**（同上但静默，仅留痕）。
- **审计**：落 `_explore.jsonl`（`autonomy.py:290-315` 的 `rec`）新增字段，或经派生重算（仿 `gain_gate` 读台账）。

### 3.1 选项 预算‑1 · 单次夹取（per-call cap）

| 项 | 建议 |
|---|---|
| env 名 | `MDCG_EXPLORE_BUDGET`（备用名 `MDCG_CURIOUS_BUDGET`） |
| 值域/单位 | 正整数；单位＝**单次 `explore` 调用的提案上限**（条） |
| 粒度 | 每次调用 |
| 缺省值 | **3**（＝现 `limit` 缺省，`autonomy.py:244`，零行为变更） |
| 超限行为 | **拒绝**（夹取到上限，超出部分不入 steps） |
| 审计 | `_explore.jsonl` 新增 `budget: {limit, used, exhausted}` |
| 理由 | 最小步：只把「隐式 `limit`」提升为「显式声明」，闭合缺口 b 的字面要求 |

### 3.2 选项 预算‑2 · 滚动窗口预算（per-window budget）

| 项 | 建议 |
|---|---|
| env 名 | `MDCG_EXPLORE_BUDGET_WINDOW`（窗口秒数）＋ `MDCG_EXPLORE_BUDGET_MAX`（窗口内上限） |
| 值域/单位 | 窗口＝秒（如 86400＝每日）；上限＝**窗口内累计探索条数** |
| 粒度 | 每滚动窗口（如每日） |
| 缺省值 | 窗口 `86400`、上限 **30**（保守；待标定） |
| 超限行为 | **降级**＝回落任务定价（`enforce_gain=True`）：预算内正常豁免，耗尽后同一入口自动按任务定价走，**无需调用方重试**——直接实现 L1847「预算耗尽即回到任务定价」 |
| 审计 | 台账派生：仿 `gain_gate` 扫描 `_explore.jsonl` 的 `bypass_gain` 记录（`autonomy.py:92-111` 同款读法），新增 `budget_gate` 计算；落 `budget: {window, max, used}` |
| 理由 | **语义最忠实**：L1847 的「耗尽」是**跨时间**的，仅单次夹取无法表达「耗尽」 |

### 3.3 选项 预算‑3 · 双层（单次夹取 + 滚动窗口）

| 项 | 建议 |
|---|---|
| env 名 | 预算‑1 与预算‑2 的并集 |
| 粒度 | 每次 + 每窗口 |
| 缺省值 | 单次 3、窗口 86400/上限 30 |
| 超限行为 | 单次超→拒绝；窗口超→降级（回落任务定价） |
| 审计 | 两字段并列 |
| 理由 | 最保守（防「单次小但高频刷」）；复杂度略高 |

### 3.4 我的倾向（留编排侧裁定）

- **倾向 预算‑2 为语义主件，预算‑1 为最小首步**：先落预算‑1 闭合「显式声明」缺口（零行为变更、可立即验证），预算‑2 作为实现 L1847「耗尽即回落」的正解同时或紧随落地。
- **取值不拍板**：缺省值（3 / 30 / 86400）仅为**保守占位**，真源明言上限是「设计决策」，**取值归编排侧**（§9 待裁）。
- **env 命名留裁**：本仓 env 惯例为 `MDCG_*` 且「默认关＝非 `1`、容量/阈值可配」（见 `hotcache.py:39-43` 与 README env 表），三选项已循此惯例；最终名以编排侧为准。

## 4. 隔离保证（可断言的隔离点清单）

**目标**：证明 `bypass_gain=True` **只**影响 `proposals` 的 `σ(Gain)` 筛选这一个环节——不碰 `score`（资格）、不碰 `judge_*`、不碰写入闸。

| # | 隔离点 | 断言 | 对应守卫 |
|---|---|---|---|
| **I1** | 只改 `enforce_gain` 一个开关 | `explore` 内 `enforce_gain=not bypass_gain` 是唯一受影响量（`autonomy.py:261`）；`bypass_gain` 不再流向任何其它调用 | `test_gain_gate.py` 第⑥组（扩）；新守卫结构断言 |
| **I2** | 不碰 `score`（ΔD 定价器） | 同一信号下，`bypass=True` 与 `bypass=False` 的提案 `score` **逐条相等**（`autonomy.py:198-211` 在 `enforce_gain` 分支之前计算） | 新增断言（同库同信号两态对拍） |
| **I3** | 不碰资格（`score<=0` 排除） | `score<=0 → continue` 发生在加分与 `enforce_gain` **之前**（`autonomy.py:200-201` vs `:222`）；豁免**不得**让零信号项获得资格——`n_signals` 与 `proposals` 的零信号排除两态一致 | 新增断言 |
| **I4** | 不碰 `σ` / `gain_gate` | 豁免路径下 `deferred_exhausted` 为空（`autonomy.py:222-228` 未执行）；`gain_gate()` 纯读函数对同一台账输出**逐字段不变** | `test_gain_gate.py:76-104`（既有）+ 新增对拍 |
| **I5** | 不碰 `judge_*` / 终排 / 信任 | `autonomy` 的 import 面为 `d_meta, metacognition, predict`（`autonomy.py:29`），**不含** judge/trust/weights/writepipe；`explore` 返回体只排 `proposals`，不产生判定 | 结构断言：`inspect.getsource`/`__dict__` 扫描 import 面（仿 `test_retr_gates_prodpath.py:123-129` 的 P4 防悬空写法） |
| **I6** | 不碰写入闸 | `learn_blindspots(apply=...)` 的调用参数与 `actor` 不因 `bypass_gain` 改变（`autonomy.py:277`）；豁免只改「筛选」，不改「回写」 | 新增断言（apply 路径两态一致） |

**一句话口径**（可写入返回体/文档）：`bypass_gain` 是**筛选器的旁路**，不是**资格的旁路**，更不是**写入的旁路**——它恰好对应 §2.9.3.1 第 3 条「预算内探索在**任务外**条件空间生效，任务内 `Gain` 筛选口径不动」。

## 5. 守卫草案（至少四条能红断言）

> 落点建议：新守卫文件 `md_cg/test_curious_prodpath.py`（命名对齐 `test_retr_gates_prodpath.py` / `test_i28_hotcache_prodpath.py` 的「生产路径」语义）。断言需能**红**——即对「未修」（无挂载点）或「过度修」（无条件开启/无预算）两类误修都亮红。

### C1 · 默认关零变更（能红「无条件开启」的过度修）

- 未设任何新 env、调用方不传 `bypass_gain` 时，`explore` 的返回体与 `_explore.jsonl` 记录**与基线逐位一致**（仅 `t` 字段可变）。
- 对拍口径：**排序面 + 提案字段面逐位一致**（沿用 W4 实施裁定的「反向腿口径」）。
- 能红对象：若把 `explore` 默认改成 `bypass_gain=True`、或 env 缺省开启 ⇒ 本断言红。

### C2 · 开关生效（预算内照常探索、留痕 `bypass_gain=True`）（能红「旧实现」）

- 显式以 `bypass_gain=True`（或开关 env 开启）调用：冷却中的盲区（连续终态停滞、`σ=0`，构造见 `test_gain_gate.py:81`）**仍产生 steps**。
- `_explore.jsonl` 末条记录 `bypass_gain is True`（`autonomy.py:294`）。
- 能红对象：无挂载点的旧实现（`explore` 永收不到 `True`）⇒ 本断言红。

### C3 · 预算耗尽即回落任务定价（能红「无预算」的过度修）

- 构造窗口内已达上限的台账（或等效注入），再以豁免入口调用：**不得**再豁免——表现为回落任务定价（`deferred_exhausted` 出现或 `proposals` 按 `σ` 拦住），返回体标 `budget_exhausted`/`exhausted=True`。
- 能红对象：只做单次夹取、无窗口计数的实现 ⇒ 本断言红（无法表达「耗尽」）。

### C4 · 留痕可审计（台账字段齐）

- 豁免记录须含：`bypass_gain`（`autonomy.py:294`）、`actor`（`:290`）、**预算字段**（`budget: {limit/window/max/used/exhausted}` 中至少 `used` 与 `exhausted`）。
- 能红对象：只改行为、不加预算留痕的实现 ⇒ 本断言红。

### C5（加分） · 豁免不改变资格与终排

- 同库同信号两态对拍：`score` 逐条相等（I2）；零信号项两态都不产生提案（I3）；`n_signals` 相等；非豁免态终排顺序不被豁免路径影响。
- 结构防悬空（仿 P4）：生产入口源码（`md_cg/mdcos.py` 的 explore 分支）**必须引用** `bypass_gain` 透传——防止未来再写出「不含豁免透传的第三个入口」（本病灶的复发形态）。

## 6. 风险与失败模式（最重要的三个）

### R1 · 预算滥用 / 无限探索

- **失败形态**：豁免通道被反复调用而无上限 ⇒ 探索无限展开，`_explore.jsonl` 膨胀、写面持续被 `gap_hint` 触碰。
- **缓解**：① 预算上限**硬夹取**（选项 预算‑1/‑3 的单次夹取，不可被调用方越过）；② 窗口预算（预算‑2）实现「耗尽即回落」；③ 审计 `used/exhausted` 字段，超限**留痕不静默**；④ 缺省保守 + 上限值待标定（§9）。

### R2 · 与「缺口驱动」争资源

- **失败形态**：好奇线（任务外）与缺口驱动（任务内，威胁/盲区）共用同一 `explore` 与同一 `limit` 预算池 ⇒ 好奇探索挤占缺口探索的算力/注意力。
- **缓解**：① **明示共享预算池**：`bypass_gain` 不新增独立 `limit`，仍在同一 `limit` 内（`autonomy.py:261` 已如此）；② 若编排侧要求隔离，则在 `proposals` 层显式拆分预算（**待裁**，§9）；③ 审计 `n_signals` 与 `bids`（`autonomy.py:292`）观察两侧占比；④ 首版仅显式触发（候选 A），天然限量。

### R3 · 豁免被当成绕过 Gain 的后门

- **失败形态**：有人以 `bypass_gain=True` 绕过 `σ(Gain)` 去喂**任务内**提案，使 §2.9.3.1 的「不同条件空间」退化为人人可走的万能豁免（真源 L1851–1854 明言要「避免统一变量豁免成为万能豁免条款」）。
- **缓解**：① **隔离点 I1–I6 全绿**（豁免只达筛选器，不达资格/信任/写入）；② **结构断言 C5** 锁死「唯一挂载点」，禁止第二入口；③ **默认关 + 显式 actor 归因**（`autonomy.py:290`），滥用可追责；④ 文档口径固化（§4 末「筛选器旁路 ≠ 资格/写入旁路」）；⑤ 预算上限即「豁免额度」，超额即回落（R1 缓解同源）。
