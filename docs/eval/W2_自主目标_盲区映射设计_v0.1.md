## 〇、结论先行

1. **缺口的准确位置**（承接探针读数，并做一处诚实收窄）：探针读数断言「自动生产者为零」——该断言对 **goal 台账**成立（`md_cg/sleep.py` / `md_cg/sustain.py` 全码 **0 处** goal 写入，已复核）。但本步核实发现：**「盲区 → 产物」的链路已存在两条**，只是产物不是 goal：
   - `md_cg/blindspot_tickets.py` `make_tickets()`（:66）——盲区 → 四类**任务卡**；
   - `md_cg/autonomy.py` `explore()`（:210）——信息差 → **gap_hint 待补线索**回写。
   二者共同点：**均 opt-in、默认 `apply=False`（预演）、只被显式调用**（`autonomy.py` 头部自述「缺口只在触发器」）。故真缺口收窄为三点：**(a) 目标粒度**（落 `goals` 层而非 task/gap_hint）、**(b) 自动/周期触发器**、**(c) 显式确认闸**。
2. **设计立场**：本设计**不新造发生器地基**，而是把既有的「盲区信号源 → 确定性分类 → 落卡」范式（`blindspot_tickets.classify` :37）从 task 面**上提到 goal 面**，并把既有的**自治档位闸**（`md_cg/autonomy_modes.py` `decide` :335）与**审核队列**（`cg.propose`/`review_decide`）接成「自主 ≠ 自裁」的确认面。
3. **边界（本文不处理，如实登记）**：退出权/自毁（§1.6.3 红线五）归 W3；情感权重对目标选择的调制归 W4。本文只交「盲区→目标」的映射规则、确认闸、失败模式与实施拆步。

## 一、映射规则（字段级）

**公共字段面**（每条候选目标统一携带，供确认闸与守卫审计）：

| 字段 | 取值来源 | 说明 |
|---|---|---|
| `source` | 六路信号源之一（S1–S6，见下） | 原料出处，可回溯 |
| `evidence` | 触发点的实读读数（计数/样本 id） | 目标不是断言，是「带着证据的候选」 |
| `impact` | 影响面（层 / 节点数 / 是否核心面） | 优先级因子，非硬判据 |
| `goal_text` | 模板渲染（见下） | **确定性文本**——同一信号渲染出同一串，享受 `add_goal` 的 sha1 幂等去重（`mdcg.py` :2939） |
| `priority` | `clamp(base + w₁·频次 + w₂·影响面 − 去重惩罚)` | `add_goal` 的 priority 兼作 importance（检索偏置强度） |
| `conditions` | 该目标的生效条件（情境词面） | 落 `# 生效条件：` 行；缺省视为任意情境有效 |
| `class` | `维护类` / `探索类` / `越权类` | **确认闸分档依据**（见 §二） |

### S1 · unresolved 层（未解问题台账）

- **形态**：`layer="unresolved"` 节点，正文四字段「问题 / 已知线索 / 现场 / 目标」（`md_cg/mdcg.py` `add_unresolved` :2857，模板 :2869-2875），importance 固定 0.3（:2887）。
- **触发条件**：① 存在 unresolved 节点，且 ② 该节点 `# 目标：` 行为「（未设定）」或 ③ 建单超过冷却窗仍无关联 task（关联判据复用 `blindspot_tickets` 的「query 命中 unresolved 首行 → task」思路 :40）。**首版阈值保守，标「待标定」**。
- **候选目标形态**：`goal_text = "消解未解问题：<问题首行>"`；`priority = 0.5 + w₁·(该工单未解时长分位)`；`conditions = "库内存在该 unresolved 工单且未被裁决时"`。
- **§1.6.1 条件三对齐**：需求来自**系统自己的未解问题台账**（内部状态），触发源是内部台账的存量与老化，而非外部下发的奖励/损失。这是「内部生成的需求」的最直接形态。

### S2 · insight 蒸馏（pending 待验证项）

- **形态**：`md_cg/insight.py` `record`（:164）写入 `state="pending"` 的洞见事件（`STATE_PENDING` :41）；待裁决计数见 `report`/`outlook`（`outlook` :423 已有「pending ≥ 3 ⇒ 建议裁决」的既有建议）。
- **触发条件**：`pending ≥ 3`（沿用既有建议阈值，非新造）。
- **候选目标形态**：`goal_text = "裁决待验证洞见：<statement 摘要>"`；`priority` 随 pending 计数递增；`conditions = "该洞见仍处 pending 且无外部证据时"`。
- **§1.6.1 条件三对齐**：目标是「把内部累积的未裁决认知缺口推到可裁决」——需求源于内部认知一致性压力。

### S3 · sustain diagnose（缺口读数）

- **形态**：`md_cg/sustain.py` `diagnose`（:547）返回 `issues`，含 `ccg_backlog`（:655，无验证基底 `no_basis` / 无负条件 `no_neg`）、`importance_drift`（:662）等 code。
- **触发条件**：某 issue code 的计数越过阈值（如 `ccg_backlog.n ≥ N`）。**注意**：`ccg_backlog` 是**索引代理指标**（`_ccg_backlog` :484 docstring 明示「代理指标 ≠ 判定结论」），故只作驱动信号，不作「确该固化」的裁决。
- **候选目标形态**：`goal_text = "固化候补清账：<layer> 层 <n> 个无验证基底节点"`；`priority` 与计数正相关；`conditions = "库内该层固化候补 ≥ 阈值时"`。
- **§1.6.1 条件三对齐**：需求源于**内部结构完整性缺口**（记忆自维护压力），非外部任务。

### S4 · BLINDSPOT / health（四态判定如实落档）

- **形态**：`md_cg/metacognition.py` `blindspots`（:259）返回盲区地图（`items` 含 blindspot/defer 计数 + `unresolved` 清单）；`_advise`（:371）已能产出「为高频盲区邻域建 unresolved 节点」的建议；`BLINDSPOT_DENSE` 阈值（:53）。
- **触发条件**：某盲区簇 `blindspot ≥ 3`（反复未知，与 `blindspot_tickets._JUDGE` 的 research 判据同源）或 BLINDSPOT 占比 ≥ `BLINDSPOT_DENSE`。
- **候选目标形态**：`goal_text = "补条件消解高频盲区：<query 的 metacognition._key>"`；`priority` 与盲区密度正相关；`conditions = "该盲区簇 BLINDSPOT/DEFER 计数未归零时"`。
- **§1.6.1 条件三对齐**：需求来自**盲区感知**（§1.6.4 五标志之一，探针读数判「全亮档」）——系统对「自己不知道什么」的感知直接转成「要去补什么」的需求。

### S5 · predict（空路由 / 低命中方向）

- **形态**：`md_cg/predict.py` `routes`（:625）返回推演路线，`hit_rate`（:353）/`channel_posterior`（:411）给命中读数；盲区驱动入口 `routes_from_blindspot`（:650）；`predictability`（:478）支持显式声明 `# 可预测性：unknowable`。
- **触发条件**：routes 为空 或 命中率低于阈值，**且** `predictability != "unknowable"`（结构性不可知不生成，`predict.py` 头部 :15-16 明示）。
- **候选目标形态**：`goal_text = "补锚点/边：<盲区> 推演路由为空"`；`priority` 与低命中显著度正相关；`conditions = "该方向可预测（非 unknowable）且路由仍为空时"`。
- **§1.6.1 条件三对齐**：需求源于**推演失败的自检**（系统发现「这条路走不通」），是内部认知路径的缺口驱动。

### S6 · 演化账本 evolution（规律缺口）

- **形态**：`md_cg/evolution.py` `patterns`（:308，`by_missing`）与 `summary`（:337，`most_missing` / `top_pattern`）；缺失维度对应结构维四要素（`evolution.py` :477）。
- **触发条件**：`by_missing` 中某维计数 ≥ 阈值。
- **候选目标形态**：`goal_text = "补条件维度：<missing 字段>"`；`conditions = "该维度缺失计分位仍 ≥ 阈值时"`。
- **§1.6.1 条件三对齐**：需求源于**规律缺口的自统计**（系统对自己「最常缺哪一维」的内部读数）。

**去重与幂等**：`add_goal` 的 gid = `goal_<sha1(goal_text)[:10]>`（`mdcg.py` :2939），**同文本 → 同 id → 覆盖更新**（幂等）。故模板必须**确定性**（不含时间戳/随机数），否则同一盲区换措辞会开出多张目标（`tasks.py` :22-24 已记录该病根）。反向代价：差异化的目标（如同层不同缺口）需在文本中带**稳定标识**（如层名/缺失字段），而非自由散文。

## 二、显式确认闸设计（自主 ≠ 自裁）

### 2.1 三区划分（候选 → 放行 → 台账）

| 区 | 落点 | 谁能进 | 依据 |
|---|---|---|---|
| **候选区** | 生成器 `dry_run` 输出 + append-only 留痕日志（形态参照 `autonomy.py` 的 `_explore.jsonl` :47 / `insight` 事件日志） | **全部**六路候选 | 零落库；与 `blindspot_tickets` 的 `apply=False` 预演、`maintain` 的 dry_run 同构 |
| **放行区** | **审核队列**（`cg.propose` → `review_queue`，`writepipe._gate_audit` 非 ACCEPT 出口 :256；裁决 `review_decide` mdcos.py :2683） | **探索类** 候选（新方向/跨面） | 目标先成「变更单」，经 accept 才落台账 |
| **台账区** | `goals` 层（`add_goal` :2926） | **维护类** 候选（结构自维护，白名单） | 走 `decide(A_ADD)` 判 allow 后自动登记 |

### 2.2 分档判据（复用既有自治档位，不新造）

- 既有**自治档位**：`md_cg/autonomy_modes.py` ↓ 三档 `MDCG_AUTONOMY = plan|confirm|full`（:129，缺省 confirm），`decide(action_class)` 返回 `allow|confirm|forbid`（:335），矩阵真源 `MATRIX`（:156）。**新增节点＝动作类 A_ADD**（:138）。
- **自动登记白名单**：仅「维护类」目标（S3 固化候补 / S6 条件维度补全）——它们是**结构自维护**，不改语义、不涉外部动作。判定：`decide(A_ADD)` 为 `allow`（confirm/full 档）时方可自动 `add_goal`；**plan 档无计划步骤 ⇒ `forbid`**（fail-closed，`_gate_plan` 语义）。
- **必须留候选/走审核**：S4 盲区消解（可能牵出**新方向**）、S5 路由补全（可能牵出**跨面知识**）、S1/S2 中触及**协议真源/重要判断**者——一律只出变更单进 `review_queue`，等主脑（reviewer 角色）或设计者 accept。
- **永不自动（硬边界）**：对齐纲领「须停下待裁的边界」（`纲领` §七运行规则 5，L156）——**对外发送 / npm publish / 智能论真源修改 / 资金与账号**。生成器对命中这些词面的候选**直接丢弃并记 `moved_to="boundary_refused"`**（不静默）。

### 2.3 留痕可审计

1. **台账自身**：goal 节点带 `created_at`（`_goal_entry` :2960）、`goal_status`、`importance`，可经 `cg(op=goal, action=list)` 回读（清单含来源可见性靠 `tags`）。
2. **生成留痕**：每轮生成 append 一条记录（源 / 证据 / 候选 / 分档 / 判定 / 是否落库），形态照 `_explore.jsonl`（`autonomy.py` :256-280 的 `outcomes`/`meta_outcomes` 结构）。
3. **裁决留痕**：走审核队列的候选自动获得 `pid` 与轮次历史（`review_rounds`，`review_cli.py` :162），accept/reject 全程留档。
4. **审计钩子**：落卡走 `cg.add` → `cg._audit`（`tasks.py` `_audit` :230；目标面同理经 `add` 链），不新造日志格式。

### 2.4 「自主」与「自裁」的分界（一句话）

**自主 ＝ 系统自己发现缺口并产出候选；自裁 ＝ 系统未过确认闸即改台账/对外动作。** 本设计把「自主」放在生成器（候选区，只读信号 + 零落库），把「自裁」堵在确认闸（放行区/台账区，过 `decide` + 审核队列）。

- **待裁项**：自动触发频率、与心跳台账（纲领 §七）的耦合方式——**留设计者/主脑裁定**。
