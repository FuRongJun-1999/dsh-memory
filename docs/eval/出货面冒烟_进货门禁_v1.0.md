## 一、缺陷定义与真实站点

### 1.0 术语：本腿与「进货门禁」

- **出货面冒烟腿**（本文正文用词）：`scripts/check_publish_smoke.py` 这道门禁腿。
- **进货门禁**（**文件名用词**，仅出现在本文件路径里）：本腿守的口径＝**出厂件必须真到货**——`files` 白名单声明的必要件必须**出现在 pack 出的 tarball 里**（S1）、**出现在装好的目录里**（S2/S3）、且到货件能**真启动**并给出文档口径的缺省工具面（S4/S5）。「到货」与「进货」同指本腿的落地检查，不指任何采购/入库流程。

### 1.1 缺陷

发布门禁链（`npm run gate`）**缺一道「出货面」判据**：既有门禁只检查**包内件的内容**（凭据/私有数据/隐私/非追踪件），**不检查某个必要件是否出现在发货清单里**。于是「**仓库里在、包里不在**」这一族缺陷全链无感——修前实测两次同族事故：`#38`（`scripts/` 与 `hive/` 整目录未被 `files` 收录）与 `issue #48`（仓根 `utf8_boot.py` 未被 `files` 收录 ⇒ 0.6.1 **装机即挂**）。#48 的补丁（提交 `52677077`）只把件加回白名单，**没有补上机器检查**——同类再犯仍无人拦（此判断的解除条件见 §八.2，**未完全解除**）。

### 1.3 定因：为什么八道全漏

`scripts/check_publish_artifact.py` 的 `local_mode()`（`HEAD:556` / 工作树 `:568`）判据面是 **R1–R6 六档**——凭据面、私有数据面、隐私文本、非追踪件面、清单路径安全、清单来源可信（`:589`–`:615` 六处 `report.rule`）。这些全是对**已列进清单的件**做内容/来源检查；一个必要件**整体缺席**时，它**没有任何可扫的对象**，照样 `VERDICT=PASS`（`:938`）。**「缺席」不是「命中」，扫描面天然看不见空集**——这就是同类缺陷两漏的结构性根因（不是某条腿写错了）。
