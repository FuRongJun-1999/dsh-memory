## 二、九项探针：三处预判被推翻

探针全部独立 `tempfile` 沙箱 root（独立 `MDCG_ROOT`/`MDCG_AUX_ROOT`/`MDCG_MASTER_KEY`）、argv 列表 + `shell=False` + 显式 UTF-8，**不写入在役库**。三条结论与我事前的判断相反：

1. **P-4（分片目录删除后能否自愈）**——我原以为「新进程也看不到节点」，**被证伪**：全新短命进程本就会重建目录，故不自愈的必要条件是「本进程已持有 `ShardLog` 实例」（长驻 MCP serve 形态）。B4 的修法与反证据此写成。
2. **P-9a（H4 统一归一层默认开影响英文检索）**——**直接证伪报告结论**：默认态下英文查询命中 gold top1，且仓内本就有两条测试断言这一点。报告该条**不成立**。按使用者裁定「不动默认，补探针与文档」，本版**不翻全局默认**。
3. **P-3（MERGE 还是熵 DROP 吞正文）**——我原以为只有一条分支有问题，**实测是两条都吞**：`0.85` 的 MERGE 与 `0.60` 的熵 DROP 都丢新正文。第 2 包据此两分支一起修。

九探针另额外挖出**报告里没有**的三条缺陷：

- **①** CCG 哨兵 `不适用条件：无` 会无条件触发 `condition_clash`（假冲突）⇒ 第 2 包 H8-⑤ 收口（`_is_null_condition` + 输入剥空值）。
- **②** 基类 `MdCG.search` 的负记忆提示段会把同一节点**重复出条** ⇒ 随 H10 负尾单点化一并收口。**诚实边界**：收口后「重复出条」这一具体形态**我未单独立断言复验**，只由 `test_neg_tail_honesty.py`（44 断言）与 `test_read_face_semantics.py`（123 断言）间接覆盖 ⇒ **记为待复验项**。
- **③** `scripts/linkref_backfill.py` 仍在铸造裸毫秒 id（存量现场遗漏）⇒ 第 1 包 B1 把它改为委托 `mint_auto_id`，守卫断言「`def mint_auto_id(` 全仓仅 1 处」。

## 四、自有回归：自查抓到的一条，比新增守卫更重要

容器栈一（Linux）第一次跑出 `[FAIL] md_cg.test_policy_required_ccg --head-baseline`。取证链条：

1. **红项集合比对**：实际 `{G2b,G2c,G2d,G3b,G3c,G4a,G4b,G4c,G5a,**G8a**,G8c,**G8d**}` vs 预期 `{…,**G8b**,G8c}` ⇒ 多出 G8a/G8d（`ModuleNotFoundError: No module named 'mdcg_head.mdcg'`），且**预期该红的 G8b 变绿了**。
2. **基线对拍（决定性）**：把改前的 `06db0f74` 检出到**独立 worktree** 跑同一守卫 ⇒ 红项**恰好**是预期 11 项、自带红基线 PASS ⇒ **这是我这四批引入的回归，不是既有状态**（worktree 已 `remove`，工作区未被触碰）。
3. **根因**：该守卫用「假包 `mdcg_head` + 转发层 `_SHIMS`」把工作区源码做定点变异后单测。我这四批给 `md_cg/writepipe.py` 新增了两处**函数内**委托（`from .mdcg import …`、`from . import forgetting`），而 `_SHIMS` 没跟上 ⇒ 假包缺模块 ⇒ 调用期抛异常 ⇒ 被 `_try` 收成 `err`、`got` 退化为 `{}` ⇒ `hint=""` ⇒ **G8b 的 `"重试同样结果" not in ""` 恒真**，于是「守卫坏了」伪装成「多两个红项 + 一个假绿」。

**修法（治三处，不只是补一个名字）**：

1. 补齐转发层：`_SHIMS` 增加 `mdcg`/`forgetting`/`units`/`coldverify`/`hotcache`/`hyperedge`/`nodefile`——注意后五个是我这条新判据**自己查出来的**（历史靠「那条路径没跑到」侥幸绿着）。
2. **新增 fail-closed 判据 `_check_shim_coverage`**：用 AST 抽取基线源里**全部**相对 import（含函数内延迟导入），凡未登记即报 `SHIM-MISS` 并点名模块 ⇒ 同类缺口从此在**装配期**就叫停，不再退化成假绿。**定点变异自证**：抽掉 `_SHIMS` 里的 `forgetting` ⇒ 立刻 `SHIM-MISS` 且**逐字点名 `writepipe -> .forgetting`**。
3. **堵死假绿**：G8b 断言补 `err is None and bool(hint)`。**定点变异自证**：用一个「一碰就抛」的 `wp_mod` 桩跑 `run_checks` ⇒ G8b **转红**（detail = `RuntimeError: boom-stub(WritePipeline)`），而旧写法在同一输入下判定为 `True`（假绿形态**在进程内复现**）。

修后：绿态 **28 pass / 0 fail**、红基线**红项恰好 11 项**（`rc=0`），容器栈一该腿 `[PASS]`。
