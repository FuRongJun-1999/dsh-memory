> `check_publish_artifact.py` 的 R1–R8 校验的全是「**清单内的东西安不安全**」，

## 二、补了两条判据，但**先说我第一版写错的事**

### R9a 的第一版：恒绿，等于没有判据

我最初写的判据是：「**随包模块**按路径装载的件必须随包」。

实测结果：**装载点 0，缺失件 0** —— 恒绿。

原因：真实的动态装载点几乎全在 `scripts/` 下，而 `scripts/` 本身不随包（白名单只发 `workspace_index.py`），于是判据①「装载方在包内」把**所有**真实装载点都跳过了。

**更关键的是**：这条判据**抓不住本轮那个真实缺陷**。我做了正面验证：

```
R9a 对本轮缺陷的判定：未捕获
```

因为本轮的形态是「**包外**模块（`sync_zcode_session.py`）装载**包外**件（`state_extract.py`）」，落在 R9a 的「整链不发布」NOTE 档，不会红。

**如果我不做这次验证，就会宣称「R9 已堵住该缺陷」——那是假的。**

### 改成的正确形态：R9b「同一判据不得分叉两落点」

回头看清本轮缺陷的真形态，不是「装载关系断了」，而是：

> `state_extract.py` 的**本体**已在 `md_cg/`（随包），
> `scripts/` 下留的**薄垫片**不随包。
> ⇒ **同一判据两个落点，一个发货一个不发。**

R9b 就判这个：同名 `.py` 落在「混合位置」（有随包的、有不随包的），且互为薄壳/等价实现 ⇒ 分叉风险。

实测精准命中 **3 组**，其中就包括 `state_extract.py`。

### 为什么不能「同名即判」

本仓有 **33 组同名 `.py`**。若不区分，会误报一大片：

| 误报类型 | 例子 | 为何不是缺陷 |
|---|---|---|
| 同名不同物 | `compiler/parser.py` vs `md_cg/whitebox_kb/wisdom/core/parser.py` | 不同包、不同职责 |
| 并行测试套件 | `md_cg/test_*.py` vs `tests/test_*.py` | 两条测试面并行，设计如此 |
| 包标记文件 | 各处 `__init__.py` | 结构件 |

故 R9b 只判「同名 **且** 有薄壳/等价实现信号」的混合位置。误报多了闸门就会被忽略，等于没有闸门——本仓 N251 已有同款教训。

## 三、登记机制：**带前提**的豁免

3 组命中里，`review_cli.py` / `judgment_manifest.py` 是设计上的源码树薄壳，不发货**不是缺陷**。所以需要登记。

但登记**不能是「永久免死金牌」**。本轮栽的正是这个坑：

`state_extract.py` 的薄垫片之所以当前安全，**依赖一个可检验的前提**——

> 装载它的 `scripts/sync_zcode_session.py` 自己**不随包** ⇒ 装机侧不执行这次装载。

一旦 `sync_zcode_session.py` 进了 `files` 白名单，这个前提立刻失效：装机侧会真的去 open `scripts/state_extract.py`，而它不发货 ⇒ **断链**。

所以登记写成：

```python
"state_extract.py": {
    "why": "薄垫片（只 re-export md_cg.state_extract）...",
    "requires_not_shipped": "scripts/sync_zcode_session.py",   # ← 前提
}
```

**前提成立 ⇒ NOTE（可见但不判负）；前提失效 ⇒ 自动重新判负**，并写明「登记已失效：其前提不再成立」。

实测验证：

```
前提成立     → NOTE（前提：scripts/sync_zcode_session.py 不随包，现成立）
装载方进包后 → FAIL（登记已失效：其前提不再成立）
```
