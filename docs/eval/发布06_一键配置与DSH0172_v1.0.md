### 2.4 语义注记（口径对齐，均已读取核对）

1. 片段 env 口径与 `mdcgChildEnv()`（src/lib/mdcg_client.ts:115-129）对齐——`PYTHONIOENCODING`/`PYTHONUTF8` 是硬约束非可选（中文记忆场景，该函数头注 2026-09-20 读线程崩溃现场）；`MDCG_MCP_SURFACE=kernel` 与既有直挂样例同口径——kernel 面无 `mdcg_*` 细粒度工具，直挂端写入走 `cg(op=write)`+凭据，与插件端「必须 full」的场景（src/lib/mdcg_client.ts:68-74：唯一写入通道是 `mdcg_remember`，kernel 面下写入静默失败）不同，**刻意不跟插件对齐**。
2. 缺省记忆根 `~/.lingshu/memory` 是本命令的显式缺省并写进 MDCG_ROOT，与插件运行时缺省（`~/.dsh/.dsh-memory`，src/lib/datapath.ts stateRoot()）不同源——片段显式指定即无歧义，两套默认各安其位。
3. `PYTHONPATH=repoRoot()`（import.meta 向上找 package.json，src/lib/datapath.ts:41-56）：npx 场景指向 npx 缓存中的包根（files 含 md_cg/ 故随包可用），输出含「建议换 git clone 常驻仓库路径（免疫 npx 缓存清理）」的诚实提示（src/init.ts:312）。
4. `MDCG_PYTHON` 键对直挂端是文档性（解释器由 command 决定），对 DSH 插件端真实生效（`defaultPython()` 读 env 覆盖，src/lib/python_path.ts:46-47）——输出文案如实区分（src/init.ts:122）。
5. readline 对「attach 前预缓冲且不 end」的 PassThrough 只消费第一行（隔离实验结论：首问 OK 次问 ERR_USE_AFTER_CLOSE/question 永久 pending），可靠形态是先启动 runInit 再逐问 write——该结论已写进测试注释（test/init.test.ts:97-100），后来者不必重踩。
