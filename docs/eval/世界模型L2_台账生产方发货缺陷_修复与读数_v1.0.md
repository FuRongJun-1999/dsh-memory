## 0. 一句话结论

上一轮把 L2 的**读面**（`alternatives`）修好了，但生产台账 `events=0`——源头没有数据。
本轮查明根因不是"没接线"，而是**接线的生产方根本没随包发出去**：`scripts/` 不是整目录
发货，`package.json` 的 `files` 只列了 `scripts/workspace_index.py`。

**已修**：生产方迁入随包发货的 `md_cg/`，`scripts/` 留薄垫片；实测打包清单从 1791 → 1792
件，`md_cg/state_extract.py` **SHIPPED**。

**未修（如实）**：DSH 宿主侧（`src/hooks.ts`）与 zcode 侧都**仍然没有真正运行这条链**
（见 §5）。本轮修的是"发了包也不带抽取器"这个**前置阻塞**，不是"链路已在跑"。

## 1. 缺陷（实测，非推测）

### 1.2 成因（证据链）

| 环节 | 实测 |
|---|---|
| `package.json` 的 `files` 白名单 | 27 条，`scripts/` 下**只有** `scripts/workspace_index.py` |
| `npm pack --dry-run --ignore-scripts` | 发货 **1791** 件，`scripts/` 实发 **1** 件 |
| `scripts/state_extract.py`（抽取器本体） | **MISSING** |
| `scripts/sync_zcode_session.py`（zcode 侧装载点） | **MISSING** |
| 装机副本实测 | `~/.dsh/profiles/desktop/node_modules/@furongjun1999/dsh-memory/scripts/` 下**仅** `workspace_index.py` |

⇒ 装机侧 `sync_zcode_session._load_state_extract()` 装载不到抽取器 ⇒
`state_events.append` 永不发生 ⇒ 台账恒空。

### 1.3 发布闸为什么没拦

`scripts/check_publish_artifact.py` 的 R1–R7 校验的是**清单内的文件安不安全**
（凭据 / 私有数据 / 隐私 / 非追踪件 / 路径逃逸 / 清单来源可信 / 扫描面完整）。
它**没有"必需件"概念**——不校验"某个运行时被装载的模块在不在清单里"。
故白名单漏项是它的**结构性盲区**，不是它失职。

## 2. 修法

判据：**运行时被装载的模块，其所在目录必须被 `files` 白名单覆盖。**
`md_cg/` 整目录在册且已随包发货；`scripts/` 只剩一件。故：

| 文件 | 角色 |
|---|---|
| `md_cg/state_extract.py` | **生产方**（本体；RULES / extract_turn / extract_and_record / enabled） |
| `scripts/state_extract.py` | **薄垫片**（只 re-export，零判据、零实现——沿本仓 `aliases_is_thin` 的薄别名纪律） |

垫片存在的理由：`sync_zcode_session` 按**文件路径**装载
（`spec_from_file_location("state_extract", scripts/state_extract.py)`），
保留垫片可使既有装载点与 import 路径**逐字不变**，不必改调用方。

**不是**把文件复制两份——两份实现正是本仓反复出现的病灶形态
（#375 / #383 的"同一判据两个落点"同族）。故断言直接钉"同一对象"：

```
垫片 extract_turn        is 本体 extract_turn        → True
垫片 extract_and_record  is 本体 extract_and_record  → True
垫片 RULES               is 本体 RULES               → True
```

## 5. 仍然存在的缺口（这是本轮最该看的部分）

修好"发货"只解决**前置阻塞**。记账链要真正产出数据，还差**运行侧接线**：

1. **DSH 宿主侧（`src/hooks.ts`）未接本链路。**
   宿主每轮确实已经调 `cg(op=recent, action=add)`，看似是天然接线点；但
   `op_table` 里 `recent` 的 `require` 是 **`recent`**，而记账
   （`state_event` / `write`）是 **`write`**。
   **把记账挂进 `recent` 会让该 op 的实际权限从 `recent` 抬到 `write`** ——
   授权面被静默扩大，故本轮**刻意不接**，留作需裁决项。
   本机亦无 `node_modules`（`lib/` 未构建），TS 侧改动**无法构建验证**，
   不写未验证的 TS。

2. **zcode 侧钩子不在本仓。** `zcode/` 下只有 `AGENTS.md` / `README.md`，
   无钩子脚本；`sync_zcode_session` 没有任何配置引用指向它。
   故"zcode 端已接线"在本仓内**无法核实**，只能确认"装载点可用"。

3. **`package.json` 的 `prepare` 在 `npm pack` 时会失败**（缺 `typescript` /
   `node_modules`）——本次靠 `--ignore-scripts` 才取到清单。这是打包体验问题，
   未修（越界到发布物构建，须单独立项）。

**诚实结论**：生产台账 `events=0` **本轮之后仍是 0**（已复测确认）。本轮的价值是把
"就算接了线、装了机也没抽取器"这个隐性阻塞变成可测、可防腐的已知项——**不是**让台账
开始有数据。

4. **修复尚未到达装机副本。** 实测
   `~/.dsh/profiles/desktop/node_modules/@furongjun1999/dsh-memory/md_cg/state_extract.py`
   仍 **MISSING** —— 那台机器上跑的是**旧发布**。本次改的是仓库源码，
   要生效还需**发新版本并重装插件**。在那之前，装机侧行为与修复前完全一致。
