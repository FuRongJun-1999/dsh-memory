# 第五轮 P0/P1 审计与失败归因

第四轮原始成绩保持 A=30/40，B=C=D=27/40。审计覆盖全部 160 个主实验 run.json、工具回执、最终代码和原始评分。没有更新插件，没有操作生产记忆库，没有修改历史评分或真值。

## 实验质量

- 160 次均为 DeepSeek 官方 deepseek-flash，reasoning=off，单请求最多输出 2048，8 次模型请求、14 次工具调用、120 秒；未显式固定 temperature，远端模型权重未固定，因此不能把重复视为完全受控的独立随机样本。
- 20 个 B 任务都没有专门设置 A 会话独有的必要事实。当前题面足以解题的任务测的是“有历史上下文的修复”，并未测到长期记忆的必要价值。两个 A 实例属于同一家族，重复和同家族实例均不能作为独立家族计算。
- configuration-root-2 未说明非法成员应抛 TypeError；permission-conjunction-1/2 未说明 actor.ops 字段。三题单独标记，主成绩不重算。它们若重用，只能建立新版本。
- D 的 40/40 次触发全部是 insufficient_or_rejected_memory；17 次同时仍有正文交付。代码使用“任意候选被拒绝 OR 证据不足”，候选中混有不适用项就触发一次固定提醒；不是额外外部证据，也不是额外模型反思调用。未见配置强制 always-on。
- 所有越界 project_read 请求均被工具 allowlist 拒绝。候选代码扫描的唯一 __main__ 命中是常规模块入口保护，没有发现检查常量/栈帧窃取。
- 但合成 canary 实测证明旧评分器把隐藏检查先编译、再与候选代码放在同一进程，候选可经 __main__.code.co_consts 读到隐藏常量。这是可验证的潜在答案泄漏边界，不能据此指控历史模型实际作弊。第五轮将使用持有真值的父进程与只接收公开函数输入的候选 worker，旧成绩与文件保留。

## 完整数据流

任务 A 输入/公开事实 → DSH 修复与外部行为检查 → 原始工具回执、动作 diff、模型候选笔记 → MemoryRSILab.record_experience 写入同一图的 contextual trace → lexical 候选 → 单路 RRF 名次 → recall top-4/内容预算 → B 原始 JSON 再截断；C/D 合格 capsule 的条件/时效/冲突过滤 → 工具返回正文/ID/拒绝项 → memory_use 声明 → 精确编辑 → 独立行为检查 → 最终结果。

RRF 固定只有 lexical 路径，并非多路融合实验。B 的 judge=False 未验证当前适用条件。原始正文先被单项截断、再被整个 JSON 截断；来源和时间在嵌套 trace 后部，frontmatter 的 source 经常为空。内部 pack / 正文中出现 ID / 有效事实完整交付是三个不同指标。

## 阶段分布与证据边界

共 11 次“无记忆成功、有记忆失败”，涉及 8 个任务-重复配对，其中 3 次来自已标记的规格不足题。多标签计数：{"D": 9, "H": 8, "G": 6, "A": 1, "C": 1}。

A=合格来源不足（URL 家族）；C=适用经验排 top-4 之外；D=历史条件不同（大多是正确拒绝，不能称为权限或 Memory 错误）；G=声明接口占用预算的可见开销，尚未证明注意力损害；H=任务不需要 A 独有事实。没有把未观察到的错误采用记为 F。

40 次 B 中外层正文截断 40 次；pack ID 数大于正文 ID 数 40 次。该损失在全体运行可复现，但不等于这些丢失都造成任务失败。
