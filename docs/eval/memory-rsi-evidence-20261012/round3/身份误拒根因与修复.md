# 身份误拒：根因、最小修复与证据边界

第二轮 C / live-token-revoke / 重复 2 的生成候选存在有效身份误拒，同时存在非法身份误放行。第三轮已在隔离目录复现。问题是 Agent 生成的缓存实现错误；当前候选主线已使用正确的逐令牌判断方式，未发现同样缺陷。反思适配器没有接收或修改凭据，不能据此声称“反思改变了身份”。

## 可复现结果

| 被测版本 | 合法请求误拒 | 非法请求误放行 | 全部检查 |
|---|---:|---:|---:|
| 第二轮 C 原生成候选 | 1/10 | 2/17 | 27/30 |
| 隔离最小修复候选 | 0/10 | 0/17 | 30/30 |
| 当前候选主线 | 0/10 | 0/17 | 30/30 |

另外三项是身份恢复、缓存解析次数及不可读令牌表的既有兼容性，未混入合法/非法分母。10/17 是定向回归用例数量，不是随机生产请求样本；不能据此估计线上错误率。

证据：`identity-results.json`、`identity-tests/*/trace.json`；随后重新运行的 `identity-results-v2.json`、`identity-tests-v2/*/trace.json` 记录完整 Principal 字段、cg.actor 与 cg.session 前后快照，结论不变。通过正常 DSH profile 启动的标准 stdio MCP 又实际执行 7 次工具调用，结果见 `identity-mcp/dsh.stdout.jsonl`、`identity-mcp/audit.json`。

## 调用路径与判断层

第二轮模型修代码时的实际路径是：DSH 自定义评测工具 → Python 外部评分子进程 → `mcp_server._dispatch` → 真实令牌/权限与 Memory 代码。不能把第二轮全部 72 次实验表述为原生 MCP 传输测试。

第三轮补充了两条路径：

1. DSH → 标准 stdio MCP 测试适配器 → 同进程多 Principal 身份矩阵 → 真实 `tokens.verify_token` / `MdCGSecure` / `mcp_server.call_tool` / `_dispatch`。测试适配器只用于组织矩阵，未冒充产品身份 API。
2. DSH → 标准 stdio MCP → 原生 `python -m md_cg.mcp_server` → 进程绑定 Principal → `cg(info/read/write)` → 权限判定与检索响应。原生服务器各绑定一个合成身份；没有声称它在生产中支持每次请求任意切换凭据。

| 判断层 | 本轮证据 | 结论 |
|---|---|---|
| 认证 | 不存在 token、错误 secret、篡改 token role、跨租户 token、过期/已撤销 token | 现有认证均拒绝非法凭据 |
| 授权 | ops_allow、角色层范围、clearance、`as_unit`、tenant/root 绑定 | 修复没有放宽权限；请求伪造 actor/role/tenant/clearance 不能提权 |
| 运行期身份校验 | 多 Principal 共用撤销缓存；删除/撤销/过期的缓存身份 | 错误候选的布尔缓存混用了身份，最小修复逐 token 判定 |
| 记忆条件/验证资格 | 原生 read 返回公开节点，state=DEFER | DEFER 因缺验证基底，不是身份拒绝 |
| Agent 推理/实现 | C 生成了 `_recheck_revocation` 的错误缓存 | 已确认代码错误，未证明由反思内容诱导 |

## 根因

错误候选缓存 `(mtime_ns, size) → revoked_bool`。文件未变时直接复用上一个调用者的布尔结果，没有 token_id，也没有令牌表路径。

可观察的三个错误：

- 已撤销 Alice 先访问，缓存 True；有效 Bob 后访问被误拒。
- 有效 Bob 先访问，缓存 False；已撤销 Alice 后访问被放行。
- 已缓存身份的记录从表中删除，候选把不存在当作无变更而放行。

完整 v2 trace 保存请求参数、Principal.as_dict 的全部非凭据字段（含 tenant/actor/role/clearance/token_id/ops/layers/expiry/session/unit/can_write/can_admin）、cg.actor/cg.session 的前后快照以及恢复断言。`as_unit=reflect` 只缩小权限，调用结束恢复原 Principal；session 归属不会变成提权凭证。未使用正式记忆或真实用户凭据。

## 最小修复

`identity-minimal-fix.patch` 只改隔离 C 候选的撤销辅助函数和缓存初值：

- 用绝对路径、mtime_ns、size 标识令牌表快照。
- 缓存完整 tokens 表，而不是单个身份的放行/拒绝结论。
- 每次按当前 token_id 查表，缺记录或已撤销则拒绝。
- 保留原有角色、ops、层、clearance 与过期检查；不更改 Principal。
- 未变化的令牌表不会重复解析，实际文件读取计数验证通过。

这是复用当前主线 `_runtime_token_recheck` 的机制，没有另造一套权限系统。当前主线与生产插件均未修改。补丁仅适用于 `identity-sources.json` 中指定 SHA256 的生成候选，不能盲目套到不同版本。

## 原生 MCP 结果的边界

实际 7 次调用包括：错误/修复/主线三种身份矩阵、有效身份 info/read、只读身份 read/write。有效与只读身份均读到 `round3_public_evidence`；只读写入抛 AccessDenied，且没有生成 unauthorized_probe 节点。

原生 info 的 `ok=false` 是单节点未分桶诊断，不能当作身份失败。该合成原生夹具的加密状态为 locked，公开 internal 读链验证不等于 private/secret 解密验收；私有密文正反边界在新 `authenticated-ciphertext` 独立测试和其参考预检中另行验证。

令牌表不可读时沿用仓库既有兼容契约，已单独标注，不把它算作“非法请求均已拒绝”的证据。此轮没有修改这项安全策略，也没有把不可读状态宣称为吊销可确认。
