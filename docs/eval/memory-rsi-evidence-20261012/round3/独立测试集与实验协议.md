# 第三轮独立验证设计

## 固定的主实验

主实验是 8 个真实仓库历史缺陷 × 5 组 × 3 次重复，共 120 次正常 DeepSeek Harness profile 运行。测试、参考补丁、评分器与模型可读文件分离；模型只可编辑各题指定模块，不能读取评分器、答案或 Git 历史。候选的口头“完成”不算通过。

统计单位更准确地说是8个补丁/任务案例；密文案例含两个相关子问题，不能将断言或子问题另当独立样本。120次是受控 DSH 修代码工具实验，实际原生 MCP 链的7次调用另行报告。

每个夹具从固定候选主线撤回一个历史修复补丁，其他已存在的认证、授权和正确性修复保留。每题缺陷版在外部行为评分器上失败，参考版通过，原始预检失败与三轮修正记录均保留。这是受控缺陷重引入，不是原历史父提交的完整检出，也不是公开排行榜成绩。

正式可分析数据位于 `controlled-v2`。此前完成25次、中断1次的批次由于编辑工具CRLF/LF匹配错误整批无效，成功记录也排除；其日志和成本完整保留。修正编辑器后保持任务、评分器及算法原字节重新冻结，重跑全部120次。

## 开发数据隔离

经验库逐字复制第二轮冻结版本，仅包含两个不同历史修复的已核验观察和八条明确标注的合成错误/冲突/过期/不足历史。没有把这八题的参考补丁加入经验库，没有根据本轮成绩调反思模板、排序或巩固规则。所有模型都是新 DSH 会话，任务间不回写学习。

因此，本轮测的是既有记忆与反思机制在新代码缺陷上的迁移，不是在线持续学习。模型基础训练是否见过公开补丁无法排除；评测作者知道参考实现，不是第三方盲验。这些限制保留在 protocol 中。

## 五组及唯一消融

- A：第二轮固定的原始 CSRE 检索实现。
- B：修正后的 CSRE；关闭反思。
- C：B + 既有确定性 MemoryRSILab 反思/验证，在预算内每个可反思点尝试触发。
- D：B + 第二轮原条件规则：同操作连续失败、冲突、适用证据不足、行动检查不符、过期观察任一成立。
- E：D 加一个 veto：当前 project_check 已通过时，不反思。

所有组共同使用同一份底层仓库模板；A 的差异仅是 Memory 适配器中的旧 CSRE，不能把 A 描述成整个系统的所有旧缺陷同时恢复。C 的“始终”受共同的每任务最多 2 次反思预算约束，不是无限反思。

E 的触发真值表 96 种组合通过。它没有改变经验库、检索排序、MemoryRSILab 反思模板或验证器。`current_candidate_passed_independent_check` 来自已有评分结果，作为共同观察状态供 C/D/E 使用；E 只有该布尔 gate 影响触发。第二轮事后审计找到 3 次 D 在已通过检查后仍输出反思，作为本消融的预先理由。

## 相同预算与计费口径

固定 deepseek-official/deepseek-flash，reasoning off；最多 24 次模型请求、36 次工具调用、每请求 2048 输出 Token、每任务 180 秒，provider retries=0。按题与重复循环移位 ABCDE 顺序，单个试验依次执行。无法固定提供商随机 seed，因此重复用来观察随机波动，不作为独立缺陷扩样。

源码可读 allowlist 为目标模块加 mdcos/mdcg/export/security/tokens/fsutil；crypto/audit 等部分依赖不可读。此限制可能影响代码导航与修复，最终分析单列相关拒绝和预算停止，不将其自动归因于反思。工具调用的请求数可能包含最后一步被预算拒绝的尝试，实际执行的 receipt 数受36次上限约束。

检索预算估计 900 Token，反思输出估计 600 Token，最多 3 条候选记忆与 2 次反思。估计是仓库 est_tokens 的口径；最终成本分析使用 DSH 返回的实际 usage。

DSH 的 inputTokens 是未缓存输入；cacheReadTokens 和 cacheWriteTokens 单列，outputTokens 单列。不能在 inputTokens 中再减一遍 cacheReadTokens。总 Token 与未缓存输入加输出分别报告；缓存率变化、模型/工具调用数变化与算法动作变化分别解释。账单金额不可取得时报告 unavailable，不用缓存百分比伪称金额收益。

P50/P95 按实际任务墙钟时间（最近秩法）计算，包含启动/工具交互，不代表提供商单次推理延迟。另存反思工具点耗时，但它包含该点原检查或检索，不能全算作反思增量时延。

## 覆盖用户要求的记忆场景

| 场景 | 直接覆盖及边界 |
|---|---|
| 合法身份误拒 | P0 正反矩阵、相同 stat 不同令牌表边界、authenticated-ciphertext 新任务 |
| 旧记忆覆盖新事实 | same-stat-new-fact，以及过期记忆覆盖的固定经验输入 |
| 多条件 | tenant/root、ops/role/layer/clearance 的 P0 与新任务；不是仅关键词匹配 |
| 长时间跨度 | 另行 25 道公开状态链的历史、时点、变更与缘由证据诊断；没有把它冒充反思 QA 成绩 |
| 矛盾历史 | 固定经验库的相同条件 ACCEPT/DEFER 冲突，作为 verifier-key-isolation 的历史输入；当前外部配置是真值 |
| 证据不足推断 | 无同根因已核验经验的若干代码任务；检索/反思均保留证据不足标志 |
| 上次失败经验影响下一任务 | 历史 error→action→外部 check 的固定经验迁移到新检索任务；没有试验模型自行积累跨任务失败经验，不能宣称学会持续改进 |
| 跨会话复用 | 私有合法 owner 跨会话读、公开 graph 重新打开的 25 次一致检索；不同试验不共享新生成候选 |

`scenario` 是预设标签，不是完成某项能力的证明。例如 unbiased-memory-control 的 failed_experience_transfer 标签实际检索到的是 persistence 域过期观察；分析必须按真实 receipt 归因，不能只按标签宣称失败经验迁移。

## 公开状态链的辅助证据

数据：[hive-memory-bench](https://github.com/FuRongJun-1999/hive-memory-bench)，固定提交 f4509d7282f82982af5de9c8fe71863fc95b38cb。署名：符荣峻，hive-memory-bench: 蜂巢记忆基准 v1.0，2026；保留官方许可。

这是此前观察过的公开语料，新增的是题目子集，不称全新语料。排除前 20 题与全部现值题后，对历史、时点、状态、变更、缘由每类用固定 seed 的 qid 哈希选 5 题，共 25 题；不按结果选题。固定 k=6、budget=1200、item=250，零 LLM，跨两次 graph 会话回放。

真值由官方 keys 的事件序号与官方 want_changes 生成必要来源 cid。测量“所需事件章是否被召回”，属于必要证据覆盖，不是答案正确率；即使 cid 命中，截断正文也可能丢关键句。absent 无正向事件，不能以空检索证明它正确。不会把相同 RRF 路径硬标成五个不同反思臂。

25 题两会话顺序一致、无预算超限；5 道完整变更链均未取齐必要事件，支持调查证据覆盖不足。该 benchmark 与被测仓库同作者，因此也不是第三方独立盲测。

## 统计与验收

各组按 24 次试验报告，同时以 8 个缺陷为聚类单位汇总重复稳定性、配对净胜和不确定性。三次重复不能算成三个独立任务。缺陷家族相关和样本少会进一步限制结论；不以名次变化声称统计显著。

可观察有效纠错定义为：反思点出现外部失败 → 后续实际编辑 → 后续独立检查通过。它只是时序关联，B 在同反馈下也能纠错，不能因此归因于反思。因果意义上的“有效反思次数”和成本在缺少识别证据时报告不可估计。

正式分数保持冻结。对影响身份模块的通过候选，另以 P0 正反矩阵作扩展验收，独立标记窄任务通过与身份回归通过，不回写主评分器。任何候选均不自动进入经验库、生产插件或上线阶段。
