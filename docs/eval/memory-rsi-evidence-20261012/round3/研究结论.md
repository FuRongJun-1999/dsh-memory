# dsh-memory 第三轮研究结论

本轮完成8个新仓库缺陷、五组、三次重复，共120个有效试验。两次余额不足原件保留，同配置另补跑，合计122次主实验尝试。结论是：身份缓存缺陷已在隔离候选中修复并完成正反验证；条件反思有局部正向信号，仍不足以确认稳定净收益。继续保留底层正确性修复，反思默认关闭，暂不进入预测驱动 Memory-RSI。

## 结果与不确定性

| 组 | 成功 | 三次重复（每次8题） | 实际反思次数 |
|---|---:|---|---:|
| A 原始CSRE检索 | 7/24 | 3、3、1 | 0 |
| B 底层修复 | 9/24 | 3、3、3 | 0 |
| C 始终反思，最多2次/任务 | 10/24 | 3、4、3 | 40 |
| D 当前条件反思 | 11/24 | 4、4、3 | 39 |
| E D加“当前候选已通过检查则不反思” | 11/24 | 4、3、4 | 30 |

D 对 B 配对2胜0负，来自 tenant-root-binding 第2次、same-stat-new-fact 第1次；C 对 B 为2胜1负。E 对 D 为1胜1负，总成功数相同。按8个缺陷聚类，D−B描述性95%区间为0～16.7个百分点，E−D为−12.5～12.5个百分点。没有统计显著性或上线结论；相同缺陷的三次重复不算三个独立任务。

新测试消除了原先全满分的天花板，但4个案例五组均零通过，出现地板效应。密文题含两个相关子问题，源码allowlist也限制了crypto/audit依赖导航；输出和工具预算会影响修复。当前结果不能外推为所有困难任务的反思效果。

## 身份问题解决到了哪一层

根因是第二轮C生成候选将整个令牌表的mtime/size缓存为上一次调用者的撤销布尔值。它同时导致合法身份误拒和已撤销/已删除身份误放行；这是生成代码错误，未发现反思传递或修改凭据。

最小修复复用主线机制：缓存带绝对路径的完整令牌表快照，每次按当前token_id查表。原候选误拒1/10、误放行2/17；修复及当前主线均0/10、0/17，30项全通过。另3项相同stat但不同表路径的边界、旧六题两版本共12项回归、7次原生DSH→stdio MCP调用均完成。权限没有放宽。

新实验中所有60个可编辑身份模块的候选都进入扩验，59个矩阵完成：合法请求0/590误拒、非法请求0/1003误放行。另1个候选因SyntaxError无法导入，单列未执行。以上是定向回归覆盖，非线上错误率。密文任务的MAC与合法owner边界另有独立评分，不能用公共读写矩阵的通过替代。

令牌表不可读沿用原兼容契约，未计入非法请求分母；没有宣称完整fail-closed保证。修复仅应用到隔离的错误候选，当前主线原本已有正确实现，生产插件和正式记忆库未修改。

## 反思何时可能有用，能修正什么

最有价值的观察是“独立失败反馈→实际编辑→独立通过”：C有2个、D有1个、E有3个这样的事件，但只证明时序关联。B也能读到完全相同的失败反馈，因此不能将这些事件直接计作反思的因果收益。

- tenant-root-binding / r2 / D：首次改动造成reg_err未初始化，独立检查明确报UnboundLocalError；第二次反思重呈已有失败，后续编辑后4项正反检查通过。这支持继续验证反思对具体实现错误纠正的帮助。
- verifier-key-isolation / r3 / E：检查同时指出跨端点key误复用与同端点key丢失；后续编辑使7项兼容与隔离检查通过。它支持研究“明确外部反例下的修正”，没有证明模型能自行验证未知事实。
- same-stat-new-fact：D三次均通过，B两次、C一次、E两次。D的优势是一个值得独立复验的局部信号；其中r1反思先提示过期经验与证据不足，首次实际检查已通过，没有“失败后被反思救回”的轨迹，不能把胜出自动归为新增证据。

失败也很具体：C在same-stat-new-fact / r3最终留下未定义_file_bytes_digest；E在r2留下不存在的_whole_file_digest。反思并未可靠阻止接口臆造。E的这个失败全程没有通过检查，veto从未生效，所以不能把它归因于“通过后不反思”。四个全零案例说明当前模块没有解决所有复杂代码修复问题。

## 是否提高了新任务成功率

本批观察到C比B多1次，D/E比B多2次。D/B的正向变化覆盖两个不同缺陷，但每题仅三次、模型seed不可固定，仍不足以证明持续泛化。旧第二轮D比B也多1次，但新旧题目、预算和基准不同，不合并分母，不将两轮名次当作显著性证据。

本轮没有任务间在线学习，经验库一直是第二轮的两条已核验历史观察及八条明确标注的构造历史。不能宣称已经实现跨轮自我改进、组间经验演化或持续改善。

## 条件触发是否降低额外开销

E相对D总Token减少10.70%，未缓存输入加输出减少4.79%；总Token差额约96.17%来自缓存桶。E相对B总Token减少7.16%，未缓存输入加输出反而增加0.40%。因此不能声称反思相对关闭有确定的计算节省，更不能换算成账单金额。

D相对C总Token减少0.41%，未缓存输入加输出减少4.54%，两组缓存读取只差256 Token。这个比较的差额主要来自未缓存输入和输出，与第二轮的缓存主导不同；但实际仅少触发一次，其余行动轨迹也不同，仍不能把全部差额归因于触发条件。

E确实把通过检查后的反思从D的9次降到0次，总触发39→30。同样90条已发生轨迹重放，D会计算114次、E89次，少25次，证明单个gate可复现地减少无用调用点；反馈可能改变后续轨迹，这不是反事实API费用或成功率。

D首次检索就触发21/24次，总触发39次与C的40次很接近，主要因为经验不足持续为真。当前条件规则在稀疏经验库上选择性弱。E的P50/P95为27.52/44.81秒，D为31.66/57.00秒；这是整任务实测延迟，受随机轨迹、缓存及启动影响，不是纯反思增量延迟。

实际API账单未取得。所有已返回usage合计35,189,527 Token，包含有效样本、两次服务中断、整批无效编辑器运行和身份MCP探针；其中未缓存输入2,517,177、输出472,670、缓存读取32,199,680。未返回的中断usage不可补算，费用边界见完整报告。

## 外部证据能否支持记忆修正

本实验的不可改评分器、原始工具日志、候选哈希与正反回归能够支持“这个候选在这些明确条件下通过”。它们不能证明经验对其他任务普遍有效。

第二轮18段历史动作、第三轮5段历史动作均已在实际基础检索里呈现；反思没有新增当前任务外部证据，主要重组原有失败和约束。它仍可能影响注意力与行动，信息重复不等于反思必然无效，但不能把重复当成发现新事实。

13项边界探针确认失败和自述不会自动进入知识、范围扩张和证据改写被拒绝、整理只提案且可回滚。MemoryRSILab的哈希与动作绑定仅验证调用者提供的观察结构，不能认证外部工具来源。当前实验可信性来自独立收集的运行记录；生产记忆自动修正的来源真实性尚未得到该模块本身保证。

## 瓶颈与下一阶段决定

目前不是单一瓶颈：

| 层 | 本轮直接证据 | 可支持的判断 |
|---|---|---|
| 触发规则 | D≈C；缺经验几乎持续触发；E去掉9次通过后反思 | gate能减少无用点，尚不能证明净任务收益 |
| 经验适用质量 | 只有两条旧修复；5次已核验检索经验出现在新整串同分题，仍全失败 | 历史动作验收不等于当前根因适用；缺高质量可迁移经验 |
| 证据检索与预算 | 25题公开诊断的5道变更链完整覆盖0/5 | 需要同时调查选择和交付预算，不能单归咎排序 |
| 代码生成与工具可达性 | 缺失helper、语法错误、部分依赖不可读、4题全零 | 不能把所有失败解释为Memory算法失败 |

公开变更题必要来源分别27、7、27、5、2章。前三题在k=6下完整覆盖不可能；后两题k足够仍仅命中1/5、1/2。此诊断没有运行LLM作答，测的是必要来源cid，正文截断还可能进一步丢证据；语料已见过且与被测仓库同作者，不是第三方盲测。

暂不引入预测控制器：尚未证明不同反思方案存在稳定、可由行动前特征选择的互补优势；E/D的一胜一负也没有证明固定规则不足。ACE、GEA、Mind the Gap、AIDE²、Hyperagents与RSI-Anything保留为后续研究参考，没有因此修改本轮题目或引入新模型。

下一阶段优先单独验证“证据能否完整交付”，将来源选择与硬性k/Token上限区分，并使用另行冻结、未据本轮调参的验收集。先做简单机制对照，不同时改排序、巩固和反思Prompt。只有之后获得可重复的策略互补性，才比较轻量预测器与固定B/D/E、随机选择的相同预算基线。

本轮停止在证据封存与研究结论。所有新机制可禁用、可回滚；没有提交PR、安装生产插件、操作正式记忆库或让模型批准上线。代码清单、测试命令及回滚入口见README.md；原始逐案例、完整成本与统计表见第三轮实验报告.md。
