# Memory-RSI 第二轮实验结果

当前状态：实验完成；反思默认关闭；没有更新生产 DSH 插件，没有提交 PR。

## 对照结果

6 个不同真实历史缺陷，每组各重复 3 次，共 72 次实际 DSH 模型运行。三个重复是同一缺陷上的随机样本，不是 18 个独立任务。

A 使用固定上游版本的 CSRE 检索；B 仅替换为底层修正版本；C 在检索/检查反馈点始终触发外显反思；D 只在可观察条件满足时触发。C/D 同样最多 2 次。A 不是整套生产 Memory 的历史部署快照；四组的 Agent、图存储与非实验模块保持共同版本。

反思复用现有 MemoryRSILab 的确定性提取/验证，再向同一任务模型提供证据和纠错清单。没有额外 LLM 反思模型，没有在线算法自修改。B 仍可由任务模型根据检查反馈自行纠错；本实验评估的是额外 Memory-RSI 模块的增量价值。

Token 分量按 DSH 的互斥字段统计：未缓存输入 + 缓存读取 + 缓存写入 + 输出 = 总量。缓存写入实际为 0。总 token 的百分比不是账单百分比。

触发条件：同类检查连续失败至少两次；现有一致性检查发现冲突；没有相关且有独立检查记录的经验；修改后的行动未通过独立检查；检索到明确过期经验。阈值在留出任务运行前冻结；Python/JS 48 组触发判定一致。

文本估计 token 是模块发出一次文本的估计长度，不能与模型多轮上下文 token 或账单直接相减。模型总成本还受读代码范围、修改次数和运行步数影响。

同一次任务检查失败后成功是纠错观察，不证明反思是唯一原因；四组都有相同的独立检查反馈。C/D 没有把当前失败经验自动接纳为知识。

## 底层正确性

保留第一轮 9/20→0/20 的收益：在 100 与 1000 条目下重复均成立；过期索引和跨来源索引均拒绝。新的 120 个查询按独立字面契约未出现误拒绝和违规，12 项边界断言通过。

发现并修正了一项真实边界风险：prod/product、production/nonproduction 与非生产环境的子串误拒绝。修正前独立反例有 12 个失败子例；修正后通过。54 项 CSRE/会话回归通过，早期测试夹具清理错误保留在日志中。匹配仍是有限字面规则，复杂否定作用域和所有语言变体尚未证明。

真实 DSH MCP 调用包含两条链：实验 CSRE 适配器的 13 项边界检查全部通过；原生 md_cg.mcp_server 的 info/read/访客 write 共 3 次调用，读可用，写被拒绝且未创建节点。info 返回诊断与孤儿桶问题，不应解释为生产健康检查全部通过。实验适配器不是已存在的生产 CSRE MCP 端点。

## 失败分解与证据边界

```json
{
  "model_output_limit_reached": 4,
  "candidate_exception_in_independent_check": 4,
  "remaining_behavior_failures": 22,
  "invalid_model_tool_json": 1,
  "no_source_change_within_budget": 3
}
```

单次输出上限、执行预算、候选代码异常和残余行为错误分开保存。部分候选在 CLI 因预算结束后，经外部评分器仍通过，因此以冻结的最终行为评分为依据；normal_completion 单列保留。没有根据模型自述判断成功。

源码阅读工具省略整行注释、保留原始行号，精确文本修改有时因不可见注释/空白失败。这是执行接口限制，不能全部归因于记忆检索或反思策略。Python 审计限制保护普通实验流程，不是经过认证的恶意代码沙箱。

检索域由任务配置预先给定，实验经验仅 10 条；本轮没有测量域路由错误或大规模长期记忆召回。真实开发难度解决了原有任务天花板，但不能代替完整长期记忆 Benchmark。

延迟包含 DSH 启动、模型请求及工具调用，不含运行后独立最终评分；它受服务端状态、缓存与本机负载影响。另有一次 13 秒的独立 MCP 探针与主实验重叠；延迟不用于证明纯算法因果加速。

# 本轮五个研究问题的回答

本轮完成 6 个真实历史缺陷、4 组、3 次重复，共 72 次实际 DSH 模型运行。最终成功数为 A 7/18、B 10/18、C 10/18、D 11/18。仅有 6 个独立缺陷，不能把 18 次当作 18 个不同任务，也不据此声明统计显著性。

## 1. 反思在什么情况下有实际收益？

目前看到的候选信号出现在冲突、修改后独立检查失败、证据不足的场景。D 相对 B 的配对运行有胜也有负，总共只多通过 1 次。它在凭据吊销任务上产生的候选通过了额外跨身份与缓存验收，值得继续验证；该任务 A 也有一个通过候选，因此没有证明反思解锁了原模型完全不具备的能力。

C 没有提高总体成功率；D 的小幅优势尚不能认定为稳定因果收益。不要因为本轮没有强证据就宣布反思无效，也不要把观察到的差异当作已经成立的普遍净收益。四组都有同样的检查反馈，普通任务模型本身也会纠错。

## 2. 哪类错误能被修正？

已观察到检查失败后的真实修正，包括结论解析、检索截断、并发导出、凭据吊销等行为错误。A/B/C/D 的“出现模型可见检查失败后最终成功”次数分别为 3/4/6/7。这表明可执行反馈有纠错价值，但并不能将这些成功全部归因于额外反思。

输出截断、工具参数 JSON 错误、精确修改失败、候选异常和剩余行为缺陷仍存在。神经后端诊断任务四组均为 0/3，反思没有解决这一瓶颈。

## 3. 能否提高新任务成功率？

留出缺陷与训练经验的根因和提交不同。C 与 B 同为 55.6%；D 为 61.1%，比 B 高 5.6 个百分点，但只是 1/18 的净差。不同任务有收益也有退步，第三次重复还改变了早期排名。现在可以保留 D 为研究候选，不能据此默认启用或宣称跨仓库泛化。

## 4. 条件触发降低了多少额外 Token？

D 比 C 少 349,361 总 token（6.65%）：缓存读取少 346,240，未缓存输入少 2,310，输出少 811。约 99.1% 的总量降幅来自缓存读取；未缓存输入与输出合计只少 0.75%。这不是账单下降 6.65% 的证明。

D 触发 16/18 个任务、30 次事件；C 为 18/18 个任务、31 次事件。一次发出的反思文本估计量从 6,762 降至 6,209（8.18%），这个估计量不是提供商计费 token。条件触发降低了部分暴露量，但当前规则仍较宽；模型总量也受随机读代码与执行步数影响，不能把所有差额归为触发策略。

相对 B，D 总 token 少 6.50%，但未缓存输入反而增加 12,925，输出减少 10,231。因此仍应按缓存、输入、输出的真实费率分别计费。

## 5. 瓶颈是反思、经验质量，还是检索？

现有证据不能唯一归因，但可排出下一步优先级：

1. **验收覆盖**：凭据吊销的 3 个原成功候选中，v2 扩展验收通过 2 个。C 候选将一个身份的吊销状态错误复用于另一有效身份，原来的三个检查没有覆盖这一点。原始 A/B/C/D 分数保持不变，不用事后规则重写主结果，也不将未扩展验收的其他候选视为完全正确。
2. **执行和生成能力**：34 次失败分为输出上限 4、候选异常 4、剩余行为失败 22、工具 JSON 错误 1、预算内未修改源码 3。精确修改接口省略注释，也带来执行摩擦。这些都不能全部归因于反思算法。
3. **经验覆盖与适用性**：只有两条不同历史缺陷的验证经验；四类任务没有相关的已验证经验。存在同族历史修复，也不证明它适用于当前根因。
4. **检索**：A 有 9/18 次召回负条件违规，B/C/D 为 0，底层安全收益明确。当前域是预先给定的、小型实验记忆库，无法据此判断生产路由或大规模召回是否成为瓶颈。
5. **反思增量**：当前模块是确定性证据提取加纠错清单，不是通用的 LLM 反思学习器。清单和历史证据同时存在，还需要在新任务上做单因素消融。

扩展验收 v1 使用特定辅助 API 计数，可能误判采用不同读取方式的正确候选；v2 改为观察真实文件读取，并加入首次派发前已撤销的场景。维护者参考修复五项均通过；v1/v2 日志都保留。这个修正只涉及事后验收诊断，未改变冻结评分器或原始分数。

当前决定：保留底层修复及边界反例，反思继续默认关闭。优先提高独立验收覆盖，再研究反思清单与经验内容的单独价值。新增六份资料已登记在 research-followup.md，没有因此加入世界模型或循环自修改。
