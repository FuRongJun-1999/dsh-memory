# 最小经验巩固设计与预注册边界

目标是检验多次实际成功的经历能否成为更易正确迁移的限定条件经验，而非自动证明普遍规律。复用原认知图、MemoryRSILab原始记录、CCG、MdCGOS检索、signer.HmacLocalSigner、索引和审核/保护接口；不创建第二权威记忆库、不改变MCP权限或生产钩子。

## 原始经历与真实回执

同一图保存task_id、source、timestamp、conditions、observations、actions、outcomes及完整工具轨迹。超过既有64KiB轨迹上限时，完整观察分块保存在同一图并由根记录引用。任务A的原始经历只收集一次，B/C/D复制完全相同的图；任务B聊天上下文独立。

受信任实验控制器使用现有签名器，签名绑定trace_id/hash、task_id、候选文件hash、实际检查结果和当时条件。模型只能读任务工程，不能读取签名私钥或给自己出通过回执。签名只认证本机控制器的回执来源及完整性，不证明检查覆盖范围之外的事实；本地审计边界不是认证的恶意Python沙箱。

## 巩固与条件

至少两份不同task_id的成功经历、相同明确条件与范围才形成经验胶囊。支持计数是已观察任务数量，不是统计独立样本数；相关家族、构造任务及重复运行另行聚类，不自动抬高校准置信度。

胶囊保留每个实际成功动作及其已经检查的任务要求，不凭文本相似度把不同动作强行宣称等价。模型产生的候选总结及负条件原样留在raw经历中，不晋升进胶囊。共同条件作为使用范围；不匹配表示“超出已验证范围”，缺字段表示证据不足。不能把未知等同于条件满足。

本轮对任意自然语言总结不声称具有自动语义蕴涵证明。persistent verification_state继续为unverified，一般规律的状态为source-supported candidate；可信的是其绑定的A观察。若两份经历对同一个明确断言给出相反结果，则暂缓形成统一规则，保留原件供检查。候选知识必须显示该边界，不能升级成无条件事实。

本机制的新增部分是回执绑定、限定条件使用与追加版本；原有induce/CCG/图存储不改名包装为新发明。对照C同时包含这条最小完整链，消融再分别考察移除条件检查及证据门带来的影响。

## 版本与反馈

原始经历不可变；新增支持追加知识版本，不覆盖旧文。真实失败反馈产生新的disputed版本，保留旧版本与原始来源；默认召回只使用有效头版本，不能通过召回旧版本绕过失败标志。反馈不能写入未执行的当前测试结果，也不能用模型自述成功恢复旧规则。

主A/B/C/D对照在冻结A经验的独立副本上运行，不让一个B的答案泄漏给其他B。反馈更新首先通过独立工程回归验证，另行报告，不能把它假称为已完成在线长期学习成功率实验。

## 评测

先6对开发试运行，再另建至少20对正式未见任务。正式任务尽量取可公开复现的真实API/依赖/配置契约，不将自行编写的最小复现冒充上游历史Issue或官方排行榜。固定输入、模型、B预算和评分，任务对按家族聚类，重复不作独立扩样。

A无长期记忆；B现有raw experience；C限定条件的源支持巩固；D同C加保守条件反思。四组A源经历相同，B的新会话没有A聊天。实验账包括共同A学习、离线巩固及B执行，Token缓存桶与未缓存输入/输出分列。

保存写入→召回→实际交付→使用声明→真实编辑→独立结果。声明与采纳、来源覆盖与答案正确、范围拒绝与合法身份拒绝分别报告。结果为负、天花板、经验不足或采用未知均允许；模型不能据结果自批上线。
