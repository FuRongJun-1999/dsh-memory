## 八个审计问题的结论

1. **能保存完整任务经验吗？** 小型结构化经历可以直接保存在同一图。探针验证附加observations不丢失。大型轨迹须规划大小与来源引用，现有MemoryRSILab不能无限接收事件。
2. **六要素能表达适用/不适用吗？** 能表达并交付，但自然语言条件的正确性和完整性仍需外部检查。不能把条件词面命中当作充分适用证明。
3. **consolidate能经验→规律吗？** 已有induce，生成inferred概念和来源边；已有promote迁层、条件补齐及回滚。因此本轮不再重做聚类、第二记忆库或换名的“新归纳器”。
4. **证据防火墙验证什么？** 结构、负条件、词面grounding、绑定动作的成功check及哈希已有；可信执行来源与跨任务有效性是另一层。现成signer可复用，勿重写密码学。
5. **更新会丢来源吗？** 运行探针确认：普通add全量覆写一个已带source/derived_from的节点，调用者不再传这些字段时，两者会消失。某些专门血缘字段已有继承，但不能泛称所有更新自动保源。新实现应新增不可变版本并显式绑定来源，避免全局改变旧接口语义。
6. **反思会无证据晋升吗？** MemoryRSILab本身只提案，不自动commit；verify明确knowledge_verified=False和external_authenticity=not_authenticated。探针中调用者自填source=tool的结构可以通过观察检查，不能冒充真实执行来源。promote把一个unverified节点迁到knowledge层后仍为unverified；层名不能当作真值认证。
7. **召回能带可信度、条件、来源吗？** recall pack保留frontmatter、provenance与verification_state/source/derived_from等metadata。还需追踪真正交给模型的截断文本，不能只看内部pack。已有evidence_delivery原型也应复用评估，不重复实现通用检索器。
8. **什么无需重复开发？** 图存储、审核队列、冲突检查、概念归纳、时效和依赖、签名接口、层保护、索引/RRF、预算装包、影子运行与回滚均已有。本轮增量只应补“可信经历→限定条件知识→新任务使用→版本化反馈”的联结及实证。

## 最小研发边界与验收门槛

候选方向是可关闭的离线经验巩固适配层：复用同一图、现有结构化经历、CCG和签名器；将独立执行回执与具体任务、候选内容、条件和来源哈希绑定；至少两个不同任务的支持才能标作多源支持，重复同一个回执不能刷支持数。一般规律仍限定在检查覆盖范围内，不能自称普遍真理。

候选知识采用追加版本与显式source_experience_ids/derived_from；矛盾或失效来源应暂缓，失败反馈生成新的存疑版本而不抹掉原文。模型提出规则不等于批准知识上线。本轮只在已声明的隔离实验图中评估，不挂生产MCP。
