# 典型逐例诊断：采用声明、真实编辑与外部结果

以下诊断依据原始工具参数、最终源码和外部行为检查。配对胜负不自动等于Memory因果效应，声明use也不证明内部采纳。其余全部任务的逐次链路见逐案例与迁移分析.md和case-paths.json。

## 1. JSON配置：D的局部稳定正信号

`configuration-root-1`两次重复均为A/B/C失败、D成功。D两次都实际收到mapping/null条件匹配的胶囊并声明use。重复1先修改JSON根判断和复制，第一次外部检查失败；随后第二次修改补足嵌套复制/合并，最终外部检查通过。来源确实提供了None-only及mapping类型边界，最终编辑也处理了B新增的默认值所有权要求。

这是值得保留的局部信号，但源A没有证明B全部嵌套语义，D提示没有新增外部事实，也没有A+同一提示的单独对照。因此不能确定收益来自经验、通用核对提醒还是随机探索。D总计仍是对C三胜三负，不能据此默认开启。

原始路径：`formal/runs/formal/transfer/configuration-root-1/rep-1/D/`和`rep-2/D/`。

## 2. 最新状态：召回/组织差异的正信号

`stale-event-knowledge-1`重复2中B失败、C成功，A和D也成功。B交付了非目标家族的原始经历，没有召回该家族源记录；随后反复搜索、尝试读取不存在的task.md，8请求预算结束时没有编辑。不能把它描述成“采用正确记忆后判断错误”。

C实际召回并交付对应胶囊，声明use，最终补丁比较revision、保留首个同版本事件，并使用deepcopy隔离结果；独立检查通过。这说明来源组织/召回比单纯把完整轨迹存入图更可能影响可用证据。但A也通过，单次B未行动不是已证实的稳定因果收益，更不能确定检索是唯一瓶颈。

原始路径：`formal/runs/formal/transfer/stale-event-knowledge-1/rep-2/<A|B|C|D>/`。

## 3. 厂商标签：条件拒绝正确，终局仍失败

`dependency-version-2`重复2为B成功、C失败。C正确发现PEP440来源与opaque vendor priority不匹配，没有交付任何胶囊。C随后多次搜索，在最后一步按priority及稳定顺序选中了记录，却返回整个dict；公开接口要求返回tag字符串，外部检查失败。

这里不能称为“错误版本经验被采用导致负迁移”：来源正文没有交付，也没有有效use声明。真实失败是新任务返回类型遗漏及探索预算耗尽。聚合的C独输应该保留，但其原因不能全算到经验内容或条件拒绝机制。

## 4. Requests：包装器摩擦和新要求遗漏

`api-parameter-migration-2`两次C通过、D失败。重复2的D没有收到HTTPX胶囊正文，条件闸已正确拒绝跨客户端经验。D先提交不支持的decision=reject_all，接着用可见的rejected ID提交reject又被记录接口拒绝，第三次改成空ID才成功记录。

最终D代码使用了正确的Requests `proxies`复数和None-only timeout，却把调用者的proxy mapping直接放进kwargs，缺少隔离复制；独立检查失败，预算已用尽。不能断言它把HTTPX的proxy单数迁移到了Requests；实际代码并未犯这个错。可确认的是两次声明错误消耗了步骤，新任务的所有权要求没有修好。

原始路径：`formal/runs/formal/transfer/api-parameter-migration-2/rep-2/D/`，工具5/6/7的声明与最终源码可直接核对。

## 5. 时间排序：正确经验不能覆盖新任务所有要求

独立验证`timezone-contract-1`四组均失败。C交付并声明采用了aware/naive datetime经验；最终代码正确为naive附UTC，并按时间瞬间排序，但对每个事件只做dict浅复制。嵌套值仍与调用者共享，外部独立性检查失败。

来源时间规则可能正确，B的复制要求却是额外问题。这是“正确范围的来源交付、声明use和真实编辑均发生，但终局失败”的例子，不能直接称为错误记忆。另在独立图副本重放这个失败并绑定真实回执，反馈会追加disputed v2；这暴露出保守反馈可能错误撤下正确经验。v1及全部来源仍保留，追加rollback v3生效；主实验图不变。

## 6. 二进制：拒绝经验的可观察成功

验证集`payload-contract-2`要求保留opaque bytes，包括非法UTF-8。B实际收到文本解码经历并声明reject；C/D在交付前按不同payload_semantics拒绝；消融E把同一文本胶囊交付后，模型也声明reject。B/C/D/E都通过，A该次失败。

这些记录支持“适用条件可以被执行或模型识别”的工程结论。一次A独输不足以证明拒绝行为带来因果收益；E和C终局相同也不证明条件闸无价值，只说明本组三类明显边界下模型自己也能拒绝。

## 7. 不作为能力强结论的样本

YAML序列题的TypeError未在题面明确，权限题的ops字段未公开。因此其整体成绩继续保留，但不作为一般异常处理能力或生产身份权限的强结论。另补3对字段完整、操作不同的任务，算法/源经历/预算不变，四组各6/6；它们仅提供新的可复现链路证据，没有正迁移差异。主结果、事后敏感性结果及补充结果分别报告。

## 总体判断

最值得后续单独验证的是：原始轨迹的目标召回、预算下的证据交付、记录接口的无效步骤、以及失败到具体知识子结论的归因。现有数据不支持用预测器绕过这些问题，也不支持把检索命中或声明采用直接等同于实际学习成功。
