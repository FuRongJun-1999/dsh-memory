## 三、必须连着读的三条披露

1. **默认召回融合口径由 `sum` 变成 `max`**：`mcp_server.mdcg_recall` 的 `fusion` 判据把 `use_causal`（缺省开）并入 `max` 条件 ⇒ 影响**所有**默认召回调用，与库有没有边无关。读数：同一库默认口径 == `max` 且 **≠ `sum`**（top-1 由 `m_lex` 变为 `m_zz`，`m_lex` 从 #1 落到 #3）。依据设计稿 §6.2（因果路为「单路独有召回型」）与既有先例表达式。
2. **主分数进了刷新/衰减乘子**：这是使用者最初反馈「召回的记忆会被旧的历史记忆干扰」的处置——实测 `a_fresh / b_30d / c_300d` 的默认召回排序由「越老越靠前」翻转为「越新越靠前」。
3. **六要素后两行进默认检索**：只影响「验证方式／什么条件下不适用」这类问句的召回面；**普通问句零位移**（R2c 两态一致）。

## 四、已知边界（如实登记）

1. **Rust 读侧缺省仍是四路**（未实现 chain/temporal）⇒ 两侧**缺省路集本就不同**；`scripts/rank_parity.py` 的 10/10 **不得读作「两侧已对齐」**（其语料无边，两条新路恒空）。
2. **守卫盲区（本版修复）**：时间核审计器的 exp 正则抓不到 Rust 的 `(...).exp()` 形态 ⇒ `rust/src/freshness.rs` 的指数核曾**靠盲区通过**。已登记进 REGISTRY + 加与 `cred_factor` 的等价性断言 + 放宽正则。
3. **`chain.adjacency` 是 O(N) 索引条目级**邻接构建（不读正文），**不是**「不走全表」；S3 契约文本已勘误。
4. **S3 ④ 只部分满足**：参与边类型集可配（`MDCG_CHAIN_TYPES`）；边权沿用唯一表 `EDGE_WEIGHTS`；方向固定为依赖方向。
5. **Δt 取整日粒度**（两侧同值 `DT_QUANTUM_DAYS=1.0`），量化损失上界 ≈ γ×1天 ≈ 2.3%；设为 0 可换连续精度，但会让「两轮结果逐位一致」的既有纪律转红。
6. **P5 方向性自检**：0.7.0 只落八步里的 ⑧反馈/⑨自检**只记账骨架**，深化顺延（设计稿 §九 允许）。
7. **公开检索数字未复跑回填**：本版只如实披露机制与变更幅度，未重跑 README 的头条检索数字（体积与时间原因）。
8. 静默缺件类（整目录未出货）无门禁信号（第九腿只断言具名文件在场）；`check_publish_artifact` 的「非追踪件面」零余量；PR #47 未并；三条残余 CI 红未修。
