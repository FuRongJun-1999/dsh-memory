## 〇、结论先行

1. **缺口**（承接探针读数，原文）：情绪读数（信息差二阶 `emotional_bias`）与情感读数（信任二阶 `affect`）**齐备且有落盘**，但全部止于「读数/卡字段/建议」——唯一被消费的两处（`consistency.py:751` 的 L2 递归调度、`autonomy.py:177` 的提案评分）都是**附带的、未以情绪命名的、且明文不参与信任/资格计算**。即「读数已长成，结构未长成」（`docs/eval/W4_情感模拟_探针读数_v0.1.md` §判定）。
2. **本设计的落点（一处）**：`md_cg/autonomy.py` `proposals()` 的**排序键 `sort_score`**——新增一个由情绪读数派生的**排序加分 `emotion_bonus`**（默认 `0.0`，即通路关闭时与现状**逐位一致**）。**不碰** `score`（资格定价器）、**不碰** `gain_gate`（σ(Gain) 资格筛选）、**不碰**任何写入/信任/检索面。
3. **为什么这一处安全**：`proposals()` 的资格判据是 `score > 0`（`autonomy.py:179` 的 `if score <= 0: continue`）与 σ(Gain) 门槛（`:191-197`）——二者都只读 `score`/`gain_gate`，**不读 `sort_score`**。情绪加分只写进 `sort_score` 与 `reason`/留痕字段，故**在结构上不可能影响资格**。该模式在本文件内已有**现成且已守卫的先例**：`d_meta_bonus`（`W_DMETA` `:44`，加在 `sort_score` 上，注释 `:36-43` 明文「只进排序键、不改 score、不改资格判据」）。
4. **开关形态**：新 env 开关 `MDCG_PROPOSAL_EMOTION`，**默认关**（未设 / 非 `"1"` ⇒ 恒定 `bonus=0.0`，与改动前逐位一致）——沿本仓默认关 opt-in 的既有惯例（`MDCG_RETRIEVAL_PIPELINE` `mdcg.py:957`、`MDCG_REACH` `reach.py:110`，均 `== "1"` 开门）。
5. **须设计者裁定**：核心三件（一处 / 默认关 / 只排序）**无需再裁**——已被第 4 条裁定覆盖且本设计自洽；仅 **①加分幅度上限 ε 的取值**（建议沿 `metacognition.D2_EMOTION=0.05`，回落到「首版保守缺省、标定放观察期」，裁定第 10 条同款）为**可选标定项，不阻塞落地**（见 §七）。

## 一、目标与范围

**目标（一句话）**：给既有的情绪读数（信息差二阶）一个**显式的、可指认、可复跑、可回滚的消费位**——使「内部状态 → 决策」在源码里从「附带的、匿名的」变为「命名的、单一开关可开合的」。

**做什么**：
- 让 `proposals()` 产出的探索提案，在其**排序**（哪条盲区先被探索）上受情绪读数调制——**仅排序，仅一处**。
- 该调制**默认关**、开门后**可观测**（读数与加分进 `reason` 与返回体，落 `_explore.jsonl` 台账）。

**不做什么（硬边界，逐条对齐裁定第 4 条与理论原文）**：
- **不改资格判定**（`judge_qualification` `mdcg.py:3474`）、**不改信任值**（`links.observe` 的 `P_trust` `links.py:348`）、**不改写入闸门**、**不改层的晋升/退役**。
- **不做自动触发**（不进心跳循环；沿裁定第 8 条「首版不进心跳」）。
- **不做多点**（首版只此一处；`self_state` 检索维度不升，沿裁定第 5 条）。
- **不落地 §2.9 的 `E_weight`**（协作者信任二阶，沿裁定第 6 条「本迭代不落地」）。
- **不碰**协议真源 `docs/theory/`（本次仅只读引用）。

## 二、候选通路评估（从探针消费面里选「一处」）

> 评估口径：**改动面**（要动几个函数/几条链路）、**可审计性**（读数与效果是否进既有台账/meta，可复跑可回滚）、**与铁律的距离**（离「资格/信任/写入」有多近）、**风险**（出错的爆炸半径）。

| 候选 | 落点 | 改动面 | 可审计性 | 与铁律的距离 | 风险 |
|---|---|---|---|---|---|
| **(a)** `autonomy.proposals` 的 `sort_score` | `md_cg/autonomy.py:184`（`sort_score`） | **极小**：一个函数内加一个加分项 + 一个 env 读点 | **高**：既有的 `d_meta_bonus`/`reason`/`_explore.jsonl` 三面同款 | **最远**：提案面根本不接触 judge/gate/trust/write | **最低**：资格判据 `score>0` 在加分之前就 `continue`（`:179`），加分不可能反向影响资格 |
| **(b)** 检索排序的次级因子（`search_rrf` 融合后重排） | `md_cg/mdcos.py:1768`（`fused_all` 排序键）、或 `:1805`（judge 终排） | **大**：改检索主排序链；须处理热缓存键（`hotcache._ENV_SWITCHES` `hotcache.py:66`） | 高（meta 有 `path_fingerprint`/`provenance`） | **最近**：`judge_ranking`（`:1793-1806`）就骑在同一个 `fs` 上——任一漏进 `fs` 即经 `fs*0.5`（`:1804`）**渗入终排** | **最高**：检索是生产主路径，与资格终排（`judge_ranking`）共享分数 |
| **(c)** 元认知建议面（`metacognition._advise` 的 `diverging` 显式化） | `md_cg/metacognition.py:380-383` | 极小（模板字符串/字段） | 高（`_metacognition.jsonl` `:428`） | 远 | 低，**但**：建议是**纯输出**，无任何代码据以动作（`report` 返回 `advice` 后不驱动决策）——**不产生「消费位」**，缺口（「结构未长成」）依旧 |

**逐候选说明**：

- **(a) `autonomy.proposals` 的 `sort_score`**：探针已判这是「**最接近『二阶信号→决策』**的一处」（探针 §判定 差距 4）。它天生是**排序面**：`score` 是「ΔD 定价器」（`:135` docstring 明文）、`sort_score` 是「排序键」（`:136`），二者已在源码里显式分离。缺的只是「以情绪命名的一个排序项」——`d_meta_bonus` 演示了如何安全地加（`:44`/`:183-184`/`:36-43`）。加一个 `emotion_bonus` 是对**同一母版**的复制，而非新造机制。

- **(b) 检索排序次级因子**：**否决为「首版的一处」**，但不排除将来作为第二处（本设计不做）。理由：① 检索是**生产主读路径**，爆炸半径最大；② 它紧邻 `judge_ranking`——若微调项写进 `fs`（融合分），则 `judge_ranking` 的 `fs*0.5`（`:1804`）会把情绪**乘进终排权重**，构成「层层放大影响资格/终排」的**真实泄漏通道**（正是本设计 §四要防的第一类失败模式）；③ 若只在 `fused_all` 的 tie-break 键（`:1768`）上动手，还要同步改热缓存键（`hotcache._ENV_SWITCHES`，`:66-68`：影响检索结果的进程级开关**必须**登记，否则跨口径串味）——改动面与守卫面都远大于 (a)。

- **(c) 元认知建议面**：**适合作为「建议」而非「消费位」**。它 100% 安全（`metacognition` 模块 docstring `:18-23` 的硬约束「不参与裁决、只建议」），但**不解决缺口**——探针已判「建议」是被列为「止于读数/卡字段/建议」的**未消费一侧**；把 `diverging` 再显式化一遍，仍是纯输出，不会让任何「状态→决策」在源码里被指认。故首版不选 (c)；若将来要「建议」侧的显式通路，可另开一处（不在本设计范围）。

**倾向与理由（选 (a)）**：在「只开一处」的限制下，(a) 是**唯一同时满足「是真实消费位」与「结构性安全」**的候选——它是排序（端点有人据以动作：`explore` 取排序后的提案逐条驱动 `predict.learn_blindspots` `autonomy.py:243`），且它与铁律的**唯一交集面（资格）在源码顺序上被 `score<=0 → continue`（`:179`）物理隔离**。**(a) 为何不触碰资格/信任**：① 资格＝`score>0`（`:179`）＋ σ(Gain) 门槛（`:191-197`），二者只读 `score`/`gain_gate`；`emotion_bonus` 只写 `sort_score`（`:184`），**代码路径上不可达资格变量**；② 提案面**完全不引用** `judge_qualification`、`links`（`P_trust`）、`writepipe`/`admission`——`autonomy.py` 的 import 面为 `d_meta, metacognition, predict`（`:29`），**没有**任何资格/信任/写入模块，故「触碰」在 import 层面即不可能。

## 三、落点与机制设计

### 3.1 开关（默认关，沿既有 env 风格）

- **名**：`MDCG_PROPOSAL_EMOTION`（面 = proposals；语义 = 情绪排序加分）。
- **读法**：`os.environ.get("MDCG_PROPOSAL_EMOTION") == "1"`（沿默认关 opt-in 惯例：`MDCG_RETRIEVAL_PIPELINE` `mdcg.py:957`、`MDCG_REACH` `reach.py:110`）。
- **不改动** `autonomy_modes.py` 的 `MDCG_AUTONOMY` 档位键（该键是全仓唯一「档位 env」，由守卫 `test_autonomy_modes.py:555-568` 的 G 组把带引号字面量钉死在唯一入口模块）。`MDCG_PROPOSAL_EMOTION` 是**另一个**键，不并入档位表。
- **热缓存**：`proposals()` **不经** `hotcache` 的 query 缓存（它直读 `metacognition._reflections(cg)` `:148`），故**无需**登记进 `hotcache._ENV_SWITCHES`（`hotcache.py:66-68`）——这是 (a) 相对 (b) 的一处结构性简化（对照：任何进检索的开关都须登记，否则跨口径串味 `hotcache.py:60-65`）。

### 3.2 读数源与确定性映射（情绪 → 档位）

- **源**：每条提案的聚合 `a["d2_sum"]`（同一 query 窗内 `d2` 之和，`autonomy.py:158-161`）、`a["samples"]`（`:168`）。这是与 `consistency.emotional_bias`、`metacognition._emotion` **同源**的「信息差二阶」读数（`_reflection.jsonl` 的 `d2`，`mdcg.py:4522`）。
- **映射**：取窗内均值 `d2_mean = d2_sum / samples`，按**既有阈值** `metacognition.D2_EMOTION = 0.05`（`metacognition.py:56`）三判（复用 `metacognition._emotion` 的语义 `:65-71`，不新造阈值、不新造量纲）：
  - `approaching`（`d2_mean < -D2_EMOTION`，信息差**加速收敛**）→ 情绪正偏好 → `+ε`
  - `avoiding`（`d2_mean > +D2_EMOTION`，信息差**加速扩大**）→ 情绪负偏好 → `−ε`
  - `stable`（其余）→ `0.0`
  该映射**确定性**（同窗口同读数恒同档），且**逐提案不同值**（`d2_sum` 逐 query 不同）——不重蹈 `d_meta` 「本轮取库侧 query 无关代理 ⇒ 同轮各提案加分同值 ⇒ 当前口径下排序不变」的空转（`autonomy.py:36-43` 自陈）。
- **理论对齐**：PROP-EMO-DIRECTION-002「情绪是**方向性偏好**，信息差加速缩小时引导系统**继续当前方向**、加速扩大时**触发方向调整**」（`智能论3.4.md:1630`、`:1636`、`:1640`）——正偏好=继续探索该方向、负偏好=把该方向往后排，**只调排序不否决**（不 `continue`，与 `d_meta` 同为加分项）。

### 3.3 加分函数与硬上限（微调幅度）

```
ε = metacognition.D2_EMOTION            # 0.05，复用既有常量，不新造量纲
W_EMO = 1.0                             # 情绪加分权重（与 W_D2/W_BLINDSPOT/W_DEFER 同族，autonomy.py:34）
emotion_bonus = 0.0 if emotion_off else round(W_EMO * ε * sign, 4)   # sign ∈ {+1, 0, -1}
sort_score = round(score + d_meta_bonus + emotion_bonus, 4)          # 仅此一处改动
```

- **硬上限**：`|emotion_bonus| ≤ ε = 0.05`。相对 `score` 的**最小非零台阶**：`W_BLINDSPOT=2.0`/`W_DEFER=1.0`（`:34`）作用于整数计数 ⇒ score 的整数台阶 ≥ 1.0；`ε=0.05` 只可能在 **d2_abs 连续值近似相等**时翻转顺序 ⇒ 是名副其实的「微调/tie 邻域重排」，非重排。
- **作用范围**：**仅** `proposals()` 返回的 `proposals` 列表**排序**（`:199` 的 `out.sort(key=(-sort_score, -last_t))`）。**不**作用于 `score`（资格）、**不**作用于 `gain_gate`（σ 筛选）、**不**作用于 `explore()` 的终态判定。

### 3.4 可观测（沿 `path_fingerprint`/`per_path` 风格）

「只增不改」地加**命名读数**（对照 `mdcos.py:1855-1915` 的 `path_fingerprint` 落地法）：

- 每条提案新增两键（对照既有 `d_meta_bonus` `:183`）：
  - `a["emotion"] = {"bias": "approaching|stable|avoiding", "d2_mean": <float>, "source": "reflection.d2"}`
  - `a["emotion_bonus"] = <float>`（关时 `0.0`，仍占键——字段完备）
- 返回体顶层新增一个块（对照 `d_meta` 块 `:202-203`）：
  - `"emotion": {"enabled": bool, "w_emo": 1.0, "cap": 0.05, "source": "metacognition._emotion(d2_mean)", "note": "只加排序分、不改资格（score>0）与 σ(Gain)"}`
- **台账**：`explore()` 已把 `proposals` 原样并入 `_explore.jsonl`（`:254-278`），故加分与读数**自动落痕**、可复放可对账；`reason`（`:185-190`）追加一段「情绪排序加分 ±x（bias=…，d2_mean=…；不改资格/σ(Gain)）」文案，供人读面直接看见。

### 3.5 与铁律的对齐（自查表）

|---|---|
| 不得影响 `judge_qualification` | `autonomy.py` import 面（`:29`）**无**判据模块；加分只写 `sort_score` |

## 四、失败模式与红线对照（≥4 条）

> 对照真源：§PROP-EMO-DIRECTION-002「情绪**不可覆盖存在级决策**……存在级决策须执行完整递归」（`智能论3.4.md:1645`）；公理化基石 §十一「情绪＝`emotional_bias`……**独立通道，不参与信任计算**」（`智能的公理化基石.md:508`）。

1. **微调被层层放大、渗入资格**（最重）→ 对策：**硬上限** `|emotion_bonus| ≤ ε`（§3.3）；**只写 `sort_score`**，资格判据 `score>0` 在加分**之前**（`autonomy.py:179`）；**只加排序分不改定价器**（`score` 与 `sort_score` 分离 `:135-136`）。守卫设「关/开对照 + 资格不变量」断言（§五）。
2. **情绪被误用到不适用场景 ⇒ 覆盖存在级决策**（`智能论3.4.md:1645` 的「不适用」面）→ 对策：落点**只在「探索提案排序」**这一**非存在级**面；`proposals()` **不产生/不修改任何存在级判定**（不写节点、不改资格、不改生命周期）；且**默认关**——未显式开门时零行为。
3. **情绪读数被当作信任/资格的输入**（`公理化基石.md:508` 明文禁止）→ 对策：本设计**不新增任何情绪→信任/资格的边**；加分函数的**唯一输出**是排序键；`P_trust` 的更新入口仍是 `links.observe`（`links.py:348`），本设计不改一行。
4. **空转/伪通路**（加了分但排序从不变化，制造「已接线」的假象）→ 对策：映射用**逐提案**的 `d2_sum`（§3.2）而非库侧 query 无关代理；守卫加**判别力断言**（构造两提案 d2_mean 异号 ⇒ 排序必须翻转；同号 ⇒ 排序不变）。
5. **默认关被静默打开 / 反向默认** → 对策：读法固定为 `== "1"`（非 `"1"/未设` 即关），沿 `MDCG_RETRIEVAL_PIPELINE`（`mdcg.py:957`）惯例；守卫断言「未设/`"0"`/`"false"` ⇒ 返回体与改动前**逐位一致**」。
6. **热缓存跨口径串味**（若将来搬到检索面）→ 对策：本落点**不经** query 缓存（§3.1），无此风险；若将来另开 (b) 落点，(b) 必须先登记 `hotcache._ENV_SWITCHES`（`hotcache.py:66-68`）——本设计就此**显式登记为「(a) 相对 (b) 的简化」**。
7. **确定性破坏**（涨落源于时间/随机）→ 对策：加分只依赖 `_reflection.jsonl` 里已落痕的 `d2`/`samples`，无 `time()`/随机；同窗口恒同值（对照 `build_path_fingerprint` 的确定性纪律 `mdcos.py:110`）。

## 五、验证方式

**新守卫**：`md_cg/test_w4_emotion_sort.py`（照 `test_w5_path_fingerprint.py`「正向 + 定点变异自证」双档形态）。

**要点（正向）**：
