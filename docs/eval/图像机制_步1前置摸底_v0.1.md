## 二、★ 关键陷阱：`convert` 不是 ImageMagick

本机 PATH 上的 `convert` 解析到 **`C:\WINDOWS\system32\convert.EXE`** —— 那是 **Windows 自带的 NTFS↔FAT 卷转换工具**（`convert D: /FS:NTFS` 那种），**不是** ImageMagick 的 `convert`。

⇒ **对本线的硬要求**：任何脚本/命令**禁止**使用裸 `convert` 这一名字；ImageMagick 侧一律走 **`magick`**（IM7 的推荐入口），或在 Python 侧走 Pillow。
⇒ 这条不写进文档就会**必然**被踩（类 Unix 习惯的教程全用 `convert`），且症状具迷惑性——`convert` 会**真的执行**并试图转换一个卷，不是「命令找不到」。

## 三、判定与建议的安装路径

**判定**：本条线的**前置为零**——CLI 工具链（vips/magick/ffmpeg）与语言侧成像增强库（pyvips/cv2/sharp）**一个都不在场**；目前只有 **PIL + numpy** 这一条可用的纯 Python 通路。

**安装路径（供步 1 采用，未执行）**：
1. **ImageMagick**：`winget install ImageMagick.ImageMagick`（winget 在场，无需新增包管理器）；装后**入口用 `magick`**。
2. **libvips**：Windows 官方无 winget 包，可选 ①`pip install pyvips` ＋ 手工放置 libvips 二进制并设 `VIPS_HOME`/PATH；或 ②走 `scoop`（需先装 scoop）。**建议**：libvips 的实际收益（速度/内存）在本线当前体量下未证，**可后置**——先用 ImageMagick ＋ Pillow 打通为要。
3. **ffmpeg**：`winget install Gyan.FFmpeg`（若本线涉及视频帧抽取再加）。
4. **Pillow 已在场** ⇒ 最小可用通路（读写/缩放/色彩/直方图/掩膜）**今天就能跑**，不必等安装。

**给步 1 的实施前提（三条）**：
- ① 装 ImageMagick 后**验收只看 `magick -version`**，并**显式断言 `convert` 未被动用**（防 §二 陷阱）；
- ② 任何调用走 **argv 列表 + 显式 UTF-8**（纪律 15），不拼 shell 串；
- ③ libvips 是否上，**以「本地编辑链是否真的撞到性能/内存瓶颈」为判据**，不以「方案里写了」为由——先证瓶颈，再引依赖（沿本仓「先证缺口再施工」的既有节奏）。

## 四、局限

- 只探了 **PATH 与常见安装位**：装在非标路径（未入 PATH、未在候选目录）的工具**会漏检**。
- `winget` 在场 ≠ 可装：**未验证**网络/源可用性与权限面（安装动作不在本轮，属步 1）。
- Python 库探测按**当前解释器**（`python` → Python 3.12）；其它解释器/venv 内的库未探。
