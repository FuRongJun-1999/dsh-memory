## 一、执行摘要

本轮自主迭代做两件事：先收口 v1 报告 compiler/md_cg 组全部 3 项遗留缺陷（audit 外部验证器 NameError、api LLM 辅助 NameError、parser 指令吞噬语句开头关键字），再对 compiler 域做第 3 轮深挖，产出并确认 20 个候选（候选→确认零差值）。确认项按问题族分布：

1. **静默语义丢失族**（4 项，parser/lexer）：CJK 标识符分支吞并内嵌「于」（N1，已修，数值操作数凭空消失）、parse 循环双推进吞掉句号后首 token（N2，已修，与 v1 #18 同一缺陷）、条件/函数体多语句静默泄漏顶层（N4）、字符串到 EOF 未闭合零诊断（N5）；
2. **约束绕过族**（1 项）：「伴侣」条件空间情感权重上限 0.15 的名实校验对无空格自然中文写法完全失效（N6）——项目自家 api.py 模块自测样例即走在失效路径上；
3. **代码生成产物可靠性族**（5 项，全部遗留）：字符串内容未转义可击穿引号边界（N11）、五类 parser 节点静默丢弃（N12）、表达式位置写行中 `#` 注释产出必坏代码（N13）、多术曰块同名 `def` 互相覆盖（N14）、footer 无条件调用未定义函数（N15）；
4. **API 契约/死配置族**（4 项）：strict 是纯死配置（N7）、验证单元终裁否决分支不可达（N8）、LLM 建议计算后静默丢弃（N9）、validate_source 声明不生成代码实则全量生成（N10）；
