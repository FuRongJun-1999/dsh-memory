# 发布 v0.9.0：CI 双红归因与守卫可信度修复（浅克隆 · 超时容纳 · 写读配对 · 提取器覆盖）

> 版本 0.9.0 ｜ 基线 `dc64313f` 及之前若干笔 ｜ 2026-10-18

## 一、本版范围（v0.8.1 → v0.9.0）

本版不含新功能，全部是**把「守卫到底还在护什么」修回可信**。三类：

| 类 | 内容 |
|---|---|
| CI 基础设施 | 浅克隆导致 4 个守卫在 CI 上读不到历史；单测超时不能终止 job |
| 写读配对 | 五个台账迁移只改写面、没改读面 |
| 守卫自身 | 提取器太窄（看不见包在调用里的字典）；断言与实现设计相反（fail-open vs fail-closed）|

## 二、逐项

### 2.1 `fetch-depth: 0`：让 S10 组守卫能在 CI 上取到修复前源

**病象**：`python-tests` 长期红，而同一守卫本地绿。

**根因**：`actions/checkout@v4` 无 `fetch-depth` ⇒ 浅克隆 ⇒ 守卫跑 `git show <old>:<path>` 取「修复前源」时取不到。

**实证**：`git clone --depth 1` 逐字复现 CI 读数（`35/5` · `34/2` · `47/3` · `32/3`），`git fetch --unshallow` 后全部 `0 失败`。

### 2.2 单测超时三件套：`subprocess.run(timeout=)` 不等于一定结束

**病象**：`run_tests.py` 有 `--timeout 900`，而 job 仍能挂数小时。

**根因**：`subprocess.run(timeout=)` 只杀**直接子进程**，`communicate()` 继续读管道直到 EOF；孙进程继承管道 ⇒ 永久阻塞。

**修法**：`Popen` 起独立进程组（`CREATE_NEW_PROCESS_GROUP` / `start_new_session`）+ 超时杀整棵树（`taskkill /F /T` / `killpg`）+ **第二次 `communicate()` 也带 timeout**。

**验证**：假守卫（派生子进程持管道 + sleep 600s）修前挂 600s+，修后 **8.1s 被杀**；真守卫 10.8s、`135 通过 / 0 失败` 未受影响。

### 2.3 五个台账迁移回退：写面与读面必须在同一提交改

**病象**：`test_sleep_p1` `117 通过 / 10 失败`；`test_goal_gen` / `test_reconcile_v0` / `test_p24_evidence` 各 1 红。

**根因**：`append_jsonl` → `append_jsonl_ledger` 只改了**写面**（写 `_<name>.<pid>.jsonl` 分片），读面仍 `open(_<name>.jsonl)` ⇒ 读到 0 条。

**判据**：`#546` 的 `identity`/`insight`/`self_state` 是**写+读同提交改**（6/6 守卫绿），而 `#547` 的五处只改写面（5/5 全断）。

**处置**：五处全部回退（`8153a16a` / `afad11b3`）；`append_jsonl_ledger` 本身保留。

### 2.4 G6 提取器也收「包在调用里的字典」

**病象**：`G6f 锚点 review_queue 仍存在于工具面分支块` 红。

**根因**：提取器只收 `ast.Return` 且 `value` 直接是 `ast.Dict`；而实现改成了 `return _am.apply_dedup({...}, _pr)` ⇒ `value` 是 `ast.Call` ⇒ **静默看不见**。

**修法**：`ast.Call` 的 `args`/`keywords` 里有 `ast.Dict` 也收。

**旁证**：断言数 **57 → 63** —— 旧匹配器静默漏掉 6 个字典返回，那 6 个从未被检查。

### 2.5 `#413` 守卫改钉 fail-closed 契约

**病象**：`ProtectionError: 节点 pr_t 受保护…override 需要前像，但前像不可得`。

**根因**：守卫断言 **fail-open**（「前像写失败 ⇒ override 仍放行」），而实现已改为 **fail-closed**（`protect.py:390-404`：「override 的价值来自『可回滚』，前像拍不出来就不该放行」）。

**判据**：以实现为准 —— 实现的判据更强（fail-open 允许不可回滚的覆写）。而守卫自己写着「裁定归维护者」，那不是免责，是**未完成**。

### 2.6 消费者绕过模块直开文件

**病象**：`test_predict_beta` `FileNotFoundError: _self_state.jsonl`。

**根因**：`self_state` 自 `#546` 起写分片，`history()` 读分片（配对正确），而 `test_predict_beta.py:107` **直接开单文件**。

**修法**：改走 `self_state.history(cg, limit=1)`。

## 三、判据（本版反复用到）

1. **CI 红先分三类**：①守卫真失败 ②守卫读不到输入 ③守卫被跳过 —— 界面上都是红，结论相反。
2. **本地绿 ≠ CI 绿**：查四项环境差异（git 历史深度 / 外部依赖 / 时区时间窗 / 输出流兼容性）。
3. **能本地构造的条件就别等 CI**：`git clone --depth 1` 一次复现，比等一小时快。
4. **归因六步**：发现 → 分类 → 假设 → **构造条件复现** → **验证修复** → 落地。缺第 4/5 步不算归因。
5. **统计失败要全量**：`gh run view --log-failed | grep '^FAIL ' | sort -u`。只看前几行会把 8 个报成 5 个。
6. **断言数量也是判据**：静态守卫悄悄缩窄覆盖面时不报错，唯一症状是**断言数**。
