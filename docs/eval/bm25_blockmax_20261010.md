# BM25 精确块剪枝与首次构建优化

2026-10-10；延续 PR #107。对照版本 `8d40dea36d888b22af0c29dfa229a4203bcfeabe`。

常见词命中大量文档时，原实现重复枚举候选元数据并逐条计算 BM25。本轮保持
分词、k1=1.2、b=0.75、每路 top50、RRF 和权限过滤不变，增加：

- 按写入代际、完整身份及过滤参数复用候选资格；时间/有效期过滤每次重新计算。
- 128 文档一块，保存实际 TF/长度组合的分数上界及命中位图。只有确认整块无法
  进入 top50 时才跳过；同分按 importance/id 排序，命中总数仍包含被跳过的块。
- 至少 32768 条的大库首次构建默认 4 个读取线程、最多 8 个在途任务。解密、分词和索引更新仍
  按输入顺序串行执行；大库构建后释放本次新增的正文缓存，小库及之前已有的缓存保留。
- 对最多 32 个高频词提前构建块摘要，成本计入首建时间。TF/长度高度多样的
  词使用原始逐项评分，避免无效上界增加开销；执行算法切换不裁剪候选。
- 每个索引共享重复词项字符串，文档只保留唯一词项和总长度，TF 保存在倒排表中。
  删除及权限失效时释放词项；大库构建同时释放本次新增的路径解析缓存。

没有新增明文落盘索引，也没有声明同一实例可并发调用。首次构建仍需读取全部
合格 Markdown 文件；写入、索引重载或资格变化后仍可能执行全池同步。最坏情况
的评分复杂度仍为 O(df)，块上界无法剪枝时不会减少候选。

## 复现控制

`MDCG_BM25_BUILD_WORKERS=1` 可退回串行读取（最大 16）。
`MDCG_BM25_BLOCK_MAX=0` 关闭块剪枝，`MDCG_BM25_POOL_CACHE=0` 关闭候选资格
复用。它们控制执行成本，不改变查询结果。结果缓存在上述实测中全部关闭。
主要环境为 Windows 11 / Python 3.12.10 / Ryzen 9 7945HX / 32 GB RAM。
内存清理工具退出，OS 缓存未清空，桌面上还有其他应用，结果不是服务 SLO。

块上界的设计参考：[Apache Lucene Block-Max WAND 设计说明](https://issues.apache.org/jira/browse/LUCENE-8135)。
本实现为 Python 中的精确块上界调度，并未使用 Lucene 引擎或其完整 WAND 游标算法。
