# 发布闸 R10：随包文档的「可执行引用」可达判据

> 2026-11-02 · 发布面第九条判据（R1–R7 内容政策 → R8 声明面 → R9 必需件 → **R10 文档可达**）
> 落点：`scripts/check_publish_artifact.py`（R10a / R10b）
> 守卫：`scripts/test_check_publish_artifact_docrefs.py`（29 断言，含 4 条变异自证）

## 一、结论先说

R9 补上了「**代码**按路径装载的件在不在包里」。但它管不到另一件事：
**文档让人照抄的命令，在装上之后跑不跑得起来**。这两件事不重叠——R9 全绿时，
文档里仍可能写着 `python scripts/x.py`，而 `scripts/` 只有 `workspace_index.py` 随包，
装机用户照抄即 `Errno 2` / `ModuleNotFoundError`。

R10 就是这一条。两档判据：

| 判据 | 问什么 | 修前实测 |
|---|---|---|
| **R10a** | 随包文档里以**可执行形态**点名的脚本，在某个基址下真实存在吗 | `skills/README.md` 的 `cd skills/designer-perspective`（实际是 `skills/skills/…`）⇒ 照抄即 `No such file`。修前 **3 处** |
| **R10b** | 该脚本若不随包，是否已登记（维护者工具） | 修前 **11 处**未登记（`scripts/*.py` 被 `dsh/README.md` / `codebuddy/README.md` / `zcode/README.md` / `hive/README.md` 点名） |

## 二、口径：只认**调用**，不认**提及**

这条口径是本轮最关键的取舍（也是 R9 已经吃过的教训）：

```
认：python [-flags] [-m <module> | <path>.py]      ← 现在去跑它
不认：`scripts/x.py`                                ← 叙述「它在 scripts 下」
```

实测随包 md **1100 件**：可执行形态 **63 处**，叙述性提及数十处。若混算会灌进大量
误报——而误报多了闸门就会被忽略，等于没有闸门。

**基址解析**（四种现实写法，先命中先用）：

| 基址 | 场景 |
|---|---|
| 仓根 | `cd` 到仓库根后跑 `scripts/x.py` |
| 文档所在目录 | 文档自带的相对示例 |
| 文档上级目录 | `docs/a.md` 里写 `../scripts/x.py` 的相对形态 |
| `cd <dir>` 块 | 代码块内先 `cd sub` 再跑相对路径 |

## 三、这一轮我自己犯的三个错（必须记）

### ① `-X utf8` 盲区：正则写法把一整类命令**静默漏扫**

最初 flags 面写成 `(?:\s+-[A-Za-z0-9]+)*`。对 `python -X utf8 scripts/x.py`：
`-X` 被当 flag 吃掉 → 剩下 `utf8` 不是 `.py` → **正则在此放弃该行**，整条不扫。

而本仓探针/守卫命令大量带 `-X utf8`。这不是「少扫几条」，而是**给这一类开了白名单**——
且它是静默的：扫描处数照样打印，看起来一切正常。

修法：按 CPython 真实 CLI 分两组——取值型（`-X/-W/-Q` 必须跟值）与无值型。
修完**多浮出 2 处命中**（`probe_c` / `probe_d` 的薄垫片），正是此前修过的两个探针。

> **可复用判据**：正则里的「可选前缀」如果是**枚举式**的，漏掉一个成员就等于漏掉一整类，
> 而且不会有任何告警。要么按被解析对象（这里是 CPython CLI）的真实语法分组，
> 要么把「未知形态」显式记成「不扫」并计数——不能让「扫不到」与「扫过且干净」同形
> （这正是 R7/N251 的老教训，R10 又栽了一次）。

### ② `cd <dir>` 基址只认仓根 → 把**能跑**的命令判成 R10a

`docs/a.md` 里写 `cd sub` + `python tests/run.py`，`sub` 就在文档旁边（`docs/sub/`）。
只按仓根判目录存在性 ⇒ 判不出这个 cd 块 ⇒ 那条能跑的命令被报 R10a 红。

这是**误报**（假红），危害与漏扫相反但同样实在：假红会让人开始不信闸门。
修法：`cd` 的落点同样有两种现实读法（相对仓根、相对文档目录），都认。

### ③ 我把一条**修前就存在**的红锚说成「是我造成的」

`check_line_anchors` 报 394 条红。我看到其中一条指向 `scripts/check_publish_artifact.py:205-221`
（正是我插过 R10 块的位置），当场判定「这条红是我造成的」。

**做归因验证后结论相反**：

即：**锚在我动手之前就已经漂了 142 行**（上一轮加 R8/R9 推的，当时没人发现）。
我这轮又推了 4 行，但这不改变「它是红」这个判定。

## 五、登记面（R10b 的放行依据）

不随包 ≠ 缺陷。登记的都是「**读者须先有完整源码树**」的维护者工具，逐条给理由：

| 登记键 | 是什么 | 为何不构成装机缺陷 |
|---|---|---|
| `hive/` （**目录前缀**） | Rust 并发调度面整棵树 | 整目录不进 `files`；`hive/README.md` 会随包但命令面向部署者 |
| `scripts/run_tests.py` | 全仓测试驱动器 | 装机侧没有 `tests/` 与绝大多数 `scripts/` |
| `scripts/render_discipline.py` | 纪律渲染器 | 装机用户不需要跑：注入是**已渲染好的产物**，不是安装期步骤 |
| `scripts/verify_discipline.py` | 纪律漂移校验器 | 同上；装机侧无真源可比对 |
| `scripts/gate_output.py` | echo/版本锚判据 | 出现在**纪律正文**里，是「知道有这条纪律」而非「现在去跑」 |
| `scripts/state_atlas.py` | 多主体状态追踪图 | 依赖同样不随包的兄弟件；文档 §十 已标注并给随包替代面 |

| `scripts/probe_c_ledger_integrity.py` / `probe_d_retirement_discipline.py` | 探针薄垫片 | 本体已随包；文档 §七 自己写明「源码树可用、装机侧用 `-m`」 |

**目录前缀登记**（`hive/`）是本轮新增的形态：比逐文件登记更贴近事实
（`hive/` 是整目录不随包，不是「碰巧少发十几个文件」）。

## 八、必须说清的边界

1. **R10 不覆盖**：代码块**之外**跨行拼接的命令；`sh`/`bash` 脚本里的调用（只扫随包 `.md`）；
   命令参数对不对（只判文件在不在）；整目录不随包文档中点名的件（已按前缀登记）。
2. **`-m` 形态不保证「跑得通」**：`python -m md_cg.review_cli list` 仍要求显式
   `--root` / `MDCG_ROOT`（否则 exit 1）。R10 只判「模块文件在不在包里」，
   不判「这条命令的参数够不够」——后者属可用性，不是发布件可达性。
3. **394 条锚红里仍有 2 条真缺陷**（`md_cg/test_issue39_utf8_stdio.py` 引
   `serve_start.py:462-464` 的 `load_config` 不在该行），**本轮未修**——它不在 R10 面内。
4. **本机装机仍是旧版 0.9.16**，生产台账 `_state_events.jsonl` 仍不存在。
   本轮所有读数都在冒烟腿自装的沙箱里取。**发版重装仍是第一优先，与本轮改动无关。**
5. **`check_line_anchors` 在本工作区的读数不可直接用作判据**：本目录无 `.git`，
   守卫退化为文件系统走查，把 gitignored 的 `_md_cg_p27/`（344 条）与 `lib/`（5 条）
   也扫了进来。干净克隆下的读数会显著不同。

### 为什么 R10 块放在文件末尾

R10 有 211 行模块级代码。最初插在 R9b 那一带，把**其后所有定义**向后推 211 行
——`scan_text_hits` 从 347 推到 562。而 `docs/eval/缺陷挖掘_自主迭代_v20.md` 里有
手写锚 `scripts/check_publish_artifact.py:205-221`（历史留档，按本仓纪律**不得改写**）。

即：**加判据本身不该有「让历史锚更漂」的副作用**。放到最后一个定义之后
（`main()` 之后、`if __name__` 之前）即可零成本避免——既有定义行号一个都不动。
Python 全部定义在模块加载时先执行，`local_mode` 调用时才引用 `_r10_doc_exec_refs`，
此时早已就绪。
