## 一、定位（一句话 × 两条链）

> **本机图像引擎负责「确定性变换」，云端生成引擎负责「概率性创作」——两条链不混成一个工具。**

两条链的共同上层是**自建的 Image Skill 接口**（接口稳定、后端可替换）——Agent 只调 Skill，不直接操作任何具体软件（更不模拟人点 GUI）。

## 二、选型（本机层 / 高级编辑 / 云端层）

| 层 | 选型 | 状态 | 理由（含外部参考） |
|---|---|---|---|
| **本机基础层** | **libvips**（图像数据平面）＋**ImageMagick**（CLI／格式／杂项） | **第一批落地** | libvips：低内存、多线程、CPU 原生，Python/Rust/Node 绑定齐全（`sharp` 即建于其上）——「比 GUI 编辑器更适合做智能体底层」；ImageMagick：CLI 即成熟自动化接口（管道可组合）。两者互补不二选一（外部参考原话：libvips 做数据平面、IM 做兼容工具箱） |
| **高级编辑** | **PhotoCraft**（clean-room、纯 Rust、command/CLI/JSON control channel/**MCP server**） | **实验接入（跟踪）** | 「Agent-native image editor」方向与我们最契合；但处早期 alpha——**列为实验接入，不作生产唯一后端**。（**待核实**：外部参考指 `kuretoshi/photocraft`，设计者先前所指为 ArtCraft 套件〔storytold 组织〕的 PhotoCraft——同名关系待查） |
| **远期** | Graphite（node-based／nondestructive／procedural） | 观察 | 节点图天然适合 Agent 表达（JSON pipeline）；alpha，不列生产依赖 |
| **云端生成层** | **ComfyUI ＋ 云 GPU**（既有云方案） | 第二批（按需启用） | workflow 固化、API 调度、可换模型与 provider——「**不要让云端模型直接成为 Agent API**」；Skill 层做稳定接口，云端只做执行后端 |
| **不选** | GIMP（人类编辑器，脚本面弱于 libvips/IM）；Krita（绘画向） | — | 外部参考同判 |

## 三、架构（Skill 分层）

```
Agent（意图层：把…缩小 / 分离人物 / 生成海边场景）
   │
   ▼
Image Skill API（自建；接口稳定、后端可替换）
   ├── inspect   元数据/尺寸/格式/哈希
   ├── edit      确定性变换（★本机 CPU 承载）
   └── generate  生成式（★Job 化，云端执行）
         │
   ┌─────┴─────┐
   ▼           ▼
libvips/IM   ComfyUI+云GPU
（本机 CPU）   （云端）
   │
   ▼
Asset Store（可寻址 asset://）＋ 审计台账
```

**edit 接口约定**（全部确定性）：`inspect / resize / crop / rotate / flip / convert / composite / mask / adjust / blur / sharpen / thumbnail / extract / export`——**Agent 不接触** libvips API、IM 参数、CUDA、ComfyUI node id、模型路径（全部藏在 Skill 后面）。

**generate 接口约定**（Job 化，非 Function）：
```
generation.submit(prompt, size, count, provider, workflow) → { job_id, status: queued }
generation.status(job_id)                                  → { status, progress… }
generation.result(job_id)                                  → { asset: asset://… }
```
——为「持续性智能体」设计：Job 可恢复、可查询、可审计（对齐本仓既有「任务/台账」范式）。

## 四、三可信等级与审计字段

| 等级 | 内容 | 自动化 | 记录要求 |
|---|---|---|---|
| **L0 纯确定性** | resize/crop/rotate/convert/composite/metadata | 可**全自动**（输入相同→输出相同） | 输入输出 asset 哈希、操作、参数、工具版本 |
| **L1 确定性算法＋内容分析** | face/object detection、segmentation、OCR、background removal | 可自动（须记账） | 上列＋**模型版本**＋置信度 |
| **L2 生成式** | generate/inpaint/outpaint/style transfer/i2i | **须标记**（`deterministic:false`） | 上列＋`model`＋`seed`＋`workflow`＋`provider`＋`parameters` |

**审计原则（外部参考原话采纳）**：「不要让『看起来一样』成为图像技能的成功标准」——每次操作记：输入 asset hash、输出 asset hash、操作、参数、工具版本、模型版本、workflow hash、seed、执行环境、时间。
**收束句**：「图像本身成为可寻址 Asset，编辑操作成为可追踪事件，生成过程成为可恢复 Job」——图像能力由此成为身体层的一部分（而非外挂工具）。

## 五、落地路径（三步）

1. **步 1（本机基础层·立即）**：安装 **ImageMagick**（Windows 安装包）与 **libvips**（Windows 官方 `vips-dev` 归档解压＋PATH，Python 侧 `pyvips`）；建 `scripts/` 下的最小验证（各跑一条真实变换并记录审计字段）。
2. **步 2（Skill 接口·设计先行）**：定 `Image Skill` 的接口契约（输入/输出/审计字段/错误态）——先出接口设计文档，再实现 edit 子集（本机）。
3. **步 3（云端生成·后置）**：ComfyUI 方案与云 GPU 接入（沿用既有云迁移方案）——仅在需要生成时启用。

## 六、边界（不做什么）

- 本机**不做生成式重活**（不触 4090 密集计算——硬件约束）；生成一律走云。
- Agent **不直接操作**任何 GUI 图像软件（不做「鼠标点 Photoshop」）。
- 图像 Skill **不碰**资格/信任/写入面（它是能力子系统，不是决策子系统）。
- 不引入 GIMP/Krita 作为程序化后端。
