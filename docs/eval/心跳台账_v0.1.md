## 一、缺口与正解

**缺口**（答卷 §八 分诊第 4 项 · **甲＝能力缺口**）：「持续运行」的**严格「连续 N 周期无断」不可测得**。

**为什么测不出**（§丁 取证）：

1. `_sustain.jsonl` 是 **heal 动作台账**——`heal.act()` 只在**诊断出问题并执行修复**时写行，
   「平静期（无动作）」与「停摆期（进程死）」在该台账上**不可区分**；
2. 心跳戳 `~/.mdcg/sustain/<name>.stamp` 是**覆盖式单点**（`atomic_write` 原子替换同一文件），
   **不落历史序列**——无法从戳反推「最近 N 个心跳是否连续」。

**正解**：给心跳加一条 **append-only 周期台账**——每个心跳周期追加一行，历史行只增不改；
配合**分片轮转＋保留片数上限**（有界）与**节流探测**（写路径税摊到 1/N），
并由**只读统计**直接算出「最长连续无断区间 / 断点数 / 最近一次周期时刻」。

## 二、位置与字段

| 项 | 值 | 说明 |
|---|---|---|
| 落点 | `<root>/_heartbeat.jsonl` | 与 `_sustain.jsonl` **同域**（库根）；`root` 即记忆库根 |
| 归档目录 | `<root>/_heartbeat_archive/` | 分片存放处；**不在 `LAYERS`**，不参与节点索引（检索面零污染） |
| 归档索引 | `<root>/_heartbeat_archive/_index.json` | 分片 `bytes/events` 缓存（稳态 O(1)） |
| 记录字段 | `t`（时间戳）＋`name`（周期名）＋`pid`＋`kind`＋`ok`（结果）＋失败时 `error`（摘要，截 200） | 证书件要求的「t／name／pid／ok 或 error」齐备 |
| `kind` | `"beat"`（心跳周期）／`"rotate"`（轮转自述） | 统计**只取 `kind=="beat"`**，轮转自述不进时间序列 |
| 常量 | `md_cg/sustain.py:270-287`（`HEARTBEAT_LOG`／`HEARTBEAT_ARCHIVE`／`HEARTBEAT_INDEX`／`HEARTBEAT_ROTATE_BYTES`／`HEARTBEAT_KEEP_SHARDS`／`HEARTBEAT_PROBE_EVERY`／`HEARTBEAT_ENV`／`HEARTBEAT_GAP_THRESHOLD`／`HB_KIND_*`） | 单一真源 |

**写点（唯一）**：`SustainLoop.beat()`（`md_cg/sustain.py:1388`）——**一次 `beat()` 一行**。
写点边界**刻意收窄**（写进代码注释）：

- **只有常驻循环的 `beat()`** 记台账——那才是「心跳周期」；
- `write_stamp` 的其它调用点**不记**：进度面刷新 `_flush_progress`（进/出六档各刷一次，
  非心跳周期，会把「停摆」稀释）、MCP 手动 `action=beat`（人可手动补戳，**不是**「循环活着」
  的自证）。故台账是**循环自证面**：进程停摆 ⇒ 无新行 ⇒ 断点显形。

## 三、有界性（硬要求）——形态照抄 `_audit.jsonl` 轮转

参照 `md_cg/mdcos.py` 的审计轮转族（`AUDIT_ROTATE_BYTES`／`AUDIT_KEEP_SHARDS`／
`rotate_audit`／`_prune_audit_shards`／`_rotate_audit_if_needed`）与其守卫
`md_cg/test_audit_rotate.py`：

| 机制 | 心跳台账实现 | 缺省 |
|---|---|---|
| **活动文件上限** | `HEARTBEAT_ROTATE_BYTES`：`beat` 写前闸门，活动台账 `size ≥ 阈值` ⇒ `rotate_heartbeat` | `4 MiB`（≤0 关闭轮转＝显式退回无上界） |
| **轮转（无损）** | `publish(活动, _heartbeat_archive/_heartbeat.%06d.jsonl)`——原子 `rename`，**不动一个字节**；轮转前记录序列是轮转后（跨分片按时间序合并）序列的**前缀** | 序号零填充 ⇒ 字典序==时间序 |
| **保留片数上限** | `HEARTBEAT_KEEP_SHARDS`：`_hb_prune_shards` 保留最近 N 片、淘汰更旧的；淘汰名单写进新台账的 `rotate` 自述行（**淘汰有痕，不静默丢**） | `4`（≤0 不淘汰） |
| **节流探测** | `HEARTBEAT_PROBE_EVERY`：把 `stat` 摊到 1/N（仿 `AUDIT_PROBE_EVERY`） | `8` |
| **索引缓存** | `_hb_load_index`／`_hb_save_index`：分片封存时数一次、落 `_index.json`，稳态 O(1) | — |
| **并发兜底** | `FileLock(<root>/_heartbeat.rotate.lock)` ＋ rename 前复检大小／失败即返回 `None` | 抢输不重复切分 |

**有界性论证**（三处上界，逐条可证）：

1. **单文件字节上界**：活动台账只在 `size ≥ HEARTBEAT_ROTATE_BYTES` 时轮转，且探测步长为
   `HEARTBEAT_PROBE_EVERY` ⇒ 单文件 `≤ HEARTBEAT_ROTATE_BYTES + HEARTBEAT_PROBE_EVERY × 单条字节`；
   每个归档分片的大小即「轮转那一刻的活动文件大小」，同样 `≤ 阈值 + 单条余量`。
2. **分片数上界**：`_hb_prune_shards` 每次轮转后把分片数压回 `≤ HEARTBEAT_KEEP_SHARDS`。
3. **总量上界**：`≤ (KEEP + 1) × ROTATE_BYTES + O(单条余量)`。缺省 = `(4+1) × 4 MiB ≈ 20 MiB`。

**代价**：只读统计 `heartbeat_ledger_stats` 跨分片读**全部**保留行，代价 = `O(总量) = 有界`
（这正是轮转的意义——否则「读它」随运行时长线性劣化，同 `test_audit_rotate.py` 立卷背景）。

**可测历史窗（诚实边界）**：淘汰会丢弃最旧分片 ⇒ 可测窗口 ≈
`KEEP × ROTATE_BYTES ÷ 单条字节 ÷（每周期行数）`。缺省按每条 ~110 B、心跳 600 s 一次估算：
`4 × 4 MiB ÷ 110 B ≈ 15 万条 ≈ 1000 天`。要更长历史就调大 `HEARTBEAT_KEEP_SHARDS`／
`HEARTBEAT_ROTATE_BYTES`；要「永不淘汰」（无上界）就把 `HEARTBEAT_KEEP_SHARDS=0`——**那是显式
退回无界形态，不推荐**（与 `AUDIT_KEEP_SHARDS ≤0` 同义）。

## 五、只读统计（闭合「不可严格测得」）

### 入口

```python
# md_cg/sustain.py:473
heartbeat_ledger_stats(root, *, name=None, threshold_s=HEARTBEAT_GAP_THRESHOLD) -> dict
```

只读：不写、不轮转。跨分片（旧片在前）＋活动台账合并 `kind=="beat"` 的 `t` 序列，
以「相邻 `t` 间隔 **> threshold_s** 为断点」分段（阈值缺省 `HEARTBEAT_GAP_THRESHOLD =
2 × DEFAULT_BEAT_INTERVAL = 1200 s`；改阈值只影响断点计数，**不隐藏阈值敏感性**）。

### 返回字段

`n`（周期数）｜`threshold_s`｜`shards`（分片数）｜`absent`（无记录）｜`span_s`／`span_iso`
（时间跨度）｜`segments`（连续段数）｜**`longest_s`／`longest_iso`（最长连续无断区间）**｜
`count_in_longest`（该区间内条数）｜**`breaks`（断点数）**／`breaks_top`（最大若干断点）｜
**`last_iso`／`last_age_s`（最近一次周期时刻与距今）**。

### 使用示例

```python
import os
from md_cg import sustain as S
st = S.heartbeat_ledger_stats(r"<库根>", name="md_cg")          # 缺省阈值 1200s
print(st["longest_s"], st["breaks"], st["last_iso"], st["last_age_s"])
st6 = S.heartbeat_ledger_stats(r"<库根>", name="md_cg", threshold_s=600.0)
```

命令行等价（只读；不起进程、不写盘）：

```bash
python -X utf8 -c "import sys;sys.path.insert(0,'.');from md_cg import sustain as S;import json;print(json.dumps(S.heartbeat_ledger_stats(r'<库根>',name='md_cg'),ensure_ascii=False))"
```

## 六、在役只读实测（2026-10-07）

在役库根与心跳戳目录**均只读**（`open(...,'r')`／`os.stat`；不 append／不写戳／不轮转）。

**① 新台账 `_heartbeat.jsonl`：在役**缺席**（本台账为本轮新增）。**

```
heartbeat_ledger_stats(<在役库根>, name="md_cg")
→ {"n": 0, "absent": true, "breaks": 0, "longest_s": null, "shards": 0}
```

**原因（如实，不编数）**：本台账是本轮新增的**改码**，在役常驻进程（心跳戳 `pid=14536`、
`uptime≈72005 s≈20.0 h`、`last_tick_done=sleep(ok)`）**仍加载旧码**，尚未写过一行 `_heartbeat.jsonl`；
故「连续 N 周期无断」的**严格读数此刻仍不可取**。**正解落地**：常驻进程重启加载新码后，
`_heartbeat.jsonl` 开始按心跳周期累积，`heartbeat_ledger_stats` 即可给出严格读数
（这是本项交付的机制，落地即闭合缺口）。

**② 旁证（既有 `_sustain.jsonl`，同一 run 算法，`scripts/probe_w7v11_struct_limited.py`）**：

| 读数 | 值 |
|---|---|
| 条数 | 28705 |
| 时间跨度 | 2026-09-10T07:40:39 → 2026-10-07T15:57:28（**27.3 天**） |
| 最近一次周期 | 2026-10-07T15:57:28（采样时 **227.5 s** 前） |
| 相邻间隔 | min 0.0 ／ p50 16.3 ／ p90 217.4 ／ max 150846.7 s |
| 最长连续区间（阈值 600 s） | 188994.0 s ≈ **2.19 天**（2026-09-12T13:56:14 → 09-14T18:26:08） |
| 断点数（600 s / 1200 s） | **76 ／ 35**；最大断点 150846.7 s ≈ 42 h |

**语义边界（不拔高）**：上表是 **heal 动作台账**的读数——只在「heal 动作连续发生」的意义上成立，
**不能**等同「信息处理过程无断」（平静期与停摆期不可区分，见 §丁）。这正是为什么需要
**心跳台账**：它按「心跳周期」逐周期落行，停摆即刻显形。

## 九、局限（如实保留）

1. **在役严格读数待重启**：机制已落地，但在役常驻进程重启前 `_heartbeat.jsonl` 为空
   （§六①）；此刻「连续 N 周期无断」仍只能以 `_sustain.jsonl` 半口径旁证。
2. **多实例/多 pid 未消解**：§丁 观测到的 `pid` 漂移仍是待核实项——台账**如实记录每行 `pid`**，
   使「谁在写」可查（多 pid 会显形为同 `name` 下 `pid` 交替），但**不主动判定**是否多实例。
3. **淘汰丢弃最旧历史**：有界性以「可测窗口有限」为代价（§三）；要更长历史须调大保留参数。
4. **轮转自述行混入活动台账**：`kind="rotate"` 行在活动文件里；统计按 `kind` 过滤，但直接
   `read_jsonl(_heartbeat.jsonl)` 的其它消费者需自行按 `kind` 过滤（文档已声明不变量）。
5. **写点收窄的取舍**：MCP 手动 `action=beat` 不记台账（非循环自证）——若将来要把「人工补戳」
   也纳入「活着」的证据，需另议（当前刻意排除）。
