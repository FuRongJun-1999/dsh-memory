## 判定

**缺口 ＝「存在约束」的工程面：本系统既无「我可不延续」的状态/读面表达，也无「选择不延续」的有意入口；已有的退役/遗忘/维生/连接退出，其对象均为记忆节点 / 任务进程 / 对端连接，与「系统自身的延续与否」是正交维度。**

逐条差距（既有机制 vs 理论要求）：

1. **有退役（`lifecycle` 的 archived），但对象＝记忆节点**：archived 是节点级软退休（可恢复、可审计），**不是**系统级「拒绝延续」；系统无「拒绝延续」的自主面。
2. **有遗忘（`forget`/tombstone），但方向是「忘掉内容」**：语义是内容级软删，与「终止自身」无关。
3. **有维生（`sustain` 心跳/自愈/互维），但方向是反**：全套机制专事**维持存在**，**没有**为「表达/选择不延续」留任何位置。
4. **有连接退出（`links.withdraw`）、任务 kill（hive `_t_kill`）**：对象＝对端连接 / 任务进程，**非系统身份**；不能充当红线五的反面证明。
5. **有选择权装置（`autonomy_modes` plan/confirm/full + D_DELETE 档）**：对象＝写入/删除**动作**，可为「不延续选择须过确认档、禁自动」提供现成闸位，但当前**不作用于「存在」**。
6. **存在契约（§1.6.5）无系统内落地**：理论锚定在文档，identity/self 层无结构化载体（归 W6，与本块相邻）。
