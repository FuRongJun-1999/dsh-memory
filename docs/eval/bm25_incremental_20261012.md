# 2026-10-12：BM25 写入后检索的增量块维护

本轮交付 BM25 写入后块索引的增量维护；不重复申报既有 [Issue #2](https://github.com/FuRongJun-1999/dsh-bounty/issues/2) 的成果。

**前置依赖：** [PR #107](https://github.com/FuRongJun-1999/dsh-memory/pull/107) 的可选 BM25 路径尚未合并。本轮增量仅为本报告、增量维护实现、配对基准和两份测试文件；相对冻结基线 `b4f6b68ee3e51a34dca430b187cba3fc8d570ebb` 可独立查看。上游 PR 页面在前置合并前可能包含 #107 的改动，不能把它们计作本轮新增成果。

## 改了什么

原版每次改动一个节点，虽然只重读该文件，却重排整个块布局并重建查询词的块表。本轮把派生索引维护改为稳定基座加增量尾部：未改节点保留槽位，修改和插入的节点集中追加，旧位置标为空；分别登记旧词、新词，按需修补受影响的 128 槽块。

继续保存实际 TF/文档长度组合，查询时使用最新 N、DF 和平均长度计算安全上界；命中位图和 importance/id 同分界同步更新。首次稳定槽位实验曾让更新后的高 TF 文档散落多个块，热查询评分量上升；集中到尾部解决了这一布局问题。

更新日志最多保存 4096 个路径，只追踪至多 32 个缓存词。布局超过 max(256, 2×有效文档数) 时压缩；大批量变化回退重建。即使小候选池改走穷举或无命中，也会及时释放过大的旧布局。

实际评测从没有 .git 的源码副本运行，使用 SHA256 精确校验的冻结基线文件，网络审计钩子禁止连接、DNS 和 UDP；两种规模均为 0 网络尝试。本轮交付包含源码、原始日志、冻结基线及合成测试集，公开下载入口见对应 PR。源码包不含 Python 环境及 BEIR 原始数据；复现前需准备项目依赖。

## 限制

Windows 11、Python 3.12.10、共享桌面、合成短文本。Mem Reduct 仍在运行，当前进程停止它被 Windows 拒绝；OS 缓存未清，延迟是本机交替对照观测。每场景 10～30 个样本不足以证明生产 P99/SLO。

**写入后的资格枚举和文档代际同步仍为 O(N)**；本轮优化的是块布局与块表维护。首次索引仍全量读文件，广泛失效和必要压缩仍重建，最坏评分仍为 O(df)。本轮未新增百万条持续写入、同实例线程并发、长对话 QA、MCP 网络服务或 LLM 测试。既有百万条只读测量属于历史证据，其收益不能与本轮加速倍数相乘。
