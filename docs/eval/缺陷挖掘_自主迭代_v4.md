## 一、执行摘要

本轮收口 v3 报告遗留清单中 codegen 域 5 项里的 4 项（N11/N12/N13/N15），全部落盘为工作树未提交改动。四项同属「代码生成产物可靠性族」——此前白名单产物可被源码字符串内容击穿、五类语法节点静默蒸发、表达式位置产出必坏代码、无术曰程序产物必 NameError，且四条路径编译均报 success=True。修复后实测：注入 payload 被完整封在字符串字面量内（AST 解析零逃逸调用点）、循环/函数/返回/调用在产物中语义在位、四类探针产物全部通过 `compile()`、无术曰产物 `exec(__main__)` 正常运行。

## 二、修复明细（4 项全部落盘，本会话逐项读核 + 实跑验证）

### F1（对应 N11，high）字符串字面量/标识符内容 json.dumps 转义

- **位置**（现行）：codegen.py:362-372（`_gen_instruction` 参数收集）、codegen.py:496-497（`_gen_expression` 非数字 LITERAL）；快照时点行号 343/348/424（v3 报告）。配套 `import json`（:7）。
- **修复方式**：标识符名与字符串字面量内插前一律 `json.dumps(..., ensure_ascii=False)`——ASCII 双引号/反斜杠/控制符全部转义，引号边界不可击穿；中文经 `ensure_ascii=False` 原样保留。
- **本会话验证**（探针实跑）：
  - 引号击穿：`compile_source('道 “含"引号”。')`（全角引号包裹、内容含 ASCII 双引号）→ 生成行 `_runtime.create_path("含\"引号\"")`，产物 `compile()` OK。v3 时点同源产物为 `create_path("含"引号")` → SyntaxError: unterminated string literal。
  - 反斜杠语义：`道 “a\nb”。` → `"a\\nb"`，`compile()` OK，字面 a\nb 不再漂移为换行符。
  - 注入逃逸（权威验证，AST 解析产物）：payload `x") or __import__("os").getcwd() #` 全文置于字符串内容 → `ast.parse` 产物后 create_path 调用参数恰为**单个等于 payload 的字符串常量**，全产物 `__import__` 调用点 **0 个**——白名单代码生成不再可被源码字符串内容逃逸，success=True 的产物即安全产物。

### F2（对应 N12，high）`_generate_statement` 分派表补齐五类节点

- **位置**（现行）：codegen.py:319-331 新增五分支（LOOP_STMT :319-322 / BLOCK :323-324 / FUNC_DEF :325-326 / RETURN_STMT :327-328 / CALL_EXPR :329-331）；快照时点 292-310（v3 报告）。配套五个新生成方法：`_gen_loop`（:397-407，当…执行 → while，对齐 VM 路径条件回跳语义）、`_gen_block`（:410-413）、`_gen_func_def`（:416-426，名字/参数经 `_py_name` 校验）、`_gen_return`（:429-435）、`_gen_call_stmt`（:438-441，结果丢弃）及导入面补五类节点类型（:14-15）。
- **本会话验证**（探针实跑）：
  - 循环：`当 计数 小于 3 执行 德 0.1。` → 产物含 `while 计数 < 3.0:` 及体内德调用，`compile()` OK；v3 时点产物无任何 while、仅 warning『未处理的语句类型: LOOP_STMT』。
  - 函数+返回：`定义 加（甲，乙）：返回 甲 加 乙。` → 产物含 `def 加(甲, 乙):` 与 `return 甲 + 乙`，`compile()` OK。
  - 调用语句：`定义 早退（）：返回 7。 早退（）。` → 产物含调用行 `早退()`。
  - codegen 自身零 warning（见下述 N21：残留的『未处理的语句类型』warning 来自名实校验链 name_checker.py:531，格式带 `:C` 列号，非 codegen）。

### F3（对应 N13，high）表达式位置不再写行中 '#' 注释

- **位置**（现行）：codegen.py:502-506（CALL_EXPR 表达式分支改调 `_gen_call_expr` 生成真调用）、:507-512（其余未支持类型改 `errors.append` 记错 + `_write("None")` 占位）；快照时点 429-430（v3 报告）。配套 `_gen_call_expr`（:523-531，名字经 `_py_name`）。
- **本会话验证**：
  - CALL_EXPR：`甲 = 乙（1）。` → 生成行 `甲 = 乙(1.0)`，`compile()` OK；v3 时点产物 `甲 = # 未支持的表达式: CALL_EXPR` → SyntaxError: invalid syntax。
  - 其余未支持类型的处置以读核为准（:507-512：记 error 令编译失败、None 占位保产物语法完整，杜绝行中注释）；实测 `甲 = -乙。` 未落该分支——「-乙」经词法/语法收作字符串字面量，产物 `甲 = "-乙"`、`compile()` OK。

### F4（对应 N15，v3 记 medium / 本轮输入记 high）footer 条件调用 protocol_procedure()

## 三、本轮新发现（1 项，未修复）

### N21（medium 候选）name_checker 语句分派缺 FUNC_DEF/RETURN_STMT/CALL_EXPR——函数体内名实规则整体失效

- **位置**：compiler/name_checker.py:493-532 `_check_statement`——分派表含 CONDITION_STMT/LOOP_STMT/BLOCK/INSTRUCTION_STMT/SHUYUE/STEP/ASSIGN_STMT 及四个静默通过类型，**无** FUNC_DEF/RETURN_STMT/CALL_EXPR 分支，:529-532 else 只向 warnings 追加『L{line}:C{col} 未处理的语句类型: {name}』后整体跳过（:492 生效条件注释如实列举了缺口）。与修复前的 codegen N12 同型（分派缺口 + 静默跳过），本轮 codegen 补齐五分支后该缺口暴露在名实校验链。
- **实据**（本会话探针）：
  1. `定义 加（甲，乙）：返回 完全未声明名 加 乙。` → success=True、errors=[]、仅 warning『L1:C1 未处理的语句类型: FUNC_DEF』——函数体内名字零校验（对照：顶层指令操作数未声明同样不报，名实校验本不查操作数声明性，本条单独不构成回归）；
  2. **条件空间约束失效（实质影响）**：`若 条件空间 为 伴侣，则 定义 增（）：止 情感权重 于 0.9。` → success=True、errors=[]、仅 warning；对照同约束语句在条件块顶层 `若 条件空间 为 伴侣，则 止 情感权重 于 0.9。` → success=False、错误『在「伴侣」条件空间中情感权重不可超过 0.15，当前值: 0.9』——**同一条受约束指令包进函数体即完全绕过名实拦截**。
- **状态**：未修复（不在本轮四项修复范围，本轮验证时新发现）。修法明确：`_check_statement` 补三分支（FUNC_DEF 递归校验 body、RETURN_STMT 校验 value、CALL_EXPR 校验名字与 args）。
