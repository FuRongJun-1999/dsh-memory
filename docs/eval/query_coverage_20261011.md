# 中文长查询召回词覆盖实验

实验日期：2026-10-11。上游基线 `4ff38bbcce5932e65f5134d42a1406e63dfde586`。
这是独立编写的确定性实现，不引入同类项目代码或运行依赖。它是已有召回链上的
可选改进，不把通用的分配预算、等距取样当成新发明。

## 问题和改动

现有 `cn_recall_grams` 在第 16 个有效中文 bigram 之后立即返回。长问题前半段
用完名额时，尾部线索不会参与 LIKE 召回；有其他命中时，检索提前在该层返回。
[Issue #108](https://github.com/FuRongJun-1999/dsh-memory/issues/108) 已有这个问题，
本次不另建重复问题，也不声称复算了作者的私有数据。

新策略先按连续中文段分配名额，再在每段内分散取词；仍为最多 16 个。短查询
不超过额度时词序完全相同。仅 `MDCG_CN_GRAMS_COVERAGE=1` 开启，缺省、其他值、
总开关关闭时均保留原有约定。Python/Rust 同步实现，共享 15 例期望词序。
配置登记、生成表/校验器以及热缓存键一并接线。

## 合成配对读数

每库 701 条前缀干扰记忆 + 8 条尾部实体记忆，共 **709 个实际 Markdown 节点**。
8 个实体各生成头部、尾部和短问题三种查询，共 24 条；每臂 5 次暖查询，共
120 次/臂/库。首对用来预热，不计入延迟。按查询和轮次交替两臂顺序，
同一实例、同一数据、同一评分和 cap，关闭查询结果缓存，开启文档缓存。

| 查询形态 | 默认前缀策略 hit@10 | 覆盖策略 hit@10 |
|---|---:|---:|
| 尾部实体（8 条） | 0/8 | 8/8 |
| 同一线索移到头部（8 条） | 8/8 | 8/8 |
| 短查询（8 条） | 8/8 | 8/8 |

| 暖查询延迟 | 默认前缀策略 | 覆盖策略 |
|---|---:|---:|
| 平均 | 6.874 ms | 7.985 ms |
| P50 | 6.239 ms | 8.326 ms |
| P95 | 13.038 ms | 14.805 ms |

**平均延迟增加约 16.2%**，P95 也增加，不能宣称更快。
新策略完整扫描查询并让额外候选参与评分，改善的是这个夹具的候选覆盖。
两种策略各自的重复排名保持一致；不存在查询报错或算法回退。

另一个同规模对照把干扰正文改成完整前缀，使其相关度明显高于尾部实体。
两种策略对头部/尾部实体均 **0/8 hit@10**，短查询均 8/8。
这个失败对照保留在原始数据中：取词覆盖不能解决评分竞争和后续 cap，
不能把本轮结果外推为「长问题都修好」。

原始文件：[配对实验 JSON](query_coverage_bench_20261011.json)。记录环境、全部题目、
逐题前十排名、召回词、扫描数、候选数、两臂延迟及测量源码 SHA256。
实际评分常量与环境均固定为 `legacy`，候选 cap 为 500；即使启动环境设成
`MDCG_SCORE_MODE=jaccard`，基准也显式固定并记录实际常量。
本机为 Windows、Python 3.12；OS 缓存未清，桌面存在其他活动。
源码测量前后校验一致；字节哈希对应本机检出文件的换行形态。

## 验证

- `md_cg.test_query_coverage`：10/10 通过。含 15 例词序、120 组随机预算/成员性质检查，
  基类与生产入口、大于 500 候选、倒排候选开/关、会话过滤、缓存翻转、MCP stdio。
- Rust `cargo test --manifest-path rust/Cargo.toml --lib`：32/32 通过，含共享词序夹具。
- `md_cg.config_registry_guard`：7/7 通过，305 条配置的锚点/生成件一致。
- 定点变异：6/6 命中预定运行断言；未变异和恢复态各 6/6 通过，0 skip、0 非预期错误。
  分别移除分派、恢复前缀截断、去掉预算、漏缓存键、擅自默认开启、忽略总开关。
  [原始变异证据](query_coverage_mutations_20261011.json)保留每一项的退出码和失败断言。

相关回归与 CI 结果在 PR 中披露；未跑或未完成的检查不计入通过。

## 复现命令

```text
python -X utf8 -m md_cg.test_query_coverage
python -X utf8 -m md_cg.test_query_coverage_mutations --output mutations.json
cargo test --manifest-path rust/Cargo.toml --lib
python -X utf8 -m md_cg.config_registry_guard
python -X utf8 -m md_cg.bench_query_coverage --fillers 701 --rounds 5 --output coverage.json
```

两臂共运行 480 次计时查询（主夹具 240 + 强前缀对照 240），另有预热。
没有 LLM API、模型下载或外部服务；不是并发、压力或生产 SLO 测试。

## 结论边界

没有 #108 的 86 题原始数据库，**未复算其 1.2%/33.7% 读数**；本次没有真实对话 QA
准确率或同类产品速度排名。有限词预算也可能丢弃原来保留的前缀关键词，
段数超过预算时不能覆盖每段。后续需冻结真实长对话 dev/test 集，比较按词、按段、
多查询融合和当前默认策略，分别测候选进入率、最终 recall、QA 质量、token 和延迟。
取得该证据之前保持显式开启，状态为 `uncalibrated`。
