# 灵枢自库端到端检索实测 v1.0（原生中文 · 自然问句 vs 关键词 · 生产读路径）

> **口径**：被测库=灵枢自身在役记忆库（14095 节点 · 原生中文 · CCG 六要素为主写入面 · audit 23.9 万事件的真实累积库）；实测方式=mdcg 读检索生产路径——spawn `python -m md_cg.mcp_server`（stdio JSON-RPC，与 DSH 插件同款链路），逐题调 `cg(op=read, query=…)`，取 top-10 候选判 gold 命中。评测令牌为专用 designer 令牌（`tk_70f633dc8398`，internal 以上可见）。
> **题集**：20 道自然中文问句（口语化、非节点原文词），gold=16 个已落盘已知节点（多题一 gold / 一题多 gold）；对照组=同题关键词版（从 gold 六要素词面构造）。脚本：`bench_self.py`（本目录）；逐题明细：`self_bench_result.json`。

## 结果

| 臂 | hit@1 | hit@5 | hit@10 |
| ---- | ---- | ---- | ---- |
| 自然问句 | 4/20（**20%**） | 10/20（**50%**） | 12/20（**60%**） |
| 关键词对照 | 14/20（**70%**） | 18/20（**90%**） | 18/20（**90%**） |

## 三条对照解读

1. **与 LoCoMo 翻译语料口径对照（自然问句 40.2% / 派生题面 92%）**：原生中文 CCG 库上自然问句 **60% > 40.2%（+19.8pp）**——CCG 六要素写入面（功能名/生效条件等结构化中文槽）确实部分缩小了问句-答案词汇差，翻译噪声也被排除。
2. **鸿沟同构成立**：自库上自然问句与关键词之间仍有 **30pp**（60% vs 90%）——与 LoCoMo 口径的 51.8pp 鸿沟同向。词汇差瓶颈不依赖语料来源，是词法检索的固有边界；**认知图概念桥接（自然问句 → 92%±）的必要性在本口径下再次成立**，且 60% 是桥接实施的自库基线起点。
3. **失败定性（8 题 hit@10 外）**：6 题 kw 臂能命中（典型词汇差：问句「过期/变旧」vs 节点 `stale/observation_aged`、问句「快满了怎么交接」vs 节点 `handoff 满上下文`）——词面不同构是主因；2 题双臂皆败（Q1 serve 存活、Q12 stale 区分）经直读验证 gold 在库可检索，属**排序区分度问题**——「hive/serve」词面在众多蜂巢节点同现，gold 特异词（存活判据/三层）未入问句时被主题相近节点淹没（top-3 全为蜂巢编排类节点，score 0.44-0.59）。

## 过程发现（评测副产物，两条）

1. **审核队列对检索不可见**：`review_pending=22`——缺陷迭代九轮的归档提案全部 pending、索引不可见，`cg(op=read)` 检索不到（例：问「MCP 如何防打崩」返回的 top-10 全为授权/身份主题无关节点，第 10 轮 MCP 入口守卫归档不在候选）。知识从 propose 到可检索依赖设计者裁决，裁决积压=知识不可用。**建议：设计者批量裁决积压提案（review_cli），或为 pending 提案建立降级可见通道（另行设计）。**
2. **自然问句零桶收敛**：tier 分布 17/20 走 `T2_global_like`（全局扫 13550 节点）、3/20 走 `T3_global_scan`，**没有一题走桶收敛（T0/T1）**——自然问句不命中英文桶键；#33 的 `backfill_bucket_zh` 中文别名回填未在本库执行过。全局兜底路径承担了全部自然问句流量，S1b 桶收敛对真实问句形态未起作用。

## 边界

- 20 题小样本，百分比仅作量级参考（±1 题 = ±5pp）；
- gold 由编排会话指定（已知答案节点），非全库抽样；问句风格单一（工程事实型），未覆盖时间/条件/否定类问句；
- 关键词臂由 gold 六要素词面构造，含轻度答案侧词汇先验（与 LoCoMo 口径的派生题面同性质）；
- 被测库持续增长（audit 在写），两次运行数字可能小幅漂移。
