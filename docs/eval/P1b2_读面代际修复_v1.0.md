## 一、缺陷与证据链（DSH 端在役复验时间戳锁死证据）

**缺陷**：MdCG 常驻进程的索引只在启动时装载一次，此后 read/get/search 全走内存态——其它进程（典型：review_cli，autoflush=1）写入对常驻进程**不可见**。

**证据链（DSH 端在役复验，探针 dsh_restart_recheck_20260926，时间戳锁死）**：

| 时刻 | 事件 |
|---|---|
| 22:13:16 | 常驻进程启动装载索引快照：14135 节点 |
| 22:14:37 | review_cli（autoflush=1）写入探针节点 |
| 22:14:43 | 磁盘 `_index.json` 已含探针（写侧落盘成功） |
| 同一常驻进程 | `read` 探针 → **null**（读面不可见——病灶） |
| 旁路新起进程 | `read` 探针 → 命中（新进程装载时读盘即得） |

**关键反差**：写侧账本是平的（盘面有、新进程能读），唯独**常驻进程**的内存态停留在启动代——这不是写入丢失，是**读面代际停滞**。

## 二、根因（启动装载一次 + 批次39 指纹仅在装载时）

1. **架构根因**：`MdCG.__init__` 仅启动时调一次 `_load_index()`（mdcg.py:939），此后 `self.index` 常驻内存，读路径（`get`/`search`/`search_rrf`/`list_goals`）不再碰盘——他进程写快照对常驻进程永不生效。
2. **演进根因**：批次39 为 issue #33 加的 `_index.json` 指纹校验（`fp = idx.get("_fingerprint")` 与 `_dir_fingerprint()` 比对，mdcg.py:973-974；修前行号 966-967）**也在 `_load_index` 内部**——它防的是「快照写入后盘面有增删」的陈旧快照误信，只在启动装载那一瞬间执行一次，不防「进程存活期间盘面变化」。
3. 二者叠加：指纹校验给了「索引新鲜」的错觉，实际保鲜窗口只有启动瞬间；DSH 复验链中 22:14:43 的盘面真相到不了 22:13:16 装载的常驻进程。

## 三、修复

**【机制】**（mdcg.py）

- **:946**（`__init__` 装载后）：`self._index_sig = self._index_signature()`——记录装载时的文件签名作基线。
- **:992-1004** 新增 `_index_signature()`：`os.stat(index_path)` 取 `(st_mtime_ns, st_size)` 二元组（微秒级、无 open 无解析）；文件不存在或 stat 抛 `OSError` 时返回 `None` 静默——签名探测绝不阻塞读。`(mtime_ns, size)` 在 NTFS 100ns / ext4 ns 粒度下足以识别「他进程写快照」；`None→非 None` 同样可判（他进程首次落快照）。
- **:1006-1047** 新增 `_maybe_reload_index()`：签名对比（相等含双侧 None → 返回 False 零开销）；变化才调 `_load_index()` 重载（`OSError/ValueError` 静默放弃、沿用旧内存态——重载失败不阻塞读）；重载后把 `self._dirty` 重放回新索引（`None`=tombstone pop，与 `_load_index` 日志重放同语义）并重算 buckets——本实例未 flush 的写入不因重载从检索面消失；顺带失效 hotcache（默认关）与 readcache（默认开）两个旧索引代派生缓存。
- **:1139-1141** `compact_index` 写快照后主动刷签名；**:1308-1309** `rebuild_index` 同——**自写不自载**（防止把自己的 compact/rebuild 误判为他进程写入而做无谓重载循环）。
- **flush 无改动**：flush 只在 `FileLock` 下向 `_index_log` 追加分片、不改 `_index.json`（mdcg.py:1145 def，:1153-1164 追加临界区），签名不变——自身写入/落账**永不**触发重载，正合适。

**before / after**

- **修复前**：`MdCG.__init__` 仅启动调一次 `_load_index`（mdcg.py:939 旧行），此后 read/get/search 全走内存态；复验证据链（第一节）写侧落盘成功、同常驻进程 read null、旁路新进程可读。
- **修复后**：读路径入口每调用一次 stat（微秒级）对比签名，他进程写快照（compact/rebuild，典型在 close）即触发重载 + 日志重放，写入/删除（tombstone）对常驻进程可见；自身 flush/写入/compact/rebuild 全程零真实重载（自写不自载）。
- **守卫红转绿实测**：同解释器双实例（临时库+哑密钥），B 实例 add+close 落快照后——A 禁用 reload 时 read null（修前病灶形态）→ 恢复后 read/search 命中；C 实例 forget+close 后 A read 归 null（tombstone 可见）；goal=list 经 list_goals 可见；maintain action=reload 幂等探活（未变 False / 他写后 True 且读面立即可见）；旁路子进程 READ 1 0（修前已绿，钉住盘面账本）。
- **性能粗测**：接线态 vs 重载桩空转态——修复会话实测 157.4µs/读 vs 140.7µs/读（增幅 ~11.9%，即一次 stat 摊入 ~150µs 的 get；断言上界 ×3+30µs 内通过）；报告会话复跑 164.0µs/读 vs 149.0µs/读（增幅 10.1%，同断言通过）。

**semantics_note（语义边界，如实）**

1. **探测面边界**：签名只盯 `_index.json`——他进程**仅追加分片日志、尚未写新快照**（存活写方未 close/rebuild）不在自动探测面内。这正合适：自身 flush 也是纯日志追加，签名不变故零自重载循环；DSH 复验链中 review_cli 退出即 close→compact 落快照，落在探测面内。此类场景可用 maintain action=reload 显式探活（显式 reload 的真重载同样走 `_load_index` 的快照+日志全量口径，日志记录仍须快照重写才并入）。
2. **mtime 粒度**：NTFS 100ns 粒度下同 tick 同尺寸的两次快照写入理论上可能漏检一次，下次任何签名变化自愈（启发式哨兵的诚实边界）。
3. **重载保留本实例未 flush 写入**：`_dirty` 重放回新索引（None=tombstone pop，与 `_load_index` 日志重放同语义）并重算 buckets——`_stage` 双写 index+_dirty 的「检索看得到未落盘写入」语义不变。
4. **派生缓存失效**：重载成功时顺带失效 hotcache（默认关）与 readcache（默认开）——旧索引代的 query 结果与同 path 重写的解析产物不陈旧化；重载是稀疏事件，不构成热路径开销。
5. **未接线的读面（读码盘点）**：op=edges（provenance.all_edges→index_edges）、protect action=check（mcp_server.py:1142-1146 直读 `cg.index`）、service_info/insight/stats（mcp_server.py:3074-3079 `len(cg.index["nodes"])`）等低频读面仍走启动快照——高频面（get/search/search_rrf/route/recall/list_goals）已全覆盖，低频面如需可后续按同款单行接入。
6. **stat 成本 vs 常驻不可见取舍**：无跨进程写入时每次读多一次 `os.stat`（实测 ~11-16µs 量级，占 get 的 ~11%，search 毫秒级面摊薄至 <1%），换得跨进程写入可见——读热路径无重载（重载仅在签名变化时发生，重载成本=一次 `_load_index`，与进程重启装载同量级但免去重启）。

## 五、DSH 端复验指引（探针 dsh_restart_recheck_20260926）

修复部署后，探针应立即可读——**无需重启在役进程**：

1. **新起进程**：装载时经 `_load_index`（快照+日志全量口径）天然并入，探针直接可见。
2. **常驻旧进程**（修复前启动、仍持 22:13:16 旧内存态）：二选一——
   - 调一次 `cg(op="maintain", action="reload")`：签名对比必变（review_cli 退出即 close→compact 落了新快照）→ 真重载 → 探针立即可见，返回 `"reloaded": true`；再调一次返回 `false`（幂等探活）；
   - 或待其自然重启，重启后装载即含探针。
3. **注意语义边界①**：若某存活写方只追加了分片日志、尚未写新快照，maintain reload 的真重载也读不到该增量——日志记录须快照重写才并入。DSH 复验链的 review_cli 已退出（close→compact 已落快照），不受此限。
