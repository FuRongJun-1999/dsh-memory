## 一、背景

DSH 端曾执行「停自动写入」决策：不再把会话过程自动写进记忆库。该决策成立的前置件是——**会话日志作为冷真源必须可被事后检索**：日志若既不自动入库、又检索不到，历史会话的结论就彻底丢失，停自动写入等于信息黑洞。本次工作即偿还这笔 DSH 端欠账：

1. 新增离线摄取工具 `scripts/dsh_log_index.py`：DSH 会话日志（zstd jsonl）→ 转写 md（系统临时目录、路径确定）→ 直调生产同款索引入口，摄取进**私有活库**的灵枢检索面；
2. 对目标会话完成摄取并实测幂等；
3. 以五个真实信息需求做检索效果验证，逐层实证闭合未命中根因，给出三个 gap、对照发现与使用边界。

### 2.3 语义裁定（六条，读码定案）

① **摄取路由选定「经 MdCGSecure 直调同款索引入口」而非 `cg index_doc` op**：读码发现 `index_doc` 的节点 id 由 `docindex.node_id` 硬编码为 `doc_` 前缀（`md_cg/docindex.py:284`），无法满足 `dsh-log-` 前缀要求；故章节切分直调与 `index_doc` op **完全同一实现**的 `refindex.index_dir(kind="doc_ref")`（内含 `docindex.extract` 的 level≤3 切分 / 小节合并 / 围栏感知），写入侧逐条对照 `refindex.add_items` 的 doc_ref 分支（`md_cg/refindex.py:378-392`），仅节点 id 改为 `dsh-log-<会话id>-<章节序号>` 且不写 doc_ref 列。*（撰写会话已读码复核上述三处引证。）*

② **不写 doc_ref / 不登记 Ledger 的原因**：转写文件是临时目录暂存物，绑定列会系统性 dangling，且 `op=ref` 回读会开第二个日志原文暴露面；溯源改记 `frontmatter.dsh_log`（session/workspace/source/transcript/heading_path/lineno/end，已实测落盘）。

③ **检索覆盖遵循生产章节切分语义**：直接正文 <200 字的小节并入父节摘要（`docindex` 的 `MIN_BODY=200`，`md_cg/docindex.py:41`），故 33 个转写节中 19 个形成独立节点，其余在父节摘要（生产 `MAX_SUMMARY=200`，`md_cg/docindex.py:42`）与父节区间内。docindex 的设计即「**不存全文，节点正文=CCG 模板+摘要**，正文一律回读」（`md_cg/docindex.py:13-14`；模块头注 `md_cg/docindex.py:2`）。

④ **幂等语义**：节点 id 确定性 + 写入前查索引，已存在即计 `nodes_skipped_existing` 跳过（不覆写既有节点，符合活库只增不删）。

⑤ **private 档按 `_readable` 会话绑定**：仅归属会话的 MCP 面 + 设计者可读；写入身份与在役插件一致（tenant=default / actor=dsh-memory，复用既有 DEK 信封）；转写体内的 markdown 标题样行首加反斜杠转义防切分误认（68 处，不改动正文一字）。

⑥ **输出仅统计/计数/node id**，全程未打印日志正文（仅摘录 ≤50 字用于选查询词）；转写暂存按确定路径保留在系统临时目录（`--cleanup-transcripts` 可选清理），实验快照临时文件已清理。

## 三、检索效果验证（逐查询）

五案均为真实信息需求，按三层读者形态实测：①活库副本直调（无 DEK，词法面）；②管线重放临时库（自带 KEK 重放摄取，33 节点与在役库逐条同 id）+ **归属会话读者**（唯一合法可读面）；③后续新会话读者与 can_admin 设计者读者。实测记录（验证会话），撰写会话未重跑。各案「期望事实」以**事实点**呈现（≤50 字、重新措辞，非日志原文摘录）。

### C1 沙箱启动错误

- **查询词**：DSH 里 run_code 一执行就报 worker-exit 退出，沙箱给工作区挂写权限失败，是什么错误？
- **期望事实**（事实点）：
  - 阶段：worker 沙箱启动期失败，run_code 零执行（turn1）
  - 报错 API：SetNamedSecurityInfoW
  - 错误码：Win32 5（ACCESS_DENIED）
  - 对象：给工作区目录挂 grantWrite 授权失败
- **实测**：
  1. 在役库临时副本直调（MdCGOS 无 DEK，k=30）：top5 全为 `mem_*` 手工归档节点，`dsh-log-` 节点 0 进榜——`dsh-log` 正文是 `mdcg-enc:v1` 密文（sensitivity=private 落盘即加密），明文词法零重叠，以『SetNamedSecurityInfoW grantWrite 沙箱』三个专名组成逐字诊断查询也不现身；`search` 与 `search_rrf` 同。
  2. 管线重放临时库 + 归属会话读者：含该事实的块 `dsh-log-…-0004` 存在（token 幸存），但全排序仅 **13/19**，top-5 未进。
  3. 后续新会话读者与 can_admin 设计者读者：scanned=0，全不可见。
- **命中**：**否**。

## 四、效果总评

**总评**：`dsh-log-` 检索面在『唯一合法可读面』（重放库+归属会话读者）上 top-5 全事实命中率 **1/5**（且为部分事实），在现实使用面（后续新会话『后来想知道』）**0/5**——后者不可见是**设计行为**（private 会话绑定，`md_cg/mdcos.py:3948-3956`，issue #35 使用者拍板）。未命中根因链已逐层实证闭合，三个 gap：

**① 摄取覆盖率 gap（最重）**：docindex 设计为『不存全文，节点正文=CCG 模板+摘要』（`md_cg/docindex.py:13-14`、`md_cg/docindex.py:42` 行 `MAX_SUMMARY=200`），全文依赖 ref 回读，而 `scripts/dsh_log_index.py:50-54` **有意不写 doc_ref 绑定**（转写是临时暂存物）——实测转写 md 43,878 字符仅 14,805 字符入库（**覆盖率 33.7%**），66.3% 正文永久缺席，turn 深处的结论（C2/C4/C5 三案）物理不存在，任何检索器都无法命中。

**② 可见性 gap**：节点 frontmatter.session 绑死摄取时的会话 id，会话一换（重启/新会话即换 id）即永久不可见；设计者 can_admin 能过会话闸但过不了密钥闸——DEK 按 (tenant, actor) 签发（`md_cg/crypto.py:290-314`），封/开 AAD 均绑写入者 actor（`md_cg/mdcos.py:3764`/`md_cg/mdcos.py:3784`），跨 actor 永远解不开密——模块自述目标『使历史会话正文可被 cg search 检索面召回』（`scripts/dsh_log_index.py:7` 头注）在除『复用原会话 id』外的任何读者形态下均不成立。

**③ 排名 gap**：幸存块中数字/专名类事实（4.04MB）排第 1，共享词表高的叙事类事实（沙箱错误）仅排 13/19——19 块共享纪律尾注词表，判别弱。

**已验证的机制面**：同身份往返实验（自带 KEK、全新临时库）命中排名 1、异身份不可见；三会话重放 2+19+12=33 节点与在役库逐条同 id，分块确定性无漂移——**管线机制本身无缺陷，问题在截断与可见性策略**。

**对照发现**：在活库中 C2/C5 的信息需求实际由 internal 密级手工归档节点（`mem_*`）满足并进 top-5，『手动写记忆』面当前是可检索主力，`dsh-log` 面贡献 ≈0。

**边界与未测项**：按隐私纪律未触真实令牌库（~/.mdcg）与在役 serve 进程，持真实 DEK 的在役服务实测表现未测，此为本验证的残余盲区；在役库全程只读（实验全在临时副本/重放库），验证期间在役库簿记文件有一次 00:09:48 的写入系在役 serve 自身 sustain 周期心跳（已排除本验证责任：`refindex.index_dir` 仅在显式传 ledger 时才写，`md_cg/refindex.py:302`/`md_cg/refindex.py:323`，本验证未传）；全部临时实验产物已清理，实现员的转写暂存目录非本验证创建，保留未动。

## 五、使用指引（命令 / 参数 / 幂等）

环境：`set PYTHONUTF8=1`（第 15 条：argv 列表 + 显式 UTF-8，不经 Windows shell）。依赖：`zstandard`（pip）；`md_cg` 包（脚本自注仓库根进 sys.path）。

```text
# ① 先看会碰到什么：不写库，只转写 + 统计
python scripts/dsh_log_index.py --sessions-root <DSH会话根> --dry-run

# ② 按会话摄取进活库（--root 缺省取 MDCG_ROOT）
python scripts/dsh_log_index.py --sessions-root <DSH会话根> --root <灵枢库root> --session <session-id>

# ③ 按工作区过滤 / 指定写入身份
python scripts/dsh_log_index.py --sessions-root <DSH会话根> --workspace <工作区目录名> --actor dsh-memory --tenant default
```

- **空库首摄**须显式 `--allow-init`；对已有库不加该参数即拒绝初始化（防误指 root）。
- **幂等**：节点 id 由 (session-id, 章节序号) 决定 → 确定性；转写路径确定（临时根 + 工作区 + 会话 id），重跑生成逐字节相同的转写；写入前查活库索引，已存在即计 `nodes_skipped_existing` 跳过，**不覆写**（活库只增不删）。已实测：重跑 `nodes_indexed=0` / `nodes_skipped_existing=19`，库内无重复。
- **回收钩子**：节点 id 前缀 `dsh-log-` 专用于识别与将来回收；当前无删除路径，回收须待活库 deletion 策略裁决。
