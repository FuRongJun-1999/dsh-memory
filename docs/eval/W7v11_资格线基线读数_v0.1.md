### 甲.4 两条断言（实测结果）

**① 反向腿——默认关 ⇔ 「未引入该功能前的口径」逐位一致** ✅ **成立**

- 「未引入口径」的构造：就地取运行中 `proposals` 实现源码（`inspect.getsource` → `textwrap.dedent`），把加分行 `emotion_bonus = (round(W_EMO * eps * sign, 4) if emotion_on else 0.0)` **逐字替换为 `emotion_bonus = 0.0`**，`exec` 到模块命名空间副本（**不读 git**，故不绑某个提交）。此即「该功能不存在时」的源码行为。
- 实测：**排序面 `(query, score, d_meta_bonus, sort_score)` 逐位一致 = `True`**（关态四条 vs 该基线，逐条 `base_sort_score` 相同）。
- 退化断言：**`sort_score == round(score + d_meta_bonus, 4)` 恒成立 = `True`**；**`emotion_bonus == 0.0` 恒成立 = `True`**。
- 说明（如实）：关态下 `emotion`/`d2_mean`/`bias` 观测字段**仍在返回体与台账里**（本改动是「只增」——字段完备），
  但承载排序结果的 `sort_score` 与「未引入口径」**逐位相同**；断言判的就是这个 load-bearing 量。

**② 正向腿——开态下 `d2_mean` 不同的提案之间相对次序发生可指认变化** ✅ **成立**

- 前 → 后：`绩效查询乙 > 绩效查询甲 > …` **→** `绩效查询甲 > 绩效查询乙 > …`
- 可指认的变化：**甲（approaching，+0.05）上移到第 1、乙（avoiding，−0.05）下移到第 2**；
  二者 `score` 相差 0.06，而 `emotion_bonus` 各 ±0.05 ⇒ 相对次序翻转（0.12+0.05 > 0.18−0.05）。
- 同号对照（丙、戊 均 stable，`|d2_mean| ≤ ε`）**次序不动**——证「翻转」是由符号（读数）驱动，非位置扰动。

**断言非空转自证（`--self-proof`）**：未变异时「默认关 == 未引入口径」= `True`；
变异「忽略开关恒开」后「关态 ≠ 未引入口径」= `True`（**断言①有判别力、非空转**）。**自证 PASS**。

## 五、局限与不确定项（如实）

1. **甲的正向腿是「构造场景」而非在役库实况**：观测期真实信息差信号会出现 `d2_mean` 贴近阈值 / 同号并列等形态，
   本探针给的是**判别力上界**（异号且 `score` 间距 < 2ε 时必然翻转）；真实数据下的翻转频率属**观察期读数**，本轮不测（无在役库）。
2. **乙的六源命中数是「播种库」读数**：播种以「令各源有机会命中」为目的（法同 `test_goal_gen`）；
   在役库的真实命中分布与阈值敏感性属**观察期读数**，本轮不测（不碰在役库）。
3. **`d_meta_bonus` 本环境 = 0.0**：`d_meta.compute` 在本隔离库返回不可用/空转（query 无关代理、库内无 `unmodeled_growth`），
   故两态 `sort_score` 的差**全部来自 `emotion_bonus`**——这使对照更干净，但也意味着本读数未覆盖 `d_meta` 与情绪加分的叠加形态。
4. **`ε` 的标定未做**：`ε = D2_EMOTION = 0.05` 是**沿用既有常量**（不新造量纲），其取值是否合适属**裁定第 10 条**的标定项，本轮不动。
5. **`apply` 侧（落库/入队/丢弃）本轮只测 dry-run**：`created/queued/refused/forbidden` 的**真落点行为**在本步只经 dry-run 的计数器观测（全 0）；
   真 `apply` 的行为已由既有 `md_cg/test_goal_gen.py`（C7–C12）覆盖，非本步范围。
