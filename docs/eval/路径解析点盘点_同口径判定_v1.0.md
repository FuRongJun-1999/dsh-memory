## 0. 判定口径（三档，本盘点只用这三档）

| 档 | 含义 |
|---|---|
| **同口径** | 两侧对同一输入落同一路径（或同一锚点语义 + 同一进程 cwd 前提下同一落点）。 |
| **分叉（本件修）** | 两侧对同一输入落不同路径，本次改动把它收敛。 |
| **分叉（未修，已登记）** | 同上，但不在本件改动面内，逐条给未修理由与去向。 |
| **无对照** | 该入口只在一侧存在（另一侧无消费者），无「同口径」可对。 |

「同口径」的判据一律落到**波浪线形态**与**相对值锚点**两格，因为 N117 记录的分叉只出在这两格。

## 3. `~user` 残留分叉的处置（方案 a，双侧对称登记）

维护者对 §二格 1 给两案二选一。**本件取 (a)：两侧都不展开 `~user`**。

实测依据（同一台机器，`os.name == 'nt'`，`USERNAME=Zs`，`USERPROFILE=C:\Users\Zs`）：

| 形态 | 改前 `ntpath.expanduser` | 改前 `posixpath.expanduser` |
|---|---|---|
| `~user` | `C:\Users\user`（**不论账号是否存在都拼用户名**） | `~user`（查不到账号即原样） |
| `~abc` | `C:\Users\abc` | `~abc` |
| `~\x` | `C:\Users\Zs\x` | `~\x`（不把 `\` 当分隔符 ⇒ 走 `~user` 查账号 ⇒ 失败即原样） |

⇒ 同一份 env 在两端落点**随平台与账号而变**。(b)「两侧都展开」要求两侧都能做同一种「查账号库」查询，实际做不到（ntpath 不查、posixpath 查）；故取 (a)，把「两侧同留字面量」钉成不变量。

**双侧对称登记位置**：node 侧在 `src/lib/datapath.ts:99` 的 `expandHome` docstring；python 侧在 `md_cg/datapath.py:84` 的 `_expand_home` docstring。两侧互为指路。

**收敛代价（如实）**：POSIX 上 `MDCG_ROOT=~ybyz/mem` 从「展开成 `/home/ybyz/mem`」变成「原样 `~ybyz/mem`」；Windows 上 `~ybyz/mem` 从 `C:\Users\ybyz\mem` 变成 `~ybyz/mem`。该形态在两侧都不再自动指向别人家目录，需写全路径。

**`~\x` 一格的有意收敛**：改前 POSIX 的 `posixpath.expanduser('~\x')` 不展开（把它当 `~user` 查账号失败），node 侧（N167 先例）展开。本件把 python 侧也纳入 `~\` 判据 ⇒ 两侧一致（都展开）。这一格是**有意收敛**，不是回归；两侧 docstring 均已登记。
