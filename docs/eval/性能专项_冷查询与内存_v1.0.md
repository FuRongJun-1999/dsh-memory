## 一、背景与基线

### 1.1 生产冷态基线与根因（cProfile 引证）

- **冷态首查**（OS 文件缓存冲刷后）：`search` **61.7–200s**；**热态** 0.12–0.79s。
- cProfile 根因定位：单次冷查 **13,884 次 `_read` 累计 61.2s**，其中
  - `TextIOWrapper.read`（文件 I/O）**45.3s**；
  - `os.path.realpath`（路径规范化）**13.5s**（27,766 次调用）——占 61.2s 的 **22%**。
- 读缓存缺省已开（`md_cg/readcache.py:40-43`，`MDCG_READ_CACHE` 未设即 `enabled()==True`；本会话已核实该行），故热态 0.12–0.79s 已由既有优化覆盖；冷态首查仍全量走「open + realpath + parse」。
- 对照参考（既往同口径优化）：读缓存批次 14 per-path 精确失效 **35.8×**、MdStore 预计算 **148×**。

### 1.2 临时复现库基线（先测后修）

| 复现库 | 规模 | 口径 | 修前实测（修复会话） |
|---|---|---|---|
| `_md_cg_perf_warmup/cgroot` | 3200 池 / 10.23MB | 进程冷态（新进程首查） | search#1 = 5.456 / 1.578 / 1.574s（首轮含 OS 缓存冷启），热查 0.032–0.033s |
| 8000 文档 store×3 副本 | 全池扫描 496,002 词事件/查询 | 进程冷扫 | T3 全池冷扫中位 3.053s（HEAD 纯净） |

- 本测（3200 池）cProfile：`_node_disk_path` 子树 **0.301s cum**（候选评估测次；修前基线测次 0.303s cum，其中 realpath 本体 0.286s），占 `_read` 子树 45–48%、**全查 ~11%**；realpath 调用 **6400 次/冷查**（每读 2 次 × 3200 节点）。
- 本测（8000 文档）cProfile：**73% 耗时在 `_score`/`normalize_en`**——`_norm_word` **498,446 次/冷扫**、cum 1.301s，str 方法调用 **348.9 万次/冷扫**；readcache 已缓存文档级派生物（`_doc_norm_bigrams`，`readcache.py:25-28`）但仅限本进程，冷态首查仍逐词全量重算。

- 缓存足迹最大单项为 `_norm_bigrams_cache`（文档级归一 bigram），占读缓存足迹 **67%**（引用画像 64.1MB）。
- 外部报告的「45.8GB 内存失控」待复现/否证（结论见第五节：**未复现，无失控证据**）。

## 二、修复面与实现（定稿 4 候选，实际实施 3 项）

### 2.1 realpath 缓存（候选 a，定稿采纳，优先级 1）✅ 已实施

- **target**：`_node_disk_path`（修前位置 `md_cg/mdcg.py:1320-1327`，HEAD 版 7 行实现）每读 2 次 `os.path.realpath`（修前 1321-1322 行各一次）——改为 root realpath 进程内解析一次 + 每 rel-path 解析结果 memo 化；失效口径复用 `readcache._fresh` 的 per-path 哨兵（批次 14 纪律同源）。
- **rationale**：双数据集支持——本测 3200 池 6400 次 realpath/次冷查（0.301s cum，占 `_read` 子树 45%、全查 11%）；生产真冷态 27,766 次/13.5s = 61.2s 中的 22%。缓存后每读 realpath 降为 1 次字典命中，纯确定性字符串复用，检索结果零变化（同输入同输出；修后须以 bench.py + 结果逐项对照复验）。
- **risk**：P2-20 越界断言语义必须保持——root realpath 一次性解析的进程内边界内，越界判定结果不变；symlink/junction 中途改挂的陈旧窗口 = 进程内一致性边界，须与 `readcache.py:29-30` 同款声明写入文档；修后跑 `test_readcache_prodpath.py` 等既有守卫。

### 2.2 `_norm_word` 词级 memo（数据新增目标，定稿采纳，优先级 2）✅ 已实施

- **target**：`normalize_en` 文档侧归一为纯函数链（`md_cg/mdcg.py:416` `strip_tense_en` / 修前 `:449` 内嵌 `_norm_word`），落模块级 word→归一结果 memo（可 LRU 封顶）。
- **rationale**：本测冷态首查 73% 耗时在 `_score`/`normalize_en`（498,446 次 `_norm_word`、348.9 万 str 方法调用/次冷查）；readcache 已缓存派生产物但仅限本进程，冷态首查仍全量重算。词级 memo 纯函数无行为漂移面，同时压缩冷态装配与未来任何缓存 miss 的重推导。
- **risk**：memo 按词精确键控（纯函数，同词同结果）零结果变化；内存增量 = 词表规模（远小于 `_norm_bigrams_cache` 的 64.1MB）；若加 LRU 封顶须注意热态 0.033s 依赖派生缓存，容量不宜过小。

### 2.3 `_read` 的 json 解析懒加载（候选 b，数据否决，不修）⛔

- **target**：`_read` 内 nodefile 解析改懒加载。
- **rationale**：实测占比过低——json decode 0.117s/2.75s≈4%（`nodefile.loads` 整体 0.238s=8.6%）；且 readcache（`readcache.py:102-113`）已把解析产物按 path 缓存为进程内一次，懒加载只能再省首查的这一次解析，收益上限即这 4%。
- **risk**：懒加载 fm 语义有行为漂移面（调用方就地改 fm 的模式），收益/风险比不支持，明确不修——修了属无数据支撑的改动。

### 2.4 读缓存装配增量化（候选 c，数据否决，不修）+ 内存上限备忘 ⛔

- **target**：读缓存装配增量化。
- **rationale**：实测装配无独立成本面——`readcache.install`（`readcache.py:62-131`）是 O(1) 包装，填充按节点在读时懒进行（init 0.015s；冷查 1.37–1.66s 与 `READ_CACHE=0` 的 1.28–1.97s 在噪声内重合 = 装配零额外开销）；内存 9.4× 正文、线性于 N 且 45.8GB 未复现，无失控证据。
- **risk**：若未来生产内存水位告急，杠杆是 `_norm_bigrams_cache`（占缓存足迹 67%）做 LRU 封顶——但会侵蚀热态 0.033s 基线，须带修前修后同口径计时再动；本轮作为备忘记录而非修复项。

> 合计：**实际实施 3 项**（候选 a、词级 memo、以及候选 b/c 的数据否决裁决执行），否决 2 项不做。
