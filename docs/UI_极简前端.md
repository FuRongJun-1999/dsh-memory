# 灵枢极简前端（可选增量包）

> 这不是插件本体，也不随 npm 包分发。它是一份前端增量：给已安装的灵枢插件补一个可视化侧栏页面。

## 它解决什么

issue #625：「我其实想看看记忆了哪些内容，但是没有可以看的地方」。
灵枢的记忆面一直是 MCP 工具面（cg / stg），命令行能用、但看不见；本包补的是同一份数据的浏览与操作页面。

## 位置与内容

    ui/minimal/
      install.ps1        安装器（先检查兼容性、再落盘、可卸载）
      payload/           前端页面与同源接口代码（app.js / style.css / index.html / client.js）
      integrity.json     文件完整性清单
      LICENSE            MIT
      使用说明.md         给使用者的安装与边界说明

## 安全边界（重要）

- 不含任何人的记忆、路径、密钥、令牌、profile；服务端复用接收者自己已配置的 MdcgClient 大脑桥；
- 不改认知图 root、身份主体、自动记忆开关、MDCG_TOKEN、DSH profile 或凭据；
- 权限与护栏沿用原插件：页面依赖 DSH 宿主的 connection.admit 鉴权，不兼容宿主会明确报错而不是降级开放；
- 安装器只在本次进程使用 -ExecutionPolicy Bypass，不修改系统执行策略；卸载只恢复自己备份过的代码，不动记忆。

## 安装（Windows）

1. 先安装并启用原版灵枢插件；
2. 完全退出 DSH（含托盘后台）；
3. 解压 ui/minimal/，双击 安装UI.cmd（或 powershell -File install.ps1 -CheckOnly 先检查）；
4. 重启 DSH，左侧点「灵枢」。

## 验证范围（如实写）

- 原实现：8 项接口测试、真实只读认知图页面交互、390px 响应式、DSH 客户端模块图与受保护路由挂载——均已通过；
- 安装器：在临时插件副本验证兼容性检查、安装、幂等、不兼容拒绝、安装后变化防覆盖、卸载逐文件恢复、记忆/paths/profile 哨兵不变；
- 未验证：0.9.x（含 0.9.11）跨版本实测、跨机器实测、已登录桌面 GUI 的最后点击链路（由使用者自行确认）。

## 为什么放在仓库里而不是 npm 包里

它修改的是已安装插件的前端文件，属于部署后置步骤；放进 npm 包会让「安装插件」和「打补丁」两件事混在一起，
升级时也更容易互相覆盖（使用说明里的升级流程要求先卸载 UI 再升级插件）。
