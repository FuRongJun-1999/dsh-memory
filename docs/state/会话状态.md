# 会话状态（**状态别放在话里，放进文件**）

> **用法：每轮开头读本文件；每轮结尾更新；条目的「完成」必须附 `receipts/<name>.json`。**
>
> 为什么有本文件：本会话实测痛点 —— 上下文被压缩 · 靠记忆转述导致「上游读数照抄」≥3 次 ·
> 「已推送」而 push 实际失败 · 「§7.2 五条」而实际七条。**状态放在话里就会随上下文丢失或走形。**
>
> **与仓内既有「状态文件」的区别（免得后人以为又造一个轮子）**：
> `src/lib/hook_audit.ts:11`（小 JSON 审计状态）与 `src/lib/session_state.ts`（运行期会话状态单点）
> 都是**机器用的运行期状态**；**本文件是人读的会话级状态文档**，对象不同、不重复。

## 规则⑤的可判形态（超出四件套时的两类例外与各自判据）

规则⑤：**默认四件套（一块 + 一条配置 + 一条自检 + 一行文档）；超出时必须逐处说明理由，
且超出的每一处必须属于下列两类之一。**

| 例外类 | 判据 | 实例 |
|---|---|---|
| **会造成回归** | 必须给出**具体回归**（不是「可能」） | #490：只改服务端 ⇒ **合法前端被打成 403**（角色详情面板与翻译面板） |
| **机械连带产物** | 由**登记/重生成/版本控制等机械规则**产生，且**不含该功能的任何逻辑或判据** | ① `WORKSPACE_INDEX.md` 重生成（纪律 #18）② `receipts/.gitkeep`（空目录不入库） |

⇒ 反例（**不得**算连带）：某处**含该功能的逻辑或判据** ⇒ **必须计入上限**。
（本会话形式：登记项不带理由＝免死金牌；此处同理，**「把逻辑说成连带」是绕过规则⑤的路径**。）
