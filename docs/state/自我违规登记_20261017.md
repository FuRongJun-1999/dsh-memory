## 违规 1：提交面污染（`8a1a06db`）

**现象**：提交 `8a1a06db`（message 为「#431 随动 2：U01 守卫消除裸迭代点」）实际含 **3 个文件**：

```
md_cg/insight.py                                          |  18 +-     ← 不是我的改动
md_cg/test_issue431_432_468_protect_single_point.py       |   4 +-     ← 我的改动
md_cg/test_issue433_outlook_threshold_single_point.py     | 278 ++++++ ← 不是我的改动
```

`md_cg/insight.py` 与 `md_cg/test_issue433_outlook_threshold_single_point.py` 是**另一条会话线（DSH 端「大脑仓长期波」，hive job `h_dsh端_大脑仓长期波_输出单元_0275`）**的产出——它在我提交前 4 分钟用 `git add` 把它们放进了 index。

**根因（条件层）**：`git commit` 的判据面是**整个 index**，不是「我刚 `git add` 的那些路径」。我的前置检查只做了「`git add -- <显式路径>`」，**没有在 commit 前核对暂存集 == 预期集**。缺失的判据＝**提交前 `git diff --cached --name-only` 与预期文件集逐项比对**。

**后果**：
1. 提交信息与实际内容不符 ⇒ `git log --grep #433` 会以为 #433 已修而那条 message 没写它（检索面污染）。
2. 抢走了另一条线的暂存集 ⇒ 它的 `git commit -m "fix(#433 ...)"` 会因 nothing to commit 失败（其 `fail_fast=false`，后续 push 仍会执行并带上我的三个提交）。
3. 那条线跑全量测试时本端在写文件 ⇒ 它的全量读数**不能**当作冻结树基线。

**补救（已做/待做）**：
- 已核：`insight.py` 的 #433 修复本身可用（`md_cg.test_issue433_outlook_threshold_single_point` 8/0 绿）。
- 不改历史（`amend`/`rebase` 会与那条线随时可能发生的 push 抢 index 与历史）。
- 用后续一条 docs 提交如实登记本事实。
- **后续所有提交改用 `git commit --only -- <显式路径>`**：`--only` 只提交指定路径的**工作树内容**，**完全忽略 index 里别人的暂存**。这是本违规的机械修法（比「先核对暂存集」更强：不依赖人工比对）。

## 违规 2：同面并行未先判避让

**现象**：我在编排 issue 面修复工作流前，**没有先核「本仓是否已有另一条线在做同一交付面」**。DSH 端「大脑仓长期波」的 hive 作业从 10:47 起就在同一仓、同一批 issue 上跑（#433 提交作业进行中），而我在 10:44 就启动了覆盖全 issue 面的工作流。

**根因**：缺失的判据＝**开工前查 `hive/jobs/` 与在飞进程**（`_serve.json` 的 pid + `jobs/*/status.json` 的 state=running）。仓内已有现成的观测面，我没有读。

**影响**：两条线会同时改 `md_cg/` 面；若撞同一文件会产生互相覆盖的竞态。当前已核的写面差异：那条线提交 `insight.py` + 两个测试件；本端工作流的单元清单不含 `insight.py`（U01 已完成），**主要撞面风险在 `md_cg/{mdcg,mdcos,mcp_server,writepipe,protect}.py`**——那条线本轮 spec 未涉及这些，但后续作业可能涉及。

**处置**：
- 本端工作流继续（用户最新指令优先于旧的分工约定），但**只改不撞面的文件**；一旦发现撞面，立即停手并登记。
- 本端**不做 git commit / push**（工作流派工书红线已禁止子单元提交）；收尾时若那条线已 push，则本端的改动需重新对基线核一遍。
- 冻结树读数只能在**两条线都停下之后**取。

## 教训（可复用纪律，待写入认知图）

**「`git add -- <路径>` 限定了要加什么，但不限定 `git commit` 提交什么。」**
提交前必须核对**暂存集**（`git diff --cached --name-only`）与预期集逐项相等；在多会话共用一个仓的场景下，index 是**共享可变状态**，任何一条线的 `git add` 都会影响另一条线的 `git commit`。
