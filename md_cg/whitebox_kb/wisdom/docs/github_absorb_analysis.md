# GitHub 高星项目吸纳分析（自迭代·外部感知，2026-09）

**原则（荣）**：稳态≠停止自迭代——内部与外部始终存在信息差；外部存在
大量「有价值但未明确理论化/规范化/未声明适用条件与不适用条件」的工程
项目。自发查看高星项目，值得吸纳的进行吸纳、学习。

## 项目与映射

### 1. langchain-ai/langgraph（★40k）——图状态机编排
**核心实践**：
- **Durable execution**：agent 跨失败持久化，从断点恢复（checkpointing）
- **Human-in-the-loop**：执行中可检视/修改状态（interrupts）
- **Comprehensive memory**：跨会话记忆
**未理论化点**：这些是「工程能力」但未声明适用/不适用条件——
   checkpoint 何时该用？interrupt 的适用边界？
**吸纳**：
- 白箱工作流（§17）缺 **持久执行**——执行计划应支持断点恢复（失败后
  从已完成节点续跑，而非重头）
- 缺 **人在环中断**——escalation 的 DEFER 应支持「暂停等待人工裁决」
  （不只是 BLINDSPOT 终态）
- 未声明条件：checkpoint 适用 = 长时/跨会话任务；不适用 = 短时单步

### 2. FoundationAgents/MetaGPT（★70k）——SOP(Team)=Code
**核心实践**：`Code = SOP(Team)`——SOP 物化为「角色 × 流程」；
  产品经理/架构师/工程师分工协作。
**未理论化点**：SOP 本身是隐式流程知识——未声明「什么条件下用哪个角色
  流程、各角色的不适用边界」。
**吸纳**：
- 白箱执行计划（§9）只有单执行者；MetaGPT 启示：**角色分工层**——
  任务可按「角色条件」路由到不同能力（我们已有域/单元分层，可加
  「角色」维度：设计者/验证者/执行者）
- SOP = 可复用工作流模板——与 §17 工作流 JSON 序列化同构（已实现）

### 3. topoteretes/cognee（★30k）——agent 知识图谱记忆
**核心实践**：数据任意格式摄入 → 自托管知识图谱 → agent 跨会话召回。
**未理论化点**：图谱构建/召回未声明适用条件（什么数据该入图、什么
  该直存）——盲区3 条件完备性在记忆层的体现。
**吸纳**：
- 白箱已有 lingshu 记忆（知识层/情境层）；cognee 启示：**结构化摄入
  管道**——外部知识先结构化（MOS 声明）再入图，而非裸文本
- 与 §16 MOS 联动：外部项目代码 → MOS 提取 → 入知识图谱

### 4. anthropics/skills（★171k）——Agent 技能规范
**核心实践**：SKILL.md 文件夹 = 指令 + 脚本 + 资源，动态加载提升
  专项任务表现。
**未理论化点**：技能加载未声明适用条件（什么任务该加载哪个技能）——
  正是我们的条件路由要解决的。
**吸纳**：
- 白箱 skills.json 已是雏形；anthropic 启示：**技能 = 目录化 + 元数据**
  （SKILL.md 含 name/description 元数据）——我们应给技能加
  `适用条件/不适用条件` 元数据字段（条件路由加载）

## 本轮落地：技能条件化（anthropics/skills 吸纳）

skills.json 升级：每条技能声明 `适用条件/不适用条件`（条件路由加载）：
```json
{"skill": "不适用条件-隐式盲区显式化",
 "适用条件": ["负面测试发现返回默认值的漂移"],
 "不适用条件": ["真异常(强拒绝)——那是诚实声明非盲区"],
 "pattern": "..."}
```
