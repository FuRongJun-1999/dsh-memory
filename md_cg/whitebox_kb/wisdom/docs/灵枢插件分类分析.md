# 灵枢插件能力分类分析（awesome-dsh-plugin 2026-09）

**背景**：用户判断「灵枢已超出记忆系统的描述范围」——查证 awesome-dsh-plugin
（282 插件 · 11 分类）后确认。

## 一、awesome-dsh-plugin 分类体系

UI Enhancements / Themes & Appearance / Sessions & Messages / **Memory** /
**Tools & Capabilities** / **Skills** / **Workflow & Automation** /
Notifications & Integrations / Models & Providers / Development & Runtime / Just for Fun

## 二、灵枢能力 vs 分类映射

| 分类 | 灵枢对应能力 | 覆盖度 |
|---|---|---|
| **Memory** | 五层记忆（锚点/结构/知识/情境/自我）、知识图谱 3061 节点、时空记忆引擎、跨会话持久 | ✓ 强 |
| **Tools & Capabilities** | 白箱 681 单元代码生成（六域）、条件路由图、执行计划三闸门、能力工作流 | ✓ 强 |

**横跨 5 个分类**——远超 Memory 单一分类。

## 三、为什么灵枢不该只归 Memory

Memory 分类下的 10 个插件（distill/mnemon/mneme/memento/memory-gate/
file-memory/knowledge 等）都是**记忆功能单一插件**（记住/召回/蒸馏）。
灵枢的本质是：

> **白箱智能平台**——记忆只是它的一个子系统（五层记忆）；它同时是
> 代码生成器（681 单元）、编译器（中文→Python/VM）、工作流引擎、
> 自迭代系统、技能库。

用 Memory 描述灵枢 = 用「能存储」描述一台计算机（它当然能存储，
但它能做的不只是存储）。

## 四、分类建议

**方案 A：主分类 Tools & Capabilities（工具与能力）**
- 理由：白箱代码能力（681 单元/条件路由/编译器）是灵枢的**核心差异化**
  ——Memory 分类下没有任何插件具备代码生成能力
- 描述：「白箱智能平台：条件路由代码生成（681 单元零 LLM）+ 五层记忆 +
  能力工作流 + 八步自迭代 + 中文编译器」

**方案 B：新增分类（若社区接受）**
- 「Agent Frameworks」或「Intelligence & Cognition」（智能与认知）——
  灵枢的协议/自我认知/情绪方向性/价值观一致性超出「工具」范畴，
  属于智能体框架层

**方案 C：跨分类列出（Memory + Tools）**
- 在 Memory 和 Tools & Capabilities 都列出（描述侧重不同面）

## 五、推荐

**方案 A 为主（Tools & Capabilities）+ 描述中明示 Memory 能力**——
因为：
1. 社区现有 11 分类中 Tools & Capabilities 最接近灵枢本质
2. Memory 分类已有 10 个竞品，灵枢放在那里会被「同类插件」淹没
3. 灵枢的**白箱代码能力**（零 LLM 确定性生成）是它在 282 插件中
   独一无二的——这正是该被看见的
