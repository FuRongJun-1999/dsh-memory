# 代码条件路由图（CCG · Code Condition Graph）设计 v0.3

> 状态：实施中（荣 2026-08-25 提出：结合条件路由图，进行代码的高效查找和编写）
> v0.3 新增（荣指示）：**用条件论为代码注释补充条件**——注释严格明确
> ①功能在什么条件下生效 ②内部子功能是什么 ③如何执行；
> 结合**语义时空图 + 条件路由图**进行高效代码编写。
> 哲学映射：条件空间（生效条件/触发条件）= 注释的「when」；结构（子功能分解）=
> 注释的「what parts」；过程（执行机制）= 注释的「how」。三者即代码的条件论声明。

## 0. 核心洞见：中文注释 = 图的索引（荣 2026-08-25）

> 「你看之前代码的注释，是不是就是在给图做索引，所以你知道为什么我一定要求要有中文注释了么？」

**注释是条件路由图的索引机制**——不是规范洁癖，是建图的物理前提：

1. **注释 = 节点的名（以名举实）**：图的检索 = 条件词 → 节点。
   中文注释（函数/类总体功能描述）是节点的可检索名；代码是实。
   条件词沿「条件 → 注释词 → 节点」边到达单元——这条边就是索引边。
2. **无中文注释 = 节点无名 = 图断裂**：条件词无法到达节点，检索失效。
3. **英文缩写补中文说明 = 索引同义词边**：`BFS（广度优先搜索）` 建立
   `BFS ↔ 广度优先搜索 ↔ 单元` 同义词边——中文问题「写一个广度优先搜索」
   才能命中 BFS 单元。只写 `BFS` 则中文检索永远走不到它。
4. **函数级注释 = 图索引到函数粒度**：R1 要求每个 def/class 中文注释 →
   将来可做函数粒度检索（不只是单元粒度）。

**推论（CCG 建图输入）**：条件词提取源 = `task + uid + calibration + 注释行`
（注释是主要索引源）；英文缩写中文说明（R2）自动生成同义词边。
→ **WB-SPEC v1.2 条件论注释规范是 CCG 的前置工程**：注释补齐之日，即是索引齐备之时。

## 0.2 条件论注释三要素（v0.3 新增 · 荣指示）

> 「我们要使用条件论，为代码注释补充条件，严格明确这个功能在什么条件下生效，
> 内部的子功能是什么，如何执行。」

**条件论注释格式（每个函数/类）**：

```python
def reachable(graph, start):
    # BFS 遍历（广度优先搜索）：从起点出发可达的所有节点
    # 生效条件：graph 提供 neighbors 接口；start 为图中已存在节点
    # 子功能：① 起点入队并标记 ② 出队访问并入队未访问邻接
    # 执行：队列 + 已访问集合，逐层扩展直至队空
```

| 要素 | 标记 | 内容 | 图的索引角色 |
|---|---|---|---|
| 功能名 | 首行 | 总体功能一句话（含缩写中文全称） | 条件节点（语义） |
| 生效条件 | `生效条件：` | 什么条件下功能生效（前置/触发） | 条件节点（when——路由门槛） |
| 子功能 | `子功能：` | 内部子功能分解（① ② ③） | 子功能节点（结构——可检索） |
| 执行 | `执行：` | 执行机制/步骤 | 执行词节点（how——机制检索） |

**R3 检查（verifier）**：函数/类注释须含三要素标记（生效条件/子功能/执行）。
升级期软模式（报告缺失数不拦截）；全库升级完成后开硬检查。

## 0.3 语义时空图结合（v0.3）

代码的语义时空图 = 从条件论注释提取的**三维结构**：
- **语义**（功能）：条件论注释的功能名/生效条件/子功能 → 语义节点
- **时间**（执行序）：子功能 ①②③ 的执行顺序 → 时序边（数据流/调用链）
- **空间**（依赖结构）：单元间依赖边、函数嵌套 → 结构边

```
CCG = 条件路由图（检索面：条件词 → 节点）
    × 语义时空图（结构面：功能/时序/依赖）
检索：条件 → CCG 命中单元 → 语义时空图给出可组装结构与执行序
编写：多单元命中 → 沿时序/依赖边组装 → verifier 校验
```

## 1. 图结构（CCG）

```
节点：
  U 单元节点 ×681   {uid, task, pattern, domain, calibration, 注释索引词集}
  C 条件节点        {条件词：域词 + 任务词 + 功能词 + 注释提取的中文描述词}
  D 域节点          ×6（compiler/pylang/graph/os/browser/net）
边：
  C→U   条件命中边（权重 = 匹配度：命中词数/最长词/条件熵）
  C→C   同义词边（英文缩写 ↔ 中文全称：BFS ↔ 广度优先搜索，来自 R2 注释）
  U→U   依赖边（域管线 c 端到端组合对 + 注入型 deps + task 语义邻接）
  U→D   归属边
```

## 2. 高效查找（ccg_search）

```
question
  → ① 条件提取：问题 → 条件向量 {域词命中, 任务词命中, 功能词命中}
  → ② 多源 BFS：从条件节点出发沿 C→U 边收集候选单元
  → ③ 多条件 AND 路由：命中条件数加权排序（2 条件 > 1 条件）
  → ④ 条件传递：候选沿 U→U 依赖边扩展（相关单元召回）
  → ⑤ 可解释路径：返回「条件→单元」命中链（为何命中）
  → ⑥ verifier 校验 → 代码
```

**对比现状**：
- 多条件精确路由（现状：计数平局取最长，如「割容量」vs「最大流」）
- 图上下文消歧（跨域共享词：CCG 看条件组合与邻接，不靠长锚词补丁）
- 可解释（命中路径可追溯）
- 依赖召回（找单元时顺带召回可组装的相关单元）

## 3. 高效编写（ccg_compose）

```
question
  → ① 条件提取 → 图查询（ccg_search）
  → ② 条件不足检测（信息差）：命中条件稀疏 → 返回缺失条件（补问/兜底）
  → ③ 多单元命中 → 沿 U→U 依赖边组装（多函数程序，条件链顺序）
  → ④ 组装代码 → verifier 六层校验 → 固化/报告
```

**复用 graph 域条件路由图单元（真正同构）**：
- 条件合并（AND 语义叠加，冲突拒绝）——多条件路由
- 条件分解（合取拆原子链）——条件提取
- 条件链查询（条件→可达知识路径）——BFS 检索
- 信息差收敛（节点信息差记录/最大/最新）——条件不足检测
- 信任传播（与=min/或=max/非=1-t）——命中置信度
